# Rivu GUI 验证

## 目标与边界

运行真实 Rivu GUI，让输入经过待验证路径；截图证明实际界面，状态断言证明行为和副作用。编译、单元测试、进程存活均不能单独作为 GUI 交互验收。

本 skill 是项目验证流程，不附带已安装的输入工具或自动化框架。先发现现有工具和任务产物，再复用；历史 `.cache/` 辅助程序可能已经清理，不能假定存在。

通用流程见 [GUI 验证](skill://gskd-gui-verification)，视觉与资源对照见 [比较方法](skill://gskd-gui-verification/references/visual-comparison.md)。本文件仅为 Rivu 的 GPUI/Wayland 适配，非所有项目的默认路线。

当前行为以仓库根目录的 `doc/01_config.adoc`、`doc/23_visuals.adoc`、`doc/22_cache.adoc` 及相关实现为准；布局问题补读 `doc/24_layout.adoc`。这些是 Rivu 项目路径，不是 Skill 内文件；不要把这里的历史案例当作当前实测。

## 推荐组合

| 路线 | 用途 | 验证边界 |
| --- | --- | --- |
| 嵌套 niri＋Wayland 输入辅助程序 | 日常主线；普通点击、键盘、拖放、resize、物理缩放、失焦 | 输入经过 compositor 与 Wayland；不等价于真实桌面宿主、IME或多显示器 |
| GPUI 窗口级事件注入 | 精确诊断输入框、下拉框、快捷键、焦点、事件消费 | 覆盖 GPUI 收到事件后的路径，不覆盖 compositor 输入交付、硬件输入和 IME |
| 真实桌面点检 | 托盘图标与菜单、Raise、关闭后重开、IME、多显示器 | 宿主集成必需；受锁屏、焦点竞争、用户操作影响 |
| Weston headless | 无可用桌面时的备用；固定尺寸页面、截图和点击隔离 | 仍运行真实 GUI；窗口管理与性能不能推定等价于日常桌面 |

Weston VNC/RFB 不作为常规维护路线。仅在已有远程设施、能减少本次验证成本时使用；限制本机访问或使用安全传输，不新增无认证的外部监听。

不要在不同路线重复维护完整场景集。复用隔离数据、输入辅助、截图和状态采集；按问题选择必要层次。

## 执行流程

### 1. 明确验收与路径

- 将用户问题写成可观察结果，列出初始状态、操作、期望变化和不应发生的副作用。
- 阅读相关实现、已有行为测试及权威文档，复用项目约定。
- 区分 UI 缩放、物理输出缩放、逻辑窗口尺寸；几何问题不能只改一个尺寸代替全部验证。
- 用户已报告的错误视为事实；需要定位触发条件或建立修复前对照时，做有目的的复现，不为确认用户说得对重复检查。修复后用相同初始状态和操作验证；旧构建不可运行时明确缺少运行前对照，不虚构结果。

### 2. 准备隔离环境

- 查询可用 compositor、截图和输入工具；读取当前显示环境、实际套接字和工具帮助，不硬编码历史显示名、PID或坐标。
- 全部任务数据和构建产物置于仓库 `.cache/`；创建大产物前检查存储和 RAM/swap 余量。
- 使用任务独立的配置和数据目录，固定窗口尺寸、UI 缩放、字体、布局和必要媒体。播放样本保持静音，非桌面集成场景关闭 tray/MPRIS。
- 所有 GUI 与 CLI 客户端必须使用同一任务 `--data-dir`。`--config` 只在启动 core 时选配置，不会重配已运行实例。
- 隔离 compositor 使用独立 Wayland 套接字；niri IPC 必须指向同一隔离会话。不要让输入或截图命令误连用户桌面。
- 等待实际 compositor 就绪、对应 PID 的窗口出现及所需界面绘制完成；不要把无关日志或固定 sleep 当成成功证据。等待有界，优先状态同步。

应用启动形态：

```sh
# 所有路径和套接字均替换为本次已确认的值
WAYLAND_DISPLAY="$SOCKET" "$BINARY" \
  --data-dir "$DATA" --config "$CONFIG" gui
```

### 3. 输入与观察

**嵌套 niri 主线**

- 通过现有 Wayland 虚拟指针和键盘辅助程序输入，使用 niri IPC 控制任务窗口尺寸、输出缩放和焦点。
- 坐标依据当前截图或测量确定，明确逻辑坐标与截图物理像素的换算。
- 在关键状态截取实际表面并查看：操作前、预览中、操作后。截图命令成功不代表画面正确。
- 输入辅助的完整操作序列必须覆盖按下、移动、释放；必要时验证 Escape、离开窗口和失焦取消。

**GPUI 精确诊断**

- 运行真实窗口，用 `Window::dispatch_event()` 注入鼠标事件，`Window::dispatch_keystroke()` 注入按键；让事件经过实际焦点、控件、action 和订阅路径。
- 可临时挂载任务专用 smoke hook，断言输入值、候选、高亮、弹窗和保存状态；不用常驻生产启动入口。
- 直接调用业务方法只能证明该方法的逻辑，不能宣称对应按钮点击已经验证。例如直接 `apply_settings()` 不证明 Apply 按钮的鼠标路径。
- 若普通 key-down 未收到 Enter，检查输入框 action／Submit 路径，不绕过事件处理以使断言通过。
- 移除 hook 后重新构建最终版本，并从 compositor 级输入补验关键路径。

**真实桌面集成**

- 定位任务窗口和实际宿主，避免操作用户的现有实例或修改用户配置。
- 锁屏时不绕过或操控锁屏；完成可达的隔离验证，将真实桌面验收单独标为受阻。
- D-Bus 属性、图标数据、菜单返回正常，不等于宿主中的图标、菜单和操作已验收。

### 4. 行为断言

选与变更相关的项目状态，不只判断非空、未崩溃或截图产生：

| 场景 | 必要观察 |
| --- | --- |
| 菜单／下拉框外部关闭 | 弹窗关闭，但底层 seek、toggle、选择不变；下一次正常点击仍能执行操作 |
| 字体搜索与键盘选择 | 大小写过滤、空格输入、导航、Enter确认、Escape关闭；配置与可见字体结果分别检查 |
| 拖放 | 预览目标与提交布局一致；取消或无效目标不修改布局；读取持久化布局确认结构 |
| resize／缩放中释放 | 旧预览失效；新测量前不得提交旧目标；新测量后正常拖放恢复 |
| 设置 Apply／Discard | 实际按钮路径正确；保存值或恢复值符合草稿与生效状态边界 |
| 窗口关闭／Raise | 关闭窗口后 core与播放保持；重新打开或Raise恢复窗口；Quit才停止实例 |

仅覆盖与本次变更有关的行及受影响邻接行为，不无条件执行完整矩阵。

可通过同一任务实例的 CLI 查询播放、队列和配置状态，或读取任务配置、`layout.json`。具体命令与 JSON 字段以当前代码／帮助为准，不照抄历史接口。

涉及资源变化时，按上述参考记录可比基线、重复测量与统计口径；截图、行为断言和资源数据分别下结论，不能互相替代。

### 5. 完成与清理

- 对可信的消费者可见 bug 保留确定性回归测试；截图坐标、临时 hook 和一次性取证优先作为 throwaway smoke，不建立脆弱的大型像素断言集。
- 有意义的行为／契约变化更新权威文档；纯视觉润色不机械添加验收记录。
- 用同一任务 data-dir 的 `quit` 停止应用；仅关闭 GUI 窗口不能证明 core退出。随后停止任务 compositor和输入辅助进程。
- 删除确认属于本次且不再使用的 hook、脚本、媒体、配置与数据库；截图和日志按取证需要保留，保持缓存有界。保留共享构建及归属不明的缓存。

## 交付证据

最终报告写明：

- 被验证的构建、路线、环境和场景。
- 操作经过哪一层输入路径；是否直接调用过业务方法。
- 实际截图观察、状态变化／不变及修复前后结果。
- 若比较视觉或资源变化：认可基准的来源、保持与改变的语义、可比条件及测量波动；无法对齐的历史数字只作线索。
- 未覆盖或受阻的平台边界。未执行的操作不能写成通过。

不要将“测试通过”“窗口启动”“截图完成”“交互通过”和“宿主集成通过”混用。
