# 设计取舍与完整接入

## 触发与边界

默认先检查当前实现、既有约定与本次目标；普通修复、机械迁移和已有明确实现路径的改动，不自动展开方案比较或完整设计评审。不为使用本 Skill 凑候选方案或制造设计疑点。

仅在用户要求方案比较、存在影响行为或维护成本的实质取舍、具体责任／生命周期／接入疑点，或重复失败需要换假设取证时展开。展开前明确本次要解决的取舍或疑点，只追受影响的责任链和必要边界；不免除受影响调用方迁移、失败处理和释放正确性的必要检查。

有两个入口：**比较方案**先给判断；**已授权改造**才追实现并修正。证据闭合且无新疑点就停止，不因已经进入评审而补齐无关检查。本 Skill 补充常驻规则，不替代或放宽它们；不依赖任务状态工具、扩展或自动派发。

## 入口一：比较方案

1. **问题**：说明现在的问题、证据和目标；区分代码事实、用户观察与待验证假设。能查到的现状先查，不让用户代查。
2. **实际改变**：说明每个候选改变什么行为、责任或数据流，与保持现状有何不同。文件变短、技术更新、外观相似都不能代替这个说明。
3. **收益与代价**：比较当前需求下的收益、实现复杂度和后续维护。性能方案必须问“代价搬到哪里”：是否把计算转成内存、缓存失效、同步、更新或释放负担？没有测量的收益仅作假设，不编造指标；测量细则交给当前项目适用的验证指南，不在这里另立一套。
4. **推荐**：给出推荐及不选其余方案的关键理由；收益不足时可以推荐不改。问句、补充说明、提及方案都不是迁移授权；未获授权就停在建议，不改代码。

## 入口二：已授权改造

1. **固定边界**：从用户要求与当前任务记录确认已接受目标、不变量、非目标和验收；把疑点写成可观察的失败条件。缺少影响正确性的授权时先停在该边界，不自行扩大目标。
2. **追完整链**：读实际实现，沿“真实入口 → 状态所有者 → 更新 → 失败／取消 → 释放 → 对外结果”追踪。明确谁创建、谁修改、谁收尾；按涉及的资源检查重复进入、部分初始化失败、退出后回调／任务／句柄残留。控件必须接到真实输入、状态与业务结果，不只是画出外观或提供未被调用的接口。
3. **核对接口与执行环境**：说明受影响接口是快照读取、cache-only 查询、阻塞加载还是排队命令，以及谁承担失效、结果提交和收尾。检查真实调用者所在的线程与生命周期，不能因已有入口方便就继承不合适的成本或状态语义：
   - render／property getter 不承担冷 I/O 或等待加载；若需冷加载，使用适合的既有后台路径，并核对完成通知与当前身份。
   - 长期 worker 不重复创建可复用的 runtime、连接和缓冲；复用时仍须处理失败、取消及不确定的修改结果，不能自动重放可能已执行的命令。
   - 单项变化不无理由地全量刷新或失效无关消费者；channel／ring 容量有界不代表 drain／refill 单轮工作有界。
   - owner 提供完整状态转换，避免让调用方通过可变 payload 自行拼接失效、加载、接受与恢复定位；只搬方法或加 getter 不证明责任已收回。
4. **覆盖调用者**：搜索同类调用点和旧入口，迁移所有受影响调用者，移除被替代的路径、兼容别名和过时说明。若某条路径仍有独立契约，说明保留理由，不能用兼容层藏遗漏。
5. **选择充分且克制的修正**：边界应对应所有权、独立变化或不变量；不为行数抽象，也不以少改几行为由留下割裂责任。优先复用现有约定，删除已失去用途的层。先删除已确认的重复工作，再为有证据的热点选择最小机制，不预设缓存框架或统一调度器。只搬代码或调低断言不能证明修复；纠正测试也必须保留原验收强度，契约变化需用户接受。
6. **交回验证**：从任务契约选出能证明真实接入、失败／取消与对外结果的检查，按当前任务授权执行或交给验证负责人；普通改动不因这些检查展开全项目评审。当前实现的证据才支持当前结论；历史通过、编译通过或截图外观都不单独证明整条链正确。

## 成本失衡时回溯需求

方案比较或实施中，新证据表明需求组合与当前约束造成不成比例的实现、运行或维护成本时，不只换实现手段，也重新评估需求取舍；不能仅因难做或代码变长就削减要求。

1. **定位成本来源**：先排除方案选错、重复责任，以及自行添加的兼容、通用性、极端规模或配置要求。能保持已接受行为的简化主动执行；不能把 agent 制造的复杂度转成用户必须牺牲的功能。
2. **回到用户目的**：区分必须保持的结果与可协商的手段、适用范围和边际能力，指出哪项要求造成主要成本及依据。数据正确性、安全和关键不变量不能包装成普通简化项。
3. **提出最小取舍**：推荐保留核心价值的调整，说明减少的成本、失去的能力及剩余风险。例如限制增强引导的适用范围而保留基础操作，而非为覆盖所有极端场景持续堆叠机制。没有测量的收益明确标为推断。
4. **接受后同步基准**：改变已接受的行为、精度、性能目标或范围，须由用户接受；更新任务与验收，标明被替代的要求并重新判断旧证据是否适用。待决定时停止依赖该取舍的新增复杂实现，不阻塞无关的已授权工作。

不因沉没成本硬做到底，也不以“复杂”为由省略必要工作。不擅自缩小范围，不等于不得质疑需求；完整交付是兑现双方最终接受的要求。

## 重复失败时

同类失败反复出现且没有新证据时，停止盲重试：保留具体失败证据，指出哪条假设被推翻，换一个可证伪假设并选择能区分原因的检查。不要通过换断言、缩小验收或吞掉异常使失败消失；也不自动换模型、改配置或按次数强制启动代理。是否需要独立诊断取决于证据和现有授权，不取决于固定计数。

## 产出与停止

- **比较方案**：问题 → 实际改变 → 收益／代价 → 推荐；授权未变就到此停止。
- **已授权改造**：问题与证据 → 责任链／修正及取舍 → 当前验证与未覆盖项。证据闭合且无新疑点即停止评审，不无限加审；若真实阻塞使链无法确认，说明缺少的条件、已完成范围和未验证结论，不宣称完成。
