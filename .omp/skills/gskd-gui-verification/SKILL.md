# GUI 行为与视觉验证

## 何时使用

默认先检查相关实现、调用链、状态与生命周期边界、现有测试，判断本次要求能否在代码层得到充分证据。涉及 UI 文件、控件、渲染代码或用户可见功能，不自动触发本 Skill；代码审查、内部重构及可由代码与针对性检查充分验证的逻辑改动，不因所属模块是 GUI 就启动界面。

完成代码层检查后，仅在以下情况进入 GUI 验证：

- 用户明确要求实际界面、交互或视觉验证。
- 本次验收依赖代码层无法证明的实际表面、输入交付或平台集成，例如布局／视觉效果、焦点、拖放、IME、窗口与桌面行为。
- 代码与现有测试仍留下具体 GUI 疑点，需要实际运行区分原因或确认结果；先写明疑点和待观察结果，不以泛泛的“证据不足”展开 GUI 全面审查。

只验证上述目标及受影响的邻接边界，不扩成全界面巡检。代码层证据不能替代已明确要求的 GUI 验收；无需 GUI 时也不将未执行的交互或视觉效果写成通过。本 Skill 是工作方法，不提供现成工具或新增实施授权。

## 判断与执行

1. **确定目标。** 写明初始状态、操作、期望变化和不能发生的副作用。用户认可的目标效果与修改前实现不是同一基准。接受用户报告；复现用于定位或建立对照，不用于反复确认用户是否说对。无法运行旧版本就标明缺少前对照。
2. **选择输入层。** 从目标项目的实现、测试和可用工具判断路线。控件事件注入适合精确定位，但不证明平台输入交付；真实浏览器或隔离桌面适合实际表面与交互；系统宿主、IME、多显示器等问题补真实环境。直接调用业务函数不能证明按钮可操作。无需在所有层重复全部场景。
3. **准备隔离。** 遵守本地存储和资源约束，使用任务独立的数据、配置、用户会话或浏览器上下文；确认应用、输入控制和截图指向同一实例。不要操作用户现用实例，不假定历史工具、端口或路径仍存在。固定构建、输入数据、窗口、字体及缩放；有界等待实际就绪，不以固定 sleep 代替成功条件。
4. **执行与观察。** 让输入经过待验路径，观察操作前、过程中与操作后的实际表面。拖动覆盖按下、移动、释放及相关取消路径。截图必须查看；后台状态与持久化结果只查询同一任务实例。动态显示检查时间过程，不只看一张静态图。
5. **检查正反结果。** 不只判断未崩溃、弹窗消失或图片产生。例如外部点击应关闭菜单但不误触底层控件，随后正常点击仍有效；取消拖放不改变布局；保存与放弃分别兑现草稿契约。具体预期从当前项目要求取得，不硬套其他项目。
6. **验证最终版本并清理。** 临时 hook 只用于诊断；移除后重新构建并补验关键实际路径。永久测试只保留真实行为回归价值。按目标应用的生命周期停止任务实例及辅助进程，不假定关窗口等于服务退出；只清理确认归属且不再使用的产物。

## 按需参考

- 外观回归、颜色／幅度变化、渲染优化和资源比较：读 [视觉与资源对照](references/visual-comparison.md)。普通控件不增加性能矩阵；文中的音频可视化例子是校准，不是所有 GUI 的需求。
- Rivu 的 GPUI/Wayland 实践：读 [项目适配](references/rivu-gpui-wayland.md)。niri 主线、GPUI 注入与 Weston 备用只适用于该环境，不是本 Skill 对所有项目的推荐。

## 产出与停止

简述构建及环境、实际输入层、表面观察、状态变化与不变、未覆盖项，给出证据位置。视觉、行为与资源收益分别下结论；未执行的操作不能写成通过。没有可用真实表面时，报告已经覆盖的层和具体缺口，不拿示意图、离屏图或测试日志替代。

本轮验收满足且没有新的实质失败证据就停止，不机械展开全部参考。平台验证受阻时完成可达部分；若该平台行为正是验收目标，明确阻塞而非宣布交付。Skill 的使用本身不证明验收成功。
