# 可视化保真与资源对照

只在视觉回归、渲染优化或资源对比时读取。沿用主 Skill 的环境隔离、输入路线和清理规则；不要求每次调整都测所有指标，不提供自动截图或基准执行器。

## 1. 先确定比较对象

区分两个基准：**用户认可的目标效果**决定正确性，**修改前的实现**用于说明差异和成本；两者可能不同。不能因为当前实现能运行，就把它当作认可的视觉基准。

- 从当前要求、会话中的原图、明确认可的版本或描述定位目标，记录来源。历史助手说“已恢复”不是用户认可或本次实测。
- 将“最初那种渐变”等表述拆成可观察特征：颜色起点与终点、逐柱还是共享映射、相邻柱差异、Peak 形态、历史连续性。不要自行补成实施授权。
- 先查本地会话与现有产物。仍有会影响方案的歧义时，只问那个差异；不要求用户重新讲完整需求。不明基准时可以取证，但不宣称已恢复。
- 固定基线和候选的源码身份（包括未提交改动）、构建参数和二进制身份。需要旧构建时用隔离 worktree，不 reset 当前工作区，不覆盖其他会话的构建。

当前行为以目标项目的权威配置、渲染、缓存与布局文档及相关实现为准，不在本参考维护参数默认值。Rivu 的具体入口见 [项目适配](rivu-gpui-wayland.md)；其他项目不要照搬其路径或生命周期。

## 2. 把语义与实现拆开验证

对受影响的路径区分三层：

| 层次 | 需要确认的事实 |
| --- | --- |
| 信号数据 | 样本、RMS、Peak、频带或历史数据是否改变；缺失数据不能伪装成静音或完整覆盖 |
| 几何／幅度映射 | 相同数据的高度、位置、连续性与时间顺序是否保持；颜色调整不能暗改幅度 |
| 颜色／绘制 | 调色域、端点、压缩、插值、透明度与离散标记是否符合目标 |

tile、Quad、LUT、批处理是实现手段，不能单凭名字推断视觉等价或性能更优。例如逐柱渐变改为共享垂直渐变，可能改变相邻柱的颜色关系；即使更快，也不能当作不改变效果的优化交付。Waveform 与 Spectrum 的职责不同，不为“统一”强行使用同一种映射。

选择能区分方案的少量输入：相邻不同能量柱检查局部映射，低／高能量检查调色端点；涉及数据覆盖时才补静音、未解码区间、seek 或重播。不要无条件穷举组合，也不要为了截图好看挑选隐藏问题的输入。

## 3. 获得可比较的画面

- 固定媒体、配置、面板数量与尺寸、窗口、字体、UI 和物理缩放、背景；记录 compositor、应用 renderer 和驱动差异。
- 动态显示按相同输入序列、预热阶段和观察窗口比较。seek 到同一秒不保证相同的平滑、Peak hold 或历史状态；必要时从一致初始状态重放。暂停只适合证明暂停后的画面，不替代播放中表现。
- 保留并查看基线／候选的实际截图，用相同裁剪与缩放比较。比较边缘、颜色和遮挡时不得为了对齐而重采样掩盖差异；动态时间行为需连续观察或关键帧序列。
- 图片差分可以定位区域，但抗锯齿、字体和 GPU 差异会造成像素变化；零差异不是唯一合格条件，截图相似也不证明交互或底层数据相同。
- 离屏图、合成示意图和业务函数结果须按其真实来源标注，不能冒充真实窗口。锁屏时使用可达的隔离表面；托盘、IME等真实宿主缺口仍单列。

## 4. 资源测量只比较同一问题

先写明假设：要减少的是重复解码、分配、几何构建、提交、驻留还是 GPU 存储？选对应指标；少了提交数不自动证明总 CPU 或延迟下降。

- 两个候选采用相同构建配置、媒体、布局、播放状态、预热和采样窗口。避免其他构建或验证并发污染结果；记录无法控制的环境差异。
- 时间与 CPU 比较做多次独立重复，交错基线与候选顺序，报告次数、代表值和范围／波动，不只挑最好一次或只报相对百分比。提升与波动相当时写“未观察到稳定收益”。
- 确定性分配／容量优化可报告相同工作负载下的次数与字节，不为凑性能报告制造计时实验。保留原始采样与测量命令，区分测得值、静态容量计算和估算。
- RSS、PSS、匿名／文件驻留与 DRM VRAM／GTT 分开报告；共享页和统计域可能重叠，不直接相加。文件缓存冷热影响测量，记录条件；不为凑数清系统缓存或干扰用户实例。
- 区分启动峰值、预热后稳态、操作期间峰值、释放后的保留量。历史“72M”若缺二进制、布局、驱动或口径，就只是线索；不能关闭功能、降低画质或变换统计口径后声称等价复现。
- compositor 的软件渲染不自动说明应用未使用 GPU；headless 的性能也不自动等价于真实桌面。

## 5. 生命周期按契约观察，不把 RSS 当唯一断言

仅检查受本次改动影响的转换：创建／更新、隐藏或删除、切布局、分析暂停与恢复、窗口关闭、服务退出。不同操作的保留策略不同，不能统称“关闭”；具体名称与承诺取自目标项目。

- 对照当前所有权与释放契约，观察对象／容量／任务停止及可用的渲染资源指标。隐藏不必等于释放所有数据；缓存关闭也不必等于清空分析历史。
- 已提交图像可能要跨帧退休。等待真实帧边界或资源状态，采用有界等待，不通过反复任意 sleep 选取好看的数字。
- 重复进入／退出，观察是否持续增长、旧结果是否复活、实例间是否干涉；单次 RSS 不降不能证明泄漏，单次 RSS 下降也不能证明生命周期完整。
- 不通过直接清空业务状态来绕过要验证的删除／暂停／切换事件路径。必要的内部计数只用于诊断，不能替代最终无 hook 构建的关键冒烟。

## 收敛与交付

分别给出视觉保真、行为语义、资源收益的结论，并链接对应证据。效果正确但收益未证实，可以诚实交付视觉修复；测量更快但破坏目标效果，不能称为等价优化。是否接受这种取舍属于设计决策，不由本 Skill 授权。

达到本次验收且无新失败证据即结束；不要因本参考列出更多转换就扩大任务或增加永久测试。明显视觉问题不能靠更新快照或放宽断言掩盖；只保留能防止真实行为回归的测试。
