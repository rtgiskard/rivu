= Rivu

Rivu is a local-first music player for Linux. A shared Rust core owns the
library, queue, playback, analysis, and MPRIS state; the desktop UI, CLI, and
TUI are different clients of that core.

== Features

=== Library, queue, and playlists

* Scan local audio files, directories, and CUE sheets without blocking playback
* Read codec, sample rate, channel, bitrate, track, disc, and release-date metadata
* Manage the library with search, favorites, metadata overrides, missing-track cleanup,
  play counts, and recent-track history
* Manage the playback queue with add, remove, move, play, clear, and repeatable
  track occurrences
* Create and manage playlists with add, remove, move, play, and delete operations;
  exchange them through M3U/M3U8 and CUE import/export

=== Playback and audio

* Native audio playback through PipeWire/ALSA with seeking, volume, shuffle, and
  repeat modes
* Native multichannel routing with optional PipeWire channel remixing
* Optional FFmpeg audio extension for direct playback of additional containers
  and codecs, including audio tracks in MKV and MP4 files

=== Clients and desktop integration

* Desktop GUI, CLI, and terminal UI share one local core and state
* MPRIS 2 support for desktop media keys and compatible media applications
* Optional StatusNotifier tray with window, playback, and quit controls
* Headless foreground `serve` mode; CLI, TUI, and MPRIS can control it without a GUI

=== Customizable workspace and visualization

* DIY desktop workspace: add, remove, move, resize, and reorder panels, with
  persistent layout, tab-bar visibility, and workspace lock
* Configurable UI font, scale, colors, visualization palettes, frequency ranges,
  spectrum styles, and analysis rates
* Embedded album artwork with local caching and a generated fallback cover
* Multiple audio visualizations: progressive whole-track waveform, live Spectrum,
  Spectrogram, and Radial Spectrum views
* Dedicated Radial Spectrum control, based on the Noctalia Shell v5 Fancy Audio
  Visualizer's Bars/Rings presentation model

Rivu is local-first: it reads audio and artwork from local files and does not
fetch media or cover images from the network.

The default build does not require FFmpeg development headers. The optional
extension is compiled with `--features ffmpeg` and currently supports
little-endian x86-64 and aarch64 Linux with FFmpeg 9 development headers
(`libavutil` 61, `libavcodec` 63, `libavformat` 63). `build.rs` rejects other
FFmpeg ABI major versions until they are adapted.

== Architecture

Rivu runs one shared Rust core for each data directory. The core owns library
state, queue state, audio output, playback history, waveform/FFT analysis, and
the local IPC endpoint. Clients do not create independent playback engines.

[source,text]
----
                 +-------------------+
                 | Shared Rust core  |
                 | library / queue   |
                 | audio / analysis  |
                 +----+---------+----+
                      |         |
              local IPC       subscriptions
             rivu.sock       +---+--------+
                 |            |            |
              CLI / TUI    GUI host     MPRIS
                            window       (optional)
                            workspace
                            tray (optional)
----

* `rivu gui [PATH...]` starts the core with a desktop host, or connects to the
  existing instance and raises/recreates its window.
* `rivu serve [PATH...]` starts the same core in the foreground without a GUI
  window or tray. CLI, TUI, and MPRIS can still control it.
* `rivu tui` is an interactive terminal client connected to the running core.
* Playback, library, queue, and playlist CLI commands are short-lived IPC
  clients. `library probe` and `playback devices` can run without a core.

=== Performance and resource behavior

* Library scans and waveform work run asynchronously and do not block playback.
* The audio pipeline is shared by all clients; opening another GUI, CLI, or TUI
  does not start another decoder or audio device for the same data directory.
* Waveform preview storage is bounded to 1600 peak bins. Progressive decoding
  leaves unavailable intervals blank instead of inventing samples.
* GUI refreshes reuse unchanged state snapshots and drawing caches. Analysis is
  parked while paused or while the GUI window is closed; closing the window
  releases window and drawing resources but intentionally keeps the core and
  playback alive.
* The media read buffer is configurable at 1, 2, 4, 8, or 16 MiB. Actual CPU
  and memory use also depends on the audio backend, output format, decoder, and
  enabled visualizations.

== Build and install

On Arch Linux, install the native build and runtime prerequisites:

[source,sh]
----
sudo pacman -S --needed rust pkgconf alsa-lib libpipewire opus fontconfig libxkbcommon
----

The optional FFmpeg extension additionally needs `ffmpeg` development headers
and `libclang` for `bindgen`:

[source,sh]
----
sudo pacman -S --needed ffmpeg clang
----

[source,sh]
----
cargo build --release
# Optional additional containers/codecs:
cargo build --release --features ffmpeg
make install PREFIX="$HOME/.local"
----

`ffmpeg_enabled` can only be enabled in a binary built with the `ffmpeg`
feature. The install target places the executable in `$PREFIX/bin` and installs
the desktop entry and icons. Ensure `~/.local/bin` is on `PATH`. The GUI
currently uses Wayland.


== Source-build compatibility

The native build has no FFmpeg dependency by default. When the `ffmpeg` feature
is enabled, the compatibility boundary is enforced by `build.rs` and the
FFmpeg backend bindings:

[cols="1,1,3", options="header"]
|===
|Target |Status |Notes

|`x86_64-unknown-linux-gnu`
|Validated
|Native target. `cargo check --target x86_64-unknown-linux-gnu --features ffmpeg`
passes with FFmpeg `libavutil` 61, `libavcodec` 63, and `libavformat` 63 headers.

|`aarch64` Linux
|Accepted, not validated
|The architecture guard accepts little-endian aarch64 Linux, but matching
FFmpeg headers, pkg-config files, linker/runtime libraries, and audio backends
are still required and this target is not validated here.

|Other Linux architectures
|Unsupported with `ffmpeg`
|The FFmpeg extension build guard rejects them until its bindings are adapted
and validated.

|Windows, macOS, and other non-Linux targets
|Unsupported
|The current build requires Linux audio/Wayland integration; the FFmpeg
extension also rejects non-Linux targets.
|===

Cross-compiling is therefore not a supported build path yet. Supporting another
target requires adapting the platform backends, generating and validating the
FFmpeg bindings for that target, and testing the runtime audio dependencies.


== Start and stop

[source,sh]
----
# Open the desktop UI; paths are imported when the core starts
rivu gui ~/Music

# Start a foreground, headless core
rivu serve ~/Music

# Open the terminal client for an existing core
rivu tui

# The same as `rivu gui` with no paths
rivu

# Stop the running core and its GUI/MPRIS host
rivu quit
----

`gui` starts a core when none is running. A later `rivu gui` using the same data
directory focuses the existing graphical host or recreates its window without
restarting playback. When a StatusNotifierHost is available, the GUI host also
publishes an always-active Rivu tray with window and basic playback controls
when `tray_enabled` is true. `serve` has no graphical host and no tray. Closing
the GUI window only closes the window; the tray, playback, and core continue
until `Quit Rivu`, MPRIS `Quit` when enabled, `rivu quit`, or an explicit
application quit. The tray does not depend on MPRIS: disabling MPRIS removes
only the MPRIS service while the GUI host and enabled tray remain available. If
no StatusNotifierHost or session bus is available, Rivu warns and continues
without a tray.

== CLI quick reference

All commands accept the global options `--data-dir DIRECTORY`,
`--config FILE`, and `--json`. Run `rivu --help` or a subcommand's `--help`
for the complete generated reference.

[source,sh]
----
# Playback and devices
rivu playback play [TRACK_ID]
rivu playback pause
rivu playback toggle
rivu playback stop
rivu playback next
rivu playback previous
rivu playback seek SECONDS
rivu playback volume PERCENT
rivu playback shuffle on|off
rivu playback repeat off|all|one
rivu playback devices
rivu playback device [EXACT_DEVICE_NAME]

# Library and metadata
rivu library scan PATH... [--wait] [--force]
rivu library list [--query TEXT] [--favorites] [--missing]
rivu library probe PATH
rivu library status
rivu library stats
rivu library history
rivu library clean-missing
rivu library optimize
rivu library remove TRACK_ID...
rivu library favorite TRACK_ID... --set on|off

# Queue and playlists
rivu queue list
rivu queue add TRACK_ID...
rivu queue remove QUEUE_ID
rivu queue move QUEUE_ID INDEX
rivu queue play QUEUE_ID
rivu queue clear
rivu playlist list
rivu playlist new NAME
rivu playlist rename PLAYLIST_ID NAME
rivu playlist delete PLAYLIST_ID
rivu playlist add PLAYLIST_ID TRACK_ID...
rivu playlist remove ENTRY_ID
rivu playlist move ENTRY_ID INDEX
rivu playlist play PLAYLIST_ID
rivu playlist import PATH [--name NAME] [--wait]
rivu playlist export PLAYLIST_ID PATH
----

Library and playlist paths are resolved relative to the invoking client's
current directory, not the already-running core. `library remove` and
`library clean-missing` remove records and references only; they never delete
audio files. `library optimize` requires stopped playback and completed scans.
Use `--json` for machine-readable responses where the command supports it.

== Files and data directories

By default, Rivu uses the platform data directory reported by the OS (on a
typical Linux installation: `~/.local/share/rivu`) and
`~/.config/rivu/config.toml`. `--data-dir DIR` changes the data directory; if
`--config` is not also supplied, the config becomes `DIR/config.toml`.

The data directory contains `library.db` (library and playback state),
`rivu.sock` (the local IPC endpoint), `workspace.json` (desktop layout), and
the `artwork/` cache. When file logging is enabled, weekly logs are stored in
`logs/` and old files are retained according to `log_retention_weeks`. Stop the
core before operating on `library.db`; see link:doc/library.adoc[Library] for
database maintenance and reset behavior.
