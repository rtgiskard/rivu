= Rivu

Rivu is a local-first music player for Linux. A shared Rust core owns the
library, playlists, queue, playback, analysis, and MPRIS state; the desktop UI,
CLI, and TUI are different clients of that core.

== Features

* Local audio and CUE libraries with search, favorites, metadata overrides,
  missing-track cleanup, play counts, and recent history
* Playlists with M3U/M3U8 import/export and CUE import; queues with independent
  repeated-track occurrences
* PipeWire/ALSA playback, multichannel routing, seek, volume, shuffle, and repeat
* Optional FFmpeg decoding for additional formats, including audio in MKV/MP4
* Desktop GUI, CLI, TUI, and headless mode; optional MPRIS and StatusNotifier tray
* Persistent, editable desktop workspace with configurable appearance and layout
* Waveform, Spectrum, Spectrogram, and Radial Spectrum visualizations
* Generated desktop artwork and embedded-cover support for MPRIS; no network
  media or cover fetching

== Architecture

One core runs per data directory and owns the library, queue, playback, and live
analysis. CLI/TUI clients connect through `rivu.sock`; GUI, tray, and MPRIS use
in-process handles. Opening a client does not create a second playback engine.

Runtime ownership: link:src/core.rs[core] and link:src/core/runtime.rs[runtime].
Client transport: link:src/ipc.rs[IPC]. User-facing limits and usage are described
in the numbered topical guides below.

== Build and install

Rivu currently targets Linux; the desktop UI uses Wayland. On Arch Linux, install
the native build and runtime prerequisites:

[source,sh]
----
sudo pacman -S --needed rust pkgconf alsa-lib libpipewire opus fontconfig libxkbcommon
cargo build --release
----

The default Cargo build has no FFmpeg dependency. The optional extension needs
FFmpeg 9 development headers (`libavutil` 61, `libavcodec` 63, `libavformat` 63)
and `libclang` for binding generation:

[source,sh]
----
sudo pacman -S --needed ffmpeg clang
cargo build --release --features ffmpeg

# Build with FFmpeg and install the executable, desktop entry, and icons
make install PREFIX="$HOME/.local"
----

`make build` and `make install` always build with `--features ffmpeg`; they are not
native-only build/install paths. For a native-only executable, use the first Cargo
command and install `.cache/target/release/rivu` into a directory on `PATH`.
Build outputs default to `.cache/target/`; `CARGO_TARGET_DIR` overrides that path.
Ensure `~/.local/bin` is on `PATH` when using the install example.

The FFmpeg feature accepts only little-endian x86-64 and aarch64 Linux and rejects
other targets or header ABI major versions. These guards are compatibility
requirements, not proof of a working cross-build: target-matched headers,
pkg-config metadata, linker libraries, and platform backends are still required.
Cross-compiling is not currently a supported build path.

Compilation makes the extension available; `ffmpeg_enabled = true` enables it
at runtime. See link:doc/04_playback.adoc[Playback] for runtime dependencies and
decoding behavior.

== Start and stop

Before scanning, configure music directories using the Library `+` button or
`library_roots` in `config.toml`. See link:doc/02_library.adoc[Library] for root
and path rules.

[source,sh]
----
# Open the desktop UI without scanning; use the Library scan controls when ready
rivu gui

# Alternatively, start a foreground, headless core
rivu serve

# Open the terminal client for an existing core
rivu tui

# The same as `rivu gui` with no paths
rivu

# Stop the running core and its GUI/MPRIS host
rivu quit
----

On startup, the desktop UI does not scan configured roots. Trigger a scan from
the Library controls, or pass explicit paths to `gui PATH...`; explicit paths
select what to scan but do not add library roots. On an existing graphical
instance, `gui PATH...` requests a scan after raising the window.
All clients must use the same `--data-dir` to reach the same instance. `--config`
selects configuration when starting a core; it does not reconfigure an existing
instance.

Closing the GUI window leaves playback and the core running. Reopen it with
`rivu gui`; stop the instance with `rivu quit`, `Quit Rivu`, or MPRIS `Quit` when
enabled. A `serve` instance must be stopped before starting a graphical host in
the same data directory.

The optional StatusNotifier tray belongs to the graphical host and is independent
of MPRIS. When `tray_enabled` is true, it offers window, playback, and quit controls.
Without a StatusNotifierHost or session bus, Rivu warns and continues without a
tray; `serve` never creates one.

== CLI quick reference

CLI/TUI controls require a running core; `library probe` and `playback devices`
can run independently. All commands accept `--data-dir DIRECTORY`, `--config FILE`,
and `--json`. Generated `--help` defines exact arguments; the syntax below is a
quick reference, not a shell script.

[source,text]
----
# Playback
rivu playback ACTION
# ACTION: play, pause, toggle, stop, next, previous, seek, volume,
#         shuffle, repeat, devices, device

# Library
rivu library scan PATH... [--wait] [--force]
rivu library list [--query TEXT] [--favorites] [--missing]
rivu library edit TRACK_ID [--title TEXT] [--artist TEXT] [--album TEXT]
rivu library probe PATH
rivu library status|stats|optimize|clean-missing
rivu library history [--limit N]
rivu library remove TRACK_ID...
rivu library favorite TRACK_ID... --set on|off

# Playlists
rivu playlist ACTION
# ACTION: list, new, rename, delete, add, remove, move, play, import, export

# Queue
rivu queue ACTION
# ACTION: list, add, remove, move, play, clear
----

Mutating commands normally acknowledge acceptance, not completed playback or
scanning. Use `--wait` for scan/import completion and `--json` for machine-readable
responses; response shape depends on the command. Paths are resolved relative to
the invoking client. The topical documents below define library, playback, and
playlist contracts; generated `--help` defines exact arguments.

== Files and data directories

By default, Rivu uses the platform data directory reported by the OS (on a
typical Linux installation: `~/.local/share/rivu`) and
`~/.config/rivu/config.toml`. `--data-dir DIR` changes the data directory; if
`--config` is not also supplied, the config becomes `DIR/config.toml`.

The data directory contains `library.db` (library and playback state),
`rivu.sock` (the local IPC endpoint), `workspace.json` (desktop layout), and
the `artwork/` cache. When file logging is enabled, weekly logs are stored in
`logs/` and old files are retained according to `log_retention_weeks`. Stop the
core before operating on `library.db`; see link:doc/02_library.adoc[Library] for
database maintenance and reset behavior.
