= Rivu

Rivu is a local-first music player for Linux, with desktop, command-line,
terminal, and headless modes that share one playback instance.

== Features

* Local audio and CUE libraries with search, favorites, metadata overrides,
  missing-track cleanup, play counts, and recent history
* Playlists with M3U/M3U8 import/export and CUE import; database-backed editable
  queues with duplicate occurrences and no total-size cap
* PipeWire playback, multichannel routing, seek, volume, shuffle, and repeat
* Optional FFmpeg decoding for additional formats, including audio in MKV/MP4
* Desktop GUI, CLI, TUI, and headless mode; optional MPRIS and StatusNotifier tray
* Named, editable desktop layouts with boundary-based rows and columns, snapping,
  and configurable appearance
* Waveform, Spectrum, Spectrogram, and Audio Visualizer with radial, stereo-density,
  spatial-spectrum, fractal-beam, and fractal-flow styles
* Generated desktop artwork and embedded-cover support for MPRIS; no network
  media or cover fetching


== Build and install

Rivu currently targets Linux; the desktop UI uses Wayland. On Arch Linux, install
the build and runtime prerequisites:

[source,sh]
----
sudo pacman -S --needed rust gcc binutils clang pkgconf libpipewire opus fontconfig libxkbcommon ffmpeg
cargo build --release
----

Use the repository's Rust toolchain and `Cargo.lock` when building.

Linux builds prefer `mold` when available and otherwise use the toolchain's
default linker. Install it optionally with `sudo pacman -S --needed mold`.

Audio output requires PipeWire 1.2 or newer and a running PipeWire server;
there is no direct ALSA backend. PipeWire performs device-rate conversion.

The default Cargo build includes FFmpeg support and needs development headers
(`libavutil` 61.x, `libavcodec` 63.x, `libavformat` 63.x) and `libclang`.
FFmpeg libraries are loaded on demand, not during startup or status queries;
they are not required to start Rivu with native decoding. To build without
FFmpeg support, omit the FFmpeg package and disable default features:

[source,sh]
----
cargo build --release --no-default-features

# Build the default variant and install the executable, desktop entry, and icons
make install PREFIX="$HOME/.local"
----

`make build` and `make install` use the default features, including FFmpeg.
For a native-only executable, use `--no-default-features` as above and install
`.cache/target/release/rivu` into a directory on `PATH`.
Build outputs default to `.cache/target/`; `CARGO_TARGET_DIR` overrides that path.
Ensure `~/.local/bin` is on `PATH` when using the install example.

Font embedding is off by default, including `make build` and `make install`.
Install Symbols Nerd Font Mono on the machine displaying the GUI (on Arch Linux,
`sudo pacman -S --needed ttf-nerd-fonts-symbols-mono`). To embed a build-host font:

[source,sh]
----
cargo build --release --features embed-nerd-font
----

Embedding requires Fontconfig's `fc-list` and an installed Nerd Font on the build
host; the build fails if none is available. No font is downloaded during the build.
After changing the host font selection, rebuild with `cargo clean -p rivu` first.
Distributions of embedded-font builds must include the selected font's license.
Embedding affects the GUI only; TUI glyphs come from the displaying terminal.

Release builds strip symbols. For troubleshooting, set
`CARGO_PROFILE_RELEASE_STRIP=none` when building or installing.

The FFmpeg feature supports little-endian x86-64 and aarch64 Linux with the header
versions listed above. Cross-compiling is not currently a supported build path.

Compilation makes the extension available; `playback.ffmpeg_enabled = true` enables it
at runtime. See link:doc/04_playback.adoc[Playback] for runtime dependencies and
decoding behavior.

=== Build information

About and `rivu -V` report the build version. `make build` obtains it from Git;
plain Cargo uses the package version unless `RIVU_GIT_VERSION` is supplied.
Source archives can set that variable explicitly when Git metadata is absent.

Set `SOURCE_DATE_EPOCH` to nonnegative Unix seconds for a reproducible build
timestamp. Invalid values fail the build; About displays the timestamp locally.


== Start and stop

Before scanning, configure music directories using the Library `+` button or
`library.roots` in `config.toml`. See link:doc/02_library.adoc[Library] for root
and path rules.

[source,sh]
----
# Open the desktop UI without scanning; use the Library scan controls when ready
rivu gui

# Alternatively, start a foreground, headless core
rivu serve

# Open the terminal client for an existing core
rivu tui

# The same as `rivu gui` with no paths
rivu

# Stop the running core and its GUI/MPRIS host
rivu quit
----

On startup, the desktop UI does not scan configured roots. Trigger a scan from
the Library controls, or pass explicit paths to `gui PATH...`; explicit paths
select what to scan but do not add library roots. On an existing graphical
instance, `gui PATH...` requests a scan after raising the window.
One core runs per data directory. All clients must use the same `--data-dir` to
reach the same instance. `--config` selects configuration when starting a core;
it does not reconfigure an existing instance.

Closing the GUI window leaves playback and the core running. Reopen it with
`rivu gui`; stop the instance with `rivu quit`, `Quit Rivu`, or MPRIS `Quit` when
enabled. A `serve` instance must be stopped before starting a graphical host in
the same data directory.
Ctrl-C or SIGTERM also shuts down the core cleanly.

The optional desktop tray provides window, playback, and quit controls. See
link:doc/04_playback.adoc[Playback] for tray and MPRIS behavior.

== CLI

CLI/TUI controls require a running core; `library probe` and `playback devices`
can run independently. All commands accept `--data-dir DIRECTORY`, `--config FILE`,
and `--json`. Use `rivu --help` or a subcommand's `--help` for exact arguments.

[source,sh]
----
# Scan after configuring library roots
rivu library scan ~/Music --wait
rivu library list --query "artist"

# Control the current playback
rivu playback toggle
rivu playback volume 50
----

Mutating commands normally acknowledge acceptance, not completion. Use `--wait`
for scan/import completion. `--json` selects machine-readable output whose shape
depends on the command; library and playlist listings are streamed arrays.
Paths are relative to the invoking client. The user references below describe
library, playlist, playback, and queue operations and their failure behavior.

== Files and data directories

By default, Rivu uses the platform data directory reported by the OS (on a
typical Linux installation: `~/.local/share/rivu`) and
`~/.config/rivu/config.toml`. `--data-dir DIR` changes the data directory; if
`--config` is not also supplied, the config becomes `DIR/config.toml`.

The data directory contains `library.db` (library and playback state),
`rivu.sock` (the local IPC endpoint), `layout.json` (desktop layout), and
the `artwork/` cache. When file logging is enabled, weekly logs are stored in
`logs/` and old files are retained according to `logging.retention_weeks`. Stop the
core before operating on `library.db`; see link:doc/02_library.adoc[Library] for
database maintenance and reset behavior.
