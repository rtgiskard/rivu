= Rivu

Rivu is a local-first music player for Linux, with desktop, command-line,
terminal, and headless modes that share one playback instance.

== Features

* Local music libraries with search, favorites, metadata editing, play counts,
  and recent history
* link:doc/02_library.adoc#_albums[Album browsing], playlists with M3U/M3U8
  import/export, and editable playback queues
* PipeWire output with multichannel routing and optional FFmpeg decoding
* Optional MPRIS and system tray integration
* Named desktop layouts with dockable panels and configurable appearance
* Waveform, spectrum, spectrogram, audio visualizers, and album artwork
* Live parametric EQ and node-based audio processing with offline rendering,
  restoration, speech enhancement and vocal/accompaniment separation;
  link:doc/27_audio_processing.adoc[usage, explicit model preparation and quality limits]

Rivu plays local files; it does not fetch network media or cover art.
The desktop requires Wayland; audio output requires a running PipeWire 1.2 or newer server.


== First use

. Install Rivu using the <<_build_and_install,instructions below>>.
. Run `rivu` (equivalent to `rivu gui`) to open the desktop UI.
. Add a music directory with the Library `+` button. Hover its directory row and
  use the scan button on the right to import tracks. Adding a directory and
  starting Rivu do not scan it automatically.
  Alternatively, drag individual audio files into Queue without configuring a
  folder. This registers them under link:doc/02_library.adoc#_other[Other] and
  appends queue entries without starting or replacing playback.
. Browse Library or Albums and double-click a track to play it.

Music directories can also be set through `library.roots` in `config.toml`;
use absolute paths, not `~`. See link:doc/02_library.adoc#_roots_and_scanning[Library]
for scanning and path rules.

=== Other modes and shutdown

[source,sh]
----
# Run a foreground core without a desktop window
rivu serve

# Open the terminal client for an existing core
rivu tui

# Stop the running instance, including its GUI and desktop integrations
rivu quit
----

Passing explicit paths to `rivu gui PATH...` or `rivu serve PATH...` requests a scan
but does not add library roots. `rivu gui PATH...` also scans when raising an existing window.
One core runs per data directory. All clients must use the same `--data-dir` to
reach the same instance. `--config` selects configuration when starting a core;
it does not reconfigure an existing instance.

Closing the GUI window leaves playback and the core running. Reopen it with
`rivu gui`; stop the instance with `rivu quit`, `Quit Rivu`, or MPRIS `Quit` when
enabled. A `serve` instance must be stopped before starting a graphical host in
the same data directory.
Ctrl-C or SIGTERM also shuts down the core cleanly.

== CLI

CLI/TUI controls require a running core; `library probe` and `playback devices`
can run independently. All commands accept `--data-dir DIRECTORY`, `--config FILE`,
and `--json`. Use `rivu --help` or a subcommand's `--help` for exact arguments.

[source,sh]
----
# Scan after configuring library roots
rivu library scan ~/Music --wait
rivu library list --query "artist"

# Control the current playback
rivu playback toggle
rivu playback volume 50
----

For scan/import/relocation commands, use `--wait` to wait for completion.
A timeout can leave a mutation's result unknown; do not repeat it blindly.
See link:doc/02_library.adoc#_cli_output[CLI output] for reply semantics and JSON output.

== Files and data directories

By default, Rivu uses the platform data directory reported by the OS (on a
typical Linux installation: `~/.local/share/rivu`) and
`~/.config/rivu/config.toml`. `--data-dir DIR` changes the data directory; if
`--config` is not also supplied, the config becomes `DIR/config.toml`.

The data directory contains `library.db` (library and playback state),
`layout.json` (desktop layouts), the `artwork/` cache, and optional `logs/`.
Stop the core before operating on `library.db`. The application rejects incompatible
formats rather than migrating or resetting them. The independent `rivu-migrate`
tool, installed alongside `rivu`, validates current formats and backs up and
applies derived database maintenance; it does not convert historical formats.
See link:doc/02_library.adoc#_sqlite_maintenance[SQLite maintenance] for commands,
backups, and what rescanning cannot restore.
IPC access and upgrade constraints are described in link:doc/21_ipc.adoc[IPC].

== Build and install

=== Arch Linux package

Install the `rivu-git` AUR package with paru:

[source,sh]
----
paru -S rivu-git
----

=== Build from source

On Arch Linux, install the build and runtime prerequisites:

[source,sh]
----
sudo pacman -S --needed rust make gcc binutils clang pkgconf libpipewire opus fontconfig libxkbcommon ffmpeg ttf-nerd-fonts-symbols-mono
make install PREFIX="$HOME/.local"
----

Use the repository's Rust toolchain and `Cargo.lock` when building.
The install command builds the workspace and installs `rivu`, `rivu-migrate`,
the desktop entry, and icons. Ensure `~/.local/bin` is on `PATH`.
Use `make build` to build without installing, or `cargo build --workspace --release`
directly. Plain `cargo build --release` builds only the application and its dependencies.
Build outputs default to `.cache/target/`; `CARGO_TARGET_DIR` overrides that path.

Linux builds prefer `mold` when available and otherwise use the toolchain's
default linker. Install it optionally with `sudo pacman -S --needed mold`.

=== FFmpeg and native-only builds

The default Cargo build includes FFmpeg support and needs development headers
(`libavutil` 61.x, `libavcodec` 63.x, `libavformat` 63.x) and `libclang`.
The extension supports little-endian x86-64 and aarch64 Linux; cross-compiling
is not currently a supported build path. FFmpeg libraries load on demand, not
during startup or status queries. Native decoding works without them.
The compiled extension is disabled at runtime until
`playback.ffmpeg_enabled = true`; see link:doc/04_playback.adoc#_optional_ffmpeg_decoder[Playback]
for decoder behavior and runtime dependencies.
The application feature forwards to `rivu-audio/ffmpeg`; the
link:doc/04_playback.adoc#_audio_runtime_crate[audio runtime crate] owns binding
generation and native audio dependencies.

To build without FFmpeg support, omit the FFmpeg package and disable default features:

[source,sh]
----
cargo build --workspace --release --no-default-features
----

Install the resulting `.cache/target/release/rivu` and
`.cache/target/release/rivu-migrate` into a directory on `PATH` (or use the
corresponding paths under `CARGO_TARGET_DIR`). The desktop entry and icons are
the same as in the default build; see the `install` target in `Makefile` for their
destinations. Do not run `make install` for this variant: it rebuilds with default
features, including FFmpeg.

=== Font embedding

Font embedding is off by default, including `make build` and `make install`.
Install Symbols Nerd Font Mono on the machine displaying the GUI (on Arch Linux,
`sudo pacman -S --needed ttf-nerd-fonts-symbols-mono`). To embed a build-host font:

[source,sh]
----
cargo build --release --features embed-nerd-font
----

Embedding requires Fontconfig's `fc-list` and an installed Nerd Font on the build
host; the build fails if none is available. No font is downloaded during the build.
After changing the host font selection, rebuild with `cargo clean -p rivu` first.
Distributions of embedded-font builds must include the selected font's license.
Embedding affects the GUI only; TUI glyphs come from the displaying terminal.


=== Build information

Release builds strip symbols. For troubleshooting, set
`CARGO_PROFILE_RELEASE_STRIP=none` when building or installing.

Run `make ui-demo` on a Wayland desktop to explore the reusable GUI controls.
See link:doc/24_layout.adoc#_reusable_gpui_controls[component boundaries and host setup]
and link:doc/23_visuals.adoc#_pinned_gpu_extensions[local GPUI extensions].

About and `rivu -V` report the build version. `make build` obtains it from Git;
plain Cargo uses the package version unless `RIVU_GIT_VERSION` is supplied.
Source archives can set that variable explicitly when Git metadata is absent.

Set `SOURCE_DATE_EPOCH` to nonnegative Unix seconds for a reproducible build
timestamp. Invalid values fail the build; About displays the timestamp locally.
