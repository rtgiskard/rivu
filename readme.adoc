= Rivu

Rivu is a lightweight, local-first music player for Linux, with GUI, TUI, and CLI
access to a shared playback instance that can also run headless.

== Features

* *Performance:* on-demand audio analysis and bounded caches limit background work
  and memory retention. Visualizations can be disabled without stopping playback.
  See link:doc/22_cache.adoc[resource lifecycles]
* *Customization:* named layouts, dockable panels, themes, fonts, visualization
  and artwork styles, and i18n support
* *Library and albums:* folder and link:doc/02_library.adoc#albums[album browsing],
  search, favorites, library-only metadata edits, play counts, and recent history.
  SQLite-backed storage and link:doc/02_library.adoc#paged-views[on-demand paged browsing]
  support large collections without whole-library snapshots
* *Playlists and queue:* M3U/M3U8 import/export, drag-and-drop ordering and transfers,
  direct file additions, and a persistent playback queue
* *Playback and output:* native decoding, optional FFmpeg support, and PipeWire
  output with device selection and multichannel routing; optional MPRIS media
  controls and system tray integration
* *Audio processing:* live parametric EQ, restoration, speech enhancement, and
  vocal/accompaniment separation; node graphs support real-time, hybrid, and offline
  execution, auditioning, and WAV export.
  Neural backends require prepared local models; see
  link:doc/27_audio_processing.adoc#practical-workflow[workflow and quality limits]
* *Visualizations and artwork:* one Visualization panel with eleven styles,
  including waveform, spectrum, spectrogram, stereo analysis, and oscilloscope;
  an independent Artwork panel

Rivu plays local files; it does not fetch network media or cover art.
The desktop requires Wayland; audio output requires a running PipeWire 1.2 or newer server.


== First use

. Install Rivu using the <<build-and-install,instructions below>>.
. Run `rivu` (equivalent to `rivu gui`) to open the desktop UI.
. Add a music directory with the Library `+` button, then hover its row and use
  the scan button to import tracks. Scanning is explicit: adding a directory or
  starting Rivu does not scan it automatically.
. Browse Library or Albums and double-click a track to play it.

Alternatively, drag individual audio files into Queue without configuring a
folder. This registers them under link:doc/02_library.adoc#other[Other] and appends
queue entries without starting or replacing playback.

Music directories can also be set through `library.roots` in `config.toml`;
use absolute paths, not `~`. See link:doc/02_library.adoc#roots-and-scanning[Library]
for scanning and path rules.

=== Other interfaces and shutdown

[source,sh]
----
# Run a foreground core without a desktop window
rivu serve

# Open the TUI, starting a background core if needed
rivu tui

# Stop the running instance, including its GUI and desktop integrations
rivu quit
----

Passing explicit paths to `rivu gui PATH...` or `rivu serve PATH...` requests a scan
within configured library roots; it does not add roots. `rivu gui PATH...` also
requests scanning when raising an existing window.
One core runs per data directory. All clients must use the same `--data-dir` to
reach the same instance. `--config` selects configuration when starting a core.

The GUI menu's `Close window` exits the desktop process and leaves playback and
the core running. Reopen it with `rivu gui`, including when the core was started
with `rivu serve`. `Quit application` stops the Core and connected GUI/TUI clients,
as do `rivu quit`, the tray's `Quit application`, and MPRIS `Quit` when enabled.
Ctrl-C and SIGTERM request a clean shutdown of the process receiving them;
terminating only the desktop does not stop the core.

== CLI

GUI and TUI entrypoints connect to the existing core or start an independent
background core when absent. CLI control commands require a running core;
`library probe`, `library tags`, and `playback devices` can run independently.
`--data-dir DIRECTORY` selects the
instance. `--config FILE` selects startup/probe configuration.
`--log-level LEVEL` temporarily overrides this process's stderr and enabled file
logging (`debug`, `info`, `warning`, `error`).
See link:doc/01_config.adoc#logging-and-diagnostics[logging and diagnostics].
`--json` writes one result to stdout and runtime diagnostics as JSON to stderr;
it is not available for GUI, serve, or TUI.
Use `rivu --help` or a subcommand's `--help` for exact arguments.

[source,sh]
----
# Scan after configuring library roots
rivu library scan ~/Music --wait
rivu library list --query "artist"

# Control the current playback
rivu playback toggle
rivu playback volume 50
----

Use `rivu status` for instance state and `rivu task status KIND INSTANCE:ID` or
`rivu task cancel KIND INSTANCE:ID` for tasks (`KIND`: `scan`, `relocation`, `processing`).
For scan/import/relocation/processing commands, `--wait` returns the terminal
result rather than an acceptance acknowledgement. A timeout can leave a mutation's
result unknown; do not repeat it blindly. See
link:doc/02_library.adoc#cli-output[CLI output] for result and failure semantics.

Use the task reference printed by startup or completion output; its instance
identity prevents a saved reference from addressing a different task after restart.
Playlist commands separate summaries (`playlist list`) from entries (`playlist show ID`).
CLI preset, playlist, and graph export paths resolve against the invoking client's
working directory, not the host's; absolute paths are unchanged.

== Files and data directories

Library, queue, and playlist edits change Rivu's records, not source files;
audio processing writes separate outputs. The explicit offline
link:doc/02_library.adoc#source-file-tags[`library tags` command] can read source
tags or write selected fields with an original-file backup.

By default, Rivu uses the platform data directory reported by the OS (on a
typical Linux installation: `~/.local/share/rivu`) and
`~/.config/rivu/config.toml`. `--data-dir DIR` changes the data directory; if
`--config` is not also supplied, the config becomes `DIR/config.toml`.

The data directory contains `library.db` (library and playback state),
`layout.json` (desktop layouts), the `artwork/` cache, and optional `logs/`.
Shared-state persistence is independent of client lifetime. See
link:doc/01_config.adoc#saving-configuration[configuration saving] and
link:doc/04_playback.adoc#queue[queue restoration] for their independent guarantees.
Stop Rivu before link:doc/02_library.adoc#sqlite-maintenance[database maintenance];
external writes while it runs are unsupported. Keep `rivu-migrate` installed with
`rivu` for link:doc/26_migration.adoc#application-invocation[automatic startup migration].
Unsupported formats or migration failure stop startup without resetting data.
Client and wire contracts are in link:doc/21_ipc.adoc[IPC].

== Build and install

=== Prebuilt Linux x86_64 binaries

Download `rivu-linux-x86_64.tar.zst` and its SHA-256 checksum from
https://github.com/rtgiskard/rivu/releases[GitHub Releases].
Built on Arch Linux, these binaries require an *x86-64-v3-capable CPU*
and matching shared libraries. The archive's `build-info.txt` records the build
environment and shared-library dependencies.

Verify and extract with GNU tar and zstd:

[source,sh]
----
sha256sum --check rivu-linux-x86_64.tar.zst.sha256
tar --zstd -xf rivu-linux-x86_64.tar.zst
----

Run `rivu-linux-x86_64/bin/rivu` directly, or install both executables from the
archive's `bin/` directory into a directory on `PATH`. For desktop launcher
integration, install the archive's `share/` tree under the same installation prefix.

<<ffmpeg-and-native-only-builds,FFmpeg support>> is included;
install a Nerd Font as described under <<font-embedding,Font embedding>>.

=== Arch Linux package

Install the `rivu-git` AUR package with paru:

[source,sh]
----
paru -S rivu-git
----

=== Build from source

From the repository root, install the Arch Linux build and runtime prerequisites:

[source,sh]
----
sudo pacman -S --needed rustup make cmake gcc binutils clang pkgconf libpipewire opus fontconfig libxkbcommon ffmpeg ttf-nerd-fonts-symbols-mono
rustup show
make install PREFIX="$HOME/.local"
----

The recommended setup is rustup, which selects the stable release pinned in
`rust-toolchain.toml` and installs the requested `minimal` profile, `rustfmt`, and
`clippy`. The Arch Linux `rustup` and `rust` packages are alternatives; distribution
toolchains must match the pinned version and provide `rustfmt` and `clippy` for linting.

Keep `Cargo.lock` to retain the resolved dependency versions. Run `make lint`
to check formatting and all workspace targets with all features, including
font embedding; install its additional prerequisites below first.

Run `make test` for all behavior suites, or select a suite:

[cols="1,3",options="header"]
|===
|Command |Coverage
|`make test-rust`
|Workspace tests with default, all, and no default features; application tests
with GUI only and TUI only; standalone `rivu-dsp` and `rivu-format` tests without
default features; standalone `rivu-utils` tests with no features, logging only,
terminal only, and both features
|`make test-python`
|Audio-processing worker and evaluation tests with synthetic inputs; no model downloads
|===

Rust tests use `Cargo.lock`. Install the build/font prerequisites and `dbus`;
tests use private session buses and require no display server or audio device.
Logging session tests keep their thread-local subscriber active across startup,
reconfiguration, and shutdown so tracing rebuilds callsite filters against the
correct subscriber, independently of other tests' execution order.

Python tests require NumPy, SciPy, soundfile, and jsonschema:
`sudo pacman -S --needed python python-numpy python-scipy python-soundfile python-jsonschema`.
Use `PYTHON=/path/to/python` to select a prepared interpreter. Real-model checks
need explicitly prepared environments and local manifests; see
link:doc/27_audio_processing.adoc#quality-acceptance[audio-processing acceptance].
These behavior tests do not establish model quality or runtime memory usage.

The link:.github/workflows/build.yml[CI workflow] runs lint and behavior suites
before release builds. Tag releases also check the archive checksum and both
binaries' `--version` and `--help` output before publishing.

The install command builds the workspace and installs `rivu`, `rivu-migrate`,
the desktop entry, and icons. Ensure `~/.local/bin` is on `PATH`.
Use `make build` to build without installing, or `cargo build --locked --workspace --release`
directly. Plain `cargo build --locked --release` builds only the application and its dependencies.
Build outputs default to `.cache/target/`; `CARGO_TARGET_DIR` overrides that path.
Local builds retain the compiler's default CPU target.

Default builds enable `gui`, `tui`, `ffmpeg`, and `onnx`. Native UL-UNAS/GTCRN
speech inference requires `onnx` and a separately installed ONNX Runtime; see
link:doc/27_audio_processing.adoc#explicit-neural-installation-and-offline-deployment[neural installation].
To omit ONNX inference while keeping both frontends and FFmpeg, build with
`cargo build --locked --release --no-default-features --features gui,tui,ffmpeg`.
Use `--no-default-features --features gui,tui,onnx` to keep both frontends and
ONNX without FFmpeg.
Python-backed models remain available without `onnx`; native ONNX manifests
report an explicit disabled-feature error instead of falling back to Python.

=== Frontend selection

`gui` and `tui` select independent frontend libraries. One `rivu` executable runs
the Core service and graphical desktop in separate processes; both frontends
connect to Core over IPC. Without `gui`, the application does not depend on GPUI,
Wayland integration, or graphical controls. Selecting `tui` does not remove the
application's Core/audio services; the standalone `rivu-tui` library itself has no
engine or database dependency.

[source,sh]
----
# Native service and control commands, without either frontend
cargo build --locked -p rivu --release --no-default-features
# Native TUI and service, without graphical dependencies
cargo build --locked -p rivu --release --no-default-features --features tui
----

With no command, Rivu opens the GUI when available, otherwise the TUI when
available, otherwise the foreground service. Disabled frontend commands are
absent from help and rejected by argument parsing. Add `ffmpeg` or `onnx`
explicitly to these builds when needed. Select `-p rivu` for a frontend-pruned
application build: `--workspace` also builds the independent frontend packages.

The frontend crates are `rivu-gui` and `rivu-tui`; `rivu-presentation` holds their
shared non-graphical presentation resources. Process ownership and client
lifetimes are described in link:doc/21_ipc.adoc#consumer-and-application-lifetimes[frontend lifetimes].

With GNU tar and zstd installed, `make package` creates
`.cache/dist/rivu-linux-<host-architecture>.tar.zst` and its SHA-256 checksum
without installing into the system.


Linux builds prefer `mold` when available and otherwise use the toolchain's
default linker. Install it optionally with `sudo pacman -S --needed mold`.

=== FFmpeg and native-only builds

The default Cargo build includes FFmpeg support and needs development headers
(`libavutil` 61.x, `libavcodec` 63.x, `libavformat` 63.x) and `libclang`.
The extension supports little-endian x86-64 and aarch64 Linux; cross-compiling
is not currently a supported build path. FFmpeg libraries load on demand, not
during startup or status queries. Native decoding works without them.
The compiled extension is disabled at runtime until
`playback.ffmpeg_enabled = true`; see link:doc/04_playback.adoc#optional-ffmpeg-decoder[Playback]
for decoder behavior and runtime dependencies.

To build without FFmpeg support, omit the FFmpeg package and disable default features:

[source,sh]
----
cargo build --locked --workspace --release --no-default-features --features gui,tui
----

Install the resulting `.cache/target/release/rivu` and
`.cache/target/release/rivu-migrate` into a directory on `PATH` (or use the
corresponding paths under `CARGO_TARGET_DIR`). The desktop entry and icons are
the same as in the default build; see the `install` target in `Makefile` for their
destinations. Do not run `make install` for this variant: it rebuilds with default
features, including FFmpeg.

=== Font embedding

Font embedding is off by default, including `make build` and `make install`.
Install Symbols Nerd Font Mono on the machine displaying the GUI (on Arch Linux,
`sudo pacman -S --needed ttf-nerd-fonts-symbols-mono`). To embed a build-host font:

[source,sh]
----
cargo build --locked --release --features embed-nerd-font
----

Embedding requires Fontconfig's `fc-list` and an installed Nerd Font on the build
host; the build fails if none is available. No font is downloaded during the build.
After changing the host font selection, rebuild with `cargo clean -p rivu-gui` first.
Distributions of embedded-font builds must include the selected font's license.
Embedding affects the GUI only; TUI glyphs come from the displaying terminal.


=== Build information

Release builds strip symbols. For troubleshooting, set
`CARGO_PROFILE_RELEASE_STRIP=none` when building or installing.

Run `make ui-demo` on a Wayland desktop to explore the reusable GUI controls.
See link:doc/24_layout.adoc#reusable-gpui-controls[component boundaries and host setup]
and link:doc/23_visuals.adoc#pinned-gpu-extensions[pinned GPUI extensions].

`rivu -V` prints `package-version (build-identity)`; About shows build identity
and enabled Cargo features (`gui`, `tui`, `ffmpeg`, `onnx`, `embed-nerd-font`, or `none`).
`rivu-migrate -V` prints its package version.

`make build` uses `git describe` (including `-dirty`) as the build identity;
plain Cargo uses the package version. Override either with `RIVU_GIT_VERSION`,
including for source archives without Git metadata. Git tags may differ from package
versions. Compatibility is governed separately by
link:doc/26_migration.adoc#version-authority[disk formats] and
link:doc/21_ipc.adoc#wire-schemas[IPC schemas].

Set `SOURCE_DATE_EPOCH` to nonnegative Unix seconds for a reproducible build
timestamp. Invalid values fail the build; About displays the timestamp locally.
