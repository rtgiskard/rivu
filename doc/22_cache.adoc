= Visualization Cache

== Scope and contract

`visualization_cache` defaults to `true` and trades retained graphics memory for
less repeated rendering work. It does not change audio analysis, waveform
samples, spectrum levels, palette mapping, or playback state. Settings and
display controls are documented in link:01_config.adoc[Configuration and layout];
rendering choices are explained in link:23_visuals.adoc[Visualization Rendering Design].

The cache covers Waveform display columns and static images, Spectrum body
geometry, and Spectrogram history images. Radial Spectrum currently has no
reusable rendering cache, so the setting has no effect on that control.

Disabling the cache bypasses reusable graphics, not the underlying audio data
or Spectrogram history. Peak hold, smoothing, and display calculations retain
the same meaning. Re-enabling it requires an initial rebuild before reuse
resumes. Temporary images still remain alive long enough for their submitted
scene to render safely.

Still Mode is separate from this cache policy. It discards visualization results
and derived storage, including base waveform bins, shared analysis frames, FFT
plans/workspaces, stereo fields, and fractal scenes. It preserves settings and
source/timeline metadata, not a restorable picture. Decoder and output PCM
buffers, the bounded tap ring, and audio playback accounting are unchanged.
Submitted images still pass through frame-boundary retirement. The root release
hook requests the final retirement frame when needed, even with the analysis
timer stopped and every visualization replaced by a static status. Leaving the
mode rebuilds storage from new audio on demand; no automatic full-track scan runs.

== Reuse and invalidation

=== Waveform

Waveform separates display-column aggregation from static image caching.
Unchanged data and display mapping reuse the columns; incremental waveform
updates rebuild only affected image tiles. Playback cursor movement does not
invalidate the static waveform. Source, dimensions, amplitude mapping, and
palette changes rebuild the affected derived data.

=== Spectrum

Spectrum retains body geometry per panel. Repaints between analysis updates can
reuse it, including while paused. New analysis data or changes to panel geometry
and display mapping require a rebuild. Peak markers are drawn separately from
the cached body. The benefit depends on how often the UI repaints without new
analysis data, not on a fixed expected hit rate.

=== Spectrogram

Spectrogram retains images for unchanged history columns. New audio updates the
recent columns while older columns remain reusable. Palette, display range,
frequency mapping, and image-size changes rebuild affected images so retained
history is shown with the current settings.

Visible Spectrogram panels share one bounded history sized for the largest
requested column count. Narrow and wide panels therefore do not compete to
resize it during painting. Capacity changes preserve the newest chronological
columns. Recoloring history does not discard its underlying frequency data.

== Resource boundaries

Caches are local to active panels or bounded Spectrogram history, not an
unbounded record of earlier render states. Waveform image memory grows with
panel dimensions and panel count. Spectrum geometry cost depends on style and
bar density; dense LED layouts contain substantially more geometry than simple
curves. Spectrogram image memory grows with retained history width and image
height, in addition to the frequency data needed to preserve that history.

These are CPU and renderer resources: image payload alone does not describe
total process or GPU memory. Removed panel entries are pruned. Replaced images
and images from hidden or removed panels are retired through the window
lifecycle, without requiring those panels to paint again. Window closure
releases the remaining retained images.

== Design tradeoffs

Caching avoids repeated aggregation, geometry construction, and image creation,
but does not eliminate scene submission or rendering. Cached Spectrum paths
still incur ownership copies under GPUI's current painting API; Spectrogram
still submits its visible images. Disabling reuse reduces retained graphics
memory at the cost of rebuilding that work.

Correct invalidation takes precedence over reuse: source or display changes
must not leave stale graphics, and cache-policy changes must not erase analysis
or playback state. The design favors bounded application-level caches over a
second geometry representation or a renderer fork. Shared renderer geometry or
a combined Spectrogram texture would change that boundary and should be justified
by profiling real workloads, not assumed hit rates or submission counts alone.

== Font data and glyphs

Font retention is independent of `visualization_cache`. Primary-font selection
and fallback behavior are described in link:01_config.adoc[Configuration and layout].
Rivu uses the native GPUI/cosmic-text fallback rather than eagerly loading an
explicit application fallback list. This avoids a local font-backend fork, but
does not enforce Fontconfig ordering beyond the primary family.

The backend owns font, shaping, glyph, and atlas caches. It may retain multiple
faces or fonts considered during fallback, not only those that supplied visible
glyphs. Rivu adds no font eviction policy, so switching fonts may leave earlier
data resident. Font-file mappings share kernel file pages; parsed font and glyph
data also consume process memory. Font discovery alone is not a measure of
retained memory, and total process memory includes unrelated renderer resources.
