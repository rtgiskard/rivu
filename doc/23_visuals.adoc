= Visualization Rendering Design

== Goals

Visualization primitives must match their geometry:

* RMS is continuous energy area, with color and gradient defined per column.
* Peak is a transient marker, rendered as a lightweight solid point or short line.
* Cached data and cached geometry must have explicit, independent invalidation rules.

== Waveform

=== RMS

Each visible RMS column is a filled Quad with its own gradient:

[source,text]
----
RMS column
  -> RMS height
  -> low LUT color to lut(RMS) LinearGradient
  -> one rectangular Quad
----

The upper channel runs from the center line upward; the lower channel runs from the center line downward. Each gradient starts at the palette minimum on the centerline, keeping the center dark, and brightens toward that column's RMS edge. Nonlinear color compression keeps warm colors as high-energy accents while preserving access to the full palette range. It is a visual choice, not an amplitude or renderer limit, and does not change RMS geometry height.

The previous implementation combined all RMS columns into one Path, then painted it through a multi-stop gradient split into masked bands. Each palette interval used a cloned or retained Path and a `ContentMask` covering that interval. This minimized draw submissions, but it produced a global vertical gradient: columns at the same height received the same color, so adjacent columns with different RMS values had weak color separation. It also incurred Path cloning and repeated masked gradient submissions.

A single GPUI LinearGradient cannot assign a different endpoint color to each column inside one Path. The exact `lut(RMS)` behavior therefore uses one Quad and one LinearGradient per RMS column. This removes per-column PathBuilder and tessellation while making the scene submission count proportional to visible columns.

=== Peak

Waveform Peak is a solid 1px-high Quad:

[source,text]
----
Peak level
  -> LUT mapping
  -> solid color
  -> one thin Quad
----

Upper and lower channels use their respective Peak positions. Nonlinear color compression preserves access to the full palette range without changing Peak geometry height. Peak does not use the old global multi-stop gradient or mask path.

== Spectrum

Body gradients and Peak colors use the full palette domain without skipping or
remapping its low end, including DeaDBeeF's black floor. Waveform uses the same
palette domain but compresses its color endpoints as described above.

=== Body styles

Spectrum body remains a batched and cached Path because the body is continuous or contains many small segments:

[cols="1,2"]
|===
|Style |Rendering strategy

|`Line`
|Cached continuous Path with the global gradient.

|`Solid`
|Cached continuous filled Path with the global gradient.

|`Bars`
|All bar rectangles are combined into one Path.

|`Outline`
|All outline segments are combined into one Path.

|`Led`
|All LED segments are combined into one Path; one Quad per segment would add substantial submissions.
|===

The old multi-stop gradient implementation is appropriate for these body styles: the body has a shared spatial color field, and batching avoids one draw submission per bar or segment. Its cost is the gradient interval masks and Path reuse/clone operations when the body is painted.

=== Peak

Spectrum Peak is drawn independently as a solid 1px-high marker Quad:

[source,text]
----
Peak dB fraction
  -> palette LUT
  -> solid color
  -> 1px marker Quad
----

Peak is not stored in the body geometry cache. A body cache hit reuses the body Path while current Peak values are painted separately. This prevents Peak changes from rebuilding the body geometry.

== Cache ownership

* Waveform retains the compact per-column `values` cache. It skips raw-data binning and RMS/Peak aggregation when the frame revision, width, and mapping are unchanged.
* Waveform also retains a per-panel static layer `RenderImage` containing RMS and Peak. A layer hit paints one image instead of resubmitting all waveform Quads.
* The layer key contains frame revision/source, plot dimensions, RMS gain, Peak gain/gamma, and palette.
* Playback cursor and glow remain dynamic and never invalidate the static layer.
* A layer miss reuses `values` to generate the image; `values` therefore remains necessary and is cheaper to retain than re-aggregating raw waveform data.
* Cache-disabled mode creates a temporary layer image and does not retain it.
* Replaced images enter a retired/pending queue and are released through the existing window image lifecycle.
* Spectrum caches body Path geometry using its existing key: size, range, style, bar count, spacing, interpolation, and data revision.
* Spectrum Peak is outside body geometry and does not invalidate the body cache.

The two Waveform caches have separate responsibilities:

[source,text]
----
values cache:  raw waveform data -> per-column RMS/Peak values
layer cache:   per-column values -> static BGRA RenderImage
dynamic part:  cached layer + current playback cursor
----

== Performance trade-off

[cols="1,2,2"]
|===
|Region |Previous implementation |Current design

|Waveform RMS
|Few submissions, but multi-stop gradient masks, Path reuse/cloning, and RMS Path tessellation.
|Layer miss rasterizes one image; layer hit uses one image submission.

|Waveform Peak
|Peak Path with the global gradient and mask.
|Included in the static layer; no per-frame Peak Quad submissions on a layer hit.

|Spectrum body
|Cached Path with the global gradient and multi-stop mask behavior.
|Same batched cached Path strategy.

|Spectrum Peak
|Peak Path with the global gradient.
|One solid 1px marker Quad per visible Peak.
|===

No eight-color quantization is used. Quantization would reduce submissions but change the exact `lut(RMS)` and `lut(Peak)` colors.

The new design moves cost rather than guaranteeing a total CPU reduction: it removes Path construction, tessellation, cloning, and mask submissions for column/marker primitives, but increases Quad submissions. Spectrum body remains batched because `Bars`, `Outline`, and `Led` can contain many primitives.

== Validation

Performance comparisons must use identical panel dimensions, data frames, column/bar counts, palette, and repaint count. Measure:

* first-draw CPU time;
* cache-hit repaint CPU time;
* Path and Quad submission counts;
* tessellation count and time;
* vertex count and temporary allocation.

Important workloads are a roughly 1200-column Waveform and a high-density Spectrum `Led` style. Submission counts alone are insufficient; the actual GPUI render path must be measured before claiming an overall speedup.

=== Observed result

Measured CPU usage on the same workload:

[cols="1,1"]
|===
|Rendering state |CPU usage

|Before Peak Quad and per-column RMS rendering
|`3%–4%`

|Quad rendering, cache disabled
|`1.4%–2.0%`

|Waveform layer cache hit
|`0.8%–1.0%`
|===

The Quad renderer reduced CPU usage by approximately `1.0–2.6` percentage points relative to the old renderer. A layer-cache hit reduced it by a further `0.4–1.2` percentage points relative to uncached Quad rendering.

These values apply only to the measured workload; panel dimensions, data, refresh rate, and display configuration were not generalized.
