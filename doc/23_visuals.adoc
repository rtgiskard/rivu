= Visualization Rendering Design
:toc:
:toclevels: 2

== Goals

Rendering preserves the meaning of the signal: RMS is a continuous energy
area, Peak is a discrete transient marker, and Spectrogram is chronological
frequency history. Palette choices and rendering reuse must not alter the
underlying audio data.

This document explains rendering choices and their tradeoffs. User controls,
defaults, and display behavior are documented in
link:01_config.adoc[Configuration and layout]. Cache ownership, invalidation,
and resource lifetime are covered by link:22_cache.adoc[Caching and Resource Lifecycles].

The implemented fixed-schema GPU materials, their recorded measurements, and the
proposed general rendering API are documented separately in
link:25_gpu_rendering.adoc[Parameter-Driven GPU Rendering Design]. The current
consumer behavior is described here; a proposal there does not change it.

== Analysis boundary

`rivu-visuals` owns visual models, rendering, and track-preview rendering events.
It receives immutable analysis frames, typed `VisualParameters`, and localized
`VisualLabels`; it does not depend on the application root, layout tree,
localizer, or playback commands. The GUI presentation owner reconciles demand,
accepts current source/seek identities, and owns the shared scheduling clock.
The host routes Waveform seek, full-scan, and decoder-hint events through its
existing playback and scan owners. Moving rendering into this crate does not
introduce another analysis worker, PCM pool, or animation loop.
Renderer constructors use the same `VisualParameters` defaults as configuration
projection; they do not maintain independent initial style, interpolation, or
envelope settings. History and GPU material allocation remain demand-driven.

`FrequencyViews` accepts shared analysis frames and coordinates the frequency
plots. Its `spectrum` module owns `Spectrum` state, envelopes, bin mapping, and
GPU publications; its `spectrogram` module owns `Spectrogram` state, bounded
history, sampling, and tiled publications. Palette lookup and text painting are
shared with Waveform through the `palette` and `labels` modules.
`StyleCoordinator` reconciles style visibility and layout retention, then routes
borrowed frames to `RadialRenderer`, `StereoRenderer`, `FractalRenderer`, and
`OscilloscopeRenderer`. Each concrete renderer owns its numerical state and
drawing. The six layout-retention slots live inline in the coordinator; radial
canvas closures continue sharing the original single UI-thread state owner,
without another heap allocation or frame copy. `Waveform` owns the track-preview
view.

Visualization analysis is separate from audio output and observes samples before
master volume gain. One global `visualizations.general.signal` setting selects `before`
or `after` (default): before the active realtime processing chain, or after that
chain including monitor EQ. The audio worker sends only the selected stereo
signal to a bounded ring; analysis consumes it off the real-time thread. There
is one FFT path, not parallel before/after analyzers. Worker-driven analysis need
not be strictly synchronized to the output callback's audible clock. Spectrum
combines channel energy rather than averaging signed channels, so opposite-phase
stereo does not cancel. Optional spatial analysis retains the channels' relationship.

=== PCM admission

The tap holds at most 32,768 stereo frames and observes only PCM admitted to
output. Each refill admits at most 16,384 frames before returning to control
handling. DSP and monitor EQ process converted fragments once; later edits do
not reprocess pending output. Rolling waveform capture remains decoder-driven.

After and bypass taps borrow admitted PCM. A processed Before tap needs a
source-aligned FIFO bounded by graph latency plus one converted fragment
(at most two seconds of latency and 16,384 fragment frames, excluding preguard).
It belongs to the current capture identity: source/seek, signal, pause,
visualization enablement and capture restarts cannot relabel retained samples as current audio.
Optional-payload changes preserve admitted PCM; disabling capture releases the
FIFO on the next refill, even without output admission.

Continuity follows traversal-relative sample positions and explicit source gaps,
not comparisons of media timestamps. Seek/source replacement, confirmed gaps
and dropped analysis samples start new segments; ordinary clock corrections do
not. With a realtime graph, gap markers follow latency-trimmed output admission,
so an FFT cannot bridge a break or discard valid earlier pending audio.
Invalid seek targets leave decoder, output and analysis unchanged; obsolete
asynchronous rejections cannot undo newer transport intent. Decoder seek
execution failure stops playback rather than resuming uncertain decoder state.

=== Ingestion and publication

Audio arrival wakes analysis to ingest a finite queued prefix independently of
display requests. `analysis_rate_hz` limits FFT transforms and publications, not PCM
ingestion. Requests coalesce into one permit, retained until a complete fresh
window and its publication deadline are available. The worker publishes one
latest shared frame, not a result backlog; hidden, paused and disabled gates
revoke permits and timed wakeups.

Analysis always observes the latest complete window. When that window is shorter
than the analysis interval, a transient between observed windows can be absent
from Spectrum, Spectrogram, RMS and band-energy drive. This is a music-animation
sampling policy, not continuous metering; display interpolation cannot recover
unobserved audio. Density instead accumulates samples during ingestion.

FFT plans and working storage are prepared only when eligible audio arrives with
active playback and display demand. They remain reusable across suspension;
configuration changes alone do not allocate an analyzer. Pause or loss of demand
clears capture input; disabling visualizations also breaks semantic continuity.

Backpressure never blocks playback. A stalled worker drops stale queued input
and marks a continuity break; fresh audio wakes recovery without polling. A
ready replacement and its generation publish together. Until then, invalidation
remains visible so consumers cannot smooth across unrelated audio.

=== Demand and continuity

Display enablement and optional payloads form one coalesced control state,
independent of the business-command queue. Closing a window relinquishes demand
even when that queue is full. Playback and visualization enablement remain separate gates;
display demand never starts playback. Capture restarts fence queued input and
late publications, including quick hide/show transitions.

Load, audition-source replacement and Seek reserve monotonic audio intent.
The visualizer runtime accepts only frames matching current display demand, the actual
audio epoch and the applied intent. Queued newer commands therefore cannot
relabel old audio. Capture restarts and rejected seeks remain distinct from a
successful semantic source change.

Source/seek boundaries, Stop, dropped samples, FFT/window/signal or sample-rate
changes, and disabling visualizations break signal continuity. The producer owns its generation;
neither a delayed publication nor an optional-demand change implies an audio gap.
Changing only `analysis_rate_hz` adjusts scheduling without breaking continuity
or discarding the accepted sampling window and compatible presentations.
Views reject stale frames and reset envelopes or simulations rather than smoothing
across unrelated audio. Outside the retained pause/reveal handoff described below,
Spectrum withdraws its current bars and peak envelopes while analysis is invalid.
The next accepted window starts fresh envelopes; a retained drawing never seeds
those envelopes. Spectrogram starts a new pooling interval at a break; compatible
historical frequency buckets can remain visible. Its sample time follows accepted
audio, not wall time or the track's seek position; presentation interpolates only
within the accepted boundary described below.

Changing the selected signal resets the analysis sampling window and incompatible
history. Monitor EQ edits preserve realtime analysis history; new samples reflect
the edited processing. Neither operation automatically scans a track or clears
the rolling waveform. Active audition visualization uses the actual audible
source and admitted processing graph, not an arbitrary persisted graph recipe.

GUI analysis demand follows visible views. Stereo density, spatial spectrum,
integrated band energy, PCM, and full-bin Spectrogram data are independent requests
combined across panels; one accepted audio window and stereo FFT supply them all. Optional
demand changes preserve the sampling window, continuity generation, and surviving
consumers' display clocks. Only losing all demand fences capture, including a quick
hide/show that the worker did not observe as a steady state.

Demand is not payload readiness. Exhausting a bounded Density, PCM, or Spectrogram
snapshot pool omits that payload from the next frame, without blocking Spectrum,
RMS, band power, or other available payloads. The affected renderer keeps its last drawing and
matching readouts until a usable replacement arrives; it never pairs an old
snapshot with newer metrics.

=== Presentation scheduling and visibility

One window-local `VisualizerRuntime` shares visual models and staging across panels.
Its analysis timer requests frames at `analysis_rate_hz`; native window callbacks
consume the latest publication and advance animation independently.
`visualizations.general.animation_fps` caps Spectrum, Spectrogram and Audio Visualizer animation:
`0` follows window frames, and `1`–`240` limits requests per second. It does not
throttle analysis, Waveform or artwork. Artwork and audio visualization share one
window-local native-frame gate and one cancellable deadline timer, while retaining
their own FPS limits. Positive limits use a shared time origin so equal-rate
updates are delivered together rather than creating interleaved window redraws.
Late deadlines coalesce without catch-up. Scheduling a callback does not dirty
the window; accepted input or animation changes notify the affected panels.
Configuration-only refreshes reuse unchanged staging data rather than treating
it as new audio, and neither animation clock refreshes the business root.

The display clock advances at wall-clock speed but never beyond the latest
accepted audio timestamp. Spectrum hold/release and smoothing, radial rotation
and smoothing, generative motion, and Spectrogram placement can therefore change
between analysis publications without another FFT or history insertion. If the
producer stalls, display time stops at the accepted boundary rather than inventing
audio. Generation/sample-rate changes and clock rewinds reset continuity; the
producer marks real sample gaps independently of publication cadence. Pause
cancels analysis and audio-driven animation, preserving the last displayed frame
in every visualization style. The presentation owner does not dispatch the worker's
pause-reset publication to renderers, including during resume before fresh input
is ready. Resumption reanchors display time rather than replaying the suspension.
A paused business update can request one refresh, but does not advance animation
or start the optional Audio Visualizer idle fade; that fade applies only to stopped
playback.
Source replacement, seek intent, FFT/window/signal changes and disabling visualizations
clear incompatible retained results even while paused or hidden. These semantic
facts are independent of producer continuity generation and seek previews.
Stop retires all analysis input. With `fade_when_idle` enabled, an ordinary Stop
on the same actual playback track can fade the last bounded radial drawing for
two seconds, then release it; no worker audio is consumed while stopped.
Clearing the queue or changing the playback track clears that drawing immediately,
even if Metadata still displays the same track. Additional source/seek boundaries
observed together with Stop also clear it rather than preserve an uncertain fade.
Disabling visualizations discards the views rather than freezing them.
Radial color, geometry, sensitivity, and rotation-speed edits preserve the frozen
signal and animation time. A dB-range edit remaps the last accepted band peaks
without consuming another audio publication or advancing smoothing. Narrowing
then widening the range therefore recovers peaks clipped only for display.
Suspension and reveal reanchor radial animation time without recomputing its
integrated rotation phase from the current speed; speed edits preserve phase.

Presentation changes are not new audio: Spectrum and Spectrogram appearance,
range and axis settings invalidate only affected retained drawings and rebuild
from compatible working levels/history. Shared palette and background changes
affect both views. A suspended panel whose working data has been
released cannot reconstruct that data from its final drawing. It waits for fresh
input after an incompatible mapping change. Source/seek and FFT/window/signal
changes instead clear incompatible signal state, including when paused; they
must not redraw the prior source under the new identity.

Only affected visual panel entities are invalidated by analysis or waveform
updates. Cached scenes retain their measured panel dimensions until geometry or
visibility changes. Shared Spectrogram geometry changes invalidate sibling
scenes so every panel uses the current history dimensions. Scene caching is always
enabled. Playback, commands, and shutdown remain independent of presentation.

A reliable Hidden notification cancels both clocks and disables analysis.
The last drawable presentation survives temporary hide and tab changes until a
current drawable replacement is accepted. Layout membership bounds its lifetime;
inactive tabs do not accumulate analysis history or run simulations. Fractal tabs
retain their bounded scene to resume trajectories; hiding the window instead
releases that scene and staging, retaining only final drawing data. Actual window
destruction releases all of them; no cross-window snapshot cache or additional
clock is introduced. Switching one panel never suspends unaffected visible panels.
Loss of focus alone never disables analysis. Without a reliable visibility
notification, compositor throttling limits native animation callbacks but not
the independent analysis timer; analysis remains bounded by `analysis_rate_hz` and
retains only the latest publication until visibility is revoked.

== Visualization enablement

Visualization enablement gates both GUI demand and the audio-worker tap. Disabling discards shared
analysis, Spectrogram history, stereo fields, fractal scenes, waveform bins and
completed full-waveform previews. FFT plans and working storage remain reusable,
but resumption needs a new complete audio window. Settings, source identity,
playback and accounting survive. Transition generations reject queued samples
and late scan results even across quick on/off switches or while hidden.
Submitted graphics retain their independent
link:22_cache.adoc#_resource_boundaries[completion-aware lifetime].

Discarded waveform coverage cannot become complete at EOF. Only fresh decoded
PCM fills bins; there is no automatic backfill or rescan. A fresh uninterrupted
traversal from zero can complete the envelope. Disabling cancels explicit scans in
the audio worker. Decode loops observe cancellation between packets, but cannot
interrupt a blocking file/container/codec call. Cancellation is not reported as
a load failure, and re-enabling visualizations neither restores previews nor starts a scan.
The menu toggle changes only visualization enablement through the core's serialized request
path, preserving pending playback and device settings.
The disabled-state icon and controls are described in
link:01_config.adoc#_visualization_enablement[Visualization enablement].


== Waveform

Playback builds a progressive waveform from decoded PCM, not from the FFT tap.
It retains at most 1024 bins rather than whole-track PCM. Unknown or underestimated
timelines expand by coarsening existing bins, preserving bounded memory at the
cost of preview resolution. Normal decoder EOF corrects the timeline end even
when coverage is incomplete; only capacity beyond that endpoint is removed.
Unknown intervals inside the timeline remain blank and eligible for later
playback updates. Complete coverage requires a traversal from zero without seeks
or discarded PCM. For both native and FFmpeg decoding, its timestamp-continuity
check allows one container tick when timestamps are coarser than samples;
sample-accurate sources retain a half-sample threshold. Gaps within the container's
timestamp precision cannot be distinguished reliably from quantization.
An undecoded interval is distinct from decoded silence. A new traversal, signal
selection or EQ change retains the old display until PCM visits an interval;
that bin's peak, RMS, channel energy and sample counts are then replaced by the
new traversal's statistics. Lower gain can therefore decrease old peaks and RMS.
Successive contiguous packets in the same traversal accumulate without counting
overlapping samples twice; unvisited bins keep their prior values.

An integer sample-to-bin ratio keeps cached statistics in stable coordinates
through EOF correction and pairwise coarsening. Playback accumulates privately;
ordinary refills publish dirty statistics only when the shared write lock is
available, retaining them for a later refill on contention. EOF and retirement
flush remaining statistics. Publication never replaces shared scan-cancellation
controls, and identity/revision checks reject stale updates.

Native and FFmpeg decoding use a finite work budget across packet skipping,
seek discard, codec buffering and retained fragments. Exhaustion yields control,
not EOF. Conversion is bounded to 16,384 frames and 256 KiB per float-PCM
fragment; internal codec allocation and blocking calls are outside that bound.

An explicit full-track scan supplies a baseline for the same rolling display.
The previous display remains visible during its Track query and decode, and on
failure. Clicking captures the selected signal, monitor EQ and actual active
audition source/graph, including retained PCM when memory-backed. Later EQ or
signal edits neither change nor cancel that request. Without active playback,
the scan opens the selected original source with its saved decoder hint; it does
not activate a persisted graph.
When the captured graph specifies a published frame count, the scan stops once
that timeline is filled, without decoding or processing unrelated cached suffixes.
Preguard and processing latency are discarded before counting published frames;
real upstream EOF still drains necessary graph output if the timeline is not yet filled.

Each progressive bin carries its last PCM revision. Installing a scan overlays
only playback bins newer than the request; a late baseline cannot erase PCM
visited since the click. Subsequent playback can overwrite the installed full
result. Different full/progressive geometries map by time overlap with
sample-weighted RMS, retaining bounded bins without another whole-track PCM
copy. There is one rolling display, with no automatic full rescan.

Explicit preview identity includes the file, optional playback range, library
content fingerprint and captured opened-source provenance. Changed content,
target or committed decoder hint retires affected requests/results; ordinary
metadata and panel visibility changes retain them. A newer explicit request
supersedes the old request without dropping the current display. Request and
suspension generations reject stale completion independently of playback's
statistics revisions. Disabling visualizations cancels scans and discards the display.

Progressive identity belongs to the opened source, not the latest library
fingerprint. File content uses opened-file identity; memory-backed audition uses
immutable PCM storage and slice identity. Backend, initial timeline and audio
format also participate. Replacement content or a changed format retires the
envelope; seeking the same source retains it, with revisited bins replacing old
statistics even after complete coverage. No per-frame filesystem lookup or
extra whole-track scan is needed. Library refreshes and saved-hint changes cannot
relabel audio already opened for playback.

Display aggregation keeps left and right statistics separate. Peak takes the
maximum known value; RMS uses decoded-sample-weighted energy,
`sqrt(sum(rms_i^2 * count_i) / sum(count_i))`, before display gain and gamma.
Channel fallback uses matching mono values and mono counts. Missing intervals are
not zero-valued samples. The 1024-bin limit trades whole-track time resolution for
bounded storage; it does not introduce zoom, interpolation or a second display mode.

RMS fills extend above and below the centerline for the respective stereo
channels. Each display column has its own gradient endpoint, preserving color
differences between adjacent columns with different energy. The gradient starts
at a dimmed, desaturated palette minimum on the centerline and brightens toward
that column's RMS edge. Color compression uses an exponent of 1.2 for RMS
and 1.35 for Peak, preserving access to the full visible palette range.
These are visual choices, not amplitude or renderer limits.
Peak is a thin, solid marker at the channel's peak level. Color compression
does not change the height represented by the amplitude mapping.

A single shared vertical gradient would be cheaper to batch, but would assign
the same color to equal heights across columns and weaken those differences.
Each panel publishes numerical left/right RMS and Peak columns. The GPU expands
them into two RMS fills and two thin Peak markers; unknown components draw
nothing, while known silence retains a minimum-height fill. A shared palette
keeps floating-point center/endpoint pairs. Each fill blends its own endpoints,
not intervening palette colors; Peak uses its endpoint directly. Logical column
boundaries and ceil-height geometry preserve one-logical-pixel markers through
resize and physical scaling. Placement does not change numerical identity;
cursor and glow remain dynamic. There are no derived image or rectangle tiles.
Buffer admission and completion-aware retirement use the shared
link:25_gpu_rendering.adoc#_admission_and_retirement[GPU material budget].

== Spectrum

For non-Solid styles, bar layout is either automatic width or a fixed count;
the configuration carries only that mode's parameter. Automatic layout derives
the count from plot width, requested bar width and gap. Solid uses the drawable
logical-pixel width. All modes remain bounded by the renderer's slot limit and
available width; layout does not change FFT resolution.

Spectrum Bars and LED submit compact GPU rectangle instances: one rectangle per
visible display slot. LED uses a bottom-aligned 3-pixel segment and 2-pixel gap
pattern in logical coordinates, including the partial segment at the body's top,
rather than tessellating every segment on the CPU. Outline uses up to four
nonoverlapping edge rectangles per visible slot. Line and Solid retain their
curve and fill geometry through the shared GPU Path material.
Solid fill closes at the plot baseline. Display slots at or below the configured
decibel floor remain empty rather than creating a minimum-height colored band.

All styles normalize the gradient to the full plot bounds, with the strongest
color at the top and the visible minimum at the bottom. A curve below the plot's
ceiling neither stretches to fill it nor acquires a local-height gradient.
The full authored cubic palette mapping is retained, not a two-color approximation or duplicated,
masked palette intervals.

Waveform and Spectrum exclude DeaDBeeF's initial black-to-deep-blue interval:
normalized color levels map to `0.06 + 0.94 * level` in the original palette.
Spectrum samples the remaining visible domain across the full plot height; body
and Peak colors use that same domain. Waveform uses it for RMS endpoints and
Peak colors, retaining the color compression described above; its center color
is dimmed and desaturated separately. Tokyo Night's palette domain is unchanged.
Spectrogram continues to use the complete palette,
including DeaDBeeF's black floor. These color mappings do not alter signal levels
or amplitude geometry.

Peak markers are discrete, solid-colored markers drawn separately from the body.
They are not connected into a curve, preserving their transient-marker meaning.
Spectrum rebuilds body geometry on each panel render while reusing compatible
frequency mappings; retained scenes can replay without another panel render.

Spectrum shares one 1024-entry palette across panels and repaints, independently
of body generation. Its cubic colors use 8-bit channel quantization, unlike
Waveform's floating-point endpoints. Range, size and style change geometry or
mapping, not palette identity.

Rectangle coverage uses the shared MSAA intermediate: overlapping alpha ramps
would darken adjacent zero-gap columns. Upload or paint failure reports an error
rather than changing the fill. The closed GPU API and resource lifecycle are in
link:25_gpu_rendering.adoc#_implemented_fixed_schema_slices[Implemented fixed-schema slices]
and link:22_cache.adoc#_resource_boundaries[Resource boundaries].

More display slots still increase aggregation, geometry and fragment work;
more LED segments do not increase CPU body geometry. A shared gradient avoids
per-palette-interval submissions, but those counts alone prove no timing gain.

== Audio Visualizer ownership

All eleven styles use one `audio_visualizer` panel kind. Layout instances retain
style, reference lines, and labels, while style-specific global parameters keep
their existing configuration groups. Titles resolve from each instance's style.

Panel instances own presentation options, while analysis and simulation results
are shared by rendering style. Multiple panels of one style do not duplicate its
field or advance its simulation independently; distinct styles do not overwrite
each other's state. Overlay toggles are paint-only and do not reset analysis or
simulation. Hidden styles release working fields and PCM while retaining bounded
final drawing data until fresh drawable output is accepted. Fractal scenes have
the tab/window distinction described under Generative light below. Physical
reclamation follows the renderer lifecycle described in
link:22_cache.adoc[Caching and Resource Lifecycles].

=== Radial styles

The radial presentation follows Noctalia Shell v5's concept and parameter model;
see the pinned
https://github.com/noctalia-dev/noctalia/blob/f95e95cafde8c23f1d3a62b969e2b5717c96d741/src/ui/visuals/fancy_audio_visualizer.h[`FancyAudioVisualizer` interface (v5.0.1)].
It does not reuse Noctalia's rendering implementation or promise its pixel output.
GPUI-native paths display at most 32 logarithmic bands. Accepted audio updates
shared targets; native ticks smooth and rotate them on the bounded display
clock. Repainting, resizing or replaying unchanged audio does not advance state.
Mapping changes can initialize from compatible retained input without inventing
audio time. Idle fade is a separate wall-clock overlay; radial styles have no
reusable rendering cache.

Bar glow uses two fixed widening translucent passes. Bloom intensity scales
their opacity; zero skips both passes. Pass count is renderer policy, while
rotation, geometry, opacity and intensity remain presentation settings.

=== Oscilloscope

Oscilloscope consumes the same selected before/after signal as FFT analysis,
but uses unwindowed stereo PCM rather than reconstructing samples from FFT bins.
Only visible Oscilloscope instances request PCM.
The worker shares immutable snapshots of the latest
`min(analysis_fft_size, 4096)` stereo frames through five reusable slots, at most
160 KiB of sample storage per prepared analyzer. Pool exhaustion omits optional
PCM without blocking audio or other analysis. Panels share the selected sweep,
never old PCM paired with newer timing or metrics.

A rising zero crossing on the left anchors a sweep selected by
`visualizations.oscilloscope.time_span_ms` (1–50 ms, default 20). A silent left
channel selects the right trigger; a window shorter than two requested sweeps
shows its available half-window. Without a crossing, the latest complete sweep
is used. Trigger selection happens once per accepted publication. Painting
partitions the sweep into at most one bucket per physical pixel, preserving
finite minimum and maximum amplitudes in each channel instead of dropping peaks.
Invalid amplitudes are omitted. `visualizations.oscilloscope.gain` (0.1–10,
default 1) scales drawing before clipping, without modifying retained PCM or
playback volume. Left and right use solid primary/secondary colors, with separate
vertical centers by default. Overlay channels mode uses shared time and amplitude axes;
the panel-local mode changes drawing only, not PCM or trigger selection. Its
new-instance default and controls are described in
link:01_config.adoc#_audio_visualizer[Audio Visualizer]. The label reports input amplitude limits of ±1/gain
and the actual source endpoint duration `(samples - 1) / sample_rate`, rather
than promising a span longer than the available buffer. It is omitted when the
panel cannot fit it.

Hiding the style releases the GUI's retained PCM, keeping only a compact normalized
final sweep of at most 2048 stereo points. Disabling visualizations discards that
drawing too. Prepared analyzer storage can remain reusable across either transition; actual
PCM owners and input identities are retired, so restoring cannot replay pre-hide
PCM. Pause freezes the latest displayed sweep without another refresh timer.
Resume or reveal replaces it when a current complete PCM window arrives; Stop,
source/seek invalidation, incompatible analysis settings, and disabling visualizations clear it.
With no valid sweep, only the background and enabled guides/labels are shown;
there is no waiting-for-audio message.
This style has no FFT windowing, automatic gain, dB color mapping, trails, or idle
fade, and it does not change the independent track-preview Waveform panel.

=== Stereo analysis styles

Stereo Density uses a fixed 256 by 256 mid/side field with decay normalized to
accepted audio time. Silence advances decay without creating a false center
point. Correlation requires energy in both channels; balance and side ratio
require nonzero total energy. Undefined metrics remain absent, not fabricated
as zero. Spatial Spectrum maps individual FFT bins by frequency and channel
power balance into a fixed 256 by 128 field. Cells retain the strongest power
rather than summing crowded logarithmic rows, which would make color depend on
bin density instead of signal level.
The frequency-row mapping retains one axis keyed by the accepted frame's sample
rate and bin count. The analyzer emits every non-DC bin of its fixed FFT axis;
requested settings may change before a new frame arrives, so they do not identify
the retained axis. Repeated frames reuse the mapping without comparing frequencies.
The analyzer publishes calibrated linear bin power, including the single-sided
DC/Nyquist endpoint normalization. The field consumes it without a CPU dB-to-power
round trip, retaining the squared amplitude floor and full-scale saturation.
Overflowing power is omitted rather than promoted to a saturated bright cell.

Both styles retain fixed-resolution numerical fields and share one GPU publication
per style across panels. Enlargement does not multiply source resolution, publish
another snapshot or advance analysis. Semantic continuity breaks revoke the old
publication. Hiding retains only its last immutable field publication and releases
CPU field/history/mapping storage. Color/range changes use accepted active fields
rather than another FFT. There is no CPU-generated field image or application
image-retirement queue.

Color ramps derive from the configured visualizer colors, with increasing
lightness and pale highlights reserved for the strongest cells. Density has a
cyanward intermediate hue; Spatial Spectrum retains the primary-to-secondary
hue progression. A bounded 256-sample straight RGBA palette is rebuilt only when
configured colors change, preserving the previous 8-bit color/alpha quantization.
The shader maps each of four neighboring scalar values to its quantized palette
sample before interpolating colors. Opacity lifts faint cells without renormalizing
the field: occupancy and spectral power retain fixed dB references, and empty cells
remain transparent. Each changed field still copies/uploads four bytes per cell;
the benefit is removing CPU coloring, not automatically reducing upload bytes.

== Spectrogram

Spectrogram maps calibrated non-DC FFT bins to colored columns, independently of
Spectrum's musical display bands. Opposite-phase stereo channels retain their
power. Stable history is a natural reuse boundary: newly accepted audio changes
recent columns without requiring the entire visible history to be rebuilt.
Frequency-row reduction and frames sharing a time bucket use maximum pooling
rather than averaging, retaining narrow peaks and short transients. Display
mapping can recolor compatible retained data without re-running audio analysis.
A gap starts a new interval instead of drawing new audio across missing time.

Only accepted analysis frames write or pool history. Native display ticks move
the time cursor and tile placements without rebuilding unchanged numerical
publications; portions newer than the display cursor remain clipped.

The horizontal scale is fixed by the configured history duration. New audio
enters at the right and scrolls left with accepted audio time; startup history
occupies only its actual duration, leaving the rest blank. No expansion or
release stage stretches retained columns. Paused or stalled display time freezes
placement, and resizing reprojects the same chronological intervals.

History width and sampling resolution bound retained resources. Complete FFT
snapshots are reduced to a logarithmic grid of at most 1024 retained rows, further
bounded by the shared material budget and history capacity. Configuration changes
size history against the widest measured panel before resampling; a cadence edit
that leaves this capacity unchanged preserves the retained frequency grid.
Presentation targets one row per physical panel pixel, capped by that grid. Reduction preserves
peaks; optional interpolation smooths between known samples without lowering them.
Narrowing the time grid coalesces compatible buckets instead of shortening the
configured duration. Resizing cannot recover details already pooled at a coarser
resolution. Multiple panels share history; the cache document describes capacity
changes and numerical publication lifetime.

== Generative light

Fractal Beams uses fixed recursive topology rather than rebuilding random
branches on each frame. Three integrated frequency bands drive different
spatial scales; root-to-tip pulses follow rises in energy, not beat estimates.

Fractal Flow uses three spatial scales of a deterministic curl field. Bands
deform the field rather than steering independent random particles. Trails fade
and taper; boundary respawns discard old points rather than connecting opposite
edges. The fixed particle history is allocated on the first valid audio frame.

Both styles take band power from the stereo FFT bins with window-energy normalization,
not from summed dB values or maximum-pooled display bands. Opposite-phase
channels retain their energy.

A first valid frame seeds visible geometry; subsequent simulation advances on
native display ticks toward the latest accepted band-power targets. Accepted
energy rises inject each onset once, not once per display tick. Simulation and
publications remain shared across visible panels. Paint and resize never advance
the scene. Discontinuities reset simulation. Pause and inactive tabs freeze their
bounded scene, drive and trajectories. The first fresh frame reanchors input and
display time without catch-up or a synthetic onset. Inactive styles do not request
optional band-power analysis. Hiding the window releases the scene and retains
only the last bounded immutable segment publication. Removing a style from the
layout or crossing a semantic boundary clears both, including inactive styles.
Glow uses batched, widening translucent strokes rather than image feedback
history or a blur post-pass. This bounds retained scene storage and submissions,
at the cost of approximating light spread. Fixed topology, particle histories,
pulse slots and segment publications bound storage. Three ordered stroke layers
share segment endpoints rather than rebuilding CPU paths for every light layer.
Flow uses bounded integration substeps and rebuilds drawing segments only from
the final state. Real sample gaps reset through producer continuity; sparse
publications alone do not.

FFT/window or signal changes revoke scenes until compatible audio arrives.
Color and Bloom republish material without advancing geometry; background only
repaints. Sensitivity and display range affect future accepted audio, preserving
paused geometry.

== Artwork composition and animation

Artwork styles change composition, not acquisition or signal analysis. Card
rotates the full square cover, rounded frame, and shadow together, reserving
diagonal margin rather than cropping the source composition. Metal's sheen and
Duotone's blue/purple glow remain fixed over or behind the rotating circular
cover; neither requires extracted colors or audio data. Real and generated
default covers share animation, interaction, and lifecycle rules. Style and
frame-pacing changes preserve the rotation angle. Style controls, per-panel
persistence, defaults, and the frame-rate range are documented in
link:01_config.adoc#_album_artwork[Album artwork].

Zero frame-rate cap follows display callbacks without a timer throttle; positive
values cap animation requests per second independently of the analysis rate.
Rotation and animated source covers share one artwork demand across panels;
individual images do not create a second animation loop. The window gate batches
due artwork and audio-visualization updates before drawing, without making one
effect inherit the other's FPS limit. Playback position, input and other business
updates can still cause additional window submissions, so these limits are not
an overall window FPS cap. Lower caps drop displayed source frames rather than
slowing the source timeline. Cursor catch-up
is bounded by frame count even after a long delay; all-zero-delay sources advance
one frame per redraw. Each element retains its own cursor over shared decoded data.
Pausing or static mode stops rotation, but a visible animated source can continue.
Hiding or reduced motion cancels pending animation work. Focus loss alone does
not stop rotation; the artwork FPS cap and native frame delivery still limit it.
Animated source images retain GPUI's focus-based playback policy; source animation
alone does not keep the artwork owner ticking while the window is inactive.
Resuming rotation does not replay suspended time. Disabling visualizations affects only audio
visualizations, not artwork. Styles introduce neither per-frame CPU geometry
rotation nor a new application cache system.

== Failure boundaries

Views without accepted data do not invent signal history. Analysis frames with
incompatible FFT settings are ignored; Spectrum and Spectrogram reject mismatched
frequency and level counts. Explicit full-waveform decoding failures preserve
an error result rather than installing an incomplete scan as complete.
Before a full scan starts, its Track query must still match the selected track's
metadata stamp and request generation; unrelated library edits do not invalidate
that query. Once decoding starts, ordinary metadata changes do not cancel it:
the source, saved-hint, request-generation, and suspension checks described under
<<_waveform,Waveform>> govern pending and completed previews.

Spectrum tessellation and Waveform/Spectrogram GPU publication/paint failures are
surfaced as visualization errors. Accepted analysis clears data-consistency errors;
a successful paint clears rendering errors even while audio is paused.
Stereo-analysis publication/paint failures revoke stale GPU content while retaining
accepted CPU values. Pending publication gets at most one attempt per ordinary
update, including unchanged input, until success; no retry timer or catch-up loop
is added. An invalid mapping is rejected before publication and waits for valid
configuration. Success also clears its error-reporting latch.
These rendering failures do not issue playback commands or make the audio
callback wait for graphics. Very small plots can omit geometry rather than
attempting invalid dimensions.

== Evaluating tradeoffs

The design moves work between aggregation, geometry construction, image
generation, retained memory, and scene submission. A cache hit or a lower
submission count alone is not evidence of an overall speedup.

Compare equivalent data, panel dimensions, display settings, and repaint rates.
Include first draws, stable repaints, changing data, and dense Spectrum styles;
measure the actual renderer as well as CPU and memory use. Renderer-level
changes should be justified by those workloads rather than historical CPU
percentages from a different implementation.

== Pinned GPU extensions

`Cargo.toml` overrides `gpui` and `gpui_wgpu` with the same fixed commit
`bd54c4c1e00046d2b7aff7355c7fc0fe8a78d9f2` from
https://github.com/rtgiskard/gpui-wgpu[`gpui-wgpu`]. Both crates are maintained
together outside Rivu, under the upstream Apache-2.0 license. Their baseline is
https://github.com/zed-industries/zed/tree/df48a139ce9c292738b523252c12f044697e673f[Zed revision df48a139ce9c292738b523252c12f044697e673f];
the remaining GPUI platform crates retain that pinned dependency baseline.
This is a maintained capability patch, not a framework replacement or upgrade.
The layout engine follows the Taffy 0.15 update in
https://github.com/zed-industries/zed/commit/b488c4e81451f2042d5f47d93f6158732ac28212[Zed revision b488c4e81451f2042d5f47d93f6158732ac28212],
without upgrading the remaining platform crates.
The extensions add centered image transforms and shared GPU materials on
Rivu's Linux/WGPU rendering path. Existing untransformed images and ordinary
path backgrounds retain their drawing semantics, although ordinary Paths share
the renderer's local MSAA scratch. See
link:25_gpu_rendering.adoc#_implemented_fixed_schema_slices[Implemented fixed-schema slices]
for the available schemas, consumer cutover and resource limits. Radial Bars,
Rings and Bars + Rings retain ordinary GPUI paths. The general `Program` and
generated-schema interfaces remain proposals.

Shared images retain their normal image and atlas lifetimes.

Cached views track their own entity dependencies, including dependencies shared
with enclosing views. Parent redraw and scene replay must not sever a child's
notifications or force unrelated cached siblings to rerender. Regression commands
are listed under <<_renderer_regression_checks,Renderer regression checks>>.

=== Why the patch is needed

Album artwork reuses its decoded image and atlas texture while the GPU transforms
the already-cropped sprite. Rounded clipping follows image-local coordinates;
the surrounding content mask remains in screen coordinates. No rotated pixel
buffers or angle-indexed image cache are created. Image transforms pass through
the existing sprite rendering path, with antialiasing coverage kept in screen
pixels under scaling and rotation.

Spectrum fills its geometry with the shared GPU palette material. Its full
authored cubic palette is retained rather than approximated by two stops or
repeated masked submissions; see <<_spectrum,Spectrum>>.

Rust scene records, WGPU pipelines and shader layouts change together. Palette
Paths, ordinary fills and transformed image sprites have distinct drawing paths.

Color images clamp linear texture sampling to their atlas tile's first and last
texel centers. This prevents neighboring images from bleeding into magnified
edges without adding atlas padding or disabling interpolation.

=== Maintenance boundary and removal criteria

The implemented rendering backend is WGPU. Native Metal rejects these new
painting operations rather than silently substituting a different result;
Linux/Vulkan runtime evidence does not establish Metal or browser support.
The extra fields also increase shared vertex/sprite record sizes, so this
patch is not a universal rendering or memory improvement.

Maintain framework and renderer changes in `gpui-wgpu`, then update both Rivu
patch revisions together. When updating the upstream baseline, compare these
extensions against it, keep Rust and shader record layouts synchronized, and
preserve transformed image clipping, palette Path mapping, atlas lifetime and
drawing order. Revalidate ordinary untransformed images and plain paths as well
as all migrated consumers. Drop the overrides only when the selected upstream
revision supplies the required behavior and all Rivu callers have migrated;
a newer dependency version alone is not sufficient.

=== Renderer regression checks

Framework, shader and headless GPU regressions live in the independent
`gpui-wgpu` repository, together with licensed font and image fixtures.
Check out the exact revision pinned by Rivu before running its commands:

[source,sh]
----
git clone https://github.com/rtgiskard/gpui-wgpu
cd gpui-wgpu
git checkout bd54c4c1e00046d2b7aff7355c7fc0fe8a78d9f2
make test
----

See that repository's README for focused checks and build prerequisites.
Headless WGPU checks need an available adapter and do not establish native-window
behavior. They are not substitutes for Rivu application behavior tests.

From Rivu's repository root, run `cargo test --locked --test gpui_cached_dependencies`
for the application-side cached-view notification and replay regressions.

For a native-window smoke check, use a Wayland desktop with a working WGPU
adapter and PipeWire server. Build the updated consumer first with
`cargo build --locked --bin rivu`; an existing binary does not test a new pin.
From Rivu's repository root, create isolated application storage and disable
desktop integrations so the smoke instance does not claim the normal tray or
MPRIS identity:

[source,sh]
----
mkdir -p .cache
smoke_dir=$(mktemp -d "$PWD/.cache/gpui-smoke.XXXXXX")
printf '[interface]\ntray_enabled = false\nmpris_enabled = false\n' > "$smoke_dir/config.toml"
.cache/target/debug/rivu --data-dir "$smoke_dir" gui
----

Retain the same `smoke_dir` in another terminal to stop the instance with
`.cache/target/debug/rivu --data-dir "$smoke_dir" quit`; closing its window alone
does not stop the core. Do not point the smoke instance at normal user storage
or pass music paths unless importing test media is intentional. Keep the real
Wayland runtime environment: changing `XDG_RUNTIME_DIR` would also disconnect
the compositor and audio endpoints. This isolates application data and desktop
registration, not the shared GPU or audio server.

Check initial text and artwork rendering, cached-view updates, window resizing,
and the visualization styles being exercised. Empty isolated storage cannot
establish playback-driven visualization behavior; use disposable test media for
that check. `make ui-demo` is a separate component showcase, not an application
or playback smoke test.
