= Visualization Rendering Design
:toc:
:toclevels: 2

== Goals

Rendering preserves the meaning of the signal: RMS is a continuous energy
area, Peak is a discrete transient marker, and Spectrogram is chronological
frequency history. Palette choices and cache policy must not alter the
underlying audio data.

This document explains rendering choices and their tradeoffs. User controls,
defaults, and display behavior are documented in
link:01_config.adoc[Configuration and layout]. Cache ownership, invalidation,
and resource lifetime are covered by link:22_cache.adoc[Caching and Resource Lifecycles].

The implemented fixed-schema GPU materials, their recorded measurements, and the
proposed general rendering API are documented separately in
link:25_gpu_rendering.adoc[Parameter-Driven GPU Rendering Design]. The current
consumer behavior is described here; a proposal there does not change it.

== Analysis boundary

Visualization analysis is separate from audio output and observes samples before
master volume gain. One global `visualizations.signal` setting selects `before`
or `after` (default): before the active realtime processing chain, or after that
chain including monitor EQ. The audio worker sends only the selected stereo
signal to a bounded ring; analysis consumes it off the real-time thread. There
is one FFT path, not parallel before/after analyzers. Worker-driven analysis need
not be strictly synchronized to the output callback's audible clock. Spectrum
combines channel energy rather than averaging signed channels, so opposite-phase
stereo does not cancel. Optional spatial analysis retains the channels' relationship.

=== PCM admission

The tap holds at most 32,768 frames. Playback submits analysis only for PCM
admitted to output, not an entire decoded packet ahead of its pending tail.
Each refill admits at most 16,384 frames, independently of output queue or packet
size, and returns through control handling before another ready refill. DSP and
monitor EQ process each converted fragment once; pending processed output is
unchanged by later monitor EQ edits. Rolling waveform capture remains decoder-driven.

After and bypass taps borrow admitted PCM. A processed Before tap retains a
reusable stereo FIFO because its source-aligned samples can lead graph output
by algorithmic latency. Its length is bounded by that latency plus one converted
PCM fragment; realtime graphs admit at most two seconds of latency and each
fragment has at most 16,384 frames, excluding source preguard. Each stored frame
contains only two `f32` channels (eight payload bytes); deque capacity slack
remains, so the frame-count bound is not a byte-exact memory limit.

The FIFO belongs to one capture epoch and complete display-demand token, not
merely the current enabled flag. Staging and output admission both reconcile that
identity, and ring submission preserves it. A quick hide/show or pause/resume
therefore cannot relabel retained samples as current audio, even if the final
enablement is unchanged. Source replacement, seeking, signal changes, pause and
Still Mode discard incompatible pending tap state without reprocessing pending
output. Inactive analysis releases FIFO capacity on the next audio-worker refill,
even if output admits no PCM; exhausting the final output span also releases it.

Decoded PCM carries a traversal-relative frame position and an explicit source
discontinuity marker, separately from its media timestamp. Analysis advances by
admitted sample counts; neither tap nor Before FIFO alignment compares media
PTS to infer continuity. The source normalizes timestamp semantics and owns
container-gap detection. Successful seek/source replacement, confirmed source
gaps and dropped analysis samples start a new analysis segment; ordinary media
clock corrections do not. A rejected source seek does not itself retire the
current output or analysis epoch. Seek priming samples are discarded before the first new span.
With a realtime graph, explicit boundaries map into latency-trimmed output
frame coordinates, excluding source preguard; a boundary
at or before the preguard end does not publish a gap. Output admission splits at
each retained boundary so both Before and After mark the discontinuity when
that output span is admitted, not early while the decoder is feeding the graph.
The marker prevents an FFT window from bridging the break without discarding
valid earlier audio still awaiting admission. Restart and exhausted final output
release the boundary queue.

=== Ingestion and publication

While playback and display demand are active, audio arrival wakes the worker to
ingest a finite queued prefix into its rolling sampling window and demanded
accumulators. Ingestion does not wait for a display request or its FPS deadline:
at 192 kHz and 5 FPS, the 38,400 frames between publications need not fit in the
tap at once. Continuing production cannot postpone control handling or shutdown
beyond one queued prefix.

FFT plans and analysis working storage are prepared on the analysis worker only
when it accepts current-identity audio with active playback and display demand,
outside Still Mode. Startup, configuration changes and metadata invalidation alone
do not prepare them. Once prepared, hide/Still transitions clear published results
and continuity but retain reusable working storage. An FFT configuration change
is prepared when eligible audio next arrives, not while analysis is suspended.

Consumer requests coalesce into one publication permit, retained until a fresh,
complete FFT window is available. `analysis_fps` caps transforms and publications,
not PCM ingestion; audio arrival without a permit never runs an FFT. One latest
shared frame is published rather than an unbounded result queue. An incomplete
window waits for input, not repeated deadline wakeups; a complete window with a
pending permit waits only for its publication deadline. Hidden, paused and Still
Mode gates revoke permits and stop timed wakeups.

Analysis backpressure never blocks playback. A genuinely stalled worker drops
the stale queued prefix and resets continuity; the next accepted tap marks the
gap. Fresh audio wakes recovery without a polling/acquisition loop. A ready
replacement and its generation are published together, without an intermediate
invalid frame. When fresh analysis is unavailable, invalidation remains visible
so consumers never smooth across unrelated audio.

=== Demand and continuity

The display enable flag and optional-payload demand are submitted as one
coalesced control state, independently of the core business-command queue.
Closing a window relinquishes that demand even when the command queue is full.
Playback activity and Still Mode remain separate execution gates; requesting a
display never resumes playback or overrides Still Mode. Destructive demand
transitions invalidate queued input and late frame publication.

Stream resets, analysis restarts, dropped samples, FFT/window changes, and
display-demand transitions break signal continuity. Views reject stale frames
and reset envelopes or simulations rather than smoothing across unrelated audio.
Spectrum withdraws its current bars and peak envelopes while the analysis
snapshot is invalid; the next accepted window starts fresh envelopes rather
than holding the previous source on screen.
Spectrogram starts a new pooling interval at a break; compatible historical
frequency buckets can remain visible. Its sample time follows accepted audio,
not wall time or the track's seek position; presentation interpolates only within
the accepted boundary described below.

Changing the selected signal resets the analysis sampling window and incompatible
history. Monitor EQ edits preserve realtime analysis history; new samples reflect
the edited processing. Neither operation automatically scans a track or clears
the rolling waveform. Active audition visualization uses the actual audible
source and admitted processing graph, not an arbitrary persisted graph recipe.

GUI analysis demand follows visible views. Stereo density, spatial spectrum,
and integrated band energy are independent requests combined across panels;
one accepted audio window and stereo FFT supply all requested payloads. This
avoids separate analyzers for different views while allowing unused result
storage to be released. A demand transition invalidates the sampling window,
including a quick hide/show that the worker did not observe as a steady state.

=== Presentation scheduling and visibility

The GUI presentation owner owns the shared visual models, staging buffer,
display demand, and per-panel view entities. One analysis timer requests frames
at `analysis_fps`; one pending native window callback consumes the latest
publication and advances display animation independently of that timer.
`visualizations.fps` sets a shared display cap for Spectrum, Spectrogram, and
Audio Visualizer: `0` (default) follows window frames, while `1`–`240` limits
animation frames per second. The cap does not throttle analysis or control
Waveform or album artwork. The setting is under Settings → Visualizations →
General → Animation, separate from Frequency analysis.
The owner coalesces capped requests behind one cancellable timer; late frames
do not create a catch-up backlog. Audio Visualizer's idle fade uses the same cap.
Business/configuration changes update its inputs; neither clock refreshes the
business root. Missed analysis deadlines coalesce rather than replaying a backlog.
A configuration-only refresh reuses the current staging frame when its analysis
sequence is unchanged, without copying its payloads or treating it as new audio.

The display clock advances at wall-clock speed but never beyond the latest
accepted audio timestamp. Spectrum hold/release and smoothing, radial rotation
and smoothing, generative motion, and Spectrogram placement can therefore change
between analysis publications without another FFT or history insertion. If the
producer stalls, display time stops at the accepted boundary rather than inventing
audio. Generation/sample-rate changes, clock rewinds, and accepted gaps longer
than half a second reset continuity. Pause cancels analysis and audio-driven
animation; a paused business update can still request one refresh. The optional
Audio Visualizer idle fade continues at the display cap until it finishes.

Only affected visual panel entities are invalidated by analysis or waveform
updates. Cached scenes retain their measured panel dimensions until geometry or
visibility changes. Shared Spectrogram geometry changes invalidate sibling
scenes so every panel uses the current history dimensions. Disabling visualization
caching also disables scene caching for these panels. Playback, commands, and
shutdown remain independent of presentation.

A reliable Hidden notification cancels both clocks and disables analysis.
Loss of focus alone never disables analysis. Without a reliable visibility
notification, compositor throttling limits native animation callbacks but not
the independent analysis timer; analysis remains bounded by `analysis_fps` and
retains only the latest publication until visibility is revoked.

== Still Mode

Still Mode overrides visualization demand at both GUI and audio-worker
boundaries. It stops the worker tap and parks analysis without reopening
playback. Entry discards shared analysis results, Spectrogram history, stereo
fields, fractal scenes, progressive and shared waveform bins, and any completed
GUI full-waveform preview. FFT plans and working buffers remain reusable, but
their sampling window is reset.

Settings, source identity, playback timeline, and accounting survive. Mode
transitions invalidate queued samples and publications even across quick on/off
switches. Sample-rate, FFT-size, or window changes rebuild the analyzer;
resumption waits for a new complete audio window. Already submitted graphics
follow link:22_cache.adoc#_resource_boundaries[completion-aware renderer retirement],
independently of suspended analysis.
The application-menu toggle changes only Still Mode in the core's serialized
request path; pending playback and device settings are preserved rather than
reapplied from a GUI configuration snapshot.

Waveform coverage is also discarded: prior samples cannot count toward a
complete envelope, and EOF cannot make a skipped or discarded interval complete.
Only fresh decoded PCM allocates and fills bins. There is no automatic backfill
or full-track rescan; an uninterrupted fresh traversal from zero can complete
the envelope. The audio worker cancels explicit full-waveform scans on entry,
without waiting for GUI refresh. Native and FFmpeg decode loops observe cancellation
between packets, including packets that return no PCM. Blocking file/container/codec
calls cannot be interrupted; cancellation takes effect when control returns. A shared suspension generation
rejects late results and installed previews, even across quick on/off transitions
or while hidden. Resumption neither restores discarded previews nor starts another
scan, and intentional cancellation is not reported as a waveform-load failure.

== Waveform

Playback builds a progressive waveform from decoded PCM, not from the FFT tap.
It retains at most 1024 bins rather than whole-track PCM. Unknown or underestimated
timelines expand by coarsening existing bins, preserving bounded memory at the
cost of preview resolution. Normal decoder EOF corrects the timeline end even
when coverage is incomplete; only capacity beyond that endpoint is removed.
Unknown intervals inside the timeline remain blank and eligible for later
playback updates. Complete coverage requires a traversal from zero without seeks
or discarded PCM. For both native and FFmpeg decoding, its timestamp-continuity
check allows one container tick when timestamps are coarser than samples;
sample-accurate sources retain a half-sample threshold. Gaps within the container's
timestamp precision cannot be distinguished reliably from quantization.
An undecoded interval is distinct from decoded silence. A new traversal, signal
selection or EQ change retains the old display until PCM visits an interval;
that bin's peak, RMS, channel energy and sample counts are then replaced by the
new traversal's statistics. Lower gain can therefore decrease old peaks and RMS.
Successive contiguous packets in the same traversal accumulate without counting
overlapping samples twice; unvisited bins keep their prior values.

Sample-to-bin mapping uses a retained integer ratio, not the rounded display
span. EOF can truncate trailing bins and normalize the display timeline without
moving cached samples between bins. Pairwise coarsening doubles the sample width;
source changes or discarded bins reset the geometry. The accumulator publishes
this geometry with its statistics so later playback uses the same coordinates.
Ordinary refill publishes only when the shared waveform write lock is immediately
available. Contention retains private dirty ranges for a later refill rather than
delaying output replenishment or dropping coverage. EOF, Still transitions and
source retirement flush pending statistics and may wait for a current reader;
identity and revision checks still reject stale publications.
Both first and subsequent publications copy only waveform statistics: live scan
cancellation registration and suspension controls remain shared-frame-owned.
A scan registered after the decoder captures its private seed therefore still
receives cancellation when Still Mode starts, even after the first PCM publication.


Each native or FFmpeg decode call uses one work budget across packet skipping,
seek discards, codec buffering and retained PCM fragments. Exhausting the budget
yields control, not EOF; playback and full-waveform callers can continue later.
Rivu converts at most 16,384 frames and 256 KiB of float PCM per fragment. These
bounds do not limit internal codec allocations or the duration of a single demux
syscall or blocking file/container/codec operation.

An explicit full-track scan supplies a baseline for the same rolling display.
The previous display remains visible during its Track query and decode, and on
failure. Clicking captures the selected signal, monitor EQ and actual active
audition source/graph; later EQ or signal edits neither change nor cancel that
request. Before playback, the explicit scan uses the selected original source
and the latest saved decoder hint without activating a persisted graph.

Each progressive bin carries its last PCM revision. Installing a scan overlays
only playback bins newer than the request; a late baseline cannot erase PCM
visited since the click. Subsequent playback can overwrite the installed full
result. Different full/progressive geometries are mapped by time overlap with
sample-weighted RMS, retaining bounded bins and no whole-track PCM. There are
no separate before/after waveform caches and no automatic full rescans.

Explicit preview identity includes the file, optional playback range, library
content fingerprint and captured opened-source provenance. Changed content,
target or committed decoder hint retires affected requests/results; ordinary
metadata and panel visibility changes retain them. A newer explicit request
supersedes the old request without dropping the current display. Request and
suspension generations reject stale completion independently of playback's
statistics revisions. Still Mode cancels scans and discards the display.

Progressive playback identity belongs to the opened decoder, not the latest
library fingerprint. Each successful Load captures the actual opened regular
file's device/inode, size, modification and change timestamps, together with the
path, range, decoder hint, actual backend, initial duration, sample rate and
channel count. Atomic replacement or a changed decode/timeline format retires
the prior envelope even at the same path. Seeking the existing decoder and
reopening unchanged content retain the baseline and EOF-corrected timeline,
but revisited bins replace old statistics, even after complete coverage.
Identity is captured once at open: there is no
per-frame filesystem lookup or extra whole-track PCM scan. A library refresh or
saved hint change cannot relabel or discard data from an already opened old
file descriptor; only a subsequent Load selects the replacement content.

Display aggregation keeps left and right statistics separate. Peak takes the
maximum known value; RMS uses decoded-sample-weighted energy,
`sqrt(sum(rms_i^2 * count_i) / sum(count_i))`, before display gain and gamma.
Channel fallback uses matching mono values and mono counts. Missing intervals are
not zero-valued samples. The 1024-bin limit trades whole-track time resolution for
bounded storage; it does not introduce zoom, interpolation or a second display mode.

RMS fills extend above and below the centerline for the respective stereo
channels. Each display column has its own gradient endpoint, preserving color
differences between adjacent columns with different energy. The gradient starts
at a dimmed, desaturated palette minimum on the centerline and brightens toward
that column's RMS edge. Color compression uses an exponent of 1.2 for RMS
and 1.35 for Peak, preserving access to the full visible palette range.
These are visual choices, not amplitude or renderer limits.
Peak is a thin, solid marker at the channel's peak level. Color compression
does not change the height represented by the amplitude mapping.

A single shared vertical gradient would be cheaper to batch, but would assign
the same color to equal heights across columns and weaken those differences.
Each panel instead publishes numerical left RMS, left Peak, right RMS and right
Peak columns. The GPU expands them into two RMS fills and two thin Peak markers;
unknown components draw nothing, while known silence retains a minimum-height fill.
A shared palette stores floating-point center/endpoint color pairs for all existing
1024 amplitude-color samples, without an intermediate 8-bit quantization. The
vertex stage applies color compression and continuously interpolates neighboring
pairs' endpoints. Each RMS fill then blends only its own two endpoints in RGB,
not intermediate palette colors; Peak uses its endpoint directly. Color selection
is per primitive, not repeated per fragment. Integer logical column boundaries and
ceil-height geometry preserve the drawing recipe, including fractional placement
height and one-logical-pixel Peak thickness after resizing or physical scaling.
Height and placement do not alter numerical publication identity. Cursor and glow
remain dynamic. There are no application rectangle tiles or colored images.
Buffer admission and completion-aware retirement use the shared
link:25_gpu_rendering.adoc#_admission_and_retirement[GPU material budget].

== Spectrum

Spectrum Bars and LED submit compact GPU rectangle instances: one rectangle per
visible display slot. LED uses a bottom-aligned 3-pixel segment and 2-pixel gap
pattern in logical coordinates, including the partial segment at the body's top,
rather than tessellating every segment on the CPU. Outline uses up to four
nonoverlapping edge rectangles per visible slot. Line and Solid retain their
curve and fill geometry through the shared GPU Path material.
Solid fill closes at the plot baseline. Display slots at or below the configured
decibel floor remain empty rather than creating a minimum-height colored band.

All styles normalize the gradient to the full plot bounds, with the strongest
color at the top and the visible minimum at the bottom. A curve below the plot's
ceiling neither stretches to fill it nor acquires a local-height gradient.
The full authored cubic palette mapping is retained, not a two-color approximation or duplicated,
masked palette intervals.

Waveform and Spectrum exclude DeaDBeeF's initial black-to-deep-blue interval:
normalized color levels map to `0.06 + 0.94 * level` in the original palette.
Spectrum samples the remaining visible domain across the full plot height; body
and Peak colors use that same domain. Waveform uses it for RMS endpoints and
Peak colors, retaining the color compression described above; its center color
is dimmed and desaturated separately. Tokyo Night's palette domain is unchanged.
Spectrogram continues to use the complete palette,
including DeaDBeeF's black floor. These color mappings do not alter signal levels
or amplitude geometry.

Peak markers are discrete, solid-colored markers drawn separately from the
body. They are not connected into a curve, and the body cache does not own their
geometry. This preserves their transient-marker meaning while keeping body
reuse separate from Peak rendering.

Spectrum shares one 1024-entry RGBA palette across panels and repaints, even when
geometry caching is disabled. Authored cubic colors are quantized to 8-bit channels
before conversion to f32, unlike Waveform's floating-point endpoint pairs. Range,
dimensions and style change geometry or mapping, not palette identity. Minor sampling
differences from the old texture are accepted; its half-texel knots are not reconstructed.

Rectangles use per-sample coverage in the shared MSAA intermediate so adjacent
zero-gap columns do not darken one another through overlapping alpha ramps. A
direct single-sample draw is not equivalent. The closed GPU API and palette encoding
are described in link:25_gpu_rendering.adoc#_implemented_fixed_schema_slices[Implemented fixed-schema slices];
publication retention and completion-aware retirement belong to
link:22_cache.adoc#_resource_boundaries[Resource boundaries]. Upload or paint failure
reports an error rather than substituting a different fill.

More display slots still increase aggregation, rectangle construction, and
fragment work. Increasing LED segments does not increase CPU body geometry.
The common gradient needs one body submission per plot without copying geometry
for each palette interval. These bounded changes are not by themselves evidence
of an application CPU or GPU timing improvement.

== Audio Visualizer ownership

Panel instances own presentation options, while analysis and simulation results
are shared by rendering style. Multiple panels of one style do not duplicate its
field or advance its simulation independently; distinct styles do not overwrite
each other's state. Overlay toggles are paint-only and do not reset analysis or
simulation. Hidden styles release result storage and revoke their GPU field
publications; physical reclamation follows the renderer lifecycle described in
link:22_cache.adoc[Caching and Resource Lifecycles].

=== Radial styles

The radial presentation follows Noctalia Shell v5's concept and parameter model;
see the pinned
https://github.com/noctalia-dev/noctalia/blob/f95e95cafde8c23f1d3a62b969e2b5717c96d741/src/ui/visuals/fancy_audio_visualizer.h[`FancyAudioVisualizer` interface (v5.0.1)].
It does not reuse Noctalia's rendering implementation or promise its pixel output.
GPUI-native paths use a bounded display of at most 32 logarithmic bands.
Each accepted spectrum maps its levels to retained target bands once. Native
display ticks smooth toward those targets and advance rotation using the bounded
display clock. Replaying the same generation and sample time with an unchanged
valid band mapping does not inject new input or advance animation. A reset,
configuration change, or return from hidden state invalidates the mapping so the
latest compatible frame can initialize it again without inventing audio time.
Paint and panel size changes do not advance these levels or rotation; the
optional idle fade is a wall-clock presentation overlay, not audio smoothing.
There is no reusable rendering cache for these styles.

=== Stereo analysis styles

Stereo Density uses a fixed 256 by 256 mid/side field with decay normalized to
accepted audio time. Silence advances decay without creating a false center
point. Correlation requires energy in both channels; balance and side ratio
require nonzero total energy. Undefined metrics remain absent, not fabricated
as zero. Spatial Spectrum maps individual FFT bins by frequency and channel
power balance into a fixed 256 by 128 field. Cells retain the strongest power
rather than summing crowded logarithmic rows, which would make color depend on
bin density instead of signal level.
The analyzer publishes calibrated linear bin power, including the single-sided
DC/Nyquist endpoint normalization. The field consumes it without a CPU dB-to-power
round trip, retaining the squared amplitude floor and full-scale saturation.
Overflowing power is omitted rather than promoted to a saturated bright cell.

Both styles retain fixed-resolution numerical fields and share one GPU publication
per style across panels. Enlargement does not multiply source resolution, publish
another snapshot or advance analysis. Continuity breaks revoke the old publication
while preserving reusable numerical storage for visible styles; hiding releases
that storage. Color/range changes use retained fields rather than another FFT.
There is no CPU-generated field image or application image-retirement queue.

Color ramps derive from the configured visualizer colors, with increasing
lightness and pale highlights reserved for the strongest cells. Density has a
cyanward intermediate hue; Spatial Spectrum retains the primary-to-secondary
hue progression. A bounded 256-sample straight RGBA palette is rebuilt only when
configured colors change, preserving the previous 8-bit color/alpha quantization.
The shader maps each of four neighboring scalar values to its quantized palette
sample before interpolating colors. Opacity lifts faint cells without renormalizing
the field: occupancy and spectral power retain fixed dB references, and empty cells
remain transparent. Each changed field still copies/uploads four bytes per cell;
the benefit is removing CPU coloring, not automatically reducing upload bytes.

== Spectrogram

Spectrogram maps retained frequency history to colored columns. Stable
history is a natural reuse boundary: newly accepted audio changes recent
columns without requiring the entire visible history to be rebuilt. Frames that
share a time bucket are max-pooled rather than averaged, retaining short
transients without storing every frame. Display mapping can recolor compatible
retained frequency data without re-running audio analysis. A gap starts a new
interval instead of drawing new audio across the missing time.

Only accepted analysis frames write or pool history. Native display ticks move
the time cursor and tile placements without rebuilding unchanged numerical
publications; portions newer than the display cursor remain clipped.

Flow is a display transform, not a second audio queue. A viewport-relative
quintic fill progressively stretches history from the right toward the left.
At the far edge it stops expanding; continued input compacts the same retained
columns. Once the accumulation threshold is reached, an integrated quintic
gradually opens the outflow and converges to the existing history time span.
This preserves chronological order and gaps, with no reverse motion or added
steady-state delay. Very short histories may fill their retention capacity
during the initial reveal and proceed directly to audio-time scrolling.

Flow speed bounds the transient filling front in panel-widths per second;
steady scrolling remains one second of audio per second. The accumulation
threshold is a fraction of the effective history capacity, subject to the
filling and speed limits. Editing controls does not clear history; a release
already in progress keeps its threshold to avoid pulling outgoing content back.
All panels project the same normalized motion into their own viewport sizes.
Only scalar display state is added: unchanged GPU tiles and pooled audio
columns remain reusable. Paused or stalled display time freezes the motion;
changes to the effective history window still reproject retained columns
immediately, without advancing fill or release progress. Clearing or releasing
history also resets the flow.

History width and sampling resolution bound retained resources. Increasing display
resolution does not create additional FFT information. Multiple panels share
history rather than maintaining competing copies; the cache document describes
capacity changes and numerical publication lifetime.

== Generative light

Fractal Beams uses fixed recursive topology rather than rebuilding random
branches on each frame. Three integrated frequency bands drive different
spatial scales; root-to-tip pulses follow rises in energy, not beat estimates.

Fractal Flow uses three spatial scales of a deterministic curl field. Bands
deform the field rather than steering independent random particles. Trails fade
and taper; boundary respawns discard old points rather than connecting opposite
edges. The fixed particle history is allocated on the first valid audio frame.

Both styles take band power from the stereo FFT bins with window-energy normalization,
not from summed dB values or maximum-pooled display bands. Opposite-phase
channels retain their energy.

A first valid frame seeds visible geometry; subsequent simulation advances on
native display ticks toward the latest accepted band-power targets. Accepted
energy rises inject each onset once, not once per display tick. Simulation and
publications remain shared across visible panels. Paint and resize never advance
the scene. Discontinuities clear state, and hidden styles do not request optional
band-power analysis.
Glow uses batched, widening translucent strokes rather than image feedback
history or a blur post-pass. This bounds retained scene storage and submissions,
at the cost of approximating the light spread. Beams retains 189 branches, 756
line segments, and 12 pulse slots. Flow retains 96 filaments with at most 24
points each and 2208 line segments. Both styles publish shared segment endpoints
with nine intensity/color groups and three ordered stroke layers per panel,
instead of rebuilding 27 CPU light paths. Flow limits each integration step to
1/120 second and each display tick to 60 steps. Integration, history fading, and
respawn retain those substeps, but render segments are rebuilt only from the
final state. An accepted-audio gap longer than half a second resets the scene
instead of attempting unbounded catch-up.
FFT/window or Before/After signal changes revoke the scene until compatible audio
arrives. Color or Bloom changes republish material over the accepted geometry without advancing simulation;
background changes only repaint. Sensitivity and display-range changes affect future
accepted audio, preserving the paused geometry and publication. Beams construction
and reset initialize state without building geometry that the first accepted frame
would immediately replace.

== Artwork composition and animation

Artwork styles change composition, not acquisition or signal analysis. Card
rotates the full square cover, rounded frame, and shadow together, reserving
diagonal margin rather than cropping the source composition. Metal's sheen and
Duotone's blue/purple glow remain fixed over or behind the rotating circular
cover; neither requires extracted colors or audio data. Real and generated
default covers share animation, interaction, and lifecycle rules. Style and
frame-pacing changes preserve the rotation angle. Style controls, per-panel
persistence, defaults, and the frame-rate range are documented in
link:01_config.adoc#_album_artwork[Album artwork].

Zero frame-rate cap follows display callbacks without a timer throttle; positive
values cap animation requests per second independently of the analysis rate.
Rotation and animated source covers share one frame/timer gate across artwork
panels; individual images do not create a second animation loop. Lower caps drop
displayed source frames rather than slowing the source timeline. Cursor catch-up
is bounded by frame count even after a long delay; all-zero-delay sources advance
one frame per redraw. Each element retains its own cursor over shared decoded data.
Pausing or static mode stops rotation, but a visible animated source can continue.
Hiding or reduced motion cancels pending animation work. Focus loss alone does
not stop rotation; the artwork FPS cap and native frame delivery still limit it.
Animated source images retain GPUI's focus-based playback policy; source animation
alone does not keep the artwork owner ticking while the window is inactive.
Resuming rotation does not replay suspended time. Still Mode affects only audio
visualizations, not artwork. Styles introduce neither per-frame CPU geometry
rotation nor a new application cache system.

== Failure boundaries

Views without accepted data do not invent signal history. Analysis frames with
incompatible FFT settings are ignored; Spectrum and Spectrogram reject mismatched
frequency and level counts. Explicit full-waveform decoding failures preserve
an error result rather than installing an incomplete scan as complete.
Before a full scan starts, its Track query must still match the selected track's
metadata stamp and request generation; unrelated library edits do not invalidate
that query. Once decoding starts, ordinary metadata changes do not cancel it:
the source, saved-hint, request-generation, and suspension checks described under
<<_waveform,Waveform>> govern pending and completed previews.

Spectrum tessellation and Waveform/Spectrogram GPU publication/paint failures are
surfaced as visualization errors. Accepted analysis clears data-consistency errors;
a successful paint clears rendering errors even while audio is paused.
Stereo-analysis publication/paint failures revoke stale GPU content while retaining
accepted CPU values. Pending publication gets at most one attempt per ordinary
update, including unchanged input, until success; no retry timer or catch-up loop
is added. An invalid mapping is rejected before publication and waits for valid
configuration. Success also clears its error-reporting latch.
These rendering failures do not issue playback commands or make the audio
callback wait for graphics. Very small plots can omit geometry rather than
attempting invalid dimensions.

== Evaluating tradeoffs

The design moves work between aggregation, geometry construction, image
generation, retained memory, and scene submission. A cache hit or a lower
submission count alone is not evidence of an overall speedup.

Compare equivalent data, panel dimensions, display settings, and repaint rates.
Include first draws, stable repaints, changing data, and dense Spectrum styles;
measure the actual renderer as well as CPU and memory use. Renderer-level
changes should be justified by those workloads rather than historical CPU
percentages from a different implementation.

`Cargo.toml` overrides `gpui` and `gpui_wgpu` with `vendor/gpui` and
`vendor/gpui_wgpu`, derived from
https://github.com/zed-industries/zed/tree/df48a139ce9c292738b523252c12f044697e673f[Zed revision df48a139ce9c292738b523252c12f044697e673f]
under the upstream Apache-2.0 license. The remaining GPUI platform crates and
standalone manifests retain that pinned dependency baseline. This is a
maintained rendering capability patch, not a framework replacement or upgrade.
The extensions add centered image transforms and shared GPU materials on
Rivu's Linux/WGPU rendering path. Existing untransformed images and ordinary
path backgrounds retain their drawing semantics, although ordinary Paths share
the renderer's local MSAA scratch. See
link:25_gpu_rendering.adoc#_implemented_fixed_schema_slices[Implemented fixed-schema slices]
for the available schemas, consumer cutover and resource limits. Radial Bars,
Rings and Bars + Rings retain ordinary GPUI paths. The general `Program` and
generated-schema interfaces remain proposals.

GPUI also captures entity dependencies independently for each cached-view scope,
including entities already accessed by a caller or enclosing cached view. On
scope exit, local dependencies are merged back into the caller's set; cache
reuse must retain them for later notifications. This keeps children created
during render and nested cached consumers live after parent-only redraws,
without refreshing the whole window or rerendering unrelated cached siblings.
Its notification and cache-reuse regressions are included under
<<_vendor_regression_checks,Vendor regression checks>>.

=== Why the patch is needed

Album artwork reuses its decoded image and atlas texture while the GPU transforms
the already-cropped sprite. Rounded clipping follows image-local coordinates;
the surrounding content mask remains in screen coordinates. No rotated pixel
buffers or angle-indexed image cache are created. `Img` forwards its existing
transformation matrix through image painting to the WGPU sprite shader.
Edge coverage uses the analytic local edge normal projected through screen-to-local
coordinate derivatives, so scaling and rotation do not widen the antialiasing ramp
in screen pixels. No additional sprite fields or transformed textures are needed.

Spectrum fills its geometry with the shared GPU palette material. Its full
authored cubic palette is retained rather than approximated by two stops or
repeated masked submissions; see <<_spectrum,Spectrum>>.

Rust scene records, WGPU pipelines, and shader layouts change together. Spectrum
no longer uses a gradient image, atlas tile or specialized textured-Path API.
Ordinary fills and transformed image sprites retain their independent paths.

Color images clamp linear texture sampling to their atlas tile's first and last
texel centers. This prevents neighboring images from bleeding into magnified
edges without adding atlas padding or disabling interpolation.

=== Maintenance boundary and removal criteria

The implemented rendering backend is WGPU. Native Metal rejects these new
painting operations rather than silently substituting a different result;
Linux/Vulkan runtime evidence does not establish Metal or browser support.
The extra fields also increase shared vertex/sprite record sizes, so this
patch is not a universal rendering or memory improvement.

When updating GPUI, compare these extensions against their pinned baseline,
keep Rust and shader record layouts synchronized, and preserve transformed
image clipping, palette Path mapping, atlas lifetime, and drawing order.
Revalidate ordinary untransformed images and plain paths as well as all migrated
consumers. Drop the local overrides and obsolete vendor code only when
the selected upstream revision supplies the required behavior and all Rivu
callers have migrated; a newer dependency version alone is not sufficient.

=== Vendor regression checks

Run the following commands from the repository root. The standalone vendor
workspaces keep copied upstream crates outside Rivu's workspace lint targets;
they are not substitutes for application behavior tests. Headless WGPU checks
need an available WGPU adapter and do not establish native-window behavior.

Run `cargo test --manifest-path vendor/gpui_wgpu/Cargo.toml --lib` to exercise
the patched shader and headless GPU regressions in their isolated test workspace.
The companion GPUI workspace runs publication/replay regressions with
`cargo test --manifest-path vendor/gpui/Cargo.toml --lib gpu::tests --no-default-features`
and existing scene regressions with
`cargo test --manifest-path vendor/gpui/Cargo.toml --lib scene::reclamation_tests --no-default-features`.
Run `cargo test --manifest-path vendor/gpui/Cargo.toml --lib elements::img:: --no-default-features`
for source-animation cursor and frame-request ownership regressions. Automatic
frame requests are exercised beneath a rendered entity, matching real image views.
Compilation also requires the pinned upstream `assets/fonts/lilex` and
`assets/fonts/ibm-plex-sans` fixtures, placed under this repository's
`tests/fixtures/fonts/` with their original subdirectory names.
Upstream test-only font and image fixtures retain their original licenses.

Run `cargo test --test gpui_cached_dependencies` for the application-side
cached-view notification and replay regressions.
