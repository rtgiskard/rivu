= Visualization Rendering Design

== Goals

Rendering preserves the meaning of the signal: RMS is a continuous energy
area, Peak is a discrete transient marker, and Spectrogram is chronological
frequency history. Palette choices and cache policy must not alter the
underlying audio data.

This document explains rendering choices and their tradeoffs. User controls,
defaults, and display behavior are documented in
link:01_config.adoc[Configuration and layout]. Cache ownership, invalidation,
and resource lifetime are covered by link:22_cache.adoc[Caching and Resource Lifecycles].

The next rendering interface, implemented vendor prototype and migration plan are
documented in link:25_gpu_rendering.adoc[Parameter-Driven GPU Rendering Design].
That design distinguishes agreed constraints from mechanisms to refine during
implementation; the visualizer behavior described below remains unchanged.

== Pinned GPU extensions

`Cargo.toml` overrides `gpui` and `gpui_wgpu` with `vendor/gpui` and
`vendor/gpui_wgpu`, derived from
https://github.com/zed-industries/zed/tree/df48a139ce9c292738b523252c12f044697e673f[Zed revision df48a139ce9c292738b523252c12f044697e673f]
under the upstream Apache-2.0 license. The remaining GPUI platform crates and
standalone manifests retain that pinned dependency baseline. This is a
maintained rendering capability patch, not a framework replacement or upgrade.
The extensions add centered image transforms and caller-owned path textures on
Rivu's Linux/WGPU rendering path. Existing untransformed images and ordinary
path backgrounds retain their existing behavior.
The vendor patch also contains experimental fixed-schema rectangle, numerical-field
and existing-path drawing through one shared publication and recording interface;
see the link:25_gpu_rendering.adoc#_internal_led_vertical_slice[GPU rendering slice].
No application visualizer has migrated to this interface.

Run `cargo test --manifest-path vendor/gpui_wgpu/Cargo.toml --lib` to exercise
the patched shader and headless GPU regressions in their isolated test workspace.
The companion GPUI workspace runs publication/replay regressions with
`cargo test --manifest-path vendor/gpui/Cargo.toml --lib gpu::tests --no-default-features`
and existing scene regressions with
`cargo test --manifest-path vendor/gpui/Cargo.toml --lib scene::reclamation_tests --no-default-features`.
Compilation also requires the pinned upstream `assets/fonts/lilex` and
`assets/fonts/ibm-plex-sans` fixtures, placed under this repository's
`tests/fixtures/fonts/` with their original subdirectory names.
Upstream test-only font and image fixtures retain their original licenses.
The isolated regression-test workspace keeps copied upstream crates outside
Rivu's workspace lint targets, without suppressing upstream warnings or mixing
framework cleanup into this rendering patch.

=== Why the patch is needed

Album artwork reuses its decoded image and atlas texture while the GPU transforms
the already-cropped sprite. Rounded clipping follows image-local coordinates;
the surrounding content mask remains in screen coordinates. No rotated pixel
buffers or angle-indexed image cache are created. `Img` forwards its existing
transformation matrix through image painting to the WGPU sprite shader.
`Window::paint_path_with_texture` fills actual path geometry from a caller-owned
`RenderImage`, mapping it to `path.bounds` while preserving coverage and opacity.
Spectrum requires the full authored cubic palette: approximating it with a plain
two-stop fill changes its transitions, while masked palette intervals multiply
path submissions.
Spectrum's mapping and bounded ramp ownership are described in <<_spectrum,Spectrum>>.

Rust scene records, WGPU pipeline/bindings, and WGSL/WebGL shader layouts change
together so transforms and path texture coordinates reach the fragment shader
consistently. Textured paths reuse the image atlas, path antialiasing, opacity,
and intermediate compositing. Adjacent paths with the same atlas texture can
batch without changing submission order; plain fills keep their untextured
pipeline. Palette generation and image retirement remain the caller's existing
window owner's responsibility, not the renderer's.

Color images clamp linear texture sampling to their atlas tile's first and last
texel centers. This prevents neighboring images from bleeding into magnified
edges, including Spectrogram's one-pixel-wide history columns, without adding
atlas padding or disabling interpolation.

Artwork styles change composition, not acquisition or signal analysis. Card
rotates the full square cover, rounded frame, and shadow together, reserving
diagonal margin rather than cropping the source composition. Metal's sheen and
Duotone's blue/purple glow remain fixed over or behind the rotating circular
cover; neither requires extracted colors or audio data. Real and generated
default covers share animation, interaction, and lifecycle rules. Style and
frame-pacing changes preserve the rotation angle. Style controls, per-panel
persistence, defaults, and the frame-rate range are documented in
link:01_config.adoc#_album_artwork[Album artwork].

Zero frame-rate cap follows display callbacks without a timer throttle; positive
values cap animation requests per second independently of the analysis rate. A lower cap
reduces rendering work and resource use at the expense of motion smoothness;
display-following mode can do more work on high-refresh displays. Each owner has
at most one pending frame or timer; pausing, hiding, and static mode cancel
pending work, and resuming does not replay missed frames. Still Mode affects
only audio visualizations, not artwork. Styles introduce neither per-frame CPU
geometry rotation nor a new application cache system.

=== Maintenance boundary and removal criteria

The implemented rendering backend is WGPU. Native Metal rejects these new
painting operations rather than silently substituting a different result;
Linux/Vulkan runtime evidence does not establish Metal or browser support.
The extra fields also increase shared vertex/sprite record sizes, so this
patch is not a universal rendering or memory improvement.

When updating GPUI, compare these extensions against their pinned baseline,
keep Rust and shader record layouts synchronized, and preserve transformed
image clipping, path texture mapping, atlas lifetime, and drawing order.
Revalidate ordinary untransformed images and plain paths as well as the two
new consumers. Drop the local overrides and obsolete vendor code only when
the selected upstream revision supplies the required behavior and all Rivu
callers have migrated; a newer dependency version alone is not sufficient.

== Analysis boundary

Visualization analysis is separate from audio output and observes samples
before output volume gain. The output callback sends a stereo analysis tap to a
bounded ring; analysis consumes it off the real-time thread. Spectrum combines
channel energy rather than averaging signed channels, so opposite-phase stereo
does not cancel. Optional spatial analysis retains the channels' relationship.

The tap holds at most 32,768 frames. Analysis backpressure never blocks playback:
dropped samples mark a discontinuity in the next accepted input. Ordinary
processing consumes only the queued prefix present at its start; overflow
recovery has a finite acquisition deadline, so continued production cannot
postpone publication or shutdown indefinitely. One latest
shared frame is published rather than an unbounded queue of analysis results.
The priority is reliable playback and coherent displays, not collecting every
frame regardless of whether it can be consumed.

The worker parks until a consumer requests another frame. Requests coalesce
into one pending permit, and `analysis_fps` remains an upper bound, not an
independent production clock. If the ring overflows, the worker discards the
stale queued prefix and acquires a fresh sampling window within that request,
with a deadline of twice the FFT window duration plus 20 ms. This also covers
normal low-FPS/high-sample-rate operation where every ordinary request interval
can exceed the ring capacity. Recovery is cancelable, never replays the backlog,
and does not keep polling after the request ends.

The display enable flag and optional-payload demand are submitted as one
coalesced control state, independently of the core business-command queue.
Closing a window relinquishes that demand even when the command queue is full.
Playback activity and Still Mode remain separate execution gates; requesting a
display never resumes playback or overrides Still Mode. Destructive demand
transitions invalidate queued input and late frame publication.

Stream resets, analysis restarts, dropped samples, FFT/window changes, and
display-demand transitions break signal continuity. Views reject stale frames
and reset envelopes or simulations rather than smoothing across unrelated audio.
Spectrogram starts a new pooling interval at a break; compatible historical
frequency buckets can remain visible. Its sample time follows accepted audio,
not wall time or the track's seek position.

GUI analysis demand follows visible views. Stereo density, spatial spectrum,
and integrated band energy are independent requests combined across panels;
one accepted audio window and stereo FFT supply all requested payloads. This
avoids separate analyzers for different views while allowing unused result
storage to be released. A demand transition invalidates the sampling window,
including a quick hide/show that the worker did not observe as a steady state.

The GUI presentation owner consumes analysis on window frames and owns the
shared visual models, staging buffer, display demand, and per-panel view
entities. Business/configuration changes update its inputs; frame callbacks
never refresh the business root. Native callbacks, local redraws, and core
wakeups share one pending frame or deadline rather than parallel analysis loops.
A frame consumes the latest publication and requests the next one; paused
business updates permit a single refresh without starting an idle clock.

Only affected visual panel entities are invalidated by analysis or waveform
updates. Cached scenes retain their measured panel dimensions until geometry or
visibility changes. Shared Spectrogram geometry changes invalidate sibling
scenes before retired images can be reused. Disabling visualization caching also
disables scene caching for these panels because transient renderer images cannot
outlive their retirement boundary. Playback, commands, and shutdown remain
independent of presentation.

A reliable Hidden notification cancels frame scheduling and disables analysis.
Without that notification, compositor-throttled frames reduce analysis demand
rather than declaring the window hidden. Loss of focus alone never disables
analysis, and a compositor that still delivers occasional offscreen frames
does not imply zero analysis work.

== Still Mode

Still Mode overrides visualization demand at both GUI and audio-worker
boundaries. It stops the output tap and parks analysis without reopening
playback. Entry discards shared analysis results, Spectrogram history, stereo
fields, fractal scenes, progressive and shared waveform bins, and any completed
GUI full-waveform preview. FFT plans and working buffers remain reusable, but
their sampling window is reset.

Settings, source identity, playback timeline, and accounting survive. Mode
transitions invalidate queued samples and publications even across quick on/off
switches. Sample-rate, FFT-size, or window changes rebuild the analyzer;
resumption waits for a new complete audio window. Already submitted graphics
follow link:22_cache.adoc#_resource_boundaries[frame-boundary retirement],
independently of suspended analysis.
The application-menu toggle changes only Still Mode in the core's serialized
request path; pending playback and device settings are preserved rather than
reapplied from a GUI configuration snapshot.

Waveform coverage is also discarded: prior samples cannot count toward a
complete envelope, and EOF cannot make a skipped or discarded interval complete.
Only fresh decoded PCM allocates and fills bins. There is no automatic backfill
or full-track rescan; an uninterrupted fresh traversal from zero can complete
the envelope. Explicit full-waveform scans are cancelled by the audio worker on
entry, without waiting for GUI refresh; quick on/off transitions cannot miss the
cancellation. Native and FFmpeg decode loops observe the cancellation flag
between packets, including unrelated-stream skips, discarded seek packets and
codec preroll, even when no PCM is returned to the scan. Priming and segment
seeking use the same signal. Blocking file/container/codec calls are not
interruptible; cancellation takes effect when control returns. The
cancellation flag and a shared suspension generation reject late completions,
including requests registered before the worker has processed resumption, so
old scans cannot restore discarded data or report an intentional cancellation
as a waveform-load failure.
An installed full preview is checked against the same suspension generation as
an in-flight result, including while the window is hidden. Returning from Still
Mode cannot restore that preview or automatically start another full scan.

== Waveform

Playback builds a progressive waveform from decoded PCM, not from the FFT tap.
It retains at most 1600 bins rather than whole-track PCM. Unknown or underestimated
timelines expand by coarsening existing bins, preserving bounded memory at the
cost of preview resolution. Normal decoder EOF corrects the timeline end even
when coverage is incomplete; only capacity beyond that endpoint is removed.
Unknown intervals inside the timeline remain blank and eligible for later
playback updates. Complete coverage requires a traversal from zero without seeks
or discarded PCM. For both native and FFmpeg decoding, its timestamp-continuity
check allows one container tick when timestamps are coarser than samples;
sample-accurate sources retain a half-sample threshold. Gaps within the container's
timestamp precision cannot be distinguished reliably from quantization.
An undecoded interval is distinct from decoded silence. Peaks can survive
disjoint visits, but RMS represents a contiguous sample interval rather than
repeatedly counting seeked or replayed samples.

Sample-to-bin mapping uses a retained integer ratio, not the rounded display
span. EOF can truncate trailing bins and normalize the display timeline without
moving cached samples between bins. Pairwise coarsening doubles the sample width;
source changes or discarded bins reset the geometry. The accumulator publishes
this geometry with its statistics so later playback uses the same coordinates.

Each native or FFmpeg decode call uses one work budget across packet skipping,
seek discards, and codec buffering. Exhausting the budget yields control, not EOF;
playback and full-waveform callers can continue on a later call. This bounds
decode-loop work per call, not the duration of a single demux syscall or other
blocking file/container/codec operation.

A completed explicit full-track scan takes precedence in the GUI, without
replacing the audio worker's progressive buffer. The GUI retains one bounded
full result; playback continues to update its own bounded buffer. Rendering
selects one result rather than copying or combining bins between decoders.
Explicit preview identity is the file, optional playback range and library
content fingerprint. A changed fingerprint, including after overwriting a file
at the same path and forcing a scan, cancels a pending preview and retires its
completed result. Late query responses, scan completions and display selection
must still match that content identity. A target change has the same effect;
ordinary metadata and panel visibility changes retain pending and completed
previews and do not start a decoder. Saving a changed decoder hint cancels the
matching request and retires its full result, leaving playback untouched. A
subsequent explicit load reads the latest saved hint and replaces any pending
request. Request generation, captured content/decode identity and suspension
generation reject stale results independently of the playback buffer's hint or
revision.

Progressive playback identity belongs to the opened decoder, not the latest
library fingerprint. Each successful Load captures the actual opened regular
file's device/inode, size, modification and change timestamps, together with the
path, range, decoder hint, actual backend, initial duration, sample rate and
channel count. Atomic replacement or a changed decode/timeline format retires
the prior envelope even at the same path. Seeking the existing decoder and
reopening unchanged content retain cached coverage, including completed results
and duration corrected at EOF. Identity is captured once at open: there is no
per-frame filesystem lookup or extra whole-track PCM scan. A library refresh or
saved hint change cannot relabel or discard data from an already opened old
file descriptor; only a subsequent Load selects the replacement content.

RMS fills extend above and below the centerline for the respective stereo
channels. Each display column has its own gradient endpoint, preserving color
differences between adjacent columns with different energy. The gradient starts
at a dimmed, desaturated palette minimum on the centerline and brightens toward
that column's RMS edge. Nonlinear color compression keeps warm colors as high-energy accents
while preserving access to the full visible palette range. It is a visual choice, not an
amplitude or renderer limit.
Peak is a thin, solid marker at the channel's peak level. Color compression
does not change the height represented by the amplitude mapping.

A single shared vertical gradient would be cheaper to batch, but would assign
the same color to equal heights across columns and weaken those differences.
The design keeps per-column color fidelity without quantizing the palette.
Static RMS and Peak layers are cached as image tiles, while the playback cursor
and glow remain dynamic. This trades image memory and rebuild work on changes
for less repeated rendering of an otherwise unchanged waveform.

== Spectrum

Spectrum uses batched body geometry with a shared spatial gradient texture.
Continuous curves and filled areas, as well as bars, outlines, and LED segments,
each submit their body as one path. GPUI fills that actual path from a custom
one-column image, normalized to the common plot bounds with the strongest color
at the top and the visible minimum at the bottom. Linear sampling is clamped to
the image's texel centers. The texture contains the full authored cubic palette
mapping, not a two-color approximation or duplicated, masked palette intervals.

Waveform and Spectrum exclude DeaDBeeF's initial black-to-deep-blue interval:
normalized color levels map to `0.06 + 0.94 * level` in the original palette.
Spectrum samples the remaining visible domain across the full plot height; body
and Peak colors use that same domain. Waveform uses it for RMS endpoints and
Peak colors, retaining the color compression described above; its center color
is dimmed and desaturated separately. Tokyo Night's palette domain is unchanged.
Spectrogram continues to use the complete palette,
including DeaDBeeF's black floor. These color mappings do not alter signal levels
or amplitude geometry.

Peak markers are discrete, solid-colored markers drawn separately from the
body. They are not connected into a curve, and the body cache does not own their
geometry. This preserves their transient-marker meaning while keeping body
reuse separate from Peak rendering.

The shared `PaletteLut` owns a bounded 1 by 1024 BGRA ramp, constructed once when
the active palette changes and reused across Spectrum panels and repaints,
including when geometry caching is disabled. Range, dimensions, and style
changes alter geometry or the plot mapping, not the ramp. Palette replacement
queues the old image through the visualization owner's existing frame-boundary
retirement mechanism; closing the window explicitly drops the current ramp and
all retired images from its atlas. The active LUT retains the CPU ramp for reuse.
Upload or paint failures follow the existing visualization error reporting path,
without substituting a different fill.

Batching does not make dense styles free: more bars or LED segments still
increase geometry work. The common gradient needs only one body submission
per plot, without copying its geometry for each palette interval. The choice
favors batching where the visual model allows it, rather than forcing Waveform
and Spectrum through one strategy.

== Audio Visualizer ownership

Panel instances own presentation options, while analysis and simulation results
are shared by rendering style. Multiple panels of one style do not duplicate its
field or advance its simulation independently; distinct styles do not overwrite
each other's state. Overlay toggles are paint-only and do not reset analysis or
simulation. Hidden styles release result storage; submitted analysis images
retain the retirement boundary described in link:22_cache.adoc[Caching and Resource Lifecycles].

=== Radial styles

The radial presentation adapts Noctalia Shell v5's
https://github.com/noctalia-dev/noctalia-shell/blob/e56a9db5/Widgets/AudioSpectrum/NMirroredSpectrum.qml[`NMirroredSpectrum.qml`]
concept and parameter model, not its rendering implementation or pixel output.
GPUI-native paths use a bounded display of at most 32 logarithmic bands.
Rotation and smoothing follow accepted sample time. Replaying the same
generation and sample time with an unchanged valid band mapping leaves the
displayed levels intact, including partially decayed falling levels. A reset,
configuration change, or return from hidden state invalidates that display and
allows the latest frame to be mapped again without inventing new audio time.
Paint and panel size changes do not advance these levels or rotation; the
optional idle fade is a wall-clock presentation overlay, not audio smoothing.
There is no reusable rendering cache for these styles.

=== Stereo analysis styles

Stereo Density uses a fixed 256 by 256 mid/side field with decay normalized to
accepted audio time. Silence advances decay without creating a false center
point. Correlation requires energy in both channels; balance and side ratio
require nonzero total energy. Undefined metrics remain absent, not fabricated
as zero. Spatial Spectrum maps individual FFT bins by frequency and channel
power balance into a fixed 256 by 128 field. Cells retain the strongest power
rather than summing crowded logarithmic rows, which would make color depend on
bin density instead of signal level.

Both styles retain fixed-resolution field images independently of panel size;
enlarging a panel does not multiply analysis resolution or allocate another
field. Continuity breaks clear existing field contents while preserving storage
for visible styles; hiding a style releases it. Recoloring uses retained fields
rather than another FFT. This trades fixed display resolution for predictable
storage and coherent reuse across differently sized panels.

Color ramps derive from the configured visualizer colors, with increasing
lightness and pale highlights reserved for the strongest cells. Density has a
cyanward intermediate hue; Spatial Spectrum retains the primary-to-secondary
hue progression. A bounded lookup table supplies BGRA pixels and is rebuilt
only when the configured colors change. Opacity lifts faint cells without
renormalizing the field: occupancy and spectral power retain their fixed dB
references, and empty cells remain transparent.

== Spectrogram

Spectrogram maps retained frequency history to colored image columns. Stable
history is a natural reuse boundary: newly accepted audio changes recent
columns without requiring the entire visible history to be rebuilt. Frames that
share a time bucket are max-pooled rather than averaged, retaining short
transients without storing every frame. Display mapping can recolor compatible
retained frequency data without re-running audio analysis. A gap starts a new
interval instead of drawing new audio across the missing time.

History width and image resolution bound retained resources. Increasing display
resolution does not create additional FFT information. Multiple panels share
history rather than maintaining competing copies; the cache document describes
capacity changes and image retirement.

== Generative light

Fractal Beams uses fixed recursive topology rather than rebuilding random
branches on each frame. Three integrated frequency bands drive different
spatial scales; root-to-tip pulses follow rises in energy, not beat estimates.

Fractal Flow uses three spatial scales of a deterministic curl field. Bands
deform the field rather than steering independent random particles. Trails fade
and taper; boundary respawns discard old points rather than connecting opposite
edges. The fixed particle history is allocated on the first valid audio frame.

Both styles take band power from the stereo FFT bins with window-energy normalization,
not from summed dB values or maximum-pooled display bands. Opposite-phase
channels retain their energy.

Simulation advances once per accepted analysis frame and is shared across
visible panels. Paint and resize never advance the scene. Discontinuities clear
the state, and hidden views do not request the optional band-power analysis.
Glow uses batched, widening translucent strokes rather than image feedback
history or a blur post-pass. This bounds retained scene storage and submissions,
at the cost of approximating the light spread. Beams retains 189 branches, 756
line segments, and 12 pulse slots. Flow retains 96 filaments with at most 24
points each and 2208 line segments. Both styles draw at most 27 light paths per
panel; Flow limits each integration step to 1/120 second and each accepted-frame
update to 60 steps. Integration, history fading, and respawn retain those
substeps, but render segments are rebuilt only from the final state. A gap longer
than half a second resets the scene instead of attempting unbounded catch-up.

== Failure boundaries

Views without accepted data do not invent signal history. Analysis frames with
incompatible FFT settings are ignored; Spectrum and Spectrogram reject mismatched
frequency and level counts. Explicit full-waveform decoding failures preserve
an error result rather than installing an incomplete scan as complete.
Before a full scan starts, its Track query must still match the selected track's
metadata stamp and request generation; unrelated library edits do not invalidate
that query. Once decoding starts, ordinary metadata changes do not cancel it:
the source, saved-hint, request-generation, and suspension checks described under
<<_waveform,Waveform>> govern pending and completed previews.

Spectrum tessellation and Spectrogram image upload/paint failures are surfaced
as visualization errors. Stereo-analysis image failures are reported separately.
These rendering failures do not issue playback commands or make the audio
callback wait for graphics. Very small plots can omit geometry rather than
attempting invalid dimensions.

== Evaluating tradeoffs

The design moves work between aggregation, geometry construction, image
generation, retained memory, and scene submission. A cache hit or a lower
submission count alone is not evidence of an overall speedup.

Compare equivalent data, panel dimensions, display settings, and repaint rates.
Include first draws, stable repaints, changing data, and dense Spectrum styles;
measure the actual renderer as well as CPU and memory use. Renderer-level
changes should be justified by those workloads rather than historical CPU
percentages from a different implementation.
