= Visualization Rendering Design

== Goals

Rendering preserves the meaning of the signal: RMS is a continuous energy
area, Peak is a discrete transient marker, and Spectrogram is chronological
frequency history. Palette choices and cache policy must not alter the
underlying audio data.

This document explains rendering choices and their tradeoffs. User controls,
defaults, and display behavior are documented in
link:01_config.adoc[Configuration and layout]. Cache ownership, invalidation,
and resource lifetime are covered by link:22_cache.adoc[Visualization Cache].

== Analysis boundary

Visualization analysis is separate from audio output and observes samples
before output volume gain. The output callback sends a stereo analysis tap to a
bounded ring; analysis consumes it off the real-time thread. Spectrum combines
channel energy rather than averaging signed channels, so opposite-phase stereo
does not cancel. Optional spatial analysis retains the channels' relationship.

The tap holds at most 32,768 frames. Analysis backpressure never blocks playback:
dropped samples mark a discontinuity in the next accepted input. Each processing
cycle consumes only the queued prefix present at its start, so continued
production cannot postpone publication or shutdown indefinitely. One latest
shared frame is published rather than an unbounded queue of analysis results.
The priority is reliable playback and coherent displays, not collecting every
frame regardless of whether it can be consumed.

Stream resets, analysis restarts, dropped samples, FFT/window changes, and
optional-payload demand transitions break signal continuity. Views reject
frames from stale analysis settings and reset envelopes or simulations at a
break rather than smoothing across unrelated audio. Spectrogram does not pool
new samples across that break; compatible historical frequency buckets can
remain visible. Its sample time follows accepted audio, not wall time or the
track's seek position.

GUI analysis demand follows visible views. Stereo density, spatial spectrum,
and integrated band energy are independent requests combined across panels;
one accepted audio window and stereo FFT supply all requested payloads. This
avoids separate analyzers for different views while allowing unused result
storage to be released. A demand transition invalidates the sampling window,
including a quick hide/show that the worker did not observe as a steady state.

== Still Mode

Still Mode overrides visualization demand at both GUI and audio-worker
boundaries. It stops the output tap and parks analysis without reopening
playback. Entry discards shared analysis results, Spectrogram history, stereo
fields, fractal scenes, and progressive and shared waveform bins. FFT plans and
working buffers remain reusable, but their sampling window is reset.

Settings, source identity, playback timeline, and accounting survive. Mode
transitions invalidate queued samples and publications even across quick on/off
switches. Sample-rate, FFT-size, or window changes rebuild the analyzer;
resumption waits for a new complete audio window. Already submitted graphics
follow link:22_cache.adoc#_resource_boundaries[frame-boundary retirement],
independently of suspended analysis.

Waveform coverage is also discarded: prior samples cannot count toward a
complete envelope, and EOF cannot make a skipped or discarded interval complete.
Only fresh decoded PCM allocates and fills bins. There is no automatic backfill
or full-track rescan; an uninterrupted fresh traversal from zero can complete
the envelope. Explicit full-waveform scans are cancelled by the audio worker on
entry, without waiting for GUI refresh; quick on/off transitions cannot miss the
cancellation. Decoder packet boundaries observe the cancellation flag. A shared
suspension generation also rejects late results, so old scans cannot restore
discarded data or report a cancelled request as a waveform-load failure.

== Waveform

Playback builds a progressive waveform from decoded PCM, not from the FFT tap.
It retains at most 1600 bins rather than whole-track PCM. Unknown-duration
timelines expand by coarsening existing bins, preserving bounded memory at the
cost of preview resolution. An undecoded interval is distinct from decoded
silence. Peaks can survive disjoint visits, but RMS represents a contiguous
sample interval rather than repeatedly counting seeked or replayed samples.

A completed explicit full-track scan takes precedence over an in-flight
progressive update. Source identity is the file and optional playback range,
not metadata or panel visibility. A source change cancels the explicit scan;
ordinary display changes do not start a decoder. This keeps the preview from
regressing after a complete result becomes available and avoids background
full-track reads merely to display a panel.

RMS fills extend above and below the centerline for the respective stereo
channels. Each display column has its own gradient endpoint, preserving color
differences between adjacent columns with different energy. The gradient starts
at the visible palette minimum on the centerline and brightens toward that column's
RMS edge. Nonlinear color compression keeps warm colors as high-energy accents
while preserving access to the full visible palette range. It is a visual choice, not an
amplitude or renderer limit.
Peak is a thin, solid marker at the channel's peak level. Color compression
does not change the height represented by the amplitude mapping.

A single shared vertical gradient would be cheaper to batch, but would assign
the same color to equal heights across columns and weaken those differences.
The design keeps per-column color fidelity without quantizing the palette.
Static RMS and Peak layers are cached as image tiles, while the playback cursor
and glow remain dynamic. This trades image memory and rebuild work on changes
for less repeated rendering of an otherwise unchanged waveform.

== Spectrum

Spectrum uses batched body geometry with a shared spatial gradient. This suits
continuous curves and filled areas as well as styles composed of many bars,
outlines, or LED segments. In dense styles, separate submissions for every
primitive would add overhead without improving the intended color mapping.

Waveform and Spectrum exclude DeaDBeeF's initial black-to-deep-blue interval:
normalized color levels map to `0.06 + 0.94 * level` in the original palette.
Spectrum's remaining stops are rescaled to fill the plot height; body and Peak
colors use the same visible domain. Waveform uses that domain for its centerline,
RMS endpoints, and Peak colors, retaining the color compression described above.
Tokyo Night is unchanged. Spectrogram continues to use the complete palette,
including DeaDBeeF's black floor. These color mappings do not alter signal levels
or amplitude geometry.

Peak markers are discrete, solid-colored markers drawn separately from the
body. They are not connected into a curve, and the body cache does not own their
geometry. This preserves their transient-marker meaning while keeping body
reuse separate from Peak rendering.

Batching does not make dense styles free: more bars or LED segments still
increase geometry work, and the shared gradient requires renderer submissions
for its palette intervals. The choice favors batching where the visual model
allows it, rather than forcing Waveform and Spectrum through one strategy.

== Audio Visualizer ownership

Panel instances own presentation options, while analysis and simulation results
are shared by rendering style. Multiple panels of one style do not duplicate its
field or advance its simulation independently; distinct styles do not overwrite
each other's state. Overlay toggles are paint-only and do not reset analysis or
simulation. Hidden styles release result storage; submitted analysis images
retain the retirement boundary described in link:22_cache.adoc[Visualization Cache].

=== Radial styles

The radial presentation adapts Noctalia Shell v5's
https://github.com/noctalia-dev/noctalia-shell/blob/e56a9db5/Widgets/AudioSpectrum/NMirroredSpectrum.qml[`NMirroredSpectrum.qml`]
concept and parameter model, not its rendering implementation or pixel output.
GPUI-native paths use a bounded display of at most 32 logarithmic bands.
Rotation follows accepted sample time. There is no reusable rendering cache
for these styles.

=== Stereo analysis styles

Stereo Density uses a fixed 256 by 256 mid/side field with decay normalized to
accepted audio time. Silence advances decay without creating a false center
point. Correlation requires energy in both channels; balance and side ratio
require nonzero total energy. Undefined metrics remain absent, not fabricated
as zero. Spatial Spectrum maps individual FFT bins by frequency and channel
power balance into a fixed 256 by 128 field. Cells retain the strongest power
rather than summing crowded logarithmic rows, which would make color depend on
bin density instead of signal level.

Both styles retain fixed-resolution field images independently of panel size;
enlarging a panel does not multiply analysis resolution or allocate another
field. Continuity breaks clear existing field contents while preserving storage
for visible styles; hiding a style releases it. Recoloring uses retained fields
rather than another FFT. This trades fixed display resolution for predictable
storage and coherent reuse across differently sized panels.

Color ramps derive from the configured visualizer colors, with increasing
lightness and pale highlights reserved for the strongest cells. Density has a
cyanward intermediate hue; Spatial Spectrum retains the primary-to-secondary
hue progression. A bounded lookup table supplies BGRA pixels and is rebuilt
only when the configured colors change. Opacity lifts faint cells without
renormalizing the field: occupancy and spectral power retain their fixed dB
references, and empty cells remain transparent.

== Spectrogram

Spectrogram maps retained frequency history to colored image columns. Stable
history is a natural reuse boundary: newly accepted audio changes recent
columns without requiring the entire visible history to be rebuilt. Frames that
share a time bucket are max-pooled rather than averaged, retaining short
transients without storing every frame. Display mapping can recolor compatible
retained frequency data without re-running audio analysis. A gap starts a new
interval instead of drawing new audio across the missing time.

History width and image resolution bound retained resources. Increasing display
resolution does not create additional FFT information. Multiple panels share
history rather than maintaining competing copies; the cache document describes
capacity changes and image retirement.

== Generative light

Fractal Beams uses fixed recursive topology rather than rebuilding random
branches on each frame. Three integrated frequency bands drive different
spatial scales; root-to-tip pulses follow rises in energy, not beat estimates.

Fractal Flow uses three spatial scales of a deterministic curl field. Bands
deform the field rather than steering independent random particles. Trails fade
and taper; boundary respawns discard old points rather than connecting opposite
edges. The fixed particle history is allocated on the first valid audio frame.

Both styles take band power from the stereo FFT bins with window-energy normalization,
not from summed dB values or maximum-pooled display bands. Opposite-phase
channels retain their energy.

Simulation advances once per accepted analysis frame and is shared across
visible panels. Paint and resize never advance the scene. Discontinuities clear
the state, and hidden views do not request the optional band-power analysis.
Glow uses batched, widening translucent strokes rather than image feedback
history or a blur post-pass. This bounds retained scene storage and submissions,
at the cost of approximating the light spread. Beams retains 189 branches, 756
line segments, and 12 pulse slots. Flow retains 96 filaments with at most 24
points each and 2208 line segments. Both styles draw at most 27 light paths per
panel; Flow limits each integration step to 1/120 second and each accepted-frame
update to 60 steps. A gap longer than half a second resets the scene instead of
attempting unbounded catch-up.

== Failure boundaries

Views without accepted data do not invent signal history. Analysis frames with
incompatible FFT settings are ignored; Spectrum and Spectrogram reject mismatched
frequency and level counts. Explicit full-waveform decoding failures preserve
an error result rather than installing an incomplete scan as complete.

Spectrum tessellation and Spectrogram image upload/paint failures are surfaced
as visualization errors. Stereo-analysis image failures are reported separately.
These rendering failures do not issue playback commands or make the audio
callback wait for graphics. Very small plots can omit geometry rather than
attempting invalid dimensions.

== Evaluating tradeoffs

The design moves work between aggregation, geometry construction, image
generation, retained memory, and scene submission. A cache hit or a lower
submission count alone is not evidence of an overall speedup.

Compare equivalent data, panel dimensions, display settings, and repaint rates.
Include first draws, stable repaints, changing data, and dense Spectrum styles;
measure the actual renderer as well as CPU and memory use. Renderer-level
changes should be justified by those workloads rather than historical CPU
percentages from a different implementation.
