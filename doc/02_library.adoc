= Library
:toc:
:toclevels: 2

The library is shared by the desktop GUI, CLI, and TUI. Register local files by
dropping them into Queue, or configure a music folder and scan it for directory
browsing and CUE discovery. Registration does not itself start playback. Browse
tracks, albums, or recent activity to build a queue or a
link:03_playlist.adoc[playlist]. Registration, scanning, and ordinary metadata edits
change Rivu's database, not the audio files. Explicit <<source-file-tags,source tag
editing>> is a separate offline operation.

CLI paths are relative to the invoking client's working directory; absolute paths
are accepted. Rivu does not expand `~` or shell variables inside a path: use shell
expansion (for example, `"$HOME/Music"`), not a quoted `"~/Music"`. Except for the
local `library probe`, `library tags`, and independent migration tool, library
commands address the running host for the selected data directory.

[[other]]
== Other

`Other` contains registered tracks outside configured music folders, or all tracks
when no folders are configured. It appears after the folders and is hidden when
empty. Adding or removing a folder changes this grouping, not tracks or saved data.

Tracks appear in a flat list; hover a track for its full source path. Search,
favorite and missing-file filters, sorting, selection, and track actions work within this
collection. Dragging its header adds the complete collection, not only search
matches. To add local files, see link:04_playback.adoc#adding-local-files[Adding local files].

Hover its header for `Check files`. Checking visits registered audio files without
discovering new tracks or reimporting CUE sheets. Confirmed absence marks a track
missing; permission and read errors do not. A successful check clears missing state.
`Force reread` also refreshes unchanged metadata. Both preserve identities, user
data, and queue/playlist references. CUE labels and source bounds are retained;
audio properties and durations are refreshed from the source.

[source,sh]
----
rivu library other list --query "artist"
rivu library other check --wait
rivu library other check --force --wait
----

`library other list` returns one page (100 rows by default, at most 256); use
`--offset` and `--limit` to read more. List and locate accept `--query`, `--favorite true|false`,
`--missing true|false`, and `--sort id|album|most-played`. Omit a boolean filter to
include both states. Count always returns the unfiltered collection total.
`rivu queue add-other` appends the complete collection without starting playback,
independently of browsing filters. Terminal browsing and keys are documented in
link:04_playback.adoc#terminal-client[Terminal client].

[[roots-and-scanning]]
== Roots and scanning

Scanning requires at least one configured `library.roots`. Add a directory with
the GUI Library `+` button or set absolute directory paths in `config.toml`.
Saved roots appear immediately in the desktop Library, even when empty or not
yet scanned. Saving roots does not scan or enqueue music. Use a root's scan action
or choose `Scan paths` in Library.

Configured roots must not overlap after logical path normalization: duplicate
and parent/child paths are rejected. Symlink targets are not resolved, so logical
aliases remain distinct. Correct existing overlaps before starting the host or
saving settings.

To stop managing a root, right-click its header, choose `Remove library folder...`,
and confirm. Only the configured root is removed; indexed tracks, user data,
queue/playlist references, and audio files are kept.

To scan from the command line, run:

[source,sh]
----
rivu library scan ~/Music --wait
----

The desktop does not scan roots at startup. Scans run in the background without
stopping playback. `--force` rereads unchanged audio metadata; CUE sheets are always
reread. Readable tracks may be saved even when the task fails: fix errors and rescan
before cleaning missing records. Path, admission and recovery rules are under
<<scan-policies-and-recovery,Scan policies and recovery>>.

Scans, Other checks, playlist imports, and external-file queue additions share one
media-task slot; another request is rejected while one is active. Library shows
scan and check results, Playlists shows imports, and Queue shows file additions.
Rejected requests have separate dismissible errors and do not replace accepted
task feedback. See <<cancellation,Cancellation>> for waiting, status, and shutdown.

Failed desktop media tasks offer a Copy button beside Dismiss in the result
heading. Copy preserves the complete error message, including text truncated in
the panel; it neither dismisses the result nor changes the task. Library scan
errors stay in Library rather than replacing the window-global notification.

Cancelling a desktop file chooser changes neither configuration nor existing
errors; this also applies to playlist import and export.

[[cue-library-tracks]]
== CUE library tracks

`rivu library scan album.cue --wait` creates one library track per audio entry
and one ordinary whole-file track per referenced source. Both are independently
visible and playable, with their own metadata, history, and statistics. Shared
sources have only one whole-file identity per logical audio path, even when
referenced by several sheets. Invalid sheets are rejected as a whole; readable
audio discovered independently remains eligible for ordinary import.

CUE titles use each entry's `TITLE`, or `Track NN` when absent. The entry's
`PERFORMER` takes precedence over the sheet's performer; without either, the
source artist is kept. The sheet's `TITLE` supplies the album when present;
otherwise the source album is kept. Technical metadata comes from the source,
while duration is the individual segment's length.

CUE subtracks and whole-file tracks retain independent user edits, history, and
playlist references. Changes to a source during a scan require a subsequent scan.

Track details distinguish whole-file tracks from CUE subtracks and show the audio
source path. CUE details also show the sheet, track number, and source-relative
start and exclusive end as `MM:SS:FF` at 75 frames per second. A segment without
an explicit end is labeled as ending at the file's end. Removing either library
identity does not remove the other or delete the audio file.

Supported formats and playlist exchange: link:03_playlist.adoc#cue-import[CUE import].

[[desktop-selection-and-directory-tree]]
== Desktop selection and directory tree

Use tree view to browse directories, or the flat list to browse recursive tracks
grouped by configured roots in configuration order. Empty roots remain visible.
Click a directory or root header to expand or collapse it; the two views retain
their expansion choices independently. Search, favorites, and missing-only filters
combine in either view; the tree keeps matching tracks and their ancestors.

Double-click a track to play it. Hover it for its favorite toggle, which does
not change selection or start playback. Hover a directory or root for Rescan;
rescanning does not change selection or expansion. The toolbar's Append and Remove
actions require selected tracks, not just folders.

Right-click the Library panel → `Track information` to choose Artist, Album,
Duration, Codec, and Bitrate columns for both views. Duration and Codec are enabled
by default; choices survive restart. Hover truncated rows for full metadata and paths.

Root totals include missing files and tracks in unloaded or collapsed directories.
See <<desktop-list-search,Desktop list search>> for filtered counts. If a count
fails, the directory action retries it before returning to Rescan, including when
filtered counts are waiting for a failed root total. Changing filters does not
retry that failed dependency.

Dragging a directory adds its full contents, regardless of display filters. To add
only matching, favorite, or missing tracks, select and drag the track rows.

Click selects one row; Ctrl/Command-click toggles it. Shift-click selects a range
from the original anchor; Ctrl/Command-Shift-click adds that range. Range selection
includes unloaded rows, disabling selection actions and dragging until loading
finishes. Track transfers follow display order, independent of which pages are
cached. Changing search or filters cancels a loading range.

Right-clicking a selected track preserves its group; right-clicking an unselected
track selects that track alone. Track menus offer Play, Append to queue,
Add to playlist, Favorite, and Unfavorite, followed by removal where applicable.
Play targets the clicked track; the other actions target the captured group.
Favorite and Unfavorite set every target explicitly, rather than toggling mixed
states. Library removal deletes records and references, never audio files.
Panel and background menus contain panel or collection operations, not actions
on a previously selected track group.

Dragging carries the selection at drag start, or only the dragged row if it was
unselected; Esc cancels. Grouped-list selections can include root headers across
groups and unloaded pages. Selected headers support recursive rescanning and
dragging; overlapping sources contribute each track once.

Scans refresh affected views, including empty expanded folders; collapsed folders
load current contents when reopened. Unchanged scans preserve existing views.

[[desktop-list-search]]
== Desktop list search

Use a list's Search button or Ctrl+F with that list focused. Each list keeps its
own query; the placeholder and Search tooltip identify its scope and fields.
An empty field folds on losing focus. A nonempty field stays visible; Clear search
restores the complete list without closing it. From list focus, Esc first clears
the query, then folds an empty field; editors, popups, and composition take precedence.

The open field shows matches / total; unavailable totals do not hide loaded results.
No matches is distinct from an empty collection. Search changes the view, not
saved contents or playback order.

Nonempty edits apply after 150 ms without input; Enter does not bypass the delay.
Surrounding whitespace is ignored, and clearing applies immediately. The
link:04_playback.adoc#terminal-client[terminal client] instead applies search on Enter.

Library searches title, artist, and the full source path, combined with its
favorite and missing-file filters; it does not search album metadata. Albums
searches album titles and member artists. Playlist names search by name; playlist,
queue, and album track lists search track title, artist, album, and file name.
Recent tracks searches the displayed track titles. Searches are case-insensitive
literal substring matches, not wildcard patterns: `%` and `_` match themselves.
Track searches cover the whole collection, including unloaded pages, rather
than just the rows on screen.

Each Library root shows its recursive track total. While any text, favorite, or
missing-file filter is active, it shows matching tracks / total tracks instead,
including tracks in collapsed folders and unloaded pages. Roots with no matches
remain visible with a zero matching count; a pending or failed count is shown as
an em dash, not zero. Clear all filters to return to the total alone.

Changing the search clears that list's selection. Select all operates on matching
rows only. Queue and playlist drag reordering is unavailable while filtered; clear
the search before dragging to reorder. Playing or appending a whole playlist still uses its
complete saved contents, not its search results. If search hides the playing
track, use the explicit clear-and-locate action to reveal it.


== Locate the playing track

Use `Locate playing track in Library` to reveal the current track, also while paused.
It expands the root and parent directories in tree view or uses the current flat
sort, scrolls to the exact library identity, and briefly emphasizes it. Selection,
playback, and the Details target are unchanged; track changes do not automatically follow.

If filters hide the track, only the explicit `Clear filters and locate` action
clears them. Tracks outside roots are located in Other. The control is disabled
without a current track; a removed track is reported, not replaced by another identity.

[[track-information]]
== Track information

Playlist, Queue, and album track rows show the title above the artist and album,
with duration aligned at the right. Album track rows omit the repeated album name.
Missing artists and albums use compact person and disc symbols; hover a symbol
for its meaning. Unknown duration is `-`, not a zero-length recording.
A missing or whitespace-only title falls back to the source filename without its
extension; untitled CUE entries also include their track number.
The TUI uses the same title fallback.

Hover track text for full metadata and audio specifications: codec, sample rate,
source bit depth, channels, and bitrate. Unknown specifications are omitted;
estimated bitrate uses `≈`. Library hover also shows the full source path,
including in Other and when information columns are hidden. Directory hover
shows its complete path.


[[albums]]
== Albums

Add the dockable `Albums` panel to browse the cover grid. Double-click a card to
open its tracks; Back returns to the grid. Hover a card, or use Tab, to reach Play
and Add to queue; Enter or Space activates the focused action. Both target the
complete album, including unloaded tracks. For replacement and confirmation, see
link:04_playback.adoc#transport-and-timing[Playback]. Double-clicking a track plays
only that track.

Right-click a card to add the complete album to a playlist or set its favorites.
Drag it to Queue to insert at a row boundary or append in blank space, or to a
named playlist catalog row to append in album order; track rows can be transferred
individually. Transfers, Favorite, Unfavorite, and New playlist reject changed
album membership rather than using stale or partial results. External database
edits while Rivu is running are unsupported.

Press Esc or Left to cancel loading for Favorite, Unfavorite, or New playlist.
A cancelled action cannot later change favorites or open the playlist dialog.
See link:22_cache.adoc#demand-cancellation-and-physical-retirement[collection resolution]
for internal loading and source-identity rules.

Search matches album titles or member artists across the library. An artist match
keeps the complete album, including other artists' tracks. The sort icon switches
between title and artist order. Search and sort changes return to the top; Back,
resizing, hiding, playback, and refreshes preserve browsing position where possible.
Each Albums panel keeps independent browsing state. Both views load while scrolling;
failed loads offer Retry without replacing other rows.

Track rows show duration, missing-file status, and playback state by library track,
not queue occurrence. Missing artists use `-` on cards and the shared person symbol
in track rows.

Albums group tracks by exact effective album title and immediate parent directory.
Blank titles, including empty overrides, form no album; those tracks remain in
Library and other collections. Titles retain spelling and whitespace. Same-name
albums in different directories stay separate; disc subdirectories are not merged.
Different artists within one group form a compilation labeled `Various artists`.
Members sort by disc number, track number (unknown last), title, then library ID.
Metadata overrides affect grouping.

== Recent tracks

Recent tracks uses the <<desktop-selection-and-directory-tree,shared selection rules>>
and track menus, independently of Library selection. Ctrl+A selects all matches
in the focused panel. Sorting preserves selected tracks; refresh discards removed
ones. Double-click plays the clicked track; hover for its favorite toggle.

Drag a selection to Queue or a named playlist catalog row in displayed order,
without removing history entries. Queue row drops insert at the indicated boundary;
blank space and playlist catalog rows append. Columns remain sortable and shrink to fit.

`Remove from recent tracks` removes the selected history records and clears their
last-played times, without deleting tracks or changing play counts. Playback is
uninterrupted; removed tracks return to history when played again.

The loaded playback track shows only `Playing`, `Paused`, or `Stopped` in the
Last played column, even before playback has confirmed any audio was heard.
This follows the playback track, not the Recent tracks selection. Other rows
show their stored last-played timestamps. Merely selecting a track or restoring
it in a stopped state does not create history; a successful playback start does.
Only tracks already in history appear here. See
<<play-counts-and-recent-tracks,Play counts and recent tracks>> for activity and
counting rules.

[[play-counts-and-recent-tracks]]
== Play counts and recent tracks

A playback increments its play count once when confirmed heard time *strictly
exceeds* `playback.play_count_threshold_percent` of the track duration (20% by default).
Exactly reaching the threshold does not count. Pause/resume and seeks do not
reset count state or create additional counts; skipped or unconfirmed output
time is not heard time. When duration is unknown, counting waits for a complete,
seek-free traversal from the beginning through natural EOF to supply a positive
decoded duration; pauses do not invalidate this traversal. After a seek, duration
remains unknown and no percentage-based count is added.

A successful playback start creates or updates one recent entry per track,
ordered newest first. Paused time and failed loads do not advance activity.
History records the last playback activity, not necessarily a counted play;
it is not a per-play log. Timestamps are Unix seconds in JSON.
Recent entries reflect edited titles and current counts. Crossing the counting
threshold refreshes activity; editing a title does not. GUI Last played sorting
and TUI Recent ordering use the current playing or paused track's live timestamp,
placing it first among equal-second timestamps when newest-first.
Up to 256 recent tracks are retained.

If saving final listening statistics fails, Rivu keeps the pending facts in memory
and retries on playback transitions and orderly shutdown, without double-counting
an already saved play. A new playback may be blocked by unsaved statistics;
independent controls such as volume remain available. A failed Recent view refresh
retains its own recovery work without blocking new playback or resaving confirmed
statistics. Pending in-memory recovery does not survive process exit.

`rivu library history --limit N` returns up to N retained rows (default 20) in both
text and JSON output. See <<cli-output,CLI output>> for result shapes.

[[paged-views]]
== Paged views

GUI/TUI library and playlist views, and GUI Albums, load while scrolling. Directory
collapse preserves descendant expansion choices; loading rows preserves selection
and active Details input. Failed GUI loads offer Retry without rescanning files.
Desktop queries time out after 12 seconds. TUI failures can be retried by leaving
and reopening the view; obsolete or cancelled reads retire without a query error.

Navigation and selection keys act on the focused visible panel. Library, Queue,
and playlist tracks support Home/End. The TUI Library lists configured roots,
including empty ones, followed by <<other,Other>> when nonempty; it does not infer
filesystem roots from registered tracks. Terminal actions are documented in
link:04_playback.adoc#terminal-client[Terminal client].

In the GUI, PageUp/PageDown scrolls a viewport without changing selection. It uses
the last-clicked visible viewport, or the one under the pointer after clicking
elsewhere. Editors, Settings, About, and open menus retain their own key behavior.
`interface.query_batch_size` controls query batches, not viewport size or total
results; see link:01_config.adoc[Configuration]. In the TUI, these keys move the
selection by one screen; returning to a parent restores selection and viewport.
Exiting the TUI does not wait for stalled queries.

CLI `library list`, `queue list`, `playlist list`, and `playlist show` include all
matching rows, independently of `interface.query_batch_size`. If relevant data changes while a listing
is being read, the command stops, prints a `Listing incomplete` notice on stderr,
and exits with status 1. Already emitted text may be incomplete, and JSON may be
invalid; discard it and retry. GUI/TUI refresh stale query results automatically.
The explicitly paged `library other list` and `library duplicates` commands do
not traverse the full collection automatically.

Query limits, revisions, and batch contracts: link:21_ipc.adoc[IPC].

[[metadata-and-favorites]]
== Metadata and favorites

[[database-edits]]
=== Database edits

Title, artist, album, favorite, play-count, and decoder-hint edits in the library
change Rivu's database only; they do not rewrite media files, tags, or CUE sheets.
Rescans preserve matching IDs, overrides, favorites, decoder hints, counts, and
last-played timestamps. `library remove` and `library clean-missing` atomically
remove records and their queue/playlist
references, compacting positions without changing surviving occurrence identities
or relative order. They never delete media files. Missing rows remain visible in
playlist views until removed or cleaned.

Failed writes leave saved data unchanged. A refresh error after a committed edit
does not roll it back; older rows may remain visible until refresh succeeds.
Repeating an already-saved edit is not a refresh retry.

Metadata edits override only fields you change. An omitted CLI option or an
unchanged Track details field keeps its current value and continues to follow
rescanned metadata if it has no previous override. Concurrent edits to different
fields preserve both changes; edits to the same field use the last applied value.
Passing an empty string explicitly clears that field's displayed text.
An explicitly supplied CLI field records an override even when its value equals
the current scanned metadata; that field then stays fixed across rescans.

[source,sh]
----
rivu library list --favorite true
rivu library list --missing true
rivu library favorite on 12 34
rivu library edit 12 --title "New title" --artist "Artist" --album "Album"
rivu library clean-missing
----

[[source-file-tags]]
=== Source-file tags

`rivu library tags PATH` reads source tags without opening a player instance or
loading its configuration. Supplying `--title`, `--artist`, or `--album` explicitly
writes those fields to the source file. Omitted fields remain untouched; an empty
string clears the selected field. This is distinct from `library edit ID`, which
only records database overrides.

[source,sh]
----
rivu --json library tags /path/to/track.flac
rivu library tags /path/to/track.flac --title "New title" --artist "Artist"
----

Source editing makes an independent original-file backup and reports its path.
Unchanged edits neither rewrite the source nor create a backup. Replacement uses
a verified same-directory temporary copy and checks that the source has not changed.
Allow space for two complete files in addition to the source. Stop other writers
first: the lock is advisory. Keep the backup until the result has been checked.

Source-edit results distinguish `unchanged` and `replaced`; a replacement reports
the independent `backup_path`. Failures report `before_replace`, including any
retained backup. Inspect the source and reported original backup before retrying
or rescanning; failure does not authorize replay. With `--json`, structured
failures go to stderr and retain the outcome, source path and backup evidence.
Neither source replacement nor backup publication requests a storage sync;
successful completion does not promise survival of power or operating-system failure.
See link:91_design_decisions.adoc#DEC-018[file publication policy].

For tag inspection, edit results (including failures), and offline `library probe`,
JSON `path` and `backup_path` values are strings when the path is valid UTF-8. Other Unix paths
use `{"unix_bytes":[...]}` containing the complete original path bytes as integers
from 0 to 255; consumers can reconstruct the path without character replacement.
An absent optional backup remains `null`. This representation applies to the
whole path, including non-UTF-8 parent directories.

Symlinks and multiply linked files are rejected. Replacement must preserve ownership,
permissions, and extended attributes, including POSIX ACLs; inability to preserve
them fails the edit. Native tag structures retain non-target fields and artwork.
Upstream Lofty may normalize tag representations; parsing and encoding follow its
allocation limits.
ID3v2.2 edits requiring a version conversion are rejected. Clearing a field also
fails if a secondary tag would make the old value reappear, rather than silently
deleting that secondary tag.

This offline command does not update the running library. Rescan the affected
source afterward; matching IDs, user overrides, favorites, history, and list
references remain intact. Existing overrides still take precedence over newly
read source fields. Restoring a backup also requires a rescan.

Lofty supplies source tags and embedded artwork; containers outside its metadata
coverage may still play but have no audio-backend tag fallback. Inspection
distinguishes unsupported containers from supported files without tags. Editing
does not transcode audio or change CUE boundaries. Declared text encoding is
respected: incorrectly labeled legacy bytes are not automatically repaired, and
lost text cannot be reconstructed.

=== Inline Track details edits

Hover Title, Artist, Album, or Play count for Edit and Copy. Edit selects the
current value; Enter saves that field, while Escape or leaving the input cancels
unsubmitted text. Unchanged values send no write. Empty text displays as `-` but
starts empty in the editor; saving it clears the database field, not source tags.

Play count accepts integers from `0` to `9223372036854775807`. Setting it does not
change last-played time or reset the current playback's already-counted state;
pending playback statistics are recovered first. Decoder guidance is available
beside its dropdown.

Only one inline field is edited at a time. Same-track refreshes preserve its input;
a failed save retains the input and an error for correction or retry. Selecting a
different track, clearing selection or reloading cancels unsubmitted text without
confirmation. Playback-follow details switch immediately when playback changes;
an explicit selection remains on that track. Closing the window or quitting does
not ask about unsubmitted text.

Submitted saves can finish after cancellation or a selection change, but cannot
replace a newer editor or another track's details. A refresh failure does not undo
a saved edit; see <<database-edits,Database edits>>. Decoder hint saves immediately,
independently of text edits, and applies on the next track open or full waveform request.

=== Loading and unavailable records

Details distinguishes no selection, loading (`Not loaded`), query failure, an
unavailable record, and unknown metadata on a loaded track (`—`). Editing and
actions are disabled until the selected track is ready. Switching tracks clears
old values and artwork; same-track refreshes retain ready details and active input,
including after query failure.

Reload leaves manual selection and follows the current Playback track without
changing list selections; with no current track, it clears details. A confirmed
unavailable record clears details and cancels editing until a successful read
restores that record.

Decoder routing and DTS-WAV safety:
link:04_playback.adoc#optional-ffmpeg-decoder[Playback].

=== Read-only probing and displayed metadata

`rivu library probe PATH` reads audio metadata and decoder support without
starting a core; it does not create or update a library row. Add `--enhanced`
to explicitly load FFmpeg for this command, even when `playback.ffmpeg_enabled` is off.
Missing libraries or a native-only build make an enhanced probe fail rather
than silently use native recognition. JSON includes `probe_backend` and
`decoder_backend` (`native` or `ffmpeg`); these may differ for ordinary PCM.
Without `--enhanced`, a fresh probe process does not enhance native-supported
WAVE recognition. Recognition and DTS-WAV limitations:
link:04_playback.adoc#optional-ffmpeg-decoder[Playback].

GUI/TUI lists show compact display metadata. Track details and
`library list --json` expose full technical metadata, paths, CUE boundaries,
and statistics. Unknown values appear as `—` in human output or `null` for
nullable JSON fields.

In GUI Track details, hover a read-only field to reveal Copy value, or reach
the action with keyboard focus. It copies the complete value even when the
display is truncated; File path copies the original path even for a missing
file. Empty, unknown, and unloaded values have no copy action.

`bitrate_bps` describes the encoded audio stream. `bitrate_exact` distinguishes
confirmed values from estimates (`≈`); scans do not read whole streams just to
measure bitrate. Unchanged sources retain confirmed values, while changed sources
invalidate precision. See link:04_playback.adoc#playback-metadata-updates[Playback metadata updates].

[source,sh]
----
rivu --json library probe album.wav --enhanced
----

[[scan-policies-and-recovery]]
== Scan policies and recovery

=== Scan boundaries

Scan paths are normalized without resolving symlinks and must be at or below a
configured root; a mixed inside/outside request is rejected before scanning.

Symlinks are followed even when their targets are outside configured roots;
logical aliases remain distinct library identities. Directory cycles are scan
errors. CUE sheets and their sources must also lie within configured logical roots.

`library.scan_max_depth` applies independently to each requested directory. The start
directory is depth `0`; files in a directory at the limit are scanned, while
directories beyond the limit are skipped and reported. Direct file and CUE
requests are unaffected by this directory limit; `0` is invalid. An explicit
nested scan has its own boundary, even when an enclosing walk skipped it.

[[minimum-duration-for-new-tracks]]
=== Minimum duration for new tracks

`library.scan_min_duration_seconds` is a new-track admission policy, not a constraint
on library contents. It applies to ordinary audio discovered by directory scans,
direct requests, forced scans, and playlist imports. `0` disables it; otherwise
only new tracks with a known, finite, positive duration strictly less than the
configured seconds are excluded. A duration equal to the threshold is accepted;
unknown, unavailable, zero, or invalid duration is not treated as a short track.
Existing tracks, including recognized relocations, are retained and their metadata
is updated normally, even when short. `--force` rereads metadata but does not
bypass ordinary new-track admission.

Successfully validated CUE sheets exempt both their subtracks and referenced
whole-file tracks from this duration filter. The exemption also applies when the
same source is discovered independently in that scan. Failed sheets grant no
exemption. File, path, probe, and segment-boundary checks still apply; probe errors
remain scan errors. Duration exclusions are counted separately from errors.

Each scan or playlist import captures the threshold at startup and keeps it for
the entire task; saving a setting during a task affects only later tasks.
Changing the setting neither starts a scan nor deletes or cleans existing tracks,
and has no playback effect.

[[errors-and-partial-results]]
=== Errors and partial results

Readable tracks are saved even when other paths fail. Depth exclusions and scan
errors protect affected existing tracks from being newly marked missing or used
for relocation. A failed CUE sheet protects its owned tracks; readable whole-file
sources may still be imported. Invalid UTF-8 paths are local errors, not grounds
to reject unrelated readable tracks.

An initially `NotFound` requested path is confirmed absent and can mark tracks
missing. Disappearance during reading is uncertain until a later scan. Invalid
scopes or bounded diagnostics may also restrict missing detection and relocation.
Fix reported errors and rescan before cleaning missing records. Detailed coverage
rules: link:21_ipc.adoc#scanning-and-metadata-ownership[Scanning and metadata ownership].

=== Rereading sources

CUE sheets must be ordinary files no larger than 1 MiB. Audio sources, including
CUE references, must also be ordinary files; symlinks to them work. Devices,
FIFOs, oversized sheets, and unreadable sources report local errors without
waiting for a producer or blocking unrelated imports. A source changed during
analysis fails rather than saving mixed-version metadata. Playback and waveform
loading also require ordinary files.

Ordinary scans reuse fingerprints when size and modification time are unchanged;
metadata reuse also requires the current probe version. `--force` rereads both
while preserving user edits; CUE sheets are always reread. Reuse does not suppress
playlist creation: an unchanged import still creates its requested playlist.

Overlapping explicit scan scopes are traversed once while retaining their own
depth and missing-detection boundaries. Configured roots still must not overlap.
Cancellation and saving follow <<cancellation,the shared media-task lifecycle>>;
worker and coverage contracts are in
link:21_ipc.adoc#scanning-and-metadata-ownership[Scanning and metadata ownership].

Descriptive tags use upstream Lofty; native audio parsing has separate metadata
limits and may skip oversized fields while retaining usable audio. See
link:22_cache.adoc#native-metadata-admission[Metadata admission]. Force a
scan to refresh metadata already stored in the library.

[[cancellation]]
=== Cancellation

Scans, Other checks, playlist imports, and external-file queue additions share
this lifecycle. An accepted CLI request returns a `scan_id`, not proof of success;
use `--wait` to wait for its result, or query and cancel that task explicitly:

[source,sh]
----
rivu task status scan INSTANCE:TASK_ID
rivu task cancel scan INSTANCE:TASK_ID
----

Use the instance-qualified reference printed by the command, not a bare numeric
ID. References from a stopped instance are rejected. The core retains its latest
32 media-task results, not persistent history. Status success confirms retrieval,
not task success: inspect phase and error. Closing a waiting client stops waiting,
not the task; request cancellation explicitly.

In the desktop, the owning panel shows phase, counts, current path, and message.
Completed, failed, and cancelled results stay visible until dismissed or replaced
by a later accepted media task. Dismissal hides progress and message, without
undoing saved data, clearing a separate request error, or deleting the retained
task result. Closing the desktop window does not cancel a task.

Cancel during preparation to discard all prepared results. Shutdown also cancels
preparation. Cancellation is cooperative: an active probe must return and work
must retire before another media task starts.

Saving requires queue recovery and persistence of pending playback selection.
If recovery fails, the task saves nothing; existing playback is not rolled back.

Once Saving begins, cancellation is refused. Database reads and edits report
maintenance in progress; published status and existing-playback controls remain
available. Shutdown waits for the result. A failed task may have committed changes:
inspect its result before retrying. Playlist imports have additional
link:03_playlist.adoc#commit-and-export-lifecycle[commit boundaries].

[[same-files-and-relocation]]
== Same files and relocation

Automatic relocation requires a unique missing old identity and a unique new
destination with matching content. Exact identities take precedence and do not
count as new destinations. Ordinary files match by fingerprint; CUE segments
match by source fingerprint, track number, and exact start/end boundaries, and
require the old sheet to be absent. Ambiguous copies on either side retain
separate IDs and the missing identity's user state and playlist references;
scan order never chooses a destination. Ambiguity is per CUE segment key, so it
does not prevent other uniquely matched segments from relocating.

Open Settings → Library → `Same files / Relocation candidates` to inspect ordinary
file groups. Cached BLAKE3 hashes identify candidates, not fresh proof. Rows show
paths, existence, scan state, metadata, user state, and reference counts. Choose
`Use as old record` on a missing identity and `Use as destination` on a present
one, then review and confirm. Ineligible destinations show a rejection warning.

The review uses the same height as Settings, constrained by the window. Group and
file lists scroll independently without moving the heading, pagers, or bottom
note; selection feedback has its own bounded scrolling area.

Group and file pages are independent; paging preserves the selected pair.
Confirmation locks selection and paging. Use Back to selection to revise the pair
or Refresh to reset. Close or Esc leaves undecided pairs unchanged and returns
to Settings without applying or discarding its draft; Tab stays within the review.

`Keep destination independent` persistently excludes that row from automatic and
manual relocation, including after rescanning. No audio files are deleted.

Confirmation verifies the destination's current full-file hash, file identity,
and source absence before an atomic database update. The old ID, overrides,
favorite, history, and references survive at the destination; its redundant row
is removed. Destinations with user state or references, active source/destination
playback, changed files or database identities, and a reappearing source are
rejected rather than merged. Correct the reported conflict before retrying.

Closing the review requests cancellation of its ongoing verification. Cancellation
before commit leaves identities unchanged; it cannot undo a completed commit.
A status-read failure does not establish task completion: the review retains its
task identity, so closing it can still request cancellation.
CLI acceptance supplies a task ID, not proof of success. `--wait` reports the
final outcome; otherwise query status or cancel using that ID. The running core
retains the latest 32 task results, not persistent task history.

[source,sh]
----
rivu library duplicates
rivu library duplicates --fingerprint FULL_BLAKE3 --offset 0 --limit 100
rivu library relocate OLD_ID DESTINATION_ID --wait
rivu task status relocation INSTANCE:TASK_ID
rivu task cancel relocation INSTANCE:TASK_ID
rivu library keep-independent DESTINATION_ID
----

[[sqlite-maintenance]]
== SQLite maintenance

Rivu opens only the current database format. A new database is initialized
automatically; on a version mismatch, host startup invokes `rivu-migrate apply`
to attempt a supported offline upgrade before opening business connections.
Install `rivu-migrate` beside `rivu` or on `PATH`; migration failure stops startup
and prints diagnostics. The database stores library records, user edits and
statistics, playlists, and queue occurrences and selection. Stop Rivu before
external database edits. Queue restoration: link:04_playback.adoc#queue[Playback].

=== Independent migration tool

`rivu-migrate check` inspects formats; `apply` performs supported offline upgrades.
Stop Rivu and external writers before applying. Upgrades keep an independent backup and
preserve user data and playlist catalog order. Both commands validate current
resources without rewriting them and do not initialize missing resources.

[source,sh]
----
rivu-migrate --data-dir /path/to/rivu-data --config /path/to/config.toml check
rivu-migrate --data-dir /path/to/rivu-data --config /path/to/config.toml apply
----

Use the intended host's paths: `--config` alone does not select the database.
Both commands exit `0` for valid current resources and `2` on error. `check` does
not change configuration or database contents, though SQLite may update sidecars.
Full workflow and compatibility: link:26_migration.adoc[Database and configuration migration].

=== Database operations

Keep backups of `library.db` and its committed WAL contents: scanning media
cannot reconstruct playlists, saved queue, favorites, metadata overrides,
decoder hints, or playback statistics. Audio files, `config.toml`, and
`layout.json` are independent. Do not copy a running database's `.db` alone as
a complete backup; stop all connections before making a file-level copy.

Graceful core shutdown (`rivu quit`, `SIGINT`, or `SIGTERM`) closes its database
connection. SQLite normally checkpoints and removes the WAL/SHM sidecars when
the last connection closes; external connections can defer that cleanup.
After an abrupt exit such as `SIGKILL`, keep any remaining WAL with the database
so SQLite can recover committed transactions on the next open.

SQLite WAL with `synchronous=NORMAL` protects commits against application crashes,
but power or operating-system failure can roll back recent commits. See
https://sqlite.org/pragma.html#pragma_synchronous[SQLite synchronous modes].

To reclaim database/WAL space and refresh SQLite query statistics, ensure
playback is stopped and no scan is active, then run:

[source,sh]
----
rivu library optimize
----

Optimization requires stopped playback and no active media task, relocation, or
playlist export. Queue recovery must succeed before it starts. The command waits
for the final size report. While optimization runs, database operations are
refused, but published status, volume, and shutdown remain available. A timeout
does not stop optimization or permit a duplicate; shutdown waits for completion.

Failure does not guarantee rollback: VACUUM may have completed before a later step
failed. Inspect the result and close blocking readers before explicitly retrying.
Prepared processing snapshots remain available, but cannot start audition until
optimization finishes.

[[cli-output]]
== CLI output

`library list --query TEXT` filters by the Library search fields described above.
`--favorite true|false` and `--missing true|false` combine with it; omit either
filter to include both states. For machine-readable records, use
`rivu --json library list --query "Artist"`.

Human-readable CLI output escapes terminal control characters in metadata,
names, paths, device information, and error details. Embedded tabs and line
breaks appear as `\t`, `\n`, and `\r`; other controls use visible escapes such
as `\x1b` and `\u{009b}`. Ordinary Unicode and the command's own row/column
separators are preserved. This display-only escaping does not modify stored
values or JSON data.

`--json` writes one result value to stdout. Long-running commands with `--wait`
write only their terminal task result, not acceptance/progress events. Runtime
diagnostics are JSON objects on stderr with `error` and, for transport command
failures, `status`. No Core revision or task ID is invented for an uncertain
transport result. Argument/usage errors retain Clap diagnostics and exit status 2;
runtime failures exit 1. A successful command exits 0.

After a failed listing, discard its possibly partial or invalid output before
retrying; see <<paged-views,Paged views>>.
Queue listing binds its current-occurrence marker and all batches to the initial
queue revision; a concurrent queue change fails the listing instead of combining
different snapshots.

Result shapes follow the queried resource:

* `library list` returns full track records; `queue list` returns occurrence rows.
  `playlist list` returns summaries (`id`, `name`, `entry_count`);
  `playlist show PLAYLIST_ID` returns entries. `library history` returns retained
  history rows up to `--limit`.
* `status` returns instance state. `configuration` contains the settings snapshot
  and `config_path`; live volume, shuffle, repeat and output selection are reported
  in the playback and system sections and can be newer than that snapshot.
  Field contracts: link:21_ipc.adoc[IPC].
* Command acknowledgements report `Succeeded`, `Failed`, `NotAdmitted`, or
  `Unknown`, including failed authoritative results on stdout. Failure need not
  mean rollback; an unknown outcome requires inspecting state before retrying.
  See link:21_ipc.adoc#request-failures-and-completion[IPC request failures and completion].
* Task acknowledgements and results supply instance-qualified references. Reuse
  those references rather than constructing them from numeric IDs. `--wait` exits
  unsuccessfully for failed or cancelled tasks while retaining terminal results
  on stdout. Inspect the operation's commit boundaries before retrying. See
  <<cancellation,Cancellation>>, <<same-files-and-relocation,Relocation>>, and
  link:27_audio_processing.adoc[Audio processing].
* Successful `library optimize` acknowledgements include that operation's size
  report in `database_optimization`. The latest successful report in System
  status is observational and must not be mistaken for a failed command's result.
* `library other list` and both `library duplicates` variants return one
  `{total, rows}` page. `--fingerprint` selects duplicate members instead of group
  summaries. Page size is `0..256`, default 100; `--offset` defaults to zero.
  `library other count` returns a number; `library other locate` returns its
  tagged location result.
* `library stats` returns aggregate statistics; `library probe` returns metadata
  and decoder status; `playback devices` returns an array of device names.

Playlist export returns after writing the file, not after starting a background
task. Protocol and query contracts are described in link:21_ipc.adoc[IPC].
