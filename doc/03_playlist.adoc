= Playlists

Playlists are ordered collections of library tracks. Each track ID appears at
most once; adding it again leaves the existing entry unchanged. Imports and
saved queues retain the first occurrence of each track, unlike the
link:04_playback.adoc#_queue[playback queue].

== Management

Use `rivu playlist` to create, rename, delete, add, remove, move, or play.
Playlist IDs identify collections; entry IDs identify items for removal or
movement. Move indices start at zero. `playlist list` shows both kinds of ID.
Adding no new tracks or moving an entry to its current index leaves playlist
views valid. These requests still validate the playlist, track IDs, entry ID,
and move bounds; invalid requests do not change any entries.

Creating a playlist from a queue commits the name and entries together. If an
entry cannot be saved, no empty playlist is left behind.

[source,sh]
----
rivu playlist new "Mix"
rivu playlist list
rivu playlist add PLAYLIST_ID TRACK_ID...
rivu playlist move ENTRY_ID 0
rivu playlist play PLAYLIST_ID
----

Playing a non-empty playlist replaces the queue, with no playlist or queue-size cap.
An empty or unknown playlist leaves the existing queue unchanged.
See link:04_playback.adoc#_queue[Playback queue].

== Desktop UI

In the Playlists panel, New playlist opens a blank name dialog. Select a playlist
and use Rename to edit its current name. Enter submits; Cancel or Esc discards the
draft. Empty names are rejected. Saving runs in the background and prevents
repeat submissions; failures keep the dialog and draft available for correction.
A submitted save cannot be cancelled, including by closing the window.

To save selected queue tracks under a chosen name, use the Queue panel menu's
Add to playlist → Save selected queue as new playlist action. It opens its own
name dialog; no input in the Playlists panel is required. The tracks selected
when the dialog opens are saved without changing the queue.

Use the Queue panel's Save queue as playlist control to save a non-empty queue.
The playlist name is generated from the current date and time; duplicate queue
occurrences become one playlist entry.
Saving runs in the background; the control stays unavailable until its result
arrives. Closing the window does not cancel a save already submitted to the core.

Playlist catalogs, entries, and the Queue panel's playlist-destination menu
load rows automatically while scrolling. Entry numbering and move actions use
absolute playlist positions. Scrolling away from the selected playlist preserves
its name and selected entry. See link:02_library.adoc#_paged_views[Library] for
scrolling and query failure behavior.
Deleting the selected playlist from another client clears its playlist and entry
selection on refresh. Empty playlists and unloaded pages do not imply deletion.
When refreshed pages invalidate a selected entry's position, the GUI resolves
its current location by entry ID rather than reusing the old row index. Entry
mutations remain unavailable while that lookup is pending or failed; a failed
lookup requires explicit Retry. Confirmed entry removal clears its selection.
Moving an entry refreshes only that playlist's entries and selected entry location;
the unchanged playlist catalog and library views stay loaded. This also applies
to moves submitted by another client. Renaming, creating, deleting, or changing
membership still refreshes playlist catalogs, and track metadata edits refresh
displayed entry metadata.

== Import and export

CLI paths are relative to the invoking client's working directory. Referenced
media and CUE sheets must lie within configured logical roots; see
link:02_library.adoc#_roots_and_scanning[Library scan boundaries and errors].
Imports scan referenced sources before creating the playlist and may create
partial playlists: `--wait` reports scan errors even when readable tracks were
saved. Only identities successfully read or validly reused by that import's scan
can enter its playlist; an old library row does not make a failed source eligible.
Import fails if no entries resolve successfully. Without `--name`, the playlist
name comes from the imported file's name without its extension. Another import
or scan cannot start while scanning is active.

Listings and exports include every entry, not only the visible rows. For listing
changes and retry behavior, see link:02_library.adoc#_paged_views[Paged views].

[source,sh]
----
rivu playlist import mix.m3u8 --name "Mix" --wait
rivu playlist import album.cue --wait
rivu playlist export PLAYLIST_ID exported/mix.m3u8
----

=== M3U/M3U8

Import accepts UTF-8, including BOM, and resolves entries relative to the playlist
file. Ordinary audio and complete CUE sheets may be mixed. Export writes standard
UTF-8 M3U with paths relative to the destination directory; that directory must
already exist. Export errors leave an existing destination untouched. Paths that
cannot be represented as UTF-8 or contain CR/LF line breaks are rejected before
creating the destination file. CR/LF in title or artist metadata is replaced with
spaces so it cannot introduce additional M3U lines.

=== CUE import

Direct CUE import, or a CUE path in M3U, expands every track in sheet order.
Single-file and multi-file audio sheets are supported, using UTF-8 (with or
without BOM) or BOM-marked UTF-16. `FILE` paths are relative to the sheet;
Windows separators are accepted. Sources must be supported audio with readable,
finite positive duration; data tracks are unsupported.

CUE library identities and directory scanning: link:02_library.adoc#_cue_library_tracks[Library].
Subtrack playback: link:04_playback.adoc#_transport_and_timing[Playback].

=== CUE export restrictions

A complete, contiguous, correctly ordered sheet run exports as one CUE path.
Standard M3U cannot select individual subtracks: partial or reordered runs fail
and leave the existing destination untouched. Such selections remain valid inside
Rivu. Rescan externally edited sheets before exporting.
