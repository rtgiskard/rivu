= Playlists
:toc:
:toclevels: 2

Playlists are ordered collections of library tracks; repeated tracks have distinct
entry IDs. Additions, imports, queue saves, and transfers preserve order and duplicates.
The link:04_playback.adoc#queue[queue] is separate: loading a playlist or saving a
queue creates an independent copy, not a live link.

== Management

Create a playlist with New playlist in the desktop Playlists panel, or import an
M3U/M3U8 or CUE file with Import. To collect tracks already in Rivu, use a track
menu's Add to playlist action; to keep the listening order, use the Queue panel
menu → Save as playlist…. Neither action changes the source collection.

Names must contain a non-whitespace character and no control characters. Creating,
renaming, and saving a queue require a unique name. Imports check uniqueness
only after the library commit (see <<commit-and-export-lifecycle>>). Comparison
is exact, including case and whitespace: CLI/API names retain outer whitespace,
while the desktop name dialog trims it.

Use `playlist list` for playlist IDs and `playlist show PLAYLIST_ID` for entry IDs
and the observed entry revision. Add library track IDs; remove or move entry IDs.
Removing entries or deleting a playlist leaves library tracks and already loaded
queues intact.

[source,sh]
----
rivu playlist create "Mix"
rivu playlist list
rivu playlist show PLAYLIST_ID
rivu playlist add PLAYLIST_ID TRACK_ID...
rivu playlist move PLAYLIST_ID ENTRY_ID --before TARGET_ENTRY_ID --expected-revision REV
----

The move requires the revision printed by `playlist show` when choosing the target.
Use `--before ENTRY_ID` or `--after ENTRY_ID` for a stable target in that playlist;
omit both to append. A stale revision fails without changing order: refresh the
listing and choose again rather than replaying the old intent with a new token.
Text listings begin with `playlist_id=ID revision=REV`. With `--json`, the result is
`{"playlist_id":ID,"revision":REV,"entries":[...]}`, including empty playlists.
The revision and all streamed entry pages belong to one pinned traversal.

For queue snapshots, see <<transfers-and-queue-saving>>. For whole-playlist
versus individual-track playback, see link:04_playback.adoc#transport-and-timing[Playback].

[[desktop-ui]]
== Desktop UI

=== Catalog and naming

Select a playlist in the catalog to browse its tracks. The catalog and track list
have independent link:02_library.adoc#desktop-list-search[searches]; filtering
does not restrict whole-playlist Play, Append, or Export.

Drag a playlist name to reorder the catalog: the upper/lower half of a row inserts
before/after it, and blank space appends. The accent line marks the insertion
boundary; dropping on the source or pressing Esc cancels. Clear the name search
before reordering. Order survives restart, with new playlists appended; it does
not affect tracks or Queue. A changed catalog rejects an in-progress drag.

Hover a catalog row for Play and its actions menu; they target that row, not the
selected playlist. Empty or unknown playlists leave Queue unchanged. Append
rejects changed contents rather than copying a stale or partial list. See
link:04_playback.adoc#transport-and-timing[Playback] for Play, Append and confirmation.

The row menu also offers Add current track, Remove duplicates, Rename, and Delete.
Add current track uses the playback track, not Library selection, and requires a
current track. Remove duplicates keeps each track's first occurrence and changes
only that playlist. It rejects a request if the playlist's contents have changed.

Rename opens the current name; Enter saves in the background, and Cancel or Esc
discards the draft. Failure retains the draft for correction; closing cannot
cancel a submitted save. Delete asks for confirmation and never deletes music files.

=== Track selection and ordering

Use the link:02_library.adoc#desktop-selection-and-directory-tree[shared selection rules]
to select tracks and ranges, including unloaded pages. The count shows selection
size. With the track list focused, arrows navigate, Home/End selects the first/last
matching entry, Shift+arrows extends a range, Ctrl+A selects all matches, and Delete
removes selected entries. These keys do not operate the catalog, an editor, or
another panel. Double-click or Enter plays the active track individually. Hover
Play, Favorite, and Remove controls act only on their own row.

Drag a selection to move it in original playlist order; dragging an unselected
row moves only that entry. The upper/lower half of a row inserts before/after it,
and blank space appends. The accent line marks the boundary. The dragged group
stays fixed; dropping on that group or pressing Esc cancels. Reordering saves
the playlist without changing Queue.
Clear the track search before dragging: filtered playlist track rows cannot
start a drag, even to an unfiltered destination.

A drag is rejected if membership or order changes, the playlist is deleted, or
you switch playlists before dropping, even away and back. Renames and edits to
other playlists do not invalidate it.

A named catalog row is an explicit destination, even when another playlist is
selected. Track-row drops insert at the indicated before/after boundary; catalog
rows and blank space append. Positional drops require an unfiltered destination.
If the target queue or playlist changes before insertion commits, the old position
is rejected rather than falling back to append. Search changes the view, not the
saved collection. Playback confirmation and source-open failures are described
under link:04_playback.adoc#transport-and-timing[Playback].

Right-click a track or selected group and choose Add to playlist to select an
existing playlist or New playlist. The shared name dialog saves the captured
tracks. This selector also works when
the Playlists panel is not visible. Track menus follow the
link:02_library.adoc#desktop-selection-and-directory-tree[shared selection rules].

Open the Queue panel menu and choose Save as playlist…. The desktop requires a
nonempty queue to open the dialog. The default name is `Queue_YYYYMMDD_HHMMSS`.
Saving copies the entire queue as it exists at submission time, including an
empty queue if it was cleared while the dialog was open. Playlist creation and
copying are one transaction, but a later view refresh can still report failure.
Check Playlists before retrying after an error or uncertain response.

=== Loading and selection recovery

Catalogs, entries, and track-menu playlist selectors load while scrolling. Entry
numbers remain absolute when search hides rows; positional drops are unavailable
while the destination entry list is filtered.
Switching playlists clears track selection; deleting the selected playlist from
another client clears it on refresh. Empty playlists and unloaded pages do not
imply deletion. See link:02_library.adoc#paged-views[Paged views] for loading,
timeouts, and CLI incomplete-output recovery.

A range is selected only after all its rows load; failure preserves the previous
selection. Pending or failed selection loads disable group actions and offer
Retry, while loaded row controls remain usable. Retry reconciles the previous
selection rather than replaying a failed range or key command; refresh drops
removed entries. Group removal is atomic.

Changing the filter clears selection and cancels older navigation intent; late
results cannot restore it. Listings refresh when membership or order changes,
not on renames or edits to other playlists. Metadata changes can refresh display
without changing entry identity. Stale group edits are rejected. Protocol details:
link:21_ipc.adoc#query-results-and-pagination[IPC query validity].

== Import and export

Use Import at the top of the Playlists panel to read M3U/M3U8 or CUE. Select a
playlist before using Export; it stays unavailable without a selection. Export
always writes UTF-8 M3U, regardless of the destination extension. The CLI commands
below use the same whole-playlist semantics.

=== Import workflow

An M3U/M3U8 document itself need not be inside a library root. See
<<m3u-document-paths,M3U/M3U8>> for the distinction between command arguments
and paths stored in the document.

Imports scan referenced sources before creating the playlist. Only identities
successfully read or validly reused by that scan are eligible; an old library row
does not make a failed source eligible. Readable tracks can produce a partial
playlist even when `--wait` reports scan errors. The
link:02_library.adoc#minimum-duration-for-new-tracks[minimum-duration admission policy]
excludes short new ordinary tracks unless a successfully validated CUE sheet in
the same import references them. Import fails if no entries resolve successfully.

Without `--name`, the name is the input filename without its extension. Both
explicit and default names are checked for format before scanning. Playlists
shows import task feedback; see link:02_library.adoc#cancellation[shared media-task phases]
and link:09_cli.adoc#cli-command-conventions[CLI waiting rules].

Repeated paths retain every playlist occurrence in input order.

=== Input limits and cancellation

Import documents and referenced sources must be ordinary files, not directories,
devices, or FIFOs. Use `library scan` for recursive discovery. Preparation checks
document decoding, CUE syntax, the paths listed directly in M3U, and the path of
a directly imported CUE sheet. An out-of-root direct reference or a rejected
non-regular M3U source aborts preparation without saving tracks or a playlist.
A CUE sheet's internal `FILE` paths are checked during scanning instead. For
example, if M3U lists a readable song and a CUE whose `FILE` is out of root, the
sheet fails but the song can still be saved and included in the new playlist.

Limits are 16 MiB per M3U, 1 MiB per CUE, 64 MiB aggregate input (distinct sheets
read once), and 100,000 expanded occurrences. Exceeding input or retained-data
limits aborts before saving; these are not playlist-size caps.

[[commit-and-export-lifecycle]]
=== Commit and export lifecycle

Imports use the shared link:02_library.adoc#cancellation[preparation and Saving
lifecycle], with two separate commits:

[source,mermaid]
----
flowchart TD
    validate["Validate name format and prepare input"] -->|"Invalid input or limits exceeded"| noSave["Stop without saving tracks or a playlist"]
    validate -->|"Valid"| scan["Scan sources: later errors may leave eligible partial results"]
    scan --> library["Commit library changes"]
    library -->|"Failure"| noPlaylist["Do not create a playlist"]
    library -->|"Success: library_committed"| playlist["Resolve eligible entries, check name uniqueness, and create playlist"]
    playlist -->|"Failure, e.g. no eligible entries or name already used"| libraryOnly["Keep committed library changes"]
    playlist -->|"Success: playlist_id"| refresh["Refresh views"]
    refresh -->|"Success"| complete["Report result, including any scan errors"]
    refresh -->|"Failure"| committed["Keep both commits and report refresh error"]
----

Results retain `library_committed` and `playlist_id` as evidence of confirmed
commits, including partial success. A failed result does not imply rollback.
Imports are not replayed automatically: inspect the evidence before retrying a
missing step, rather than repeating an already-committed operation.

Export preserves the complete saved order and multiplicity, not search results,
subject to the CUE restrictions below. One export runs at a time, using a
consistent snapshot unaffected by later edits; its reply reports final output.

Export atomically replaces the destination only after successful output. Failure
or shutdown cancellation before replacement preserves the old target; cancellation
cannot undo replacement. A timeout does not cancel export or prove it failed.
Wait for completion and inspect the destination before retrying.

[source,sh]
----
rivu playlist import mix.m3u8 --name "Imported Mix" --wait
rivu playlist export PLAYLIST_ID exported/mix.m3u8
----

=== M3U/M3U8

anchor:m3u-document-paths[]
Import accepts UTF-8, including BOM, and resolves entries as local filesystem
paths relative to the playlist file. Blank lines and lines beginning with `#`
are ignored, including `#EXTINF`: imported metadata comes from the audio/CUE scan,
not those directives. Paths are not shell input, URLs, or recursively imported
M3U files. Ordinary audio and complete CUE sheets may be mixed.

Relative paths *written into* the M3U are based on the export file's directory,
which must already exist. CLI input and destination arguments follow the
link:09_cli.adoc#cli-command-conventions[CLI path rules] instead.
Invalid paths, CUE validation failures and write errors preserve an existing target
under the atomic replacement rules above.
Paths that cannot be represented as UTF-8 or contain CR/LF line breaks are
rejected. CR/LF in title or artist metadata is replaced with spaces so it cannot
introduce additional M3U lines. Relative paths beginning with `#` are prefixed
with `./` so they are not interpreted as M3U directives.

[[cue-import]]
=== CUE import

Direct CUE import, or a CUE path in M3U, expands every track in sheet order.
Referenced whole-file tracks are also registered in the library, but are not
inserted into the imported playlist unless separately requested as audio entries.
CUE subtracks and their whole-file sources bypass the scan minimum-duration
filter; all other validation remains in force.
Single-file and multi-file audio sheets are supported, using UTF-8 (with or
without BOM) or BOM-marked UTF-16. `FILE` paths are relative to the sheet;
Windows separators are accepted. Sources must be supported audio with readable,
finite positive duration; data tracks are unsupported.
Track numbers must increase within `01..99`, and every track requires `INDEX 01`.
Times use 75 frames per second. A segment ends at the next `INDEX 01` within its
`FILE`, or at the source duration for the last segment. `INDEX 00` pregaps therefore
remain at the end of the preceding segment; `PREGAP` and `POSTGAP` do not synthesize
silence. Invalid syntax, unsupported directives, source failures, or invalid
segment bounds reject the whole sheet rather than importing a partial sheet.

CUE library identities and directory scanning: link:02_library.adoc#cue-library-tracks[Library].
Subtrack playback: link:04_playback.adoc#transport-and-timing[Playback].

=== CUE export restrictions

A complete, contiguous, correctly ordered sheet run exports as one CUE path.
Standard M3U cannot select individual subtracks: partial or reordered runs fail
and leave the existing destination untouched. Such selections remain valid inside
Rivu. Rescan externally edited sheets before exporting.
Export rereads each CUE sheet as an ordinary file, limited to 1 MiB. FIFOs and
other non-regular inputs are rejected without waiting for input; read or parse
errors leave an existing destination untouched.
