= Playlists
:toc:
:toclevels: 2

Playlists are ordered collections of library tracks. Each track ID appears at
most once; adding it again leaves the existing entry unchanged. Imports and
saved queues retain the first occurrence of each track, unlike the
link:04_playback.adoc#_queue[playback queue].

== Management

Create a playlist with New playlist in the desktop Playlists panel, or import an
M3U/M3U8 or CUE file with Import. To collect tracks already in Rivu, use a track
menu's Add to playlist action; to keep the current listening order, use Queue →
Save queue as playlist. These operations do not change the source collection.

Names must contain a non-whitespace character and no control characters. Creating,
renaming, saving a queue, and importing reject an existing name. Comparison is
exact, including case and whitespace: CLI/API names retain outer whitespace,
while the desktop name dialog trims it. Existing duplicate names remain usable
by ID; rename or delete them explicitly.

Use `rivu playlist` for command-line management. `playlist list` shows collection
IDs and summaries; `playlist show PLAYLIST_ID` lists that collection's entries.
Entry IDs identify items for removal or movement. Move indices start at zero.

[source,sh]
----
rivu playlist create "Mix"
rivu playlist import mix.m3u8 --name "Imported mix" --wait
rivu playlist list
rivu playlist show PLAYLIST_ID
rivu playlist add PLAYLIST_ID TRACK_ID...
rivu playlist move ENTRY_ID 0
rivu playlist remove ENTRY_ID
rivu playlist play PLAYLIST_ID
----

Adding an existing track, moving an entry to its current position, or renaming
to the current name leaves contents unchanged, but still validates IDs and move
bounds. Creating a playlist from a queue saves its name and entries atomically;
a failed entry save does not leave an empty playlist.

== Desktop UI

=== Catalog and naming

Select a playlist in the catalog to browse its tracks. The catalog and track list
have independent link:02_library.adoc#_desktop_list_search[searches]; filtering
does not restrict whole-playlist Play, Append, or Export.

Hover a catalog row for Play and its actions menu. These actions target that row,
not the selected playlist. Play replaces the queue with the complete saved order
and starts playback; Append copies it without changing current playback. There
is no playlist or queue-size cap. Empty or unknown playlists leave the queue
unchanged.

Desktop Append submits the playlist identity and selected content revision.
Core validates that revision before atomically copying the playlist. If
membership/order changed before execution, Append fails without copying a stale
or partial playlist.

When the queue is nonempty, the GUI asks before replacing it by default. Cancel
or Esc keeps queue and playback untouched. Configure this shared album/playlist
preference under link:01_config.adoc#_volume_and_playback_controls[Volume and playback controls].

The row menu also offers Add current track, Rename, and Delete. Add current track
uses the playback track, not Library selection, and is unavailable without one.
Rename opens the current name; Enter submits, while Cancel or Esc discards the
draft. Saving runs in the background and prevents repeated submissions. Failure
keeps the draft for correction; a submitted save cannot be cancelled by closing
the window. Success refreshes the catalog under its current search. Delete asks
for confirmation and removes only the playlist, never music files.

=== Track selection and ordering

Use the link:02_library.adoc#_desktop_selection_and_directory_tree[shared selection rules]
to select tracks and ranges, including unloaded pages. The count shows selection
size. With the track list focused, arrows navigate, Home/End selects the first/last
matching entry, Shift+arrows extends a range, Ctrl+A selects all matches, and Delete
removes selected entries. These keys do not operate the catalog, an editor, or
another panel. Double-click or Enter plays the active track individually. Hover
Play, Favorite, and Remove controls act only on their own row.

Once loading completes, an empty playlist shows its empty state. Drag a selected
track to move the selected group in its original playlist order; dragging an
unselected track moves only that entry. A row's upper half inserts before that
entry; its lower half inserts after it. The accent insertion line marks the
boundary that will be committed; dropping below the rows appends. The dragged
group is fixed at drag start, even if track selection changes during the gesture.
Dropping on a member of that group or pressing Esc leaves playlist order unchanged.
This saves playlist order without changing the queue. A drag is rejected if that
playlist's membership or order changes, it is deleted, or the selection switches
before dropping, including switching away and back. Renaming a playlist or editing
another playlist does not cancel the drag.

=== Transfers and queue saving

Dragging playlist tracks to Queue or another playlist copies their track IDs in
playlist order without removing source entries. A named catalog row is an
explicit destination, even when another playlist is selected. Library tracks and
directories, album cards and tracks, recent tracks, and queue occurrences can
also be dropped on a catalog row. Dropping on a track row uses the same before/after
insertion line; catalog rows and blank space append. Playlist additions retain
existing entries and insert only previously absent track IDs in source order.
If the target playlist changes before a positional insertion commits, the old
position is rejected rather than falling back to append.

Right-click a track or selected group and choose Add to playlist to select an
existing playlist or New playlist. The shared name dialog saves the captured
tracks without changing the source collection. This selector also works when
the Playlists panel is not visible. Track menus follow the
link:02_library.adoc#_desktop_selection_and_directory_tree[shared selection rules].

Use Queue → Save queue as playlist for a nonempty queue. The name dialog suggests
an editable `Queue_YYYYMMDD_HHMMSS` name, independent of presentation language.
Duplicate occurrences become one entry, retaining the first occurrence's order.
Saving does not change the queue. The dialog uses the same
background-save and failure-retry behavior as New playlist and Rename. Loading
or failed queue selection shows status; Retry remains available after failure.

=== Loading and selection recovery

Catalogs, entries, and track-menu playlist selectors load while scrolling. Entry
numbers remain absolute when search hides rows; positional drops are unavailable
while the destination entry list is filtered.
Switching playlists clears track selection; deleting the selected playlist from
another client clears it on refresh. Empty playlists and unloaded pages do not
imply deletion. See link:02_library.adoc#_paged_views[Paged views] for loading,
timeouts, and CLI incomplete-output recovery.

A range is selected only after all its rows load and any Details draft confirmation
is resolved. Failure preserves the previous selection and draft. Refresh keeps
entries that still exist and discards removed ones. Pending or failed selection
loads disable group actions and offer Retry; loaded row controls remain row-local.
Retry reconciles the previous selection rather than replaying a failed range or
key command. With no previous selection it restores an empty selection so you
can navigate again. Failed group removal does not partially remove entries.

=== Playlist query validity

Changes to this playlist's membership or order invalidate an in-progress listing;
restart it. Rename and changes to other playlists' membership or order do not
interrupt it. Metadata edits preserve entry identity and position, but changes to
displayed fields can invalidate an entry listing, including search results.
Stale group edits are rejected rather than partially applied. Export uses one
consistent snapshot, so concurrent edits do not alter the file being written.
Query validity belongs to
link:21_ipc.adoc#_query_results_and_pagination[IPC]; retained view lifetimes belong
to link:22_cache.adoc#_query_projection_retention[Caching].

== Import and export

Use Import at the top of the Playlists panel to read a file. Select a playlist
before using Export; it stays unavailable without a selection. The CLI equivalents
below support the same exchange formats and whole-playlist semantics.

=== Import workflow

CLI paths are relative to the invoking client's working directory. Referenced
media and CUE sheets must lie within configured logical roots; see
link:02_library.adoc#_scan_policies_and_recovery[Library scan boundaries and errors].
Imports scan referenced sources before creating the playlist and may create
partial playlists: `--wait` reports scan errors even when readable tracks were
saved. Only identities successfully read or validly reused by that import's scan
can enter its playlist; an old library row does not make a failed source eligible.
The link:02_library.adoc#_minimum_duration_for_new_tracks[minimum-duration admission policy]
applies to ordinary audio entries not referenced by a successfully validated CUE
sheet in the same import; excluded new tracks do not enter the playlist.
Import fails if no entries resolve successfully. Without `--name`, the playlist
name comes from the imported file's name without its extension. Both explicit
and default names are validated before a scan starts or any scan data is saved.
Imports share one media-task slot with scans, Other checks, and external-file
queue additions; another request is rejected while one is active.

An accepted import returns a scan task ID; acceptance is not proof of completion.
Use `--wait` to observe input, scan, or playlist-creation errors. Playlist reads,
decoding, CUE expansion, and metadata scanning run in the background. In the
desktop, task feedback belongs to the Playlists panel and identifies import
progress, completion, failure, and cancellation separately from library scanning.
A rejected request reports an error without replacing an accepted task's progress
or result. Shared status
queries, result dismissal, cancellation and shutdown are documented under
link:02_library.adoc#_cancellation[Library cancellation]. Preparation can be
cancelled without saving results or creating a playlist; once Saving begins,
the commits below must finish.

=== Input limits and cancellation

Import inputs must be ordinary files, including CUE sheets referenced by M3U;
directories, devices, and FIFOs are rejected without waiting for a writer.
Referenced directories are never recursively imported; directory discovery belongs
to `rivu library scan`. M3U input is limited to 16 MiB, each CUE sheet to 1 MiB,
and aggregate input to 64 MiB (each distinct CUE sheet is read once). Expansion is
limited to 100,000 entries before first-occurrence deduplication.

Expanded entries, parsed sheets, and shared source/segment data each have an
independent 64 MiB accounting limit, including retained paths, names and vector
capacity. Shared source and sheet payloads are charged once. Replaced or discarded
metadata and temporary parsing/staging workspaces release their reservations with
their owners; raw input is not permanently charged against later retained data.
Staging charges scope indexes, owned path prefixes, and serialized query buffers
to the source/segment domain, including JSON escaping and buffer capacity. This
cost depends on requested scopes, not only on successfully probed tracks.
These are bounded-data limits, not a combined process-RSS limit. They apply to
imports, not playlist sizes for other operations. Preparation or retention-limit
failures abort before any scan or playlist commit instead of saving partial results.
Prepared CUE data is reused by scanning so the import keeps the sheet version and
track order it read. Cancellation is checked during reads and parsing; the reader
does not reopen an admitted path. Internal scheduling and ownership are described
in link:21_ipc.adoc#_core_and_client_boundary[Core and client boundary].

=== Commit and export lifecycle

Scan saving and playlist creation commit separately; view refreshes do not undo
either commit. A failure to save the scan does not create a playlist. Once the
scan has been saved, a playlist-creation or later refresh failure does not roll
back the saved tracks; once the playlist has been created, a refresh failure does
not delete it. Task results retain `library_committed` and `playlist_id` for
confirmed commits, including failures of later steps. The import is not replayed
automatically; inspect the result before retrying a missing step.

Listings and exports include every entry, not only the visible rows. For listing
changes and retry behavior, see link:02_library.adoc#_paged_views[Paged views].
Export runs in the background and permits only one active export. Its command
reply reports final output, not startup. Concurrent edits do not alter its snapshot.
Failure or shutdown cancellation before replacement preserves the old target;
a response timeout does not cancel the worker or prove that replacement failed.

Export writes a same-directory temporary file and atomically replaces the target
only after successful output. Cancellation cannot undo replacement after the
commit point. A new export is admitted only after the previous worker releases
its file and snapshot resources; timeout is not permission to start a duplicate.
The bounded worker contract is described in
link:21_ipc.adoc#_core_and_client_boundary[Core and client boundary].

[source,sh]
----
rivu playlist import mix.m3u8 --name "Mix" --wait
rivu playlist import album.cue --wait
rivu playlist export PLAYLIST_ID exported/mix.m3u8
----

=== M3U/M3U8

Import accepts UTF-8, including BOM, and resolves entries as local filesystem
paths relative to the playlist file. Blank lines and lines beginning with `#`
are ignored, including `#EXTINF`: imported metadata comes from the audio/CUE scan,
not those directives. Paths are not shell input, URLs, or recursively imported
M3U files. Ordinary audio and complete CUE sheets may be mixed.

Export writes UTF-8 M3U regardless of the destination extension, with paths relative
to the destination directory; that directory must already exist. Invalid paths,
CUE validation failures, and write errors preserve an existing target under the
atomic replacement rules above.
Paths that cannot be represented as UTF-8 or contain CR/LF line breaks are
rejected. CR/LF in title or artist metadata is replaced with spaces so it cannot
introduce additional M3U lines. Relative paths beginning with `#` are prefixed
with `./` so they are not interpreted as M3U directives.

=== CUE import

Direct CUE import, or a CUE path in M3U, expands every track in sheet order.
Referenced whole-file tracks are also registered in the library, but are not
inserted into the imported playlist unless separately requested as audio entries.
CUE subtracks and their whole-file sources bypass the scan minimum-duration
filter; all other validation remains in force.
Single-file and multi-file audio sheets are supported, using UTF-8 (with or
without BOM) or BOM-marked UTF-16. `FILE` paths are relative to the sheet;
Windows separators are accepted. Sources must be supported audio with readable,
finite positive duration; data tracks are unsupported.
Track numbers must increase within `01..99`, and every track requires `INDEX 01`.
Times use 75 frames per second. A segment ends at the next `INDEX 01` within its
`FILE`, or at the source duration for the last segment. `INDEX 00` pregaps therefore
remain at the end of the preceding segment; `PREGAP` and `POSTGAP` do not synthesize
silence. Invalid syntax, unsupported directives, source failures, or invalid
segment bounds reject the whole sheet rather than importing a partial sheet.

CUE library identities and directory scanning: link:02_library.adoc#_cue_library_tracks[Library].
Subtrack playback: link:04_playback.adoc#_transport_and_timing[Playback].

=== CUE export restrictions

A complete, contiguous, correctly ordered sheet run exports as one CUE path.
Standard M3U cannot select individual subtracks: partial or reordered runs fail
and leave the existing destination untouched. Such selections remain valid inside
Rivu. Rescan externally edited sheets before exporting.
Export rereads each CUE sheet as an ordinary file, limited to 1 MiB. FIFOs and
other non-regular inputs are rejected without waiting for input; read or parse
errors leave an existing destination untouched.
