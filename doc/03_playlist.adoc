= Playlists

Playlists are ordered collections of library tracks. Each track ID appears at
most once; adding it again leaves the existing entry unchanged. Imports and
saved queues retain the first occurrence of each track, unlike the
link:04_playback.adoc#_queue[playback queue].

== Management

Use `rivu playlist` to create, rename, delete, add, remove, move, or play.
Playlist IDs identify collections; entry IDs identify items for removal or
movement. Move indices start at zero. `playlist list` shows both kinds of ID.
Adding no new tracks or moving an entry to its current index leaves the playlist
unchanged. These requests still validate the playlist, track IDs, entry ID, and
move bounds; invalid requests do not change any entries.

Creating a playlist from a queue commits the name and entries together. If an
entry cannot be saved, no empty playlist is left behind.

Playlist names must contain a non-whitespace character and must not contain
control characters. Creating, renaming, saving a queue, and importing reject a
name already used by another playlist. Names are compared exactly, including
case and whitespace; accepted names retain their leading and trailing whitespace.
Renaming to the playlist's current name leaves it unchanged. Existing duplicate
names remain accessible by ID and can be resolved by renaming or deleting;
they are not automatically changed.

[source,sh]
----
rivu playlist new "Mix"
rivu playlist list
rivu playlist add PLAYLIST_ID TRACK_ID...
rivu playlist move ENTRY_ID 0
rivu playlist play PLAYLIST_ID
----

Playing a non-empty playlist replaces the queue, with no playlist or queue-size cap.
An empty or unknown playlist leaves the existing queue unchanged.
See link:04_playback.adoc#_queue[Playback queue].

== Desktop UI

The Playlists panel keeps New playlist, Import, and Export together at the top.
The catalog and selected playlist's tracks have independent optional searches;
see link:02_library.adoc#_desktop_list_search[Desktop list search]. Filtering does
not restrict whole-playlist Play, Append, or Export actions.
Export stays in place and is unavailable until a playlist is selected. New playlist
opens a blank name dialog. Hover a catalog row to reveal its Play and actions
buttons; these target that row without changing the selected playlist. The actions
menu offers Play / replace queue, Append to queue, Add current track (unavailable
without a current playback track), Rename, and Delete. Append copies the complete
playlist in its saved order without changing playback. Add current track uses the
playback track, not any Library selection. Rename opens the current name; Enter submits, and Cancel or
Esc discards the draft. Empty names are rejected. Saving runs in the background
and prevents repeat submissions; failures keep the dialog and draft available
for correction. A submitted save cannot be cancelled, including by closing the window.
Successful saves refresh the catalog without reopening the panel, including when
creating the first playlist. Active catalog searches still filter the result.

Playing a non-empty playlist starts immediately when the queue is empty. Otherwise
a confirmation names the playlist and offers Cancel or Replace and play. Cancel
or Esc leaves the queue and playback untouched. An empty playlist cannot replace
the queue. Deletion also requires confirmation naming the target playlist; it
removes only the playlist, never music files.

Selecting a playlist shows its tracks below the catalog. The catalog fits its
content up to about one third of the available list area, leaving the remainder
for tracks; a short track list can also shrink. With no selection, the catalog
uses the remaining panel space. Track rows use the Queue's numbering and text
layout. Use the
link:02_library.adoc#_desktop_selection_and_directory_tree[shared selection rules]
for clicks and ranges, including unloaded pages. The track count
shows the selection size. Use Delete to remove selected entries together.
Hover controls for Play, Favorite, and Remove target only that row, never the group.
Double-click or Enter plays the
active track individually. With playlist tracks focused, arrows move the active
track, Home/End selects the first/last matching entry, Shift+arrows extend a range,
Ctrl+A selects every matching entry, and Delete removes the selection.
These keys do not target the playlist catalog or steal focus from inputs,
dialogs, or another panel.

Once loading completes, an empty playlist shows its empty state. Drag a selected
track to move the selected group in its original playlist order; dragging an
unselected track moves only that entry. Dropping on a row inserts before that
entry; dropping below the rows appends. The dragged group is fixed at drag start,
even if track selection changes during the gesture. Dropping on a member of that
group or pressing Esc leaves playlist order unchanged.
This saves playlist order without changing the queue. A drag is rejected if that
playlist's membership or order changes, it is deleted, or the selection switches
before dropping, including switching away and back. Renaming a playlist or editing
another playlist does not cancel the drag.

Dragging playlist tracks to Queue or another playlist copies their track IDs in
playlist order without removing source entries. A named catalog row is an
explicit destination, even when another playlist is selected. Library tracks and
directories, album cards and tracks, recent tracks, and queue occurrences can
also be dropped on a catalog row. Playlist additions retain existing entries and
append only previously absent track IDs in source order.

Right-click a track or selected group and choose Add to playlist to select an
existing playlist or New playlist. The shared name dialog saves the captured
tracks without changing the source collection. This selector also works when
the Playlists panel is not visible. Track menus follow the
link:02_library.adoc#_desktop_selection_and_directory_tree[shared selection rules].

Use the Queue panel context menu's Save queue as playlist action to save a
non-empty queue. The shared playlist name dialog starts with a date-and-time
name that can be edited; duplicate queue occurrences become one playlist entry.
Saving runs in the background and prevents repeat submissions. Failures retain
the dialog and draft for correction and retry. Closing the window does not
cancel a save already submitted to the core. Queue selection status appears
only while loading or after an error; Retry remains available after an error.

link:02_library.adoc#_recent_tracks[Recent tracks] supports independent multiselect,
batch favorites, and transfers to Queue or playlists.

Playlist catalogs, entries, and track-menu playlist selectors
load rows automatically while scrolling. Entry numbering and drag reordering use
absolute playlist positions. Scrolling away preserves selected entry identities,
not their metadata pages. See link:02_library.adoc#_paged_views[Library] for
scrolling and query failure behavior. Switching playlists clears track selection.
Deleting the selected playlist from another client clears its selection on
refresh. Empty playlists and unloaded pages do not imply deletion.

Range selection waits for the complete range and any Details draft confirmation.
A failed range leaves the previous selection and Details unchanged. Refreshes
retain selected entries that still exist and discard removed entries; old query
results cannot overwrite a newer selection. Pending or failed selection loads
disable group actions and show status with Retry; loaded row controls stay row-local.
Group removal is atomic; a failed command leaves selection intact until refresh.

Selection query failures, including an unavailable core, stop loading and preserve
the previous selection without automatic retries. Retry reconciles that selection;
it does not replay the failed range or key command. With no previous selection,
Retry restores an empty selection so another click or navigation command can proceed.
While keyboard navigation loads, repeated arrows retain only the latest target;
superseded targets never replace the active track. Repeating an arrow at a list
boundary does not start another navigation load.

=== Playlist query validity

Reordering refreshes only that playlist's entries and selected positions, including
moves made by another client. Renaming preserves its tracks and selection; changing
another playlist does not reload the selected playlist's contents. Track metadata
edits update displayed information without changing entry identities or positions.
Empty playlists remain valid collections, not deleted or unloaded playlists.

If membership or order changes during a listing or export, restart the traversal;
renaming or changing another playlist does not interrupt it. Stale group operations
are rejected without partial changes. See
link:02_library.adoc#_paged_views[Paged views] for incomplete CLI output and retries,
link:21_ipc.adoc#_revisions_and_watching[IPC revisions] and
link:21_ipc.adoc#_query_results_and_pagination[query validity] for the internal
contract, and link:22_cache.adoc#_query_projection_retention[Query projection retention]
for cached views.

== Import and export

CLI paths are relative to the invoking client's working directory. Referenced
media and CUE sheets must lie within configured logical roots; see
link:02_library.adoc#_roots_and_scanning[Library scan boundaries and errors].
Imports scan referenced sources before creating the playlist and may create
partial playlists: `--wait` reports scan errors even when readable tracks were
saved. Only identities successfully read or validly reused by that import's scan
can enter its playlist; an old library row does not make a failed source eligible.
Import fails if no entries resolve successfully. Without `--name`, the playlist
name comes from the imported file's name without its extension. Both explicit
and default names are validated before a scan starts or any scan data is saved.
Another import or scan cannot start while scanning is active.

After early name/root configuration validation and pending-state saving, import
accepts a scan task. Playlist reads, decoding, CUE expansion, and metadata scanning
run in that task's existing filesystem worker, not on the database owner. Input
failures are terminal task errors (`--wait` observes them), not a failed
acknowledgement after acceptance. Other commands remain available during import.
Scan cancellation and shutdown also cancel input processing; a cancelled import
does not save scan results or create a playlist.

Import inputs must be ordinary files, including CUE sheets referenced by M3U;
directories, devices, and FIFOs are rejected without waiting for a writer. M3U
input is limited to 16 MiB, each CUE sheet to 1 MiB, and aggregate input to 64 MiB
(each distinct CUE sheet is read once). Expansion is limited to 100,000 entries,
before first-occurrence deduplication. Expanded entry data and retained parsed CUE
data each have a 64 MiB accounting limit, including paths, names, and record
storage. These limits allow large collections while bounding repeated-sheet
expansion and long-metadata costs; the aggregate and expansion limits apply to
imports, not playlist sizes for other operations. Input errors identify
preparation/read/decode/parse stages and occur before any scan or playlist commit.
Parsed import CUE sheets are reused by metadata scanning, preserving the sheet
version and track order read during preparation. Ordinary library scans and CUE
exports share the ordinary-file-only, nonblocking, 1 MiB CUE reader; scans also
check cancellation between read chunks and while parsing lines and segments.

Scan saving, playlist creation, and playlist refresh are separate stages. A
failure to save the scan does not create a playlist. Once the scan has been
saved, a later library refresh or playlist creation failure does not roll back
the saved tracks; once the playlist has been created, a playlist refresh failure
does not delete it. Task errors identify these committed stages. The import is
not automatically replayed after a failure.

Listings and exports include every entry, not only the visible rows. For listing
changes and retry behavior, see link:02_library.adoc#_paged_views[Paged views].

[source,sh]
----
rivu playlist import mix.m3u8 --name "Mix" --wait
rivu playlist import album.cue --wait
rivu playlist export PLAYLIST_ID exported/mix.m3u8
----

=== M3U/M3U8

Import accepts UTF-8, including BOM, and resolves entries relative to the playlist
file. Ordinary audio and complete CUE sheets may be mixed. Export writes standard
UTF-8 M3U with paths relative to the destination directory; that directory must
already exist. Export errors leave an existing destination untouched. Paths that
cannot be represented as UTF-8 or contain CR/LF line breaks are rejected before
creating the destination file. CR/LF in title or artist metadata is replaced with
spaces so it cannot introduce additional M3U lines.

=== CUE import

Direct CUE import, or a CUE path in M3U, expands every track in sheet order.
Single-file and multi-file audio sheets are supported, using UTF-8 (with or
without BOM) or BOM-marked UTF-16. `FILE` paths are relative to the sheet;
Windows separators are accepted. Sources must be supported audio with readable,
finite positive duration; data tracks are unsupported.

CUE library identities and directory scanning: link:02_library.adoc#_cue_library_tracks[Library].
Subtrack playback: link:04_playback.adoc#_transport_and_timing[Playback].

=== CUE export restrictions

A complete, contiguous, correctly ordered sheet run exports as one CUE path.
Standard M3U cannot select individual subtracks: partial or reordered runs fail
and leave the existing destination untouched. Such selections remain valid inside
Rivu. Rescan externally edited sheets before exporting.
Export rereads each CUE sheet as an ordinary file, limited to 1 MiB. FIFOs and
other non-regular inputs are rejected without waiting for input; read or parse
errors leave an existing destination untouched.
