= Library

CLI scan and playlist import/export paths are relative to the invoking client's
working directory. Playlists deduplicate track IDs while queues may repeat tracks.
Exported playlist paths are relative to the destination directory.

== Library metadata and favorites

`library probe PATH` reads audio metadata without starting a core. Library rows and
Track details show codec, sample rate, channels, bitrate, track/disc numbers,
release date, path, missing status, CUE boundaries, play count, and favorite state.
Unknown metadata is reported as `—` or JSON `null`.

Editing titles, artists, albums, and favorites changes only Rivu's library data;
media tags and audio files are never rewritten. Track identity uses the stored
path and fingerprint. Rescans preserve identity, overrides, counts, and history.

[source,sh]
----
# Force metadata reprobe while retaining library identity and user data
./target/release/rivu library scan ~/Music --force --wait

# Filter by favorites or missing status (both flags select their intersection)
./target/release/rivu library list --favorites
./target/release/rivu library list --missing
./target/release/rivu library favorite 12 34 --set on
./target/release/rivu library favorite 12 34 --set off

# Remove missing records and their queue/playlist references, not media files
./target/release/rivu library clean-missing
----

The GUI Library supports favorite/missing filters, batch favorite actions, and
force-rescan. The unfiltered view is a directory-first tree; filtered views are
flat lists. Use Up/Down, Left/Right, Space, and Enter to navigate and play.
Dragging files or directories to Queue or a Playlist adds their matching tracks.
Normal scans reuse cached probes; `--force` rereads metadata while preserving
track identity and user data.

== Play counts and recent tracks

A playback increments its track's play count once, only when confirmed heard time
*strictly exceeds* `play_count_threshold_percent` of the track duration (20% by
default). Reaching exactly the threshold does not count. Pause/resume and seeks
do not reset the playback's count state or create additional counts; skipped time
does not count as heard. When duration is unknown, counting waits until a natural
EOF can supply a duration from the final position; without one, no play is counted.

Recent history contains one entry per track, ordered by its last successful
playback start. Failed loads, pause/resume, and seeks do not create recent entries.
A recent entry is not a claim that a play reached the counting threshold. Rivu
stores only aggregate play counts and last-played timestamps, not per-play records
or per-play/cumulative heard durations; heard time exists only in memory for
playback and count decisions.

Track identity uses path and fingerprint. Rescanning or updating tags preserves
that identity, user metadata overrides, counts, and last-played timestamps.

== Database initialization and maintenance

Rivu creates the database structure directly. Stop the instance before removing
`library.db` and its `-wal`/`-shm` sidecars, then rescan the music files. This
resets playlists, queue, favorites, metadata overrides, and playback statistics;
source audio files, `config.toml`, and `workspace.json` are independent.

To optimize the database, stop playback, wait for scans to finish, and run:

[source,sh]
----
./target/release/rivu library optimize
----

Optimization is rejected while playback or scanning is active. It reclaims
database/WAL space and refreshes query statistics; failures are reported as errors.
