= Audio processing: usage, design and acceptance
:toc:
:toclevels: 2

== Scope and status

Rivu provides live Monitor EQ, source-preserving restoration and neural speech
enhancement/separation, and a node graph for combining them. Monitor EQ changes
playback; graph nodes and offline jobs use independent settings. Processing never
rewrites source media, and no model download occurs during playback or a build.
The practical workflow describes available behavior. <<_ownership_and_invariants,Ownership
and invariants>> is the implementation contract; <<_quality_acceptance,quality
acceptance>> defines evaluation requirements rather than claiming they all pass.
<<_recorded_local_evidence_and_remaining_limits,Recorded evidence>> distinguishes
measured observations from remaining acceptance gaps.

== Practical workflow

Add the Audio processing panel from the layout panel catalog. Processing graph,
Monitor EQ, Restoration, Speech enhancement, Separation, and Results are separate
single-line tabs. Tabs scroll horizontally when space is limited. Switching tabs
does not run a job, change the audition, or discard field drafts. Settings remain
core-owned and shared with the CLI. Monitor EQ changes live playback independently
of graph-node EQ. The footer identifies the source track, its sample rate and
channel count, the actual audition and transport state; Monitor EQ status stays
at the right. Processing never edits library media. Keep headroom when boosting
or remixing: there is no implicit loudness matching or limiter.

. Make the desired input track current in playback; it may remain paused while
  configuring or rendering. CLI processing commands accept an explicit track ID.
. For live tonal adjustment, use Monitor EQ. For restoration or neural processing,
  configure that operation; neural backends need explicit preparation below.
. For a combined chain, connect graph ports, apply field drafts, then Preview a
  node output or Run an Output node with the chosen execution mode.
. Follow the task summary to completion; use the selected-audio line to confirm
  what is actually being auditioned, then compare with Original at fixed levels.
. To keep a graph output, Export WAV to a new file. Retained audition results
  alone do not survive session retirement.

The selected-audio line is Core's admitted source, not a guess from the latest
task: it identifies the retained run, exact graph port and live/hybrid/cached path,
with Playing, Paused or Stopped reported separately. Explicit Offline runs do
not select their results. Auto, Realtime and Hybrid runs request audition when
ready, provided the playback generation has not changed in the meantime.
Return to original addresses the currently selected audition, even when the latest
task belongs to a different run. Invalid node/port requests leave the prior
selection unchanged; playback retirement clears it.

To return all playback effects to the original path, use the footer's bypass
button or `rivu processing bypass`. This disables Monitor EQ and restores original
audio from any live, hybrid or cached audition. EQ parameters, graph and restoration
settings, queue and retained results remain available; rendering and export jobs
continue. Pending automatic audition is revoked, so a late result cannot undo the
bypass. Re-enabling EQ or selecting a retained output is an explicit later action.

=== Node graph desktop workflow

The graph is acyclic: Source supplies the track, processing nodes transform it,
Mix combines explicit inputs, and Output marks a destination. Connections carry
all stream channels, not individual speaker channels. Separation exposes vocals
(port 0) and accompaniment (port 1); other nodes expose output 0. Fan-out is
allowed, but every required input in the selected chain must be connected.
A Mix has 2–16 inputs with independent gain, mute and solo: any solo excludes
non-solo inputs, while mute still silences a soloed input.

Add nodes from the toolbar and select one to inspect its algorithm and parameters.
Each node has independent settings, including its prepared neural backend.
Click an output port, then an input port to connect them; Escape cancels the
pending connection. Disconnecting or deleting never guesses replacement edges.
Drag a node's header or non-port surface to select and move it; positions do not
change execution order. Undo/Redo affects graph edits, not playback or results.
Delete/Backspace acts on the selected node when the canvas has keyboard focus,
not while editing parameter text.

Middle-drag or wheel pans; Ctrl+wheel zooms around the pointer. The zoom slider
covers 35%–200%. Reset view restores pan/zoom without editing nodes; Fit graph
includes offscreen nodes, and Locate selected centers the selection. Connections
lists explicit endpoint pairs and locates/highlights a selected wire; disconnect
is a separate action. The toolbar's info icon provides shortcut help.

Wide panels show a resizable, collapsible inspector beside the canvas; narrow
panels switch between canvas and parameters. The separator also supports
Left/Right when focused. Working areas scroll independently of execution controls
and the footer. Multiple panels share graph drafts and committed settings, but
retain independent input focus, cursor geometry and parameter-view scroll state.

Enter or Apply this field commits a parameter draft, except for the live EQ
numeric controls below. Apply all node drafts validates and commits that node
atomically. Discard removes unapplied text/errors without undoing accepted live
edits. Invalid values and stale revisions retain their drafts with errors;
acknowledgements do not erase text typed after submission. File selection only
changes a path draft. Unused backend settings remain available in an expandable
section. Delete/Duplicate requires that node's drafts to be resolved; Undo/Redo
requires all graph drafts to be applied or discarded.

Preview executes the selected node output's ancestors. Run targets the first
Output node, identified by ID on its button; select another Output and Preview
it, or use its ID in the CLI. Neither action applies drafts implicitly. The task
summary reports captured revision/settings, actual execution mode and progress,
independently of later edits. Results contains retained outputs and export controls.
Audition and export use the frozen run, not the current editor. Desktop Export WAV
requires an absolute path naming a new file in an existing directory; the CLI
also accepts relative destinations.

Accepted graph and processing-setting edits save to `config.toml` immediately,
independently of Settings Apply. Drafts, viewport and retained audio are not
configuration commits. See link:01_config.adoc#_saving_configuration[Saving configuration].

=== Equalizer

Monitor EQ and graph EQ share an editor but have independent settings. Presets
and playback A/B belong to Monitor EQ. Monitor EQ uses recursive IIR filters;
graph EQ can select linear-phase FIR with 3–16,385 odd taps. More taps change
resolution, preparation cost and latency, not an IIR quality label. The curve
shows the configured IIR magnitude at the current stream rate; for FIR it is the
design target, not the realized finite response or phase. Graph execution aligns
branches and compensates published audio to the source timeline.

Input/output gain and band frequency, gain, Q, shelf slope and stages submit
valid numeric edits as you type; step buttons and sliders apply immediately.
Channels requires Enter/Apply. Incomplete/out-of-range text and IME preedit stay
drafts. Committing composition submits once; Escape cancels it. Newer typed text
survives acknowledgements, and Enter on unchanged displayed text does not round
the stored value. Numeric controls retain the latest local intent while a command
is pending; unrelated graph revisions do not inherit it. Accepted edits are not
rolled back when a slider gesture is cancelled.

Enter a total band count of 0–32 and press Enter. Increasing it appends enabled,
0 dB peak bands with default Q and all channels selected; decreasing removes
bands from the end. Existing bands and overall gains are preserved. New bands
fill logarithmic gaps from 20 Hz to the lower of 20 kHz and 0.499 × the known
track rate (20 kHz when unknown). Reset clears overall and band gains, retaining
filter kinds, frequency, Q, slope, stages and channel targets. It also discards
unapplied gain drafts for that target across panels; other drafts remain.
Band-count changes and Reset are unavailable while a processing acknowledgement is pending.

Hover/focus the curve to see numbered band nodes. Drag horizontally for frequency
and vertically for peak/shelf gain; release commits once, while Escape or lost
interaction cancels the preview. Clicking an overlapping stack cycles its members
without moving them. Disabled bands remain selectable. Focused nodes support
Left/Right semitone steps, Up/Down 0.5 dB gain steps, Enter/Space selection and
Delete removal. Parameter fields provide exact values; deleting text there never
deletes a band. Response-channel selection changes only the displayed curve,
not processing targets. The curve/editor stack in narrow panels.

The footer bypass disables all playback effects. Clicking it while fully
bypassed enables Monitor EQ only, not the previous graph audition. While EQ is
off, configuration, preset, reset and A/B controls are locked, but curve selection
and values remain visible. Existing drafts and selection survive disabling and
are not applied automatically on re-enable.

Peak, low/high shelf, low/high pass, bandpass and notch filters are available.
Q controls resonance/bandwidth except for shelves, which use shelf slope S
(0.1–1). Pass/bandpass/notch filters cascade 1–4 identical sections, not an
independently designed Butterworth order; peak/shelf filters have one stage.
Gain, preamp and output gain are bounded to ±24 dB, Q to 0.1–20, and the bank to
32 bands. Active EQ supports 8–768 kHz and up to 64 channels. Stored frequencies
are 1 Hz–96 kHz; effective bands must also be at or below 0.499 × the stream rate
and address existing channels. Unsupported active settings fail validation rather
than being retuned or dropped. Disabled/solo-excluded bands keep stored values
without imposing stream-specific constraints.

Channel targets are `all`, or selected channels numbered from 1 in GUI text and
from 0 in JSON (`{"selected":[0,1]}`). Any enabled solo band excludes enabled
non-solo bands globally, even across differing channel targets. Monitor edits
and bypass crossfade complete banks over 10 ms; settled bypass preserves samples.
Graph edits affect future snapshots, not an admitted run.

Save/load/delete named presets or import/export EqualizerConfig JSON. Imports
require an ordinary file of at most 64 KiB; devices/FIFOs are rejected and reads
remain bounded if the file grows. A/B swaps with the saved alternate; the first
swap uses a disabled empty alternate. Save a preset if both alternatives must
be retained.


[source,shell]
----
rivu processing show
rivu processing eq '{"Enabled":true}'
rivu processing eq '{"PreampDb":-4.0}'
rivu processing eq '{"AddBands":{"count":6}}'
rivu processing eq '{"AddBand":{"band":{"kind":"peak","frequency_hz":1200.0,"gain_db":3.0,"q":0.8}}}'
rivu processing eq '{"BandField":{"index":0,"field":{"Channels":{"selected":[0]}}}}'
rivu processing eq '{"SavePreset":{"name":"Voice presence"}}'
rivu processing eq '"SwapAb"'
rivu processing eq '{"LoadPreset":{"name":"Voice presence"}}'
rivu processing eq '{"ExportPreset":{"path":"/absolute/presence.json","name":"Voice presence"}}'
----

`AddBands` uses the same core-owned generation rules as desktop Add and appends
without replacing earlier edits. `AddBand` remains available for an explicit
band configuration, as shown above; use it when exact frequency, gain or filter
settings are already known. Both operations respect the 32-band bank limit.

CLI preset import/export paths are relative to the invoking client's working
directory, not the host's. Absolute paths are unchanged.

=== Restoration

Stationary mode derives fixed white-noise power from the declared RMS level
(`stationary_noise_dbfs`); it does not learn colored noise from the track.
Profile uses a selected noise-only source-relative time range; Adaptive tracks
changing noise. Choose a range without wanted content: a profile containing voice
or music can remove that content. Strength scales noise power, noise floor is
the minimum spectral gain (not an input gate), attack/release control gain timing,
smoothing spans frequency bins, and transient protection preserves positive flux.
FFT size trades time/frequency resolution (power of two, 256–8192). Spectral gains
are shared across channels, preserving their per-bin phase and level ratios rather
than gating each channel independently. Wet blends the entire restoration chain
against the original.

Hum removal applies harmonic notches at the chosen fundamental (for example
50 or 60 Hz); harmonic count includes the fundamental, and Q sets notch width.
Impulse repair interpolates only short detected damage (1–8 samples), not long
dropouts. Threshold, floor and transient protection trade missed clicks against
damaged musical attacks. Hum and repair remain independent of spectral mode,
including `off`. Classical restoration supports 8–384 kHz and 1–32 channels,
with validated allocation bounds; unsupported input fails instead of silently
downmixing.

The Restoration page exposes Off, Stationary, Profile and Adaptive as direct mode
choices. Off hides only spectral-noise parameters; hum removal and impulse repair
each have their own enable switch and reveal their parameters when enabled.
Noise-range fields appear only for Profile. Wet controls the complete chain.
Speech enhancement and Separation have separate pages. Sound parameters are
separate from Model configuration; advanced runtime options are nested under
the latter. The post-filter is explicitly labeled DeepFilterNet3-only: enabling
it with another speech model reports an error, not a fallback. Environment/model
paths and numeric fields still require Enter or Apply; toggles and device choices
submit directly. Worker script, device and threads are shared by Speech and
Separation. Collapsing an advanced section preserves its drafts.

[source,shell]
----
rivu processing denoise '{"mode":"adaptive","strength":1.0,"noise_floor_db":-18.0,"wet":0.8}'
rivu processing denoise '{"hum_enabled":true,"hum_fundamental_hz":50.0,"hum_harmonics":6,"hum_q":30.0,"impulse_enabled":true,"impulse_max_width":3}'
rivu processing start 42 denoise --wait
rivu processing denoise '{"mode":"profile"}'
rivu processing start 42 denoise --noise-start 0.0 --noise-end 0.5 --wait
----

Here `42` is an existing library track ID, not a file path. Replace it with the
chosen track ID. Speech enhancement is a separate neural operation, not another
classical spectral preset.

=== Explicit neural installation and offline deployment

Speech backends are MossFormer2 SE48K, NSNet2 and DeepFilterNet3; separation
backends are Kim MelBand RoFormer and HTDemucs. Each graph node selects its own
prepared manifest, interpreter and worker. With `uv` already installed, run setup
from the repository root in separate pinned environments: their PyTorch
requirements differ. Install only the backends you need.

Installation requires 10 GiB free per invocation; allow additional space for
models, download caches, corpora and results. Preparation requires a new directory
with an existing parent and 2 GiB free. Choose `--download` or local `--weights`;
even local weights can require network access for pinned code/license evidence.
Playback, builds and worker inference never download models. CPU is the default;
CUDA requires an explicitly compatible environment and has no automatic fallback.
The pinned NSNet2 environment is CPU-only. Thread settings accept 1–8; the recorded
local evaluation workflow uses at most four.

[source,shell]
----
python3 tools/audio_processing/install.py moss
python3 tools/audio_processing/install.py separate
python3 tools/audio_processing/prepare.py moss --download --directory .cache/neural/moss --interpreter "$PWD/.cache/neural/moss-venv/bin/python"
python3 tools/audio_processing/prepare.py separate --download --directory .cache/neural/kim --interpreter "$PWD/.cache/neural/separate-venv/bin/python"
----

The primary example prepares MossFormer2 and Kim. Add only the optional
backends you intend to compare; HTDemucs shares the separation environment,
while DeepFilterNet3 needs its own pinned environment:

[source,shell]
----
python3 tools/audio_processing/prepare.py htdemucs --download --directory .cache/neural/htdemucs --interpreter "$PWD/.cache/neural/separate-venv/bin/python"
python3 tools/audio_processing/install.py df3
python3 tools/audio_processing/prepare.py df3 --download --directory .cache/neural/df3 --interpreter "$PWD/.cache/neural/df3-venv/bin/python"
----

For optional NSNet2, use `install.py speech`, then `prepare.py nsnet2` with
`.cache/neural/speech-venv/bin/python`: installation names the environment,
preparation names the model.

Preparation prints absolute `worker`, `interpreter` and `model_manifest` paths.
Configure *all three* and preserve the interpreter's venv symlink rather than
resolving it to base Python. The application does not bundle Python, workers or
models. In GUI path controls, an empty manifest clears model selection; interpreter
and worker paths are required. Placeholders are examples, not installed resources.

Keep the complete provisioned bundle together: hashed runtime sidecars/schema,
model assets and license/dependency records. Its manifest binds bundle paths,
interpreter hash and dependency pins. To copy verified assets and provision a
runtime from the current checkout without downloading:

[source,shell]
----
/absolute/moss-venv/bin/python /absolute/rivu/tools/audio_processing/provision.py --manifest /absolute/moss/manifest.json --directory /absolute/new-moss-bundle
----

The destination must be new. Provisioning does not copy the interpreter environment;
keep it installed. Assets are hard-linked on the same filesystem and copied
otherwise, so treat both bundles as immutable. Use the emitted absolute paths.
A bundle's runtime is a source snapshot: after worker updates, reprovision from
the updated checkout into a new bundle and configure all three emitted paths.
Do not patch hashed bundle files in place.

Application inference runs `worker.py --stream` with request version 2 and event
version 3. Stdin/stdout carry JSON controls and interleaved float32-le PCM in
frames: one-byte kind, four-byte little-endian length, at most 64 KiB payload.
Requests declare rate, channels and exact frame count, not audio paths. Each
process handles one task: request, declared PCM, empty input-end marker, then
immediate stdin EOF. The producer must close stdin without waiting for completion;
trailing bytes fail the task. Diagnostics go to stderr. Completion identifies
model, format, frames and stems; Rust validates framing, finite/aligned PCM,
completion and successful exit before publication. Cancellation terminates/reaps
the child, including after early stdout EOF.

Benchmark/corpus tools use the explicit `export.py --request` adapter, separate
from application execution. Its version-1 file job requires absolute `input_path`
and `output_dir`: input must be IEEE float32 WAV/WAVEX/RF64 and destination must
be new with an existing parent. It writes stem WAVs and `result.json`, with an
8 GiB total audio-output limit and 256 MiB additional free-space reserve.
Reprovision workers from this checkout when migrating to the framed protocol.


For a shared worker, select the emitted runtime worker compatible with both
prepared manifests; interpreters and manifests remain operation-specific:

[source,shell]
----
rivu processing neural '{"worker":"/absolute/new-moss-bundle/runtime/worker.py","speech_interpreter":"/absolute/moss-venv/bin/python","speech_manifest":"/absolute/new-moss-bundle/manifest.json","separation_interpreter":"/absolute/separate-venv/bin/python","separation_manifest":"/absolute/kim/manifest.json","device":"cpu","threads":4}'
rivu processing start 42 speech --wait
rivu processing start 43 separate --wait
----

MossFormer2's primary model card declares Apache-2.0; Kim's original trainer card
declares MIT. Preparation pins checkpoints and records weight evidence separately
from code permissions. HTDemucs/DeepFilterNet3 retain actual provenance and
unresolved weight-permission facts, not synthesized grants. Review notices before
redistribution; provisioning grants no additional license.

`prepare.py --proxy` applies only to preparation, never inference. Do not put
proxy credentials in shared evidence, manifests or logs.

Speech controls include wet mix and attenuation limit; the optional post-filter
is supported only by DeepFilterNet3. Enabling it for another speech model fails
rather than silently ignoring it. Separation overlap controls model overlap,
not a quality guarantee. Neural source rates are 8–192 kHz; speech accepts
mono/stereo, separation requires stereo. Speech channels are inferred
independently, so stereo image can change. Rate conversion to 48 kHz speech /
44.1 kHz separation is explicit; output is trimmed back to the original rate,
channel count and exact frame count. No implicit downmix or duplicated mono
separation is offered.

Speech Wet=0 copies dry PCM without loading/executing a model or resampling.
Input, controls, manifest and artifact hashes are still validated. Streaming
requires NumPy but skips model-execution dependency checks; the file adapter
also requires SoundFile and records bypass/model-not-executed in `result.json`.

=== Tasks, retention and audition

Only one processing task runs at a time. `queued`, `rendering` and `processing`
describe preparation/work; `complete`, `failed` and `cancelled` are terminal
task states. Not every task visits every work phase: realtime preparation need
not render a file. Start acceptance is not completion; `--wait` waits for that
task and fails on cancellation/error. Use `task status processing INSTANCE:ID` and
`task cancel processing INSTANCE:ID` for an asynchronous start. `INSTANCE:ID` is
the nonzero decimal instance/task reference returned by the accepting service;
the client binds subsequent status, cancel, audition and export requests to that
instance. A bare task number is not sufficient, and restarting the service does
not make a saved reference address a new task. A cancellation acknowledgement
accepts the request, not proof that the worker has already retired. Cancellation
invalidates publication, terminates/reaps neural workers and retires partial
PCM; it does not publish a partial result. Source identity and job settings
are captured. Later configuration or graph edits do not change that snapshot;
changes to its registered source or media invalidate publication. Switching the
playback track is different: it suppresses a pending automatic graph-audition
handoff through the playback generation, but does not discard a valid completed
result. Use task IDs for completion and the selected-audio line for playback.

Numeric progress within a phase is coalesced at a 100 ms publication policy and
does not accumulate behind a slow consumer. Phase changes, graph-node stages and
terminal results remain reliable; a progress counter is a snapshot, not one
notification per decoder or inference block.
Preparation and backend validation run on a worker, so accepted starts can fail
asynchronously. Queued can include waiting for retired audio to release its
reservation. Failure or unwinding reaches a terminal task result; neural children
are terminated/reaped before failure delivery. Core rechecks cancellation and
source identity before publication, commits the terminal state, then completes
task waits. Failed validation/admission does not revoke available PCM.

Native preparation checks cancellation between decoder calls; decoder/filesystem
operations have no hard cancellation-time guarantee. Retained audition also
checks the registered decoder hint and media identity. If database/queue recovery
is uncertain, audition is rejected without replacing playback or committing a
late stem-mix selection.

`task cancel processing INSTANCE:ID` also returns a matching selected audition to
Original after preparation has completed. For realtime/hybrid runs it marks the
task cancelled; stopping a cached offline audition leaves its completed status
intact. Current status, bounded task history and retained results agree on terminal
phase/error, including later audition or stem-mix failure.

Results are immutable shared in-memory PCM: node execution creates no processing
directory, intermediate WAV, request file or result report. A 512 MiB allocation
budget covers active, retained and retiring PCM, charging shared backing storage
once until its last owner releases it. Exhaustion fails explicitly without disk
spill. Decoder/DSP state, model weights and Python workspace are additional costs;
the budget is not a process-RSS limit.

A new non-export run releases unselected PCM and prepared runners after successful
admission, before worker allocation. Selected audition audio remains pinned.
Up to four frozen run snapshots remain available for graph recomputation even
when their PCM has been released. Availability in task status reflects this
release; completion alone does not guarantee cached audio. Export jobs preserve
their source handles and retain only a terminal receipt and the destination WAV,
not another audition slot. `id` identifies the export receipt; `graph_run_id`
identifies the frozen run used for further audition/export actions.
See link:22_cache.adoc#_processing_output_retention[Processing output retention].

Native denoise and native-only graphs decode in blocks, retaining final PCM and
bounded DSP/delay state rather than whole-track native intermediates. Profile
capture can reread the original source with identity checks. Graphs containing
neural nodes retain budgeted PCM at model boundaries; their source PCM also
counts against the budget. Input files remain bounded to 8 GiB. Actual decoded
frames, including unknown-duration streams, determine EOF and output coverage.

Neural input must be nonempty and no longer than four hours; each Python source
context window is bounded to 128 MiB. Model weights/workspace remain additional
costs. Application export writes float WAV with an atomic no-clobber commit;
evaluation exports independently choose RIFF/RF64 per stem. Shutdown joins
processing/reclamation workers while existing live handles remain valid until
released. Original media and explicit exports are never reclaimed as results.

[source,shell]
----
rivu task status processing INSTANCE:1
rivu processing audition INSTANCE:1 denoised
rivu processing audition INSTANCE:1 original
rivu processing audition INSTANCE:2 vocals
rivu processing audition INSTANCE:2 accompaniment
rivu processing audition INSTANCE:2 mix --vocal-gain-db -3 --accompaniment-gain-db 0
----

Use references actually returned by Start, including the instance identity. The
`INSTANCE` tokens above are placeholders, not literal command arguments. A speech
result uses the `denoised` audition mode. Audition starts the result's original
queue source if necessary, then hands
off to aligned rendered audio; Original returns to source audio. Separation Mix
renders the retained stems with independent gains; it is not a second inference.
Do not mistake source-preserving audition/remix for a stem export feature. EQ
remains a playback setting when comparing results. Listen at matched levels and
compare quiet words, consonants, reverb, attacks and stereo ambience; neither
exact stem summation nor a screenshot constitutes listening approval.

Configuration tables and IPC integration are described in
link:01_config.adoc[Configuration], link:04_playback.adoc[Playback],
link:21_ipc.adoc[IPC] and link:24_layout.adoc[Layouts].

=== Node graph CLI

`processing graph show` prints a readable graph summary, node IDs, connections,
and latest task. Add `--json` for the full `graph` object, including its `revision`,
nodes, positions and explicit port-to-port edges, plus `latest_task` (or null).
The latest task may belong to an older graph revision or a non-graph operation; it
is not the current graph's execution state. `processing show` summarizes playback
EQ, denoise, neural settings, graph and task; `--json` includes their complete
settings and presets. Node-local graph processing does not replace playback EQ.

Every `graph edit` takes one externally tagged `GraphEdit` JSON value and a
required `--expected-revision` matching the graph currently held by Core. Refresh after
each accepted edit or concurrent change; a stale revision is rejected rather
than overwriting another client's edits. Edits include `Add`, `Remove`, `Replace`,
`Move`, `Connect`, `Disconnect`, `Duplicate` and `ReplaceGraph`. Node kinds use
snake_case JSON names, and ports are zero-based. Quote the complete JSON argument
so negative gains and positions reach the parser unchanged.
The persisted graph is bounded to 64 nodes and 128 edges, including nodes outside
the selected ancestor closure.

For a fresh default graph (Source node 1, Output node 2, revision 0), this example
adds an explicit two-input mix, fans the source into both inputs, and connects the
mix to Output. Existing graphs may have different IDs or revisions: inspect them
first instead of replaying these edits blindly.

[source,shell]
----
rivu --json processing graph show
rivu processing graph edit --expected-revision 0 '{"Add":{"kind":{"mix":{"gains_db":[-6.0,-12.5],"muted":[false,false],"solo":[false,false]}},"position":[200.0,120.0]}}'
rivu processing graph edit --expected-revision 1 '{"Connect":{"from":{"node":1,"port":0},"to":{"node":3,"port":0}}}'
rivu processing graph edit --expected-revision 2 '{"Connect":{"from":{"node":1,"port":0},"to":{"node":3,"port":1}}}'
rivu processing graph edit --expected-revision 3 '{"Disconnect":{"to":{"node":2,"port":0}}}'
rivu processing graph edit --expected-revision 4 '{"Connect":{"from":{"node":3,"port":0},"to":{"node":2,"port":0}}}'
rivu --json processing graph run 42 2 --port 0 --mode offline --wait
----

`graph run TRACK_ID NODE_ID` snapshots the current graph and processes only the
selected output port's ancestor closure. `--port` defaults to 0; `--mode` accepts
`auto` (default), `offline`, `realtime` or `hybrid`. Auto first attempts an exact
native realtime plan, then a useful precomputed-prefix/live-suffix hybrid, then
offline rendering. It never changes algorithms. `settings.graph_mode` records
the actual selected mode; `settings.graph_boundary` identifies a hybrid boundary.
Explicit modes reject unsupported plans instead of silently changing modes.
Native realtime planning supports IIR/FIR EQ, non-Profile classical restoration,
Mix and Output; Profile capture and neural inference require an offline prefix
or fully offline execution. A native plan also has admission bounds: at most 32
channels, 64 MiB estimated state, two seconds of latency and a conservative
arithmetic-work budget. These are planning limits, not measured device-deadline
guarantees. An EQ configuration supported by the DSP crate alone can therefore
still be rejected by the realtime graph planner.

Admission counts effective DSP work: disabled/solo-excluded IIR bands and identity
peak/shelf sections do not consume stage estimates. Disabled EQ and fully bypassed
restoration have no DSP latency/state, but edges and node buffers still count.
Validation still applies; enabled flat FIR retains convolution latency, and active
hum/repair is not bypassed by spectral Off.

Hybrid uses a single cached output port as its boundary: every path into the
live target must cross that exact port. A separate uncached source branch or
another separation output cannot be substituted by the same cached stream.
Planning and FFT preparation run on the processing worker, not Core dispatch or
the device callback. `--wait` prints one terminal task result and returns failure
for failed or cancelled jobs; without it, an accepted acknowledgement is not proof
of completion. Use `task status processing INSTANCE:RUN_ID` and
`task cancel processing INSTANCE:RUN_ID` for the same task.

A realtime task reaching `complete` means its immutable live plan is prepared,
not that an offline file was rendered: `graph_outputs` is empty. Automatic
admission still depends on the captured playback generation; confirm the actual
selection in the selected-audio line. Offline and hybrid tasks can retain rendered
node outputs separately from later graph edits. Cached node/port audition is
immediate and returns no processing task ID; uncached snapshot audition prepares
a new run and returns its own task ID.
To render a selected output from any retained graph snapshot, including realtime,
use `graph export` with the actual instance-qualified run reference and node/port from that snapshot:

[source,shell]
----
rivu task status processing INSTANCE:7
rivu processing graph audition INSTANCE:7 3 --port 0
rivu processing graph export INSTANCE:7 3 'rendered outputs/mix -6 dB.wav' --port 0 --wait
----

Audition uses the retained snapshot, not subsequently edited settings.
The Results tab lists every output port in the retained graph, not only cached
ports or the original run's ancestor closure. Calculate-and-audition/export
actions can execute another valid closure from that snapshot. Both cached and
uncached requests recheck the registered source and media identity; keeping a
result does not make it independent of the original source.

Export starts a new task: it copies an already cached node output when available,
otherwise it renders the requested output offline from the retained graph and
source. Neither path uses the subsequently edited graph. The acknowledgement
supplies a new `processing_id`; `--wait` returns that export's terminal task result.
Without `--wait`, query the new task ID, not the
original run, to determine completion.
`settings.graph_export_path` records the admitted destination with its parent resolved;
`graph_exported_path` is populated only after the completed export is published.
Export accepts a real filesystem path, including spaces; relative destinations
are anchored to the invoking client's working directory, not the core's. Choose
a new file in an existing directory; existing destinations are never overwritten.
The parent is resolved at admission so retargeting a directory alias cannot redirect
the export. The worker writes a temporary sibling only for this explicit export,
then commits without overwriting an existing destination after cancellation and
source checks. These checks do not guarantee safety against arbitrary concurrent
directory replacement. In-memory results are session-owned; the exported file
is durable. Source files are not modified.

== Ownership and invariants

Core owns committed configuration and result admission. Editors retain drafts
and interaction state, submitting typed, validated edits; graph commits require
the expected revision. Failed validation leaves committed settings unchanged.
JSON is the IPC/import format, not a second configuration owner.

Prepared DSP owns its coefficients, history and stream format. Device callbacks
do no model loading, FFT planning or file I/O. Allocation, block work and retained
storage are bounded; long-running preparation stays on workers. Bypass, gain,
resampling and latency compensation are explicit, not silent quality fallbacks.

Non-finite input/intermediate PCM fails without publishing partial audio; finite
over-range samples are not clipped or silenced. A failed DSP/profile operation
requires reset before reuse because a finite prefix may have advanced history.
Seeking, source changes and incompatible formats reset history; pause does not
advance audio time. Source identity and captured settings bind every result,
while playback generation separately controls automatic audition handoff.

=== Timeline and source identity

Graph intermediates preserve causal context, including FIR ringing, denoiser
startup and branch delays. Only published audio is compensated/cropped to the
source timeline. Optional `graph_outputs[].context` describes guarded PCM with a
signed source-relative `start_frame`; hybrid suffixes consume it rather than the
trimmed audition slice. At EOF, each denoiser finishes at its actual upstream end
before tails propagate downstream; padding is not new source input.

Original audition validates the opened source descriptor; processed audition
uses immutable PCM handles. Waveform reuse follows exact PCM identity and slice
interval, not just matching path/format. Node failures identify the denoise node
for profile capture or the requested output for final compilation/decode/allocation.

=== DSP crate features

`rivu-dsp` defaults to configuration/validation only. Its optional `execution`
feature enables IIR/FIR, response sampling, denoising and `rustfft`; disabled APIs
are absent, not no-ops. The application and `rivu-audio` enable execution;
`rivu-format` does not request it, though Cargo feature unification can enable it
in a shared dependency graph. Examples `equalizer_benchmark` and `denoise_render`
require `--features execution`.

Disabled FIR allocates no convolution/FFT state. Restoration prepares only the
needed path: exact bypass for zero Wet or a disabled chain, time-domain state for
hum/repair, and STFT state for spectral modes. Configuration and required profiles
are validated even on bypass; delayed partial-wet processing retains dry alignment.

== Quality acceptance

=== Equalizer acceptance

The equalizer provides editable bands, peak/shelf/pass/bandpass/notch filters,
frequency/gain/Q controls, applicable slope choices, enable/solo, channel targets,
input/output gain, presets and response inspection. Graphical and numerical
editing operate on one authoritative filter configuration.

Numerical acceptance is based on independent transfer-function evaluation and
processed signals, not source-text or copied-value tests:

* Disabled processing is sample-exact and does not allocate in processing.
* At defined passband measurement points, steady-state measured response agrees
  with the declared transfer response within 0.1 dB. Nulls and startup transients
  are evaluated separately; dB comparisons at zero are undefined.
* Supported boundary rates, gains and Q values remain finite and stable under
  impulses, silence, tones and broadband input. No output sanitization hides
  unstable filter state.
* Reset eliminates old history; independent channels do not leak. Parameter
  changes are bounded continuous transitions, including bypass and solo changes.
* The displayed IIR response represents actual cascaded coefficients at the current
  sample rate. Frequencies beyond that rate's usable range are explicit. FIR
  acceptance measures the realized finite impulse separately from its displayed
  IIR magnitude target; target agreement alone is not realized-response evidence.

=== Denoising acceptance

Required modes cover stationary noise, a captured noise profile, adaptive noise,
speech-targeted enhancement, hum and impulse suppression. Controls must affect
real algorithm parameters, not relabel an identical preset. Suppression and
content preservation are evaluated separately.

Use clean references mixed with known noise at declared SNR, plus real noisy
recordings. Include speech consonants, quiet words, pauses, nonstationary noise,
music transients, sustained harmonics and stereo ambience. Record input/output
level, residual noise, reference distortion and speech intelligibility where a
valid reference exists. Stereo coherence and musical-noise artifacts require
additional listening; a high scalar score alone is not acceptance.

Ported neural inference must be compared against the selected upstream reference
using the same weights and parameters. An optimization may not silently replace
the model, alter rate handling or claim equal quality from throughput alone.

=== Separation acceptance

Evaluate both vocals and accompaniment against reference stems. Include backing
vocals, reverb, dense instrumentation, transients and stereo mixtures. Measure
source quality and leakage, absolute sample alignment, output length, stereo
coherence, block-boundary discontinuity and mixture reconstruction residual.
If accompaniment is defined as mixture minus vocals, exact reconstruction proves
that definition only; it does not prove separation quality.

Compare the integrated inference with its upstream algorithm under identical
weights, segment, overlap and seed settings before changing those settings for
speed. Synthetic independent components establish alignment/invariants, not
real-world vocal-separation quality. Multi-instrument stems and exporting stems
are not automatically added to the accepted scope.

=== Evidence and performance

An acceptance evidence bundle must record source revision, dirty changes,
executable/model hashes, configuration, corpus provenance/license, exact commands,
device and thread settings; a normal task status is not that evidence bundle.
Keep evaluation data and large outputs in task-owned `.cache/` paths. Never use
private library files without explicit permission.

Separate cold initialization, warm processing, file I/O and playback behavior.
Benchmark bypass, representative and worst supported configurations, and enabled
versus disabled feature branches. Report repeated measurements and variability:
wall/CPU time, real-time factor, block latency percentiles, peak resident memory,
allocations/capacity and underruns. End-to-end seek/cancel/shutdown behavior and
GUI controls require actual application smoke proof.

The Python benchmark and corpus evaluator report two distinct wall times.
`worker_subprocess_wall_seconds` covers only the worker subprocess call, including
startup and captured pipes. `evaluation_wall_seconds` starts before per-sample
reference/input reads and request creation and ends after output reads, artifact
writes, hashes, scoring and sample-record construction. It excludes record append,
progress printing, cross-sample summaries and final aggregate report serialization
or writing. `timing_summary` summarizes each field separately; compare only
measurements with matching timing boundaries.

Both tool families encode undefined scores/gains as JSON `null`. SNR requires
nonzero reference energy; SI-SDR requires nonzero mean-centered reference energy.
Exact reconstruction is `"infinity"` only when that condition holds. A constant
reference therefore has undefined SI-SDR/gain; a silent estimate has undefined
SI-SDR and zero gain for a nonconstant reference. Infinite-baseline gains can be
`"-infinity"`; infinity minus itself is undefined.

Summaries exclude undefined values, preserve infinity ordering, and report
defined/undefined and signed infinity counts. A median between opposite infinities
is undefined. These numerical cases do not establish quality.

Music corpus manifest schema 2 records each prepared directory relative to the
corpus root and explicitly binds `diagnostic_only` to source identity and SHA256.
Directory numbering is not a diagnostic rule. During preparation, mark any known
reference erratum with repeatable `--diagnostic-source` paths; the marker follows
identical source bytes even when renamed or reordered. Run the following from the
repository root after binding the variables to actual local source files. The
output directory must not already exist; keep prepared corpora under `.cache/`:

[source,shell]
----
python tools/audio_quality/prepare_music.py "$al_james_source" "$other_source" \
  --diagnostic-source "$al_james_source" \
  --output .cache/new-music-float --provenance 'actual source and license'
----

Prepare a new corpus if its manifest lacks these identity records. Keep recorded
measurements bound to their original corpus and timing definitions.

Automatic metrics and actual listening are distinct evidence. No automated
analysis is reported as human listening. Missing listening approval remains an
explicit acceptance gap, even when objective and integration checks pass.
