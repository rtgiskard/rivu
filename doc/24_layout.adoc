= Desktop Layout Design
:toc:
:toclevels: 2

== Scope and ownership

Ownership follows lifetime rather than the visible panel tree:

[cols="1,2,2",options="header"]
|===
|Owner |State |Lifetime boundary
|Playback core
|Playback, queue, global configuration and native PCM capture
|Independent of desktop panels and layout edits
|GUI session
|Latest published layout collection and its single persistence worker
|Ends with the desktop process; flushes accepted state after the GPUI loop returns
|Window workspace
|Editable named trees, docking interactions, measurements and panel scroll positions
|Recreated on reopen from persisted layouts, without transient edit state
|Window feature owners
|Business selections, drafts, reads and presentation resources
|Shared by panels of the same feature; not copied into named layouts
|===

Layout management is desktop-local, not a Core IPC or CLI API. User controls,
file syntax and Settings exclusion are in
link:01_config.adoc#layout[Configuration and layout].

Switching or duplicating replaces the active tree, cancels interactions,
invalidates geometry and reconciles panel demand. Layouts hold structure and
instance preferences, not business-state or scroll snapshots. Playback and accepted
metadata saves retain their independent owners; inline fields cancel on blur and
unused graphics retire rather than forming a hidden-layout cache. Renaming the active layout or deleting
an inactive one does not replace the tree.

=== Frontend crate boundary

`rivu-gui` owns the GPUI event loop, display connection, session and window
resources in a desktop process separate from Core. Commands, queries and shared
configuration use instance-bound IPC; state getters read locally published
snapshots. Native PCM is observed through the shared-memory transport, with
display analysis in the desktop worker. Core, storage, IPC, MPRIS and tray services
retain their service lifetime independently of the desktop.

Closing the last window releases display demand and window resources, flushes
the final layout after the GPUI event loop returns, and exits the desktop process.
Reopening starts a new desktop from the persisted layout and current Core state.
Core acknowledgment and service joins remain outside the graphical event loop.
User Quit passes through draft guards; forced application shutdown does not depend
on an open window.

`rivu-tui` owns terminal input, restoration and its IPC workers. Each frontend
keeps its own projection and transient state. `rivu-presentation` shares only
toolkit-neutral localization, shortcut policy, theme presets and application
icons; `rivu-ui` remains the reusable GPUI controls package. Semantic RGB palette
values belong to `rivu-format`; wire and query contracts belong to `rivu-protocol`,
and display analysis contracts and execution belong to `rivu-analysis`.

Shared icons and locales are packaged in `rivu-presentation`; root resource
symlinks preserve installation paths. Desktop integration files remain in
`data/applications`.

Frontend-local tests run in their owning crates. Tests requiring a real Core
use feature-gated application fixtures through the host boundary, not a second
compilation of GUI source modules inside the application crate.

=== Initial layouts

The initial collection contains Default, Album and Visual, with Default active.
Their composition is documented in link:01_config.adoc#layout[Configuration and layout]. Templates
construct panel trees and instance-option slots only; normal initialization
supplies missing artwork/visualizer defaults from configuration. They have no
special runtime identity, update or deletion policy. Additional layouts duplicate
the active tree rather than reapplying a template, and loading a saved collection
neither inserts missing templates nor rewrites proportions.

== Normalized trees and resource boundaries

A layout may have no root when it contains no panels. Otherwise, leaves are
nonempty tab groups with a valid active panel. Splits have two or more ordered
children and a horizontal or vertical axis. Empty containers disappear,
single-child containers collapse, and directly nested same-axis splits flatten.
Panel and container IDs share an allocator within each runtime layout; they are
neither collection-wide identities nor persisted IDs.

A root-to-leaf path contains at most 32 splits; tab groups do not count toward
that depth. Loading, saving, and editing enforce the same limit. There is no
fixed sibling-count budget. Depth bounds recursive model and rendering work and
keeps accepted layouts within the JSON reader's nesting allowance.

Structural edits preflight normalized depth and boundary representability before
consuming the original tree. Rejection preserves panel order, active tabs,
preferences and ID allocation. Even a mathematically nonempty interval can be
too narrow for another distinct floating-point boundary; edits must reject it
rather than round into duplicate boundaries.

== Boundary coordinates

A split stores either no explicit boundaries, meaning equal division, or one
cumulative boundary per adjacent pair. Explicit boundaries are finite, strictly
increasing fractions inside `(0, 1)`. Their coordinate space is total child
content length, excluding separator gutters. Child nodes carry no weights.

For a container length `L`, effective gutter `G`, and `N` children, the available
content length is `L - (N - 1) * G`. A cumulative fraction maps into that content
length; preceding gutters then place it in container coordinates. This keeps
proportions independent of the number of separators while making their space
cost explicit.

Equal division uses cumulative endpoints rather than independently rounding
each child's size. Endpoints are rounded in physical pixels, then adjacent
endpoints determine actual content sizes. Equal areas can differ by one physical
pixel when the available length is indivisible; there are no accumulated gaps
or overlapping areas. Fractional boundaries use the same calculation.

The renderer places regions and separators from these computed bounds rather
than asking flex layout to redistribute relative weights. Dragging, snap
selection, and rendering therefore share the same geometry.

== Local editing

An edge drop divides its target region, not every region in the parent. New
containers default to equal content division. Same-axis docking promotes the
new regions into their parent's child list; different-axis docking nests a new
container. The GUI reconciles the edit against pre-edit measurements so added
gutters are charged to the target area rather than shrinking unrelated panes.
Measurements cover each region's outer rectangle, including tab-group borders.
Measuring only the bordered content would undercount its span and redistribute
the missing pixels into unrelated regions during reconciliation.

Deleting a region gives its freed space to the following neighbor, or the
preceding neighbor if the deleted region was last. Collapsing and flattening
map descendant boundaries into the surviving parent's coordinate range rather
than independently rebalancing all regions.

The model preserves ratios without depending on a windowing toolkit. The GUI
adds current-size reconciliation because inserting a gutter changes the
available content length. Stored fractions preserve proportions after a window
resize; they do not promise immutable pixel coordinates across different window
sizes.

== Panel insertion

The catalog uses two rows. The first contains Playback, Library, Albums, Queue,
Playlists, and Recent tracks. The second contains Track details, Artwork,
Audio processing, and Visualization. Visualization inserts one `audio_visualizer`
instance, initialized from global style and overlay defaults; Spectrum,
Spectrogram, and Waveform are selectable styles rather than catalog entries.

Audio processing is limited to one panel per named layout. Once present, its
catalog entry cannot start another insertion; the existing panel can still move,
close and be added again. Loading an older layout retains the first Audio
processing panel in tree order and removes later duplicates, normalizing empty
containers without removing other panel kinds. Other panel kinds retain their
existing multiplicity. Processing drafts belong to the window feature owner,
not a named layout or panel instance; layout switches and closing/reopening the
panel cancel interactions but preserve drafts for still-valid targets.

Catalog insertion is drag-only. It shares docking geometry, preview and commit
with existing tabs; click, double-click and keyboard activation insert nothing.
The preview owns a candidate tree with the actual new panel identity. Only a
valid drop replaces the live tree and allocator; cancellation discards it.
An empty layout targets the measured workspace excluding the footer, with
`Place panel` feedback. Resize invalidates that measurement like other geometry.

== Panel docking targets

Panel dragging resolves one target from measured layout-tree rectangles, never
from overlay hitboxes. Only the hovered tab group can be a destination: its
left, right, top, or bottom edge splits that panel region, and its center merges
tabs. Enclosing rows, columns, and the layout are not separate targets. Outside
the visible tab bar, each edge zone occupies the outer 22 percent of the panel
on its axis; the remaining center merges tabs. Corners with two competing edges
and separator gutters are neutral. The outline and direction label identify
the destination panel; shading previews the moved panel's final rectangle.

Unknown panel-kind keys survive layout loading and appear as named placeholders;
they are not silently discarded.

A target transition prepares one candidate using the actual move and measured
reconciliation. Its projection previews source removal, collapse and gutters;
release consumes that same candidate, with no fallback to a different target.
Unchanged targets reuse it. Layout edits, viewport resize, interface scale or
physical scale changes revoke candidates and measurements. Until the next
prepaint publishes fresh bounds, docking has no target and release changes nothing.

Tab-index targeting checks the active panel's tab-bar visibility and takes
priority over edge zones. The entire visible tab row, including gaps and its
unused tail, reorders or transfers tabs without splitting the panel. Insertion
uses tab midpoints, with the tail inserting after the last tab. Hidden tab bars
have no tab targets; persisting visibility changes removes their old tab
measurements. Ordinary edge and central docking remain available.

The docking session owns only panel drags. Escape, window exit or deactivation,
menus and dialogs, locking, and drag completion clear it. Release rechecks the
blocking state before committing, so cancellation does not depend on a repaint.
Wayland implicit button grabs may deliver motion outside the window without an
exit event; viewport bounds provide the same cancellation in that case.

[[dragging-and-snapping]]
== Dragging and snapping

A separator drag snapshots the relevant geometry and mouse-to-separator offset.
Every update derives its target from that snapshot, not from a previous rounded
result. Moving a boundary changes only its adjacent regions. The feasible
interval reserves 160 logical pixels per horizontal neighbor or 100 per vertical
neighbor. If the pair is already too small for both minima, dragging selects its
equal-content midpoint instead; snapping cannot satisfy impossible minima.
Layout locking blocks structural edits, not playback or panel content updates.

The window owns one interaction state and epoch-tagged geometry. Escape, focus
loss or geometry changes cancel separator previews and restore the original
boundary without persistence. Tab activation likewise rolls back before
publishing the active tab. Rollback invalidates preview measurements so later
edits cannot reapply a cancelled ratio. Layout replacement instead discards the
outgoing interaction; its rollback must never touch reused IDs in the new tree.

Snapping selects feasible candidates in this priority order:

. Separator centers in other visible splits with the same axis, expressed in
  common window coordinates
. The equal-content midpoint of the adjacent regions
. The nearest configured grid line relative to the container origin

Reference and midpoint capture distance is 4 logical pixels before interface
scaling; grid spacing is configured in the same coordinate system. The grid
candidate is the nearest line, without a separate capture distance. Candidates
outside the feasible interval are ignored rather than clamped and misrepresented
as exact alignment. Physical
pixel rounding remains the final limit of precision.

Alt temporarily reverses the configured snapping switch for the current drag
without modifying the settings draft or saved file. Snapping aligns current
geometry only: no persistent cross-container constraint or general constraint
solver is stored.

[[geometry-and-constrained-viewports]]
== Geometry and constrained viewports

Visualization sizing uses the actual content canvas, after any visible
tab row, panel borders, and 0.5rem content insets. Small canvases shrink their
plots or retain only the visual background, without size warnings or tooltips.
Spectrum and Spectrogram omit their plots when the canvas is at most 64px wide
or 40px high. Spectrum omits axis labels below 78px canvas height rather than
overlapping its four dB labels, without changing the saved label preference.
Audio Visualizer styles retain their own drawing cutoffs.

Waveform hides its configured time labels at canvas heights of 32px or less,
preserving wide, shallow plots. At widths or heights of 16px or less, it retains
only the background and any existing load/error status, retires the panel's
pointer capture and cancels its seek preview. Growing the panel restores drawing
and configured labels; seeking requires a fresh press after capture cancellation.

At the supported minimum window size (760 by 480), especially at interface scale
2, not every list and plot can be useful simultaneously. Playback keeps vertical
scrolling and horizontal scrolling for its controls so transport, seek and volume
remain reachable. User adjustments are documented in
link:01_config.adoc#layout[Configuration and layout]; resizing or scaling never
rewrites saved proportions.

The separator minima in <<dragging-and-snapping>> constrain adjacent regions,
including tabs, borders and content insets, not individual widgets or recursive
nested-split sizes. Library, Queue, Albums, Recent tracks and Playlists share those
rules so switching tabs does not change separator behavior. Saved proportions,
docking and cramped viewports may still produce smaller panels: lists must shrink
inside them rather than overflow neighbors, and longer headings do not increase
the layout minimum.
Heading actions stay on one line while the title shrinks; their shared overflow
policy is described below. Track details label/value pairs stack in narrow panels
and return to equal columns when space permits. Inline edit and read-only states
share a compact single-line height; long values truncate instead of wrapping.

=== Panel chrome and overlays

The shell owns workspace/footer spacing and the outer inset of docked panels;
panel roots and captions do not repeat it. Cards, rows and forms retain internal
spacing. The full-window root remains unpadded so modal backdrops and docking
overlays use window coordinates.

Tab heights follow text and scaled padding. Unlocking adds tab-close controls
without changing tab height. The footer reserves the shared icon-button height,
following typography and interface scale independently of notification presence.
Messages and their copy/dismiss controls fill that height without extra vertical
padding; error backgrounds fill the notification area. Showing, replacing or
dismissing a message does not resize the workspace. Footer messages shrink and
truncate before the fixed action group. Menus anchor to actual footer
bounds, size to contents and scroll when taller than the viewport; each catalog
row wraps within its own group and overlong individual labels truncate. Shared
menus, tooltips and drag previews retain viewport clearance rather than expanding
the workspace minimum.
Action menus and playlist destination candidates share a single-line height that
follows typography and interface scale, including loading and recovery rows.

=== Headings and inline actions

Shared headings keep titles and secondary text independently truncated beside
fixed, non-wrapping actions. Tools align with the full title/status block;
toolbars may opt into wrapping, but heading actions do not reflow or enlarge
saved panel proportions. Track details retains full loading status in a tooltip;
its feature owns field-specific input, errors and write availability.

Panel tabs, panel catalogs and content headings share the same localized names;
settings navigation and TUI headings reuse those names for the same concepts.
Field names and generic actions also share messages, while scope explanations
and lifecycle-specific actions remain independent.

Header icon hit areas follow typography and interface scale. Search reserves
the same single-line height collapsed or expanded, and its editable region can
shrink inside the action allocation. At extremely narrow widths, panel clipping
remains authoritative.

Layout management separates its heading, list and action footer. Names shrink
while current-layout and delete actions retain equal-sized slots without changing
row height; Duplicate/Rename stay grouped and Sync sits opposite them in a wrapping footer.

Tooltip placement belongs to GPUI's window overlay. It anchors to the pointer
position at opening, prefers above, then below or a side, and clamps against
viewport clearance. Placement does not truncate oversized text or change the
hint's show/hide lifecycle.

== Persistence and failure semantics

`layout.json` contains the selected name and a nonempty map of named layouts.
Serialization borrows runtime data and writes one strict format. Unknown fields,
duplicate layout names, invalid boundaries, malformed trees, and excess depth
are errors. Runtime IDs and edit locking are omitted.

=== Session snapshots and explicit sync

The desktop-session owner retains immutable snapshots of layout edits; named
layouts share trees until an edit copies the affected tree. Rendering borrows
the active tree from a shared collection snapshot rather than copying the tree
per frame. Validation, encoding and file I/O stay off the GUI. Manual sync cancels
previews and captures committed state; panel-settings Apply publishes only to
session memory.

The writer serializes one in-flight and one replaceable pending sync snapshot.
Later edits do not alter a captured request or suppress its feedback. A newer
sync replaces pending work and visible feedback, not the running write;
superseded failures remain logged. Serialization prevents an older write from
overwriting a newer completed one without an unbounded request queue.

=== Baseline, replacement and failure

The writer validates unchanged content but skips encoding and I/O against its
last successful snapshot; runtime IDs and locks do not affect equality. Only the
captured successful request advances this baseline. Missing input is initialized
on sync or exit; failed startup input remains protected until explicit Sync.
External file changes are not watched or merged.

Validation precedes a unique sibling temporary file and atomic rename. Failure
preserves the destination, baseline and session edits; atomicity does not promise
power-loss durability. The latest request reports success or failure; success
clears only its own save error. Manual Sync retries the latest collection, not
ordinary layout edits or an automatic retry loop. Named operations preserve a
valid selected layout independently of file writes.

=== Initialization and teardown

Initialization reads persisted layouts once, admitting ordinary files and rejecting
FIFOs or links to them without waiting. Closing the last window ends the GPUI loop;
the desktop then calls `flush_layouts`, joins the persistence worker and exits,
propagating save failure. Dirty state is flushed unless failed startup input is
being protected. The quit observer does not wait for file I/O inside GPUI's deadline.
Reopening creates a new desktop from the persisted collection, with editing locked;
there is no cross-close in-memory session. Abnormal exit can lose unsynced edits.

== Rationale and alternatives

Boundaries follow the object users manipulate: a separator position. Integer
weights require rescaling and quantization to represent arbitrary positions and
can perturb unrelated regions. Floating weights remove the integer range but
still leave final placement to a separate flex allocation. Explicit boundaries
avoid both issues and make gutter accounting testable.

Absolute saved pixels would preserve one window size but need a separate policy
for resizing. A full constraint graph could maintain alignment across containers
and window sizes, but introduces conflict resolution and coupled edits. Relative
boundaries plus transient snapping retain a small tree model while meeting the
current interaction contract.

== Instance preferences and visibility

Panel instance preferences belong to the layout and survive docking and
duplication. Missing artwork options initialize from configuration once;
later global-default changes do not overwrite initialized panels. Artwork
acquisition and rotation scheduling remain shared, and frame rate remains
application configuration, not a per-layout setting.

Visibility gates rendering, analysis, and new tree/Details reads, not state
validity. Hidden windows and inactive tabs still reconcile core state and
query-owner keys; revealing a panel demands only missing current data.
Projection acceptance, identity-safe metadata saves, compact occurrence selection,
and physical-worker cancellation follow
link:22_cache.adoc#query-projection-retention[Query projection retention].
Keyboard list actions target only a visible active panel; see
link:02_library.adoc#paged-views[Paged views].

The window arbitrates explicit actions by newest input identity. Preparing an
action does not suspend playback-follow Details; only a valid selection commit
pins its target. Failure or cancellation settles that input, never a newer one,
and does not choose a Details target. The metadata owner synchronizes follow
identity directly from playback snapshots and when explicit selection is cleared;
read completions update availability, not target identity. User-facing behavior is
described in link:02_library.adoc#_inline_track_details_edits[Inline Track details edits].

Settings root-removal controls retain the configured path and edit session, not
the rendered vector index. Hidden or reopened Settings cannot accept that old
input. Content and playlist action menus bind rendered callbacks, including
dismissal and destructive confirmation, to their menu instance and page; replacing
a menu does not transfer its old controls to the replacement source.

Scroll offsets belong to panel instances in the current tree, not to their
visibility in a frame. Inactive tabs retain their viewport state but cannot
receive pointer or page-key input. Structural edits release state for removed
panels; switching or duplicating a named layout starts new view-local scroll
state. No per-layout scroll snapshots are kept.
Albums routes PageUp/PageDown only to its displayed grid or track-list viewport;
switching regions preserves the grid's retained position.

[[material-appearance]]
== Material appearance

The application owns material preferences, artwork demand and controls. Source-image
effects, ordered scene filters and procedural water execution are maintained in
https://github.com/rtgiskard/gpui-wgpu[gpui-wgpu]; both patched crates use the same
revision pinned in the workspace manifest. Rivu does not carry a renderer copy.

The footer application menu provides Settings, Layouts and Textures entries plus
a checked Visualizations switch for immediate enablement. Textures opens
the same live selector and adjustment panel from the application menu or Settings
→ Interface, beside Theme. Language occupies the first Interface row. Closing
Textures returns to its entry point: the workspace for the application menu, or
the existing Settings draft without applying, discarding or resetting it. Clicking
the menu's texture status switch enables or disables effects immediately without
opening the card; clicking the menu item body or the Settings entry opens the card
without toggling effects.
The twenty-six studies are grouped as follows, without changing their rendering
compositions:

* Texture:
** Satin glass: restrained gradients and fine panel edges
** Artwork atmosphere: cover-derived atmosphere in playback and artwork panels
** Deep glass: a shared cover-derived backdrop beneath translucent panels
** Spotlight stage: stronger playback emphasis with quieter reading-panel edges
** Borderless mist: soft surfaces with reduced panel boundaries
** Backdrop frost: blur of the actual scene painted behind each panel
* Water:
** Quiet water: expanding elliptical wavefronts and curved crest highlights
** Rain ripples: scattered raindrop impacts with outward-moving damped ripple trains
** Shallow stream: directional flow with elongated refracted light
** Mirror lake: wide sky reflection broken by fine horizontal wind
** Clear crystal: nearly colorless refracting sheets and broad curved light
* Experimental (collapsed initially):
** Prismatic architecture: faceted panes with moving specular reflections
** Nocturne light: opaque reading space with local breathing playback illumination
** Mirror lake: vertically reflected artwork with travelling horizontal displacement
** Gradient translucency: spatially varying panel tint and alpha
** Feathered artwork: linear and radial source-alpha masks
** Moving sheen: local travelling highlights behind panel content
** Fading scroll edges: vertical composite masks on Library and Queue viewports
** Cover atmosphere: shader sampling blur of the shared cover source
** Continuous water: one reflected cover field with continuous UV displacement
** Paper grain: stable surface fibers and image grain
** Cover dissolve: a bounded previous/current artwork transition
** Celtic storybook: original flat woodland, leaves, braided water and paper composition
** CG Water: independent procedural perspective water and sky reflection
** After rain: sparse fading rain impacts on overcast shallow water
** Water garden: soft leaf shadows over a refracting green water bed

The same panel selects every preset and exposes only the parameters supported by
the current selection: panel opacity, cover feather, sheen highlight, grain
strength, color levels, water displacement, wave strength, water highlight, cover
blur, backdrop blur, list edge fade, cover transition and motion speed. These are
adjustments to a predefined composition, not arbitrary effect stacking.

Without saved preferences, effects are disabled with Satin glass selected, ready
to enable. The header's texture-effects switch is independent of that selection:
turning it off renders the unmodified interface without changing the selected
material or its edited parameters. While effects are off, preset selection,
adjustments, Experimental expansion and Reset are read-only; the effects switch
and outside dismissal remain available. Turning effects back on restores the selected composition.

The enable state, selection and per-preset parameters are saved through Core's
configuration authority. Switching away and back restores each preset's edits;
closing the card or restarting the desktop does not reset saved preferences.
Reset selected preset restores only that preset's defaults. Material edits take
effect immediately and save automatically, independently of the Settings draft.
They do not change semantic theme colors, playback, queue state or saved-layout
syntax. Menus and dialogs retain opaque elevated surfaces and input barriers.

The GUI projects the saved preferences into its material state. Factory defaults
are compiled from
link:../crates/rivu-format/data/presets/material.toml[`data/presets/material.toml`];
personal overrides remain in `config.toml`. The static GUI catalog supplies control
capabilities and composition recipes. Selection, reset and parameter edits commit
through window coordination. The window-local
atmosphere runtime reconciles material identity, transition policy, track and
visibility in one resource-demand update. Material actions update only that
demand, not unrelated features; track, layout and window lifecycle changes use
the same entry. Identity or enablement changes and edits to list-edge fade
invalidate cached appearance consumers. Other parameter edits notify only the
root composition and controls. Crossing zero transition duration updates predecessor
ownership immediately, including while paused. These transitions do not depend on
a Core playback revision. The shell owns control-card attachment and focus,
not the preference lifetime.

Before constructing the layout, the window samples one material frame from the
existing atmosphere owner. Root and panel decorations consume the same accepted
source pair and transition weight. The frame shares source handles without copying
decoded pixels; it is not a second image cache, timer or long-lived state owner.

Artwork demand follows the actual composition scope. Deep glass, the Experimental
artwork-reflection Mirror lake, and the source-image studies from Gradient
translucency through Celtic storybook have root consumers that remain active
without a playback or artwork panel. Artwork atmosphere and Spotlight stage
consume the atmosphere in playback-class panels. CG Water, Rain ripples, Shallow
stream, the Water group's Mirror lake, After rain, Water garden and Clear crystal
do not request material artwork.
Full-cover materials contribute viewport-sized demand to the same tier selection
and generation acknowledgements as ordinary artwork panels. The 64-by-64 ambient
derivative requests source pixels only while being generated; its ready cache
does not retain a low-tier source. Removing an artwork panel preserves an active
material's derivative, but releases source pixels if no other source consumer
needs them. Switching to a full-cover material requests its source tier again.
Source handles cannot restart work after their material lease is retired. Budget
changes cancel both source and ambient work, retaining old scene pixels until
the usual generation/frame fence.
For Artwork atmosphere, Deep glass and Spotlight stage, the atmosphere consumer shares artwork acquisition, source decoding and
the existing decoded-image budget with artwork panels. It derives a static,
blurred 64-by-64 image from the first decoded frame off the GUI thread. This
small derivative does not eliminate the cost of decoding the full source image.
The effect uses ordinary GPUI image and gradient composition, not live backdrop
blur or desktop/compositor transparency, and adds no animation timer.

Track changes invalidate the old atmosphere immediately; obsolete completions
cannot publish for a newer track. With
link:01_config.adoc[default artwork fallback] enabled, artwork-dependent backgrounds
use the shared bundled SVG when no real cover is available or decoding rejects it.
Otherwise only the unavailable image layer is omitted; neither case retains the
previous track's cover.
Leaving an artwork-dependent material or hiding the window releases its atmosphere
consumer's image references; other artwork consumers retain their own ownership.
Turning material effects off also stops material animation and releases the
material consumer's current and previous artwork references. Ordinary artwork
panels and visualizations keep their independent behavior and ownership.

Prismatic architecture, Nocturne light, Quiet water and the Experimental
artwork-reflection Mirror lake use GPUI's synchronized animation clock, not
independent application timers. Motion requires enabled material effects, a visible
window, positive speed and reduced motion disabled; focus loss alone does not stop it.
Disabling audio visualizations does not affect material motion or cover transitions.
Nocturne light keeps reading panels still; its playback illumination moves.
Artwork-panel and audio-visualization FPS limits share their own window-local
frame gate; they do not throttle material motion or image transitions.

Rain ripples models scattered raindrop impacts on shallow water. Each impact launches an
outward-moving train of damped ripples; overlapping surface gradients drive
procedural-bed refraction and reflected light together. Impact positions, timing
and strengths vary within a deterministic seamless cycle rather than repeating
fixed rings or decorative arcs. Wave strength zero leaves a static surface.
This remains a bounded procedural scene, not a fluid simulation or refraction of
UI content. The other water presets retain their separate compositions.

The Experimental artwork-reflection Mirror lake shares the current viewport-sized decoded tier with the existing artwork owner,
not the blurred atmosphere derivative. Sixteen clipped views sample one vertically flipped
field, with phase-offset horizontal displacement of image detail. These views do
not create independent decodes or animation cursors. Native Metal currently lacks
this image transformation path and uses the water/light composition without the
photographic reflection. These studies do not implement physical fluid simulation,
live desktop transparency, or refraction of arbitrary interface content.

The Textures card is an undimmed live preview above the application footer. It
fits its content within the viewport; its parameter body scrolls independently.
The title bar owns the enablement switch. The grouped selector, Experimental
visibility and Reset controls share the next row, with localized tooltips for
symbol buttons. Fixed-appearance presets show an explanation instead of controls.
Turning effects off leaves the card open but cancels uncommitted parameter edits;
the read-only policy above applies. Outside click dismisses it; there is no Close
button. Extremely small windows are outside this card's accepted scope.

Property rows use aligned labels and plain-text values, with an edit icon revealed
by hover or keyboard focus. Rows retain their compact single-line height while
editing. Enter commits and Escape cancels; units remain visible beside the value.
Invalid numbers remain in the editor with an error indicator and tooltip, never
saved or silently clamped. Transition duration and speed accept exactly zero:
zero duration disables dissolving, while zero speed keeps static artwork without
retaining a transition predecessor. These are predefined compositions, not a user
shader compiler or node editor.

The card shares the shell's exclusive surfaces, ordered composition and keyboard
routing. Tab stays within its scope; Escape cancels a numeric edit before closing
the card. A covering metadata confirmation owns focus until dismissed. Closing
the last window drops transient editors, not saved preferences; reopening cannot
revive the old modal focus owner.

The source-image studies from Gradient translucency through Celtic storybook share
decoded artwork rather than generating per-frame bitmaps. Image masks,
sampling blur, UV waves, grain and color quantization compose on one sprite.
All effect sampling stays within the source atlas tile and handles fractional
source alpha correctly; ordinary no-effect images retain their sampling semantics.
Sharing a texture does not make sampling work free. Native Metal explicitly
rejects these new image/filter operations.

Source-image effects have a fixed order: wave displacement selects the sampling
center, source blur samples around it, then color quantization precedes grain.
Feathering masks the resulting image; this is not an arbitrary reorderable chain.
Backdrop capture and subtree isolation remain separate scene operations because
their inputs and painter-order boundaries differ from source-image sampling.

Backdrop frost captures already-painted geometry and blurs it before the panel
foreground; it does not blur the source cover. Group edge fade isolates viewport
children, including overlaps, and composites their premultiplied result once.
Headers, tabs and toolbars are outside the list mask. Groups containing backdrop
blur interpolate the composed parent/group result so translucent backdrop alpha
is not counted twice. Plain fades retain transparent isolation and source-over
composition.

Per-window target storage and fade-depth limits are runtime settings; defaults
and accepted ranges are in
link:01_config.adoc#_appearance_and_library_display[Appearance and library display].
The target-byte budget charges renderer-owned filter targets, not the output.
Ordered filter markers remain capped at 64. Exceeding a configured limit, that
marker cap or device texture dimensions skips all scene filters for the frame
and preserves ordinary content; unbalanced filter groups remain rendering errors.
Backdrop sigma is capped at 32 physical pixels after logical-to-physical conversion.
The material frame resolves its effective logical sigma to
`min(requested, 32 / physical_scale)`; the session retains the requested value
rather than changing its preset when output scale changes.
More than 256 water panels skips all procedural water for that frame. Water and
filter admission are independent, and both resume on later in-limit frames.
Filters introduce painter-order barriers and can reduce batching; fade groups
use grayscale text coverage. They add no production CPU readback or
desktop/compositor transparency. Sampling and filter-resource implementation
boundaries belong to link:25_gpu_rendering.adoc[GPU Rendering Design].

Only an enabled cover transition retains one predecessor. Its clock starts after
the new source decode is ready; hiding, disabling motion, zero duration or changing
material identity retires the predecessor. Same-material duration edits retain the
active clock. A predecessor can observe pending/ready work but never initiate a
cold decode. Material owners consume real-cover lookups directly: a missing or
failed target clears obsolete imagery. The shared
link:01_config.adoc[default artwork fallback] preference controls replacement with
the same generated default artwork used by cover panels. Opaque-cover dissolves
compensate source-over alpha to retain constant backdrop contribution. Combined
feathered masks use ordinary source-over coverage rather than exact dual-texture
alpha interpolation. Celtic storybook is an original
storybook-style experiment, not an imported film asset or character reproduction.

Procedural water presets paint one independent root canvas through
`Window::paint_cg_water`, without artwork demand or sampling/distortion of covers,
interface text or the desktop. Foreground rendering and input geometry are
unchanged; panel tints remain local. This is artistic water, not physical fluid
simulation, scene/depth reflection or an image-effect/plugin framework.

`CgWaterStyle` selects separate fixed compositions: CG Water uses perspective,
a horizon, multiscale analytic normals, Fresnel sky reflection, absorption and
glints; Rain ripples refracts a shallow bed with expanding ripples; Shallow stream
uses downstream light filaments; the Water group's Mirror lake reflects a broad
sky through horizontal wind; After rain uses sparse fading rain packets; Water
garden projects six soft leaf shadows; Clear crystal bends light through nearly
colorless curved sheets. None replaces or retunes another preset, and none is
Continuous water's cover displacement.

Their only controls are panel opacity, wave strength, water highlight and speed.
Wave strength maps the stored `0..16` range to normalized `0..1` shader amplitude
and displays as a percentage, not pixels. Rain ripples defaults to 45% panel
opacity, 25% wave strength, 32% highlight and 0.55× speed; CG Water retains its own
baseline. Per-preset restoration, Reset and modified-state tracking follow the
shared preference contract above; stale controls cannot edit a different preset.

All use GPUI's synchronized, seamless 24-second cycle at speed 1. Hidden windows,
reduced motion, zero speed or zero wave strength select a static phase without
attaching animation. The caller schedules motion; the renderer receives bounds
and scalar parameters only. No per-frame bitmaps, image uploads, geometry grids
or unbounded caches are added, but covered pixels still incur shader work: no
measured performance improvement is claimed. Unsupported native backends reject
procedural water rather than substituting artwork.


== GUI composition boundaries

GPUI remains the rendering and input framework. Library, Queue, Playlists,
History, Metadata, Duplicates, and Playback have independent window-lifetime
owners. A feature owns its inputs, model, read execution, result acceptance, and
rendering; multiple panels of that feature share its business state. The window
coordinates explicit cross-feature actions, not a second aggregate browser model
or query dispatcher. Inline metadata edits never block navigation. See
link:22_cache.adoc#query-projection-retention[Query projection retention].

Audio processing configuration and jobs belong to Core, not the docking tree.
Hiding its panel does not disable EQ or cancel work; geometry changes cancel
pointer gestures without discarding numerical drafts. Its UI and execution
contract are in link:27_audio_processing.adoc[Audio processing].


=== Feature state and commits

Features share one immutable Core snapshot refreshed per revision. Cross-feature
transfers hand owned results to the coordinator rather than retaining duplicate
row collections. Core serializes business commits and persistence; GUI refresh
failure cannot undo an accepted commit. See
link:21_ipc.adoc#business-ownership-and-transactions[Business ownership and transactions].

Shared list interactions freeze source identities and ordered selections against
the Core snapshot; features keep occurrence-reordering rules and asynchronous
Library resolution. Targets decide acceptance and insertion position. The window
coordinator owns content menus, manual-intent arbitration, queue replacement and
album-menu resolution, not feature listing models. Copying tracks and reordering
occurrences are distinct. Query cancellation, acceptance and physical-slot rules
are authoritative in link:22_cache.adoc#query-projection-retention[Query projection retention].

Settings owns its baseline, draft, target and submission identity independently
of controls. Inputs own editable text/caret. Successful completion rebases later
edits onto committed configuration; failure or obsolete completion cannot erase
new input. Panel settings share this boundary, not artwork-cache maintenance.

Relative selection uses each feature's latest desired cursor. The feature
prepares and validates its target; the window arbitrates newest manual intent.
Committing a different track cancels unsubmitted Details input without confirmation.
Terminal non-commit transitions release arbitration and reconsider playback follow;
stale results cannot settle a newer intent.

=== Surfaces, focus and input routing

The shell owns mutually exclusive application surfaces and keyboard focus
restoration. One ordered surface inventory drives composition, keyboard authority
and background blocking. Feature confirmations can cover a surface without
discarding its draft. Deferred focus requests carry a generation so an obsolete
callback cannot focus a replacement surface. Workspace activation validates the
target before cancelling an interaction; rollback follows the outgoing-tree rule
in <<dragging-and-snapping>>.

GPUI owns actual control focus and key dispatch; the shell coordinates surface
scopes and restoration, while each feature keeps selection and keyboard targets
consistent. Leaving an editor focuses its still-open surface, not the workspace
behind it. The root rejects background key dispatch while a surface owns the
keyboard. Closing a surface validates its invoking control against the next drawn
tree; a missing origin falls back to the layout, and a newer workspace focus
choice supersedes deferred restoration. Panel removal hands focus back when its
removed control owned it and routes panel commands to a surviving active panel.

Monitor EQ popovers have one panel owner and shared keyboard scope. Preset
choice surfaces and their focus containers stay out of layout flow, so opening
or closing a list does not reflow the editor. Dismissal restores the live trigger
only while the popup still owns focus; outside presses
do not activate underlying controls. Hiding or invalidating owner geometry
retires the popup, and disabled EQ removes preset actions from traversal.
Popup/name changes invalidate affected editors rather than every processing view.

Queue and Playlist owners resolve an operation into one ordered occurrence
snapshot before dispatch. Menu and drag payloads retain that snapshot, including
duplicate track IDs; stale source identities or entry-view generations are rejected.
Playlist identity and entry-view generations are independent, so filtering entries
does not replace a selected playlist's pending or failed summary lookup.

Pointer activation belongs to semantic regions. Passive row content bubbles to
its row, while independent actions isolate selection and drag initiation.
Isolation wraps the action region, not the focusable child: GPUI's native focus
handler must run before propagation stops. Capture bookkeeping, dismissal,
wheel/drop routing and gesture delivery retain separate lifecycle owners.

Interactive rows use business identity, not visible index, so replacement cannot
inherit another target's pending activation. Disabled controls expose no pointer,
Tab or accessibility focus target. Native accessibility Focus additionally checks
the live shell surface and published scope; replaced surfaces/confirmations
invalidate old requests rather than queue them for a new frame. Other native
accessibility actions are outside this gate. It does not add replay support to
the pinned GPUI accessibility cache.

=== Demand and cached views

Window visibility, layout activation, and menu transitions publish feature demand
when they change. Rendering measures viewport demand but is not a fallback for
advancing selection, retiring work, or synchronizing cross-feature eligibility.
Directory publication resumes deferred navigation; transfer state changes notify
their dependent owners even when no root frame would otherwise be needed.

The workspace publishes panel membership, active tabs, and instance preferences
when a structural edit, tab activation, or panel preference edit commits. Initial
load, layout switching/duplication, and window reopen establish this demand before
feature synchronization. Geometry-only separator commits, resize, lock changes,
and cancelled previews do not rediscover the panel tree. Rename and inactive-layout
deletion leave the active demand intact.

Playback updates consume published demand rather than searching the layout.
Visibility, visualization enablement and shutdown gate that demand. The visualizer
owner separately reconciles panel membership/preferences and dynamic playback or
waveform state. Removing an inactive panel still retires its resources; Stop,
Seek and source replacement retain distinct continuity boundaries.
Processing editor membership and hidden-panel interaction cleanup also follow
the workspace revision and effective visibility, not each playback publication.
Configuration, task and acknowledgement reconciliation remains independent.

Business panels have cached view boundaries separate from shell traversal and
observe their feature owner directly; rendering never calls back into the window
root. Feature dependencies invalidate their content. Playback timeline updates
invalidate transport and, when its live data changes, History, without rebuilding
library or playlist rows. Global font/theme changes explicitly invalidate cached
business views; geometry changes refresh the affected panel measurements.
Page-key scrolling invalidates the panel owning the changed viewport, rather than
notifying the root or every panel of the same feature.
Layout visibility, not whether a cached subtree rendered in that frame, decides
which retained scroll regions can receive input. Re-rendering a panel replaces
only that panel's region registrations. Visualization scheduling and image
retirement belong to a separate presentation owner; see
link:23_visuals.adoc#analysis-boundary[Analysis boundary].

Album grids and Artwork panels also retain cached view boundaries, so unrelated
visualization frames do not rebuild their unchanged element trees. Artwork source
and option changes invalidate their consumers; rotation frames invalidate only
visible rotating instances. Animated source images still update every visible
Artwork consumer, including instances whose rotation mode is static.


[[reusable-gpui-controls]]
=== Reusable GPUI controls

The workspace package `rivu-ui` provides the shared controls independently of
Rivu's application root. It depends on GPUI and Unicode segmentation, not the
playback core, configuration, localization catalog, or feature models. Rivu's
GUI composition layer supplies track rows, metadata/artwork presentation, and
localized search labels and count formatting. Generic controls are imported
directly from `rivu_ui`.

Rivu's composition layer adapts host appearance and localized presentation; its
cross-feature coordinator arbitrates manual intents and confirmations. Generic
controls do not absorb those responsibilities or feature-owned models and requests.

Shared track controls provide favorite state, tooltips and pointer isolation;
feature owners decide visibility and commands. Loading rows offer explicit retry
and full-error copying, including keyboard/accessibility activation. Copying does
not retry. The 150 ms loading delay is presentation only; request identity,
physical slots and recovery remain feature-owned. Tree and album-grid placeholders
retain their own geometry. Tooltip content requiring current input resolves on
opening, without an additional data subscription.

==== Appearance and semantic controls

Hosts install palette and resolved typography, initialize Input, and invalidate
views when appearance changes. The package does not resolve application fonts,
configuration or localization; tooltip and drag roots read shared typography.

Buttons, menus, checkboxes and choices expose native roles, names and state.
Accessible Click follows normal activation. Disabled controls reject activation,
remove Click/Focus and leave Tab order while retaining focus identity; business
guards remain with owners. Decorative glyphs do not create duplicate controls,
and rich menu content needs a textual accessible name.

Checkboxes and choices are controlled: owners accept changes, update dependent
state and invalidate their owning entity. They do not save configuration or replace
Settings' Apply/Discard boundary. Icon switches expose controlled on/off state;
action groups share appearance, not state or commands. Hosts choose wrapping,
inline clipping or scrolling. Hover actions appear on their row's hover or
descendant keyboard-visible focus, not list-wide focus; hidden actions leave
text width available. Mouse activation retains native focus without pinning the
actions open after the pointer leaves. Button focus borders appear only in
keyboard mode. Playback's Favorite and Locate buttons remain visible; their
hover and focus feedback does not change favorite state.
Release handling follows child gestures so a consumed dock cannot commit twice.

==== Editors and choice popups

Input owns text, selection, IME, focus and pointer-selection capture. Edits
invalidate shaped hit-test geometry until repaint, preventing pointer events
from using old text offsets. All edit paths normalize line breaks to spaces;
movement and deletion follow extended graphemes in full-text context.

Change events distinguish origin and active IME composition. Preedit is visible
but uncommitted: Enter cannot submit it, and Escape first restores the prior
text/selection. Disabling preserves the draft while rejecting edits and focus.
Inputs require an explicit accessible name, separate from placeholder text;
accessible edits share the user-edit path and validate text-node/Unicode bounds.
Platform adapters determine which text actions reach these handlers.

SearchField owns expansion, clear/Escape and cancellable debounce. The host
supplies timing, labels and count formatting. Reset or return to the applied
trimmed query cancels obsolete work; IME preedit participates in live filtering.

`ChoiceState<T>` owns `ChoiceItem<T>` candidates, highlight, popup lifetime and
scrolling; hosts supply filtering, mapping, commit and dismissal. Select and editable
modes share navigation, but text/IME submission stays with Input. Closing releases candidates.
Callbacks and retained row presses belong to the candidate generation: replacement
or reopening invalidates them, while highlight movement does not. Page movement
uses rendered row height. `ChoiceSelect` binds select-only triggers to the owning
panel/menu's candidate state and handles keys before native Enter/Space activation
is armed. Editable text and IME remain separate owner policy.

Dialog and Popover provide materials, viewport constraints and modal pointer
barriers, not global surface state, draft protection or automatic outside-close
policy. Ordinary dialogs use a scrolling card; specialized surfaces can own
internal scrolling. FormField and label/value rows share presentation only.
NumericInput groups an existing editor with optional unit and step controls,
preserving owner-provided unit widths; callers retain parsing, validation,
formatting, drafts and submission.

==== Lists and scrolling

VirtualList accepts a logical count, stable identity, existing scroll handle and
range renderer. It neither owns records/selection nor fetches data. Only the
actual viewport requests demand; sample-row measurement does not. Sparse
placeholders retain logical indices and viewport decorations share content
coordinates with drop targets.

Shared list viewport shells retain horizontal clearance but no vertical inset:
scrollable content and edge fades meet the shell's top and bottom. Content-sized
playlist viewports therefore use row heights directly, without extra vertical
padding compensation.
Edge fades use their host surface color, including elevated Choice lists, without
changing popup borders or scroll geometry.

List, tree, dropdown and paged-loading rows require an explicit resolved height.
Range renderers resolve it once per batch and reuse it for records and placeholders,
keeping virtual-list measurement and visible row geometry on the same contract.

Deferred viewport delivery runs after paint, weakly holds its owner and may repeat
equal ranges so retry/new data need not await scrolling. Owners still check
visibility and query identity. Synchronous viewport observation is available for
side-effect-free use. Library's sparse tree, Albums' grid and History's columns
remain feature-owned; bounded heterogeneous review pages need not be virtualized.

The playlist-target menu has one logical cursor and one list focus stop. Arrow,
Page, Home and End move it into view; submission checks loaded row identity and
catalog revision without copying the catalog. New/Back remain ordinary stops.

Scrollable areas reuse owner-retained handles. Workspace owns panel/region
positions: hiding retains them, layout activation resets them. Settings/help and
ordinary Metadata/Playback scrolling keep their existing independent owners.
The scrollbar owns its element-local pointer gesture; exit or deactivation
cancels it. Geometry/handle replacement stops movement but consumes the pending
release so it cannot reach a row.

==== Progress and sliders

ProgressBar displays a normalized fraction; Slider adds pointer/keyboard intents
and disabled/focus presentation. Finite display values clamp to `[0, 1]` and
nonfinite values display as zero; application validation and step policy remain
host-owned. Disabled sliders reject activation and pointer-focus transfer.

The window arbitrates pointer sessions; Playback owns seek identity, preview and
commit/cancellation. Keyboard takeover cancels a live pointer session before
dispatch, preventing a later release from overwriting it. Transport buttons keep
circular backgrounds as typography changes. Volume appears in a hover hint or
an immediate tooltip-styled value during drag/focus, without taking layout space.
Pointer volume keeps one command in flight and replaces its single waiting target;
the slider shows that target until acknowledgement, and a volume key discards
an unsent pointer target rather than racing it.

==== Integration and showcase

The package uses this workspace's pinned GPUI revision and renderer patches. It is
not a renderer-independent API or a promise of compatibility with arbitrary GPUI
versions. `make lint` and `make build` include the component package;
`cargo test -p rivu-ui` runs its interaction and viewport regression tests.

Run `make ui-demo` (or `cargo run -p rivu-ui --example showcase --features showcase`)
on Wayland. This opt-in package example installs host appearance, retains controls
and subscriptions, and demonstrates filtering, choice, disabled controls and
error recovery without pretending to perform database/network work. It uses the
same pinned GPUI and normal build/font prerequisites. Font-size controls are
independent of interface scale, and the page scrolls at larger sizes.

Playback seek/volume drag transactions and Settings validation remain application
responsibilities; the package does not provide an automatic form submission,
query-retry, global overlay or slider-session framework.
