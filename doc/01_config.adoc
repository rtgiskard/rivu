= Configuration and layout
:toc:
:toclevels: 2

Rivu reads `~/.config/rivu/config.toml` by default (or the XDG configuration
directory); path overrides are described in link:../readme.adoc[the README].
A missing file uses defaults. The optional top-level `schema_version` defaults
to the current schema (`1`).
Omitted setting groups and fields use their defaults. Unreadable files, malformed
TOML, unknown keys, misplaced fields, unsupported explicit schema versions, and
invalid values are errors, not a reason to fall back to defaults.
Paths are literal: `~` and environment variables are not expanded.

Use Settings to change the running instance, then Apply to save. To edit TOML
directly, exit Rivu first, edit the file, and restart; the core does not watch
external edits. Configuration controls application-wide defaults. Panel trees
and instance preferences are saved separately in <<_layout,`layout.json`>>.

Configuration groups application settings into `[library]`, `[playback]`,
`[interface]`, `[logging]`, and `[visualizations]`. Global visualization controls
live in `[visualizations.general]`; `[visualizations.defaults]` seeds new panels.
Shared effect colors belong to `[visualizations.effects]`, shared energy-response
parameters to `[visualizations.reactive]`, and radial geometry and motion to
`[visualizations.radial]`. View-specific settings live in
`[visualizations.spectrum]`, `[visualizations.spectrogram]`,
`[visualizations.waveform]`, and `[visualizations.oscilloscope]`.
Album artwork settings live in `[interface.album_artwork]`; audio processing uses
the additional tables described under <<_audio_processing_defaults,Audio processing defaults>>.
Desktop integration belongs to Interface; output and decoding belong to Playback;
shared analysis belongs to Visualizations. Dotted names below identify file paths.

A minimal example (all omitted settings retain their defaults):

[source,toml]
----
[library]
roots = [] # Add music-directory paths before scanning

[playback]
volume_percent = 70

[interface]
font = "monospace"
font_size_pt = 12
theme = "rivu_dark"

[logging]
level = "warning"

[visualizations.general]
enabled = true
----


== Saving configuration

Rivu saves `config.toml` on Settings Apply, IPC Configure, accepted processing edits
(graph, Monitor EQ, presets/A/B, restoration or neural settings), and orderly exit.
Processing edits save immediately. Other controls, including playback, output,
visualization enablement, Waveform seeking, Library columns and folder changes,
update memory; the next save includes their current values. Closing the window
does not exit the core. A crash can lose changes since the last successful save.

Saves patch values changed since startup or the last successful save, preserving
untouched values, comments and formatting. Omitted defaults stay absent; explicitly
written defaults remain, and returning a field to its default writes it explicitly.
Clearing an optional setting removes its key. Changed arrays may be replaced as
a unit, including their internal comments and formatting. New files contain only
default overrides.

Unchanged configuration needs no write. Startup leaves an existing file untouched;
a missing file is created on the first save or orderly exit. Database and layout
persistence are independent of configuration saving.

=== Apply and validation

Apply retains the draft on validation or save failure; earlier runtime changes
remain active. Invalid text blocks Apply even in an inactive control: Settings
opens the affected page, and Reset field text restores only that field's accepted
value. Other edits remain intact. Edits made during Apply await the next Apply;
editing after success clears its notice.

Save failures appear in logs, `rivu status` and the desktop notice. Correct the
cause and retry; exit makes one final attempt. Atomic replacement prevents partial
writes, not power loss. An audio-application failure after a successful save does
not roll back the saved configuration.

=== File access and external editors

The configuration path must be valid UTF-8, including when derived from
`--data-dir`. Existing inputs must be ordinary files; symlinks to ordinary files
are accepted. Directories, devices, sockets, and FIFOs are rejected without waiting
for input. Configuration is limited to 4 MiB of UTF-8 TOML, including retained
comments and formatting; an oversized save leaves the existing file untouched.

Saving follows symlinks, including relative chains and missing targets, and
atomically replaces the target rather than the links. Link loops and inaccessible
targets are errors.

GUI and TUI changes share the host core. Separate hosts sharing a configuration
file and external editors are not coordinated: format preservation is not
conflict detection or a concurrent-edit merge. Exit Rivu before editing the file
manually, then restart to load the changes.

== Parameters

=== Library roots and scanning

`library.roots` defaults to an empty list; add existing directories before
scanning. `library.scan_max_depth` defaults to `64` and must be at least `1`.
`library.scan_min_duration_seconds` is an unsigned 32-bit integer in whole seconds,
defaulting to `0` (disabled). Both controls are in desktop Library settings.
See link:02_library.adoc#_minimum_duration_for_new_tracks[Minimum duration for new tracks]
for the admission policy, and link:02_library.adoc[Library] for roots, scan
boundaries, and CUE/path rules.

=== Browsing and keyboard navigation

`interface.query_batch_size` accepts `20`–`256` (default `64`) and tunes internal GUI/TUI
query batches, not visible pages or CLI listing/export batches. Browsing scrolls
continuously; query batch tuning stays in the configuration file, not desktop settings. Queue behavior is described in
link:04_playback.adoc#_queue[Playback]; query and batch contracts in
link:02_library.adoc#_paged_views[Library].

Long desktop lists support mouse-wheel scrolling and a draggable right-hand
scrollbar; click its track to jump. Edge fades indicate more content above or below.

==== Desktop keyboard navigation

Use `Tab` and `Shift+Tab` to move between enabled controls; a border marks focus.
`Enter` or `Space` activates a focused button, switch, or panel tab. Open a panel
tab's menu with `Shift+F10` or the Menu key.

In menus, `Up`/`Down` or `Tab`/`Shift+Tab` moves between available actions with
wraparound, and `Enter` chooses one. `Escape` or `Left` returns from a submenu
or closes the top-level menu without triggering playback shortcuts.

Open Shortcuts from the application menu to view desktop bindings;
`Escape` or the close button dismisses the list. `F1` and `?` do not open or close it.

Dialogs keep keyboard traversal inside their controls. In Settings, activate a
page button with `Enter`, then tab through fields and Apply/Discard.

Open dropdowns with `Enter` or `Space`; select with `Up`/`Down` or
`PageUp`/`PageDown`, then accept with `Enter` (`Space` also works in non-editable
dropdowns). `Tab`/`Shift+Tab` closes the dropdown and moves focus.

Editors and input methods retain their own keys. Successive `Escape` presses
cancel preedit, close a dropdown, leave the editor, then close the dialog.
Playback shortcuts apply to the layout, not focused editors or buttons.
Playback keys: link:04_playback.adoc#keyboard-controls[Keyboard controls].


=== Language

`interface.language` selects the GUI and tray presentation language: `auto`
(default), `en-US`, or `zh-CN`. Translations are embedded; no language pack
installation is needed.
`auto` uses the first nonempty `LC_ALL`, `LC_MESSAGES`, or `LANG` value, ignoring
encoding and modifier suffixes. English and Simplified Chinese are supported;
unavailable languages, including Traditional Chinese, fall back to English.
Explicit configuration values are `auto`, `en-US`, or `zh-CN` (case-insensitive;
underscores are accepted and normalized to hyphens); other values are errors.
Choose Language in Settings → Interface → Appearance & layout, then Apply to save.
The change takes effect when the graphical host restarts. Closing and reopening
a desktop window keeps the host's startup language; quit and restart Rivu to
apply a saved language change.
CLI output, TUI, command-line help, and localized diagnostics always use automatic
selection from the process environment, independently of `interface.language`.
They do not read configuration for localization. Starting a host or probing media
still loads and validates configuration for the operation itself.
Missing translations fall back to English. Configuration keys, command names,
machine-readable output, paths, and user metadata are not translated. Diagnostic
details may remain in English.

=== Decoding and read buffering

`playback.media_read_buffer_mib` defaults to `2`; accepted sizes are `1`, `2`, `4`, `8`,
and `16` MiB.

`playback.ffmpeg_enabled` defaults to `false`. The default build includes the `ffmpeg`
feature; see link:../readme.adoc[README] for a native-only build. Enabling permits
FFmpeg use on future source opens; it does not load or validate runtime libraries.
Libraries load on the first native-unsupported source in Auto mode, a track opened
with the FFmpeg decoder hint, or an explicit
link:02_library.adoc#_metadata_and_favorites[enhanced probe]. Missing libraries
are reported when needed; native decoders continue to work. A load failure is
retained until restart. Disabling stops a track currently decoded through FFmpeg;
native-decoded playback is unaffected.
Runtime availability updates when the first explicit load completes, including
loads initiated by GUI waveform work; an unused extension has no periodic status polling.

=== Volume and playback controls

[[volume]]
`playback.volume_percent` accepts a finite percentage from `0` to `100`, including
fractions, and defaults to `70`. Zero mutes; positive values use a dB-linear
control curve: gain in dB is `0.6 * (percent - 100)`. Thus 50% is -30 dB and
100% is unity gain (no amplification). This approximates uniform perceived
steps; it does not normalize loudness between tracks.
Settings accept fractional percentages; CLI inputs remain integer percentages.
Slider, IPC, and MPRIS values use the same curve, with normalized `0–1` levels
for IPC and MPRIS. Values are not rounded to whole percentages internally.

`playback.shuffle` defaults to `false`; `playback.repeat` accepts `off`, `all`, or `one` and defaults
to `off`. `playback.play_count_threshold_percent` defaults to `20` and must be finite and
in `[0, 100)`; zero still requires some confirmed heard time. Edit the threshold
in the configuration file or desktop settings; see
link:02_library.adoc#_play_counts_and_recent_tracks[Library] for counting semantics.

`interface.confirm_queue_replace` defaults to `true`. In the GUI, album and playlist
actions that replace a non-empty queue ask for confirmation. Disable it in desktop
settings under Playback & Audio → Playback to replace the queue without prompting.
This preference does not change TUI, CLI, or IPC behavior.


=== Output and desktop integration

Output selection and application errors are described under
<<_output_and_applying_changes,Output and applying changes>> and in
link:04_playback.adoc#_output_devices_and_speaker_layouts[Playback output].
`interface.tray_enabled` and `interface.mpris_enabled` both default to `true` and
independently control desktop integration. Tray changes require a graphical-host
restart; MPRIS changes apply while running. Requirements and recovery are in
link:04_playback.adoc#_desktop_tray_and_window_lifecycle[Desktop tray and window lifecycle]
and link:04_playback.adoc#_mpris_and_artwork[MPRIS and artwork].

=== Logging and diagnostics

`logging.level` accepts `debug`, `info`, `warning` (default), or `error` and
controls file logging. By default, stderr receives warnings and errors.
Global `--log-level LEVEL` overrides stderr and enabled file logging for this
process's lifetime.

`logging.to_file` defaults to `false`; enabling it writes weekly logs under the
data directory. `logging.retention_weeks` accepts `1`–`520` and defaults to `4`.
`NO_COLOR` or `RIVU_COLOR=never` disables stderr colors.

File logging starts after configuration is loaded. Records may be dropped under
load; forced termination can lose pending records.

=== Audio processing defaults

Audio processing additionally uses top-level `[equalizer]`, `[denoise]`, and
`[neural]` tables, `[[equalizer.bands]]`, named `[[equalizer_presets]]`, and an
optional `[equalizer_ab]`. The processing DAG, including node-local parameters,
connections and canvas positions, lives in `[processing_graph]` and its nested
arrays. These are core settings in `config.toml`, not preferences in `layout.json`.
The default graph connects Source directly to Output; the top-level Monitor EQ
and restoration/neural defaults do not implicitly insert graph nodes.
Unknown fields are rejected throughout the graph, including node-kind settings,
node-local EQ/restoration/neural configuration, edges, ports, and noise selections;
they are not silently ignored. Use the documented field names when editing TOML.

For example, the following sets Monitor EQ and restoration/neural defaults; it
does not construct a processing graph:

[source,toml]
----
[equalizer]
enabled = true
preamp_db = -3.0
output_gain_db = 0.0

[[equalizer.bands]]
kind = "peak"
frequency_hz = 1200.0
gain_db = 3.0
q = 0.8

[denoise]
mode = "adaptive"
strength = 1.0
spectral_gain_floor_db = -18.0
wet = 0.8

[neural]
worker = "/absolute/model-bundle/runtime/worker.py"
speech_interpreter = "/absolute/.venv/bin/python"
speech_manifest = "/absolute/moss-bundle/manifest.json"
separation_interpreter = "/absolute/.venv/bin/python"
separation_manifest = "/absolute/kim-bundle/manifest.json"
device = "cpu"
threads = 4
----

Replace paths with preparation output; no shell expansion occurs. Missing
manifests leave neural operations unavailable, not automatically downloaded.
See link:27_audio_processing.adoc[Audio processing] for graph editing, filter
semantics, shared and isolated Python environments, licensing, CLI examples and bounds.

== Desktop settings

Settings groups Library, Playback & Audio, Interface, and Visualizations.
Interface uses one scrollable page; Visualizations has General and style-specific
pages. General separates Appearance from Frequency analysis. New-panel defaults
affect only subsequently created instances. Sidebar groups scroll when needed;
hover truncated labels, fields and errors for their full text, accepted ranges
and application timing. Errors also provide Copy. See
<<_desktop_keyboard_navigation,Desktop keyboard navigation>> for dropdown controls.

Add folders from Library; Settings lists them individually for removal. Paths are
literal, not delimited text, and retain semicolons and trailing spaces. Removal
changes only the draft until Apply. Empty field hints are not submitted values;
clearing an optional numeric override restores inheritance on Apply. Untouched
numbers retain their TOML precision even if Settings displays fewer decimal places.

Settings keeps a baseline and draft. Apply merges edited fields into the latest
configuration, preserving unrelated changes from other controls and clients.
An edited field wins over a concurrent change to that field; folder edits replace
the roots list. Media read buffering affects future opens, including waveform
scans, without reopening the current track. The application-menu Visualizations
toggle applies immediately; see <<_visualization_enablement,Visualization enablement>>.

While Apply is pending, later edits remain for the next submission and the editor
cannot close. After completion, Discard closes it and drops unsubmitted edits.
Completions from a replaced session cannot alter its successor. Save failures and
saved-but-audio-failed behavior are in <<_saving_configuration,Saving configuration>>.

Interface → Layout includes Layout snapping and Layout grid spacing. These save
`interface.layout_snap_enabled` (default `true`) and `interface.layout_snap_grid_px` (default `16`,
integer `1`–`64` logical pixels before interface scaling) in `config.toml`.

Library → Covers & cache includes Encoded cover file limit (MiB), saved as
`interface.artwork_file_limit_mib`: an integer from `1` to `64`, default `16`.
It limits each encoded embedded or directory image, not its decoded memory.
Apply saves the value; restart the entire application, including its core, to use
the new limit. Closing and reopening only the window does not apply it.

Library → Covers & cache includes Cover decode budget (MiB per cover), saved as
`interface.artwork_decode_budget_mib`: an integer from `1` to `1024`, default `64`.
It limits the retained decoded frames of each cover, not total process or GPU
memory. Different covers and windows add their own costs. Apply re-evaluates open
covers, including previously rejected images; an over-budget image shows the
default cover rather than a partial animation. Increasing the budget does not
remove other image-admission limits. See
link:22_cache.adoc#_artwork_lookup_retention[Artwork resource boundaries].


Interface → Album artwork sets new-panel style, mode, period and direction;
animation FPS remains shared. Existing panels use their own right-click Artwork
settings editor. Static mode retains rotation parameters.

=== Appearance and library display

`interface.theme` in `config.toml` selects the shared desktop and terminal theme.
Presets are built in; no separate theme files are needed. Choose Theme in
Settings → Interface → Appearance & layout, then Apply to save and update open
clients without restarting. Choosing a theme only edits the settings draft;
Discard leaves the active theme unchanged. Editing the configuration file takes
effect when starting the core; the running core does not watch the file.

[cols="1,2"]
|===
|Theme |Accepted value
|Rivu Dark (default) |`rivu_dark`
|Tokyo Night |`tokyo_night`
|Tokyo Night Day |`tokyo_night_day`
|===

Rivu Dark is a blue-gray preset; Tokyo Night Day is a light theme. The Tokyo Night
presets adapt https://github.com/folke/tokyonight.nvim[Tokyo Night]. Unknown names
are configuration errors; other applications' theme files are not imported.
Themes do not change visualization backgrounds, signal palettes, canvas labels,
cursor colors, or album artwork.

Search or browse installed fonts in Settings, including `monospace`, `sans-serif`,
and `serif`. Enter or click to select; custom family names are accepted.
The empty field identifies the `monospace` fallback; hover for font-search guidance.

`interface.font` defaults to `monospace`, including empty values. Names must not
contain control characters or exceed 128 UTF-8 bytes. Fontconfig system and user
rules (`~/.config/fontconfig/fonts.conf`) select families and missing-glyph
fallbacks. Restart the GUI after changing those rules. Unavailable primary fonts
produce a warning and fall back to `sans-serif`.

Fontconfig hinting, subpixel, and synthetic-bold settings do not control GUI
rendering. Complex shaping and named variable-font instances may differ from
other applications.

`interface.font_size_pt` accepts integer point sizes from `8` to `18`, default `12`
(16 logical pixels before interface scaling). Apply to update open windows.
It adjusts desktop text and icon glyphs, not plot annotations or terminal text,
and is independent of `interface.scale`.

`interface.scale` accepts finite values from `0.75` to `2.0` (default `1.0`) and
adjusts desktop controls and list density independently of the desktop's display scaling. Menus and editor dialogs
stay within the window; scroll them when not all content fits. Settings dropdowns
close when their control moves or the interface scale changes; reopen them at
the new position.
GUI icons use the system-installed Symbols Nerd Font Mono independently of
`interface.font`. The optional `embed-nerd-font` Cargo feature embeds a build-host font;
see link:../readme.adoc[build instructions] for requirements and licensing.
The TUI requires a Nerd Font or Nerd Symbols fallback in the displaying terminal.
For SSH, configure the local client terminal; installing fonts on the server
does not supply terminal glyphs. Missing glyphs can appear as boxes or blanks.
Use the Mono variant of Symbols Nerd Font for single-cell icons. The TUI shares
`interface.theme`, but its width-dependent information columns are built in;
desktop font, scale, and Library column settings do not configure the terminal client. See
link:04_playback.adoc#_terminal_client[Terminal client] for browsing and full details.

`interface.library_columns` selects desktop Library information columns. Its
boolean keys are `artist`, `album`, `duration`, `codec`, and `bitrate`;
`duration` and `codec` default to `true`. Omitted keys retain those defaults; set all five
to `false` for names only. Change them without restarting from the Library
right-click menu → `Track information`. Both Library views share the saved
selection; full tooltip information is unaffected. See
link:02_library.adoc#_desktop_selection_and_directory_tree[Library display].

=== Output and applying changes

`playback.output_device` selects the default PipeWire sink when omitted, or an
exact name from `rivu playback devices`. `playback.pipewire_auto_mix` defaults to
`true`; disable it to require a compatible speaker layout without remixing.
Selection syntax, unavailable-device recovery, output rebuilding, normalization,
and source-rate negotiation are documented in
link:04_playback.adoc#_output_devices_and_speaker_layouts[Playback output].

Apply validates and saves the settings draft across all four sidebar groups together;
navigation preserves the draft and each page's scroll position. An unavailable
output target can be saved; applying it reports an audio error and can stop
playback while retaining the saved selection. Draft merging, Discard, and error
handling follow the <<_desktop_settings,Desktop settings>> rules.
Artwork instance settings apply only the selected panel's style, mode, period
and direction to the in-memory layout. They do not request a `layout.json` write;
use layout sync or orderly exit to persist them. Applying fails if the instance
no longer exists. Visualization panels expose their local style, reference lines
and labels directly in the right-click menu; Oscilloscope also offers Overlay channels.
Inactive Spectrum fields retain their values and are still validated by Apply.
If a retained value is invalid, open Visualizations → Spectrum: choose a Style
other than Solid to edit the active bar-layout value or gap, or enable Peak markers to
edit marker hold or gravity. Correct the value, then restore the desired style
or toggle and apply again. Disabling a field does not discard or repair its value.

Saving library roots does not scan or enqueue tracks; use `Scan paths` in Library.
Each folder entry shows its recursive catalog track count and audio file size in
IEC units. Sizes use existing scanned metadata, not a filesystem traversal or
disk-usage measurement. Missing tracks retain their last scanned size; CUE
segments count as tracks while their shared source path contributes bytes once.
Separate source paths count separately even when their content is identical.
Unscanned folders show zero after loading. Statistics load asynchronously when
Settings opens and refresh after catalog changes or draft-root changes. Removing
a root changes the draft only; Discard restores the saved roots.

Display-only changes do not reopen audio. Hover an error to read its complete
message, or click its copy icon to copy it.

See link:../readme.adoc[README] for application lifecycle and host behavior.

=== Artwork cache maintenance

Settings → Library → Covers & cache also provides manual maintenance of encoded
cover files on disk. Enter a positive whole number in `Expire files older than (days)`
(initially 30), then choose `Calculate usage` or `Clean expired`. Neither opening
Settings nor starting Rivu scans this directory. These actions run immediately
in the background, do not require Apply, and are not undone by Discard.

The report shows file counts and encoded bytes for total usage, expired
candidates, protected files, successful removals, and failures. Cleanup totals
describe usage before deletion. Age is based on file modification time, not
recent playback; reusing a file does not update its age. Resident lookup results
protect their files, including results still used by GUI or MPRIS. Protected
files are skipped even when expired; the bundled icon and audio files are never
removed. A removed cover is regenerated on demand.

Usage and cleanup include generated thumbnails, which can be regenerated without
removing the original cover. Maintenance handles only managed cache files; it
does not follow symlinks or scan arbitrary subdirectories.

Inspect reported errors and retry after fixing access or permissions. Maintenance
has no automatic schedule or total-capacity guarantee, and the age input is not
saved to `config.toml`. Ownership and retention rationale are documented in
link:22_cache.adoc#_artwork_lookup_retention[Artwork lookup retention].


=== Album artwork

The `Album artwork` panel (`album_artwork` in layout files) follows
the current playback track independently of Metadata. Its configuration is:

[source,toml]
----
[interface.album_artwork]
style = "halo"
mode = "rotating"
period_seconds = 20.0
direction = "clockwise"
fps = 0
----

`style` accepts `plain`, `vinyl`, `glass`, `halo` (default), `metal`, `card`, or
`duotone` and supplies the initial style for new panels. Each panel saves style,
mode, period, and direction in the layout. Its right-click Style and Rotation
actions affect only that panel; Artwork settings edits all four instance options.
Saved panels missing options initialize from the current defaults. All styles
support static and rotating modes; changing style preserves the rotation angle.
`mode` accepts `static` or `rotating` (default). `period_seconds` is the time
for one full circle and must be finite and greater than zero; there is no
additional upper limit. `direction` accepts `clockwise` (default) or
`counterclockwise`. `fps` is an integer from 0 through 240 (default 0): zero
follows display callbacks without timer throttling; a positive value caps
animation requests per second. Lower caps reduce rendering work and resource
use at the cost of less smooth motion; zero can render more frequently on
high-refresh displays. Changing the cap preserves the angle. All Album artwork
panels share only frame rate; the analysis rate is independent. Mode, period, and
direction in this configuration supply defaults for new panels, not live overrides.
Playback-driven rotation and animated source covers have separate clocks but
share this FPS cap. Their pause, hiding, track-change, and visualization-enable behavior is
documented in link:04_playback.adoc#_album_artwork_panel[Album artwork panel].
Track details' full, static preview does not use the Album artwork FPS cap.


== Layout

`layout.json` in the data directory stores named panel trees, sizes, tabs and
instance preferences, plus the selected layout. Locks are window-local; each
newly opened window starts locked. Layouts do not contain separate browsing or
editing sessions. Switching keeps playback, queue, global settings, window
placement and the Track details draft.

Open `Menu > Layouts` to switch, duplicate, rename or delete layouts. Names must
be nonempty and unique after trimming. To delete the active layout, switch first;
at least one layout must remain. Hover a row or Tab to its Delete button to reveal
the action. Finish or discard Settings edits before switching; Escape closes
the manager. `Default` sorts first when present, followed by names in name order.

Without a saved collection, Rivu supplies editable `Default`, `Album` and `Visual`
templates. Default combines browsing, Queue, Track details, cover art, Spectrum
and playback controls; Album emphasizes albums and artwork, Visual the audio
visualizations. Duplicate the active layout to create another. Renamed or deleted
templates are not restored on restart.

Edits, panel-settings Apply and layout selection update session memory. Use
Sync layouts to file beside Rename to persist the collection, or quit orderly.
Window close/reopen preserves session layouts without writing; an abnormal exit
loses unsynced changes. Sync cancels drag/resize previews and captures the current
collection; later edits require another sync. Progress and completion appear in
the manager. Failure preserves the file and session edits and appears there or,
after closing it, in the footer. Press Sync to retry; ordinary edits do not retry.

Sync and orderly exit skip unchanged valid content and initialize a missing file.
If an existing file cannot load, Rivu reports the error and uses defaults, preserving
the failed input until explicit Sync authorizes replacement. Exit before external
file edits: layouts load once per GUI session and saves do not merge outside changes.

Unlock with the bottom-right layout button's context menu to add, remove, move,
resize or reorder panels. Left-click opens the catalog: drag an item onto the
workspace, including an empty workspace, to add it. Clicks and keyboard activation
do not insert panels. Playback, tab selection, layout management and the panel
context menu's tab-bar toggle remain available while locked; separators are inert.

Drag a panel to an edge to split its region, its center to merge tabs, or a visible
tab bar to reorder/transfer tabs; the unused tail appends. The shaded preview marks
the committed destination. An invalid drop or `Cannot dock here` leaves the tree
unchanged. Escape, deactivation, menus/dialogs or locking cancel a panel drag;
after resize or scale changes, wait for a fresh preview before dropping.

Separator drags resize their two neighboring regions; removing a region gives its
space to a neighbor without changing other sizes. Escape, deactivation, resize
or scale changes cancel a separator drag and restore its starting proportions.
Queue-entry drags never dock panels.

Snapping aligns separators with other separators, equal pane sizes or the configured
grid while respecting minimum sizes. Hold Alt to invert snapping for that gesture.
Layouts permit at most 32 splits along a path; tab groups do not count, and there
is no sibling/tab-count limit. A drop exceeding the depth limit changes nothing.

Layout input must be a regular file; FIFOs, including symlink targets, are rejected
without waiting. Invalid names and operations leave the UI unchanged. Geometry,
persistence and editing invariants are in link:24_layout.adoc[Desktop Layout Design].

The footer reports application errors, with Copy for full text and Dismiss for
errors; media-task progress stays in its Library, Queue or Playlists panel.
Drag empty footer space with the left button to move the window; text and controls
do not start a move. Open menus or dialogs disable footer dragging.


=== Layout file

`active` names an entry in the nonempty `layouts` object. Each entry requires
`root`; `null` means an empty layout. Lock state is not stored; each newly opened
window starts locked.

[source,json]
----
{
  "active": "Work",
  "layouts": {
    "Work": {
      "root": {
        "type": "split",
        "axis": "horizontal",
        "children": [
          {"type": "tabs", "panels": [{"kind": "library"}]},
          {"type": "tabs", "panels": [{"kind": "queue"}]},
          {"type": "tabs", "panels": [{"kind": "audio_visualizer", "style": "waveform", "reference_lines": false, "labels": false}]}
        ]
      }
    }
  }
}
----

`horizontal` orders children left to right; `vertical` orders them top to bottom.
Children are direct node objects, not wrappers. An omitted or empty `boundaries`
array divides the content equally, as in the example. To give the first pane
half the content and each remaining pane a quarter, add
`"boundaries": [0.5, 0.75]` beside `children`. Explicit boundaries must contain
exactly one fewer value than children, all finite, strictly increasing, and
strictly between `0` and `1`. They are cumulative fractions of pane content
length, excluding separator gutters, not weights or fractions of adjacent panes.
Splits require at least two children and cannot directly contain a split in the
same direction. At most 32 splits may occur along any root-to-leaf path; tabs
do not count toward this limit.
Configuration remains TOML; layout persistence remains JSON.

`tabs` requires a nonempty `panels` array. Its optional `active` is a zero-based
index, defaulting to `0`. Panel objects require `kind`; `show_tab_bar` defaults to
`true`. Audio Visualizer objects additionally store `style`, `reference_lines`,
and `labels` directly in the panel object. These three fields must be supplied
together or omitted together; omission initializes the instance from global
defaults when that layout is opened. The optional `oscilloscope_overlay_channels`
boolean selects Overlay channels; when the three fields are supplied but this flag
is absent, it defaults to `false` (separate channels). Initialized panels save
all four choices explicitly. The mode flag requires the three visualizer fields
and is valid only on `audio_visualizer` panels. Unknown fields, invalid structures,
and out-of-range indices are errors.

The catalog's `kind` values are `transport` (Playback), `library`, `albums`,
`queue`, `playlists`, `history` (Recent tracks), `metadata` (Track details),
`album_artwork`, `audio_visualizer` (Visualization), and `audio_processing`.
Spectrum, Spectrogram, and Waveform are styles of `audio_visualizer`, not separate
panel kinds. Unknown kind strings are retained and show an unknown-panel message;
they do not create a custom panel implementation.

An Album artwork panel can additionally contain an `album_artwork` object with
all four keys: `style`, `mode`, `period_seconds`, and `direction`. For example:

[source,json]
----
{"kind": "album_artwork", "show_tab_bar": false, "album_artwork": {
  "style": "halo", "mode": "rotating", "period_seconds": 20.0,
  "direction": "clockwise"
}}
----

The values use the same enums and positive finite period as
<<_album_artwork,Album artwork>>. Omit the whole object to initialize from global
defaults when that layout is opened; partial objects and `null` are invalid.
The object belongs only to `album_artwork` panels, just as the visualizer options
belong only to `audio_visualizer` panels. Animation FPS remains global.


== Visualizations

Live analysis requires playback, enabled visualizations, and a visible live-analysis
style. Waveform instead uses progressive decoding or an explicitly requested
track preview. Analysis and presentation have independent rates:

[cols="2,1,3",options="header"]
|===
|`visualizations.general.*` key |Range / default |Controls
|`analysis_rate_hz`
|`5`–`60` / `28`
|Maximum FFT transform and publication rate, not PCM ingestion or animation.
|`animation_fps`
|`0`–`240` / `0`
|Spectrum, Spectrogram, and Audio Visualizer display cadence. `0` follows native
window frames; positive values cap updates per second. Waveform and album artwork
are independent.
|===

Set Animation FPS under Settings → Visualizations → General → Appearance;
Analysis rate is in Frequency analysis. Spectrum release, Spectrogram scrolling,
radial motion, and generative light can advance between analysis publications,
but display time never advances beyond accepted audio. Stereo Density and Spatial
Spectrum use the latest result rather than replaying skipped publications.

Pause freezes the last displayed frame without running analysis or audio-driven
animation. Stop retires analysis results; the optional radial idle fade may keep
the last drawing briefly. Seek, source replacement, incompatible analysis settings,
and disabling visualizations clear stale results even while hidden or paused.

Inactive tabs and reliably reported hidden windows suspend their demand, retaining
the last drawing until fresh audio is ready without replaying hidden time.
Switching one panel does not interrupt other visible views; losing focus alone
does not suspend analysis. If the platform does not report visibility reliably,
compositor throttling can slow animation while the independent analysis timer
continues. Closing the window releases its presentation; reopening does not
restore old frames. Waveform keeps its track preview when hidden but discards it
when visualizations are disabled. Scheduling and continuity details are in
link:23_visuals.adoc#_presentation_scheduling_and_visibility[Presentation scheduling and visibility].

`visualizations.general.palette` accepts `tokyo_night` or `deadbeef` (default `deadbeef`).
Color settings use quoted `"#RRGGBB"` values.

Visualization caches are always enabled within their resource bounds. Spectrum
reuses frequency mappings but rebuilds its body on each panel render. Rendering
reuse and resource budgets are described in
link:22_cache.adoc#_visualization_caching[Visualization caching]; signal and
rendering design in link:23_visuals.adoc[Visualization Rendering Design].

Before audio data is available, visualization panels show no waiting message;
their backgrounds and any applicable reference guides remain. Loading, failure,
disabled-state icons, and unavailable frequency-data messages remain distinct from this
normal initial state.

Shared visualization settings apply as follows:

* `visualizations.general.signal` selects one shared signal for all audio-data views:
  `"before"` is before the active realtime processing chain; `"after"` (default)
  includes the active chain and monitor EQ. Both are before master volume.
  Change it under Visualizations → General → Appearance. Analysis runs
  asynchronously; strict audio/visual synchronization is not guaranteed.
  Changing the signal resets realtime analysis history, but does not clear the
  rolling waveform or automatically start a full waveform scan. Equalizer changes
  preserve realtime history; newly visited waveform intervals replace their old data.
  An explicit full waveform scan snapshots the selected signal and processing when
  requested, keeping the displayed waveform until results are available.

* `visualizations.general.background` sets the background for all views (default
  `"#08090C"`); `visualizations.general.palette` is shared by Spectrum, Spectrogram, and
  Waveform. The radial, stereo-analysis, fractal, and Oscilloscope styles use
  the Audio Visualizer primary and secondary colors.
* `visualizations.general.db_range` supplies the display span for Spectrum, Spectrogram,
  and the radial/stereo/fractal styles unless their settings override it. It does
  not affect Waveform gain, Oscilloscope amplitude, or volume.
* `visualizations.general.analysis_fft_size`, `visualizations.general.analysis_window`, and
  `visualizations.general.analysis_rate_hz` apply to live-analysis styles, not Waveform.
  Oscilloscope uses unwindowed PCM bounded by the selected FFT size.
  FFT size accepts powers of two from `512` to `32768` and defaults to `8192`.
  Window accepts `hann`, `blackman_harris` (default), or `none`.
  Changing size or window clears visualization history.
  Changing only the analysis rate preserves compatible visualization content and
  the current analysis window. Small FFT windows at low rates can miss short
  transients; increasing animation FPS cannot recover unobserved audio.
* Disabling visualizations stops visualization processing and discards results; see <<_visualization_enablement,Visualization enablement>>.
  This is independent of rendering reuse and media read buffering.
  In Settings → Visualizations → General → Appearance, its switch sits
  below the shared material-cache budget.

Each frequency view has a range override; leave it empty to inherit General,
or clear an explicit value to restore inheritance. See
<<_visualization_db_ranges,Visualization dB ranges>> for the configuration contract.

Settings → Visualizations groups shared controls, shared effects, and New panel
defaults under General, with separate pages for view-specific controls. General
has one shared editor for the colors used by radial, stereo-analysis, fractal, and
Oscilloscope styles, one range override
for radial, stereo-analysis, and fractal styles, and sensitivity and Bloom for
radial and fractal styles. These are shared values, not separate preferences per
view. View-specific pages contain only independent parameters.

Style, reference lines, and labels under New panel defaults affect new panels only;
existing panels retain their layout-local choices. See
<<_audio_visualizer,Audio Visualizer>> for panel settings and style-specific effects.
Inactive Spectrum style-dependent settings retain their values.

=== Visualization enablement

`visualizations.general.enabled` defaults to `true`. Disabling it
replaces audio-visualizer content with a large centered snowflake icon, stops
analysis sampling and FFT work, and discards all visualization results.
The Settings snowflake toggle is active when visualizations are disabled.
Progressive waveform collection stops; any running full-waveform request is
cancelled, and new requests are unavailable.

Playback, seeking through the playback slider, ordinary interface effects,
library operations, covers and their animation, IPC, MPRIS, and the tray are unchanged.
Layout and visualization settings are preserved.

Re-enabling visualizations starts the visible views fresh, without reopening audio
output or the decoder. Views rebuild from new audio; enabling while
paused does not restore an old picture. Waveform starts
accumulating from subsequently decoded PCM, with discarded and skipped intervals
left blank. An interrupted traversal is not marked complete. Full-waveform
requests do not restart automatically; request one explicitly after re-enabling
if needed. Ordinary playback pause remains different: it freezes the current
visualizations without discarding their results.

=== Visualization dB ranges

`visualizations.general.db_range` defaults to `70` dB. The optional
`visualizations.spectrum.db_range` and `visualizations.spectrogram.db_range` override
their respective views. `visualizations.reactive.db_range` is shared by radial,
stereo-analysis, and fractal styles. Every supplied range must be finite and
between `1` and `160` dB, inclusive. An explicit override remains an override even
if it equals the shared default; changing General later affects only views without
overrides.

In TOML, omit a view's override key to inherit the shared default. Do not write an empty
string or a blank assignment: overrides are numeric when present. Saving an
inherited range omits that override key.

[source,toml]
----
[visualizations.general]
db_range = 80.0

[visualizations.spectrum]
db_range = 60.0

[visualizations.reactive]
db_range = 100.0
# visualizations.spectrogram.db_range is omitted, so Spectrogram uses 80 dB
----

These ranges affect display mapping only, not FFT analysis, decoded audio,
playback volume, or Waveform's RMS/Peak gains. Spectrogram recolors retained
history without discarding it. Changing an unused shared default or setting an
override equal to the current resolved value leaves the display unchanged.

=== Waveform

Waveform shows a whole-track timeline, relative to the subtrack for CUE. Left is
above the centerline, right below; the filled body is RMS amplitude and the outer
line is peak amplitude. Unknown intervals remain blank. Playback builds the
preview progressively; `Load full waveform now` requests the complete preview.
Click or drag to seek the current track; a non-playing selection preview does
not seek playback.
Seeking gestures stay bound to the queue entry at press time. If playback moves
to another entry before release, the old gesture cannot seek the new entry.
Escape or a geometry change cancels the gesture without seeking.
To preview a track without starting playback, select it in Library and use
`Load full waveform now`. A selected track with no decoded samples can also
build its preview through playback.

`visualizations.waveform.seek_enabled` defaults to `true`. Disable Click and drag to seek in
the Waveform settings page or its panel right-click menu to prevent accidental
seeks. Disabling it cancels any active waveform drag and preview; the playback
slider remains available.

RMS uses a center-to-edge palette gradient; Peak uses the palette color at its
level. Known silence remains visible as a minimum-height RMS fill; unknown
intervals stay blank.

Waveform time labels follow the instance's Labels option. Their default for new
panels is `visualizations.defaults.labels` (`false`).
`cursor_color` defaults to `"#73DACA"`; `glow` accepts `0`–`2`, default `1.0`.
Amplitude settings are:

[cols="2,1,1",options="header"]
|===
|`visualizations.waveform.*` key |Range |Default
|`rms_gain` |0–3 |0.94
|`peak_gain` |0–2 |1.0
|`peak_gamma` |0.25–3 |2.0
|===

Gamma above `1` reduces low peaks; below `1` lifts them. These settings affect
rendering only, not playback volume or decoded preview data.

=== Spectrum and Spectrogram

Spectrum shows current frequency energy. `visualizations.spectrum.style` accepts `bars`,
`outline`, `led`, `line`, or `solid` (default `solid`). Motion freezes while paused.
Bar layout has two exclusive modes. Automatic mode derives the number of bands
from the panel width, requested bar width (`1`–`20` logical pixels), and gap:

[source,toml]
----
[visualizations.spectrum]
bar_layout = { mode = "automatic", width = 3.0 }
----

This is the default layout. For a fixed count, use
`bar_layout = { mode = "fixed", count = 64 }`; `count` accepts `1`–`512`.
Only the selected mode's parameter is allowed. Solid derives its slots from
drawable logical-pixel width, up to the renderer's slot limit, and ignores bar layout and gap.

In desktop settings, correct an invalid active value before switching layout
modes. Switching initializes the new mode to a width of `3.0` or a count of `64`.

The remaining `visualizations.spectrum.*` settings are:

[cols="2,2,1",options="header"]
|===
|Key |Range or meaning |Default
|`gap` |`0`–`8` pixels |`1.0`
|`peaks` |Show discrete peak markers |`true`
|`peak_hold_ms` |`0`–`2000` ms |`400`
|`peak_gravity` |`0`–`500` dB/s² |`50.0`
|`bar_hold_ms` |`0`–`2000` ms |`0`
|`bar_gravity` |`0`–`500` dB/s² |`400.0`
|`smoothing_ms` |`0`–`1000` ms |`80`
|===

Zero gravity snaps to the current level after hold; it does not hold peaks forever.
Display range inheritance is described in <<_visualization_db_ranges,Visualization dB ranges>>.

`visualizations.spectrum.interpolate` defaults to `false` and controls frequency interpolation and whether `solid` has a
continuous or stepped boundary. `line` always connects valid body points
continuously and skips empty slots rather than drawing them at the floor.
Peak indicators remain discrete in every style.

Spectrogram shows recent frequency history at a fixed audio-time scale. New audio
enters at the right; startup and unavailable history remain blank rather than
stretching the available audio across the panel.
Its `visualizations.spectrogram.*` settings include:

* `interpolate`: default `true`; controls interpolation between source rows.
* `history_seconds`: `1`–`60`, default `20`; sets the displayed audio-time span.

Spectrogram uses the full non-DC FFT bins rather than semitone display bands.
Frequency rows and time buckets preserve peaks when multiple source values map
to one display cell. Sampling follows physical panel pixels and available FFT
detail, bounded by internal resource limits and the shared material budget.
Interpolation does not change FFT size or create measured frequency detail.

[source,toml]
----
[visualizations.spectrogram]
history_seconds = 20
----

`interface.gpu_material_budget_mib` accepts `16`–`1024` MiB, default `64`. Change it
under Settings → Visualizations → General → Appearance, then restart the
GUI. It limits shared material buffers per window, not total GPU memory.
Long Spectrogram histories may use fewer frequency rows to fit this budget;
time resolution and playback audio are unchanged. See
link:22_cache.adoc#_visualization_caching[Visualization caching] for resource scope.
Both views use a logarithmic frequency axis and share `visualizations.general.analysis_fft_size` and
`visualizations.general.analysis_window`. Their independent `visualizations.spectrum.db_range` and
`visualizations.spectrogram.db_range` overrides inherit `visualizations.general.db_range` when omitted;
see <<_visualization_db_ranges,Visualization dB ranges>>.

=== Audio Visualizer

Every Visualization panel uses the `audio_visualizer` kind and stores its style,
reference-line visibility, and label visibility in `layout.json`. Right-click an
instance and open `Visualizer style` to choose a style; its tab title, tooltip,
and drag title follow that choice. `Back` returns without changing it. The main
menu starts with style selection. The second group contains `Reference lines`,
`Labels`, and style-specific actions; a checkmark means enabled. Choosing a style
or toggling an overlay closes the menu.
Moving panels preserves their choices; layout sync or orderly exit persists them
across restarts. Different styles can run simultaneously. Global
`visualizations.defaults.style`, `visualizations.defaults.reference_lines`, and
`visualizations.defaults.labels` seed new panels only. Style defaults to `bars_rings`;
both overlay defaults are `false`.

Reference lines and labels are independently optional. Radial guides show
normalized bar levels; analysis views use their measured axes; fractal guides
show normalized scene coordinates, not audio measurements. Small views omit
labels that would overlap. Eleven styles are available:

* `spectrum`, `spectrogram`, and `waveform` use the views described above, with
  the same instance-local overlay choices as the other styles.
* `bars`, `rings`, and `bars_rings` use the radial Spectrum presentation.
  Rotation, bar width/glow, ring opacity, inner diameter, and idle fade apply
  to these styles only. Sensitivity and Bloom also affect the fractal styles.
* `stereo_density` shows a Mid/Side occupancy field: horizontal Side `(L−R)/2`,
  vertical Mid `(L+R)/2`, both fixed at ±1 without automatic gain. Equal channels
  form a vertical trace; opposite channels form a horizontal trace. Its readout
  reports correlation, left/right energy balance, and the Side share of energy
  over the current FFT window. Correlation is undefined for silence or a silent
  channel. Color represents decaying sample occupancy in dB, not audio dBFS.
* `spatial_spectrum` shows logarithmic frequency vertically and left/right
  energy balance horizontally, with color representing frequency-bin power in
  dBFS. Equal-energy channels appear at the center even when their phases differ;
  this is not a source-direction or phase measurement.
* `fractal_beams` maps low-frequency energy to branch length, mids to bending,
  and highs to fine-branch intensity. Energy rises launch outward pulses;
  these are not detected beats.
* `fractal_flow` maps low, mid, and high energy to filament motion;
  energy rises brighten the trails.
* `oscilloscope` displays unwindowed stereo PCM using the primary and secondary
  colors as solid traces. By default, channels are separate, with left above
  right. Enabling Overlay channels draws both traces on the same time and amplitude axes.
  A rising zero crossing on the left triggers a configured sweep; right-only
  audio triggers on the right. Short FFT windows show the available half-window.
  Reference lines mark channel centers and visible amplitude limits. Dashed
  vertical guides divide the time axis into ten equal intervals; in Separate
  mode, each channel has its own guides that do not cross the inter-channel gap.
  Labels show channel order as `L / R` in every language, input amplitude limits,
  and the actual source-sample duration.
  `visualizations.oscilloscope.overlay_channels` defaults to `false` (Separate).
  Its Overlay channels switch under Settings → Visualizations → Oscilloscope is a
  new-instance default, independent of the global time span and gain controls.
  Existing panels retain their layout-local mode. Right-click an Oscilloscope
  panel and toggle Overlay channels after Reference lines and Labels to change only
  that panel; this preserves its reference-line setting and other options.
  Switching visualizer styles retains the panel's mode.
  Global controls under Settings →
  Visualizations → Oscilloscope are `visualizations.oscilloscope.time_span_ms`
  (`1`–`50` ms, default `20`) and `visualizations.oscilloscope.gain`
  (`0.1`–`10`, default `1`). Gain affects drawing only, not PCM or volume;
  a gain of `2` displays input amplitude limits of ±0.5.
  Sensitivity, dB range, Bloom, radial effects, and idle fade do not apply.

Both fractal styles are generative art, not amplitude or phase measurements.

Live-analysis styles use `visualizations.general.analysis_fft_size` and
`visualizations.general.analysis_rate_hz`; Waveform does not request FFT or PCM snapshots.
Spectrum, Spectrogram, and Waveform use `visualizations.general.palette`; the remaining
styles share `visualizations.effects.primary_color` and `secondary_color`.
`visualizations.general.analysis_window` affects FFT measurements, not Oscilloscope
PCM; changing it still clears that view.
`visualizations.reactive.db_range`
inherits `visualizations.general.db_range` when omitted; it controls analysis color
mapping and radial/fractal level normalization, not playback volume or the
Oscilloscope's amplitude scale. The two analysis styles retain a 0.5-second
exponential trail measured in accepted audio time, so pausing freezes the field.
Seeking, signal gaps, style changes, and FFT size/window changes clear the trail.

Fractal sensitivity and dB range map energy to shape and brightness; Bloom controls
the halo. Rotation, bar/ring shape, and idle fade do not apply. Silence extinguishes
the light; pause freezes it. Seeking, signal gaps, hiding the window, and FFT
changes reset the scene, while switching to an inactive tab preserves it.
See link:23_visuals.adoc[Visualization Rendering Design] for signal and rendering
mechanisms.

The effect parameters below accept finite values in these ranges.
Keys are relative to `[visualizations]`:

[cols="2,1,1",options="header"]
|===
|Key |Range |Default
|`reactive.sensitivity` |0–5 |1.5
|`radial.rotation_speed` |0–10 |0.5
|`radial.bar_width` |0–2 |0.6
|`radial.ring_opacity` |0–1 |0.8
|`reactive.bloom_intensity` |0–2 |0.5
|`radial.inner_diameter` |0–2 |0.7
|===

Radial bar glow uses two fixed rendering passes. `reactive.bloom_intensity`
controls its strength, with zero disabling the glow.

`visualizations.radial.fade_when_idle` defaults to `false` and applies only to stopped playback; pause
always preserves the last displayed frame. `visualizations.effects.primary_color` and
`visualizations.effects.secondary_color` default to `"#7AA2F7"` and `"#BB9AF7"`. These parameters remain saved even when the
selected instance style does not use them.

== Configuration schema

The application reads configuration schema `1`; explicit noncurrent versions are
rejected. Normal saves preserve an omitted `schema_version` rather than adding it.
Declaring the current schema does not bypass field or value validation. Malformed
TOML and file-access errors retain their specific causes.

`rivu-migrate` validates the selected configuration without rewriting it. Its
commands and offline ownership requirements are documented in
link:26_migration.adoc[Database and configuration migration]. Configuration and
database schemas are independent of the application release number; layout files
have their own contract under <<_layout_file,Layout file>>.
