= Configuration and layout

Rivu reads `~/.config/rivu/config.toml` by default (or the XDG configuration
directory); path overrides are described in link:../readme.adoc[the README].
A missing file uses the existing defaults. Existing files may omit top-level
`schema_version`; omission means the current schema (`1`), not a historical format.
Omitted setting groups and fields use their defaults. Unreadable files, malformed
TOML, unknown keys, misplaced fields, unsupported explicit schema versions, and
invalid values are errors, not a reason to fall back to defaults.
Paths are literal: `~` and environment variables are not expanded.
The configuration file path must be valid UTF-8, including a path derived from
`--data-dir`. A new host rejects an unrepresentable path before reading or saving
configuration or starting background services. A client controlling an existing
instance does not validate a configuration path that the instance will not use.
Configuration symlinks are followed when saving, including relative chains and
missing targets; saving atomically replaces the target file, not the links.
Link loops and inaccessible targets are reported as errors without replacing the links.
Configuration saves do not create a lock file. GUI and TUI changes share the same
host core; data-directory ownership prevents a second host for that directory.
Separate hosts sharing one configuration file, or external editors, are not
coordinated: the last save wins, without merging external changes. Exit Rivu before
editing the file manually, then restart to load the changes. Legacy
`.config.toml.rivu-lock` files are ignored and not automatically removed; remove
them only after all older Rivu instances using that configuration have exited.

Configuration is organized into `[library]`, `[playback]`,
`[interface]`, `[logging]`, and `[visualizations]`. Audio visualization settings
live in `[visualizations.spectrum]`, `[visualizations.spectrogram]`,
`[visualizations.audio_visualizer]`, and `[visualizations.waveform]`.
Album artwork settings live in `[interface.album_artwork]`.
Desktop integration belongs to Interface; output and decoding belong to Playback;
shared analysis belongs to Visualizations. Dotted names below identify file paths.
A minimal example (all omitted settings retain their defaults):

[source,toml]
----
[library]
roots = [] # Add music-directory paths before scanning

[playback]
volume_percent = 70

[interface]
font = "monospace"
font_size = 12
theme = "rivu_dark"

[logging]
level = "warning"

[visualizations]
still_mode = false
----

== Configuration upgrades

The application reads only the current configuration schema. A valid unversioned
file needs no migration and is not rewritten merely to add a version. Normal
application saves include the current `schema_version`.

When an unversioned file fails current parsing or validation, the error retains
the specific cause and explains the current-schema assumption. If it is an older
configuration, declare its original top-level `schema_version` explicitly before
using a compatible migration tool; do not label old content with the current
version to bypass validation. Malformed TOML must first be corrected so its
version can be read. File-access errors are not version errors.

Explicit noncurrent versions are rejected without trying historical decoders.
The current `rivu-migrate` validates configuration but does not convert or rewrite
it. See link:02_library.adoc#_sqlite_maintenance[SQLite maintenance] for the tool's
commands, supported inputs, backups, and retry guarantees. Configuration and
database schemas evolve independently; neither is an application release number.
Layout files are outside this migration scope.

== Parameters

=== Library roots and scanning

`library.roots` defaults to an empty list; add existing directories before
scanning. `library.scan_max_depth` defaults to `64` and must be at least `1`.
`library.scan_min_duration_secs` is an unsigned 32-bit integer in whole seconds,
defaulting to `0` (disabled). Both controls are in desktop Library settings.
See link:02_library.adoc#_minimum_duration_for_new_tracks[Minimum duration for new tracks]
for the admission policy, and link:02_library.adoc[Library] for roots, scan
boundaries, and CUE/path rules.

=== Browsing and keyboard navigation

`interface.page_size` accepts `20`–`256` (default `64`) and tunes internal GUI/TUI
query batches, not visible pages or CLI listing/export batches. Browsing scrolls
continuously; query batch tuning stays in the configuration file, not desktop settings. Queue behavior is described in
link:04_playback.adoc#_queue[Playback]; query and batch contracts in
link:02_library.adoc#_paged_views[Library].

In the desktop Queue, Playlists (catalog and tracks), Library, Recent tracks, and
Albums (cover grid and tracks), drag the right-hand scrollbar to browse long
lists, or click its track to jump.
Dragging continues outside the scrollbar until you release the mouse button.
Lists that fit in the viewport have no scrollbar thumb; mouse-wheel scrolling
remains available when content overflows.
The list's upper and lower edges indicate more content beyond the viewport;
the corresponding fade clears when that end is reached.

==== Desktop keyboard navigation

Use `Tab` and `Shift+Tab` to move between controls; a border marks the focused
control independently of its enabled or selected state. `Enter` or `Space`
activates a focused button or switch.
Unavailable controls cannot be activated and are skipped by keyboard navigation.
Panel tabs are also tab stops: activate a tab with `Enter`/`Space`, or press
`Shift+F10` (the Menu key also works) to open its panel menu.
Menus open without a focused action. Use `Up` or `Down` to enter and move between
available actions (wrapping at the ends), or use `Tab`/`Shift+Tab`. `Enter` chooses
the focused action. `Escape` or `Left` returns from a submenu; at the top level it
closes the menu without triggering a playback shortcut.
Menu action labels stay on one line; long labels are shortened, with the full name available on hover.

Open Shortcuts from the application menu to view desktop bindings;
`Escape` or the close button dismisses the list. `F1` and `?` do not open or close it.

Dialogs keep `Tab` traversal inside their controls. In Settings, tab to a page
button and press `Enter` to change pages, then tab through its fields and
Apply/Discard actions.

Open dropdowns with `Enter` or `Space`. `Up`/`Down` selects with wraparound;
`PageUp`/`PageDown` moves by the visible row count, clamping at either end without
scrolling the settings underneath. `Enter` or, in non-editable dropdowns, `Space`
accepts. Navigation and confirmation require unmodified keys; `Tab`/`Shift+Tab`
closes the dropdown and moves focus.

Editors and input methods retain their own keys. `Escape` cancels preedit, closes
an open dropdown, leaves the focused editor, then closes the dialog on successive
presses. Closing a dialog restores its invoking control if present, otherwise the
layout receives focus. Playback shortcuts apply to the layout, not focused
editors or buttons.
Text selection started inside an editor follows the pointer outside its bounds
until the left button is released. Leaving the window or moving focus away ends
the selection gesture.
Playback keys: link:04_playback.adoc#keyboard-controls[Keyboard controls].


=== Language

`interface.language` selects the GUI and tray presentation language: `auto`
(default), `en-US`, or `zh-CN`. Translations are embedded; no language pack
installation is needed.
`auto` uses the first nonempty `LC_ALL`, `LC_MESSAGES`, or `LANG` value, ignoring
encoding and modifier suffixes. English and Simplified Chinese are supported;
unavailable languages, including Traditional Chinese, fall back to English.
Explicit configuration values are `auto`, `en-US`, or `zh-CN` (case-insensitive;
underscores are accepted and normalized to hyphens); other values are errors.
Configuration language changes take effect when the graphical host restarts.
Closing and reopening a desktop window keeps the host's startup language; quit
and restart Rivu to apply a saved language change.
CLI output, TUI, command-line help, and localized diagnostics always use automatic
selection from the process environment, independently of `interface.language`.
They do not read configuration for localization. Starting a host or probing media
still loads and validates configuration for the operation itself.
Missing translations fall back to English. Configuration keys, command names,
machine-readable output, paths, and user metadata are not translated. Diagnostic
details may remain in English.
Saving the queue suggests an editable `Queue_YYYYMMDD_HHMMSS` playlist name.
Generated names do not pass through translation or contain presentation-only
bidirectional isolation characters.

=== Decoding and read buffering

`playback.media_read_buffer_mb` defaults to `2`; accepted sizes are `1`, `2`, `4`, `8`,
and `16` MiB.

`playback.ffmpeg_enabled` defaults to `false`. The default build includes the `ffmpeg`
feature; see link:../readme.adoc[README] for a native-only build. Enabling permits
FFmpeg use on future source opens; it does not load or validate runtime libraries.
Libraries load on the first native-unsupported source in Auto mode, a track opened
with the FFmpeg decoder hint, or an explicit
link:02_library.adoc#_metadata_and_favorites[enhanced probe]. Missing libraries
are reported when needed; native decoders continue to work. A load failure is
retained until restart. Disabling stops a track currently decoded through FFmpeg;
native-decoded playback is unaffected.

=== Volume and playback controls

[[volume]]
`playback.volume_percent` accepts a finite percentage from `0` to `100`, including
fractions, and defaults to `70`. Zero mutes; positive values use a dB-linear
control curve: gain in dB is `0.6 * (percent - 100)`. Thus 50% is -30 dB and
100% is unity gain (no amplification). This approximates uniform perceived
steps; it does not normalize loudness between tracks.
Settings accept fractional percentages; CLI inputs remain integer percentages.
Slider, IPC, and MPRIS values use the same curve, with normalized `0–1` levels
for IPC and MPRIS. Values are not rounded to whole percentages internally.

`playback.shuffle` defaults to `false`; `playback.repeat` accepts `off`, `all`, or `one` and defaults
to `off`. `playback.play_count_threshold_percent` defaults to `20` and must be finite and
in `[0, 100)`; zero still requires some confirmed heard time. Edit the threshold
in the configuration file or desktop settings; see
link:02_library.adoc#_play_counts_and_recent_tracks[Library] for counting semantics.

`interface.confirm_queue_replace` defaults to `true`. In the GUI, album and playlist
actions that replace a non-empty queue ask for confirmation. Disable it in desktop
settings under Playback & Audio → Playback to replace the queue without prompting.
This preference does not change TUI, CLI, or IPC behavior.

=== Saving configuration

Rivu writes `config.toml` only on desktop Settings Apply (or an explicit IPC
Configure command), or during an orderly application exit. A save is
skipped when the effective configuration matches the last successful save or
the configuration loaded at startup. Starting Rivu does not rewrite an existing
file; a missing file is created on the first Apply or orderly exit.

Playback controls and desktop shortcuts, including output selection, Still Mode,
Library columns, and library-folder changes, take effect in memory without
writing the configuration file. Apply saves these current values together with
the explicitly edited settings. Closing the desktop window is not application
exit: the core keeps running. A crash or forced termination can lose changes
since the last successful save. Database and layout persistence are independent.

Apply rejects a candidate that cannot be saved and retains the settings draft;
earlier runtime changes remain active. Saving errors are logged and exposed in
library status and the desktop error notice. A successful retry clears its own
error, not an unrelated error reported later. Exit makes one final save attempt;
a failure is reported but does not prevent exit. Writes atomically replace the
file without forcing a storage flush, so success is not a power-loss guarantee.

After Apply saves successfully, an audio-command delivery failure does not roll
back the committed configuration. Resolve the audio failure before retrying or
restarting.

=== Output and desktop integration

Output selection and application errors are described under
<<_output_and_applying_changes,Output and applying changes>> and in
link:04_playback.adoc#_output_devices_and_speaker_layouts[Playback output].
`interface.tray_enabled` and `interface.mpris_enabled` both default to `true` and
independently control desktop integration. Tray changes require a graphical-host
restart; MPRIS changes apply while running. Requirements and recovery are in
link:04_playback.adoc#_desktop_tray_and_window_lifecycle[Desktop tray and window lifecycle]
and link:04_playback.adoc#_mpris_and_artwork[MPRIS and artwork].

=== Logging and diagnostics

`logging.level` accepts `debug`, `info`, `warning` (default), or `error`. Warnings
and errors always go to stderr. `logging.to_file` defaults to `false`; enabling it
writes weekly logs under the data directory. `logging.retention_weeks` accepts
`1`–`520` and defaults to `4`. `NO_COLOR` or `RIVU_COLOR=never` disables
stderr colors. Closing the GUI window does not stop file logging. Normal application
shutdown makes a bounded attempt to drain and flush queued file logs; forced
termination cannot guarantee the final records. File output uses a lossy queue
of 4096 messages to avoid blocking producers; dropped messages are reported when
the writer stops. Changing only the log level does not trigger retention cleanup.
If creating the writer or saving the configuration fails, the previous logging
settings remain active.

Color settings use quoted `"#RRGGBB"` values. The file schema is defined in
link:../crates/rivu-format/src/config/file.rs[the grouped file adapter]; current defaults
and validation live in link:../crates/rivu-format/src/config.rs[`Config`].

== Desktop settings

Add library folders from the Library view. In Settings, folders are listed
individually; use a row's close icon to remove it from the draft. Long paths are
shortened in the middle; hover to see the full path. The list scrolls within the
editor. Paths retain semicolons and trailing spaces; they are not entered as
delimited text. Removals take effect only on Apply; Discard drops them.
The sidebar has four groups: Library, Playback & Audio, Interface, and
Visualizations. Library includes scan settings, Covers & cache, and maintenance;
Playback & Audio contains playback, output, decoding, and read buffering. Interface contains basic
preferences, layout, album artwork, desktop integration, and diagnostic logging.
Interface presents these sections together on one scrollable page, without
separate sidebar subpages. Panel-specific artwork settings remain a focused editor.
Logging is application-wide, including headless operation, and remains in `[logging]`.
Visualizations contains General and the four audio-data views.
Long sidebar labels are shortened to one line; hover over a category to read its full name.
Dropdown keys: <<_desktop_keyboard_navigation,Desktop keyboard navigation>>.
The system tray switch takes effect after restarting the graphical host, not
merely reopening its window. Media read buffering applies to future source opens,
including full waveform scans; it does not reopen the current track.
Pause visualizations (Still Mode) is under Visualizations → General →
Processing and cache and takes effect when settings are applied, without
restarting playback. The application menu also offers a Visualizations toggle below
Layouts; On enables visualizations and Off pauses them without writing `config.toml`.
Both controls use `visualizations.still_mode`; neither affects artwork or animation.

Settings keeps an independent draft based on the configuration at opening or the
most recent successful Apply. Apply submits only fields whose values differ from
that baseline. Core merges those edits into its latest configuration when the
request executes, not when it is queued. Unedited changes from playback controls,
CLI clients, or other desktop controls—including volume, output device, library
roots, Still Mode, Shuffle, Repeat, and Library columns—are preserved. An explicitly
changed field takes the draft value even if another control changed it meanwhile;
editing the folders list replaces the whole roots list.

After successful Apply, the baseline and untouched controls reflect the committed
configuration. Edits made while Apply was pending remain in the draft, including
partially typed or invalid text, for the next Apply. Failed Apply retains the draft
and its previous baseline for correction or retry; the saved-but-audio-failed
contract above still applies. Discard closes the editor and drops unsubmitted
edits, but does not cancel an Apply already sent to Core. Its later completion
cannot replace the draft or feedback of a reopened editor.

Interface → Layout includes Layout snapping and Layout grid spacing. These save
`interface.layout_snap_enabled` (default `true`) and `interface.layout_snap_grid_px` (default `16`,
integer `1`–`64` logical pixels before interface scaling) in `config.toml`.

Library → Covers & cache includes Cover decode budget (MiB per cover).
It saves `interface.artwork_decode_budget_mb`: an integer from `1` to `1024`,
default `64`. The limit includes all retained decoded frames and frame overhead
for one cover; identical covers share a decode within a window, while different
covers and windows add their own costs. Apply re-evaluates open covers, including
previously rejected images; Discard leaves the active budget unchanged.
Exceeding the budget shows the default cover rather than a partial animation.
Increasing it does not relax the fixed workspace admission estimate or dimension
limits, and is not a process/GPU memory cap. See
link:22_cache.adoc#_artwork_lookup_retention[Artwork resource boundaries].
The information icons explain decode, memory, and disk-cache limits. Cache
operation results and errors remain visible in the card rather than in tooltips.

Hover settings fields for accepted ranges and input syntax; inactive fields explain
which setting enables them. Apply errors retain the specific cause; hover to read
the full message or use Copy to copy it.
Single-line desktop text fields scroll horizontally to keep the caret visible.
Use Left/Right to navigate long values or Home/End to reach either end.
Shift+Left/Right extends a selection beyond the visible text; Shift+Home/End
selects to the beginning/end while preserving the selection anchor.

Shared visualization settings apply as follows:

* `visualizations.background` sets the background for all views; `visualizations.palette` is
  shared by Spectrum, Spectrogram, and Waveform. Audio Visualizer has independent
  primary and secondary colors.
* `visualizations.db_range` supplies the display span for Spectrum, Spectrogram,
  and Audio Visualizer unless a view overrides it. It does not affect Waveform
  gain or volume.
* `visualizations.analysis_fft_size`, `visualizations.analysis_window`, and `visualizations.analysis_fps` apply to Spectrum,
  Spectrogram, and Audio Visualizer, not Waveform. FFT size accepts powers of two
  from `512` to `32768` and defaults to `8192`. Window accepts `hann`,
  `blackman_harris` (default), or `none`. Changing size or window clears
  visualization history.
  `visualizations.analysis_fps` is the maximum analysis rate; actual updates follow window
  frames and can be slower when the compositor throttles presentation.
* Still Mode stops visualization processing and discards results; see
  <<_still_mode,Still Mode>>. `visualizations.cache` controls rendering reuse,
  separately from media read buffering; see link:22_cache.adoc[Caching and Resource Lifecycles].

Each frequency view has a range override; leave it empty to inherit General,
or clear an explicit value to restore inheritance. See
<<_visualization_db_ranges,Visualization dB ranges>> for the configuration contract.

Audio Visualizer style, reference lines, and labels are defaults for new
instances, while effect parameters are shared by all instances. See
<<_audio_visualizer,Audio Visualizer>> for instance settings and style-specific
effects. Inactive Spectrum style-dependent settings retain their values.

Interface → Album artwork edits the defaults for new panels: style, mode,
seconds per circle, and direction. Animation frame rate remains shared.
Apply and Discard follow the same draft rules as the other global settings.
Changing defaults does not change existing panels. Use a panel's right-click
Artwork settings entry to edit that instance. Static mode retains rotation parameters.

=== Appearance and library display

`interface.theme` in `config.toml` selects the shared desktop and terminal theme.
Presets are built in; no separate theme files are needed. Choose Theme in
Settings → Interface → Appearance & layout, then Apply to save and update open
clients without restarting. Choosing a theme only edits the settings draft;
Discard leaves the active theme unchanged. Editing the configuration file takes
effect when starting the core; the running core does not watch the file.

[cols="1,2"]
|===
|Theme |Accepted value
|Rivu Dark (default) |`rivu_dark`
|Tokyo Night |`tokyo_night`
|Tokyo Night Day |`tokyo_night_day`
|===

Rivu Dark is Rivu's own blue-gray preset, with subdued structural separators,
neutral hover backgrounds, and restrained blue selection and primary-action fills.
Tokyo Night Day is a light theme. The Tokyo Night presets map colors from
https://github.com/folke/tokyonight.nvim[Tokyo Night] to Rivu's interface roles;
text and selection colors receive local contrast adaptations without changing
their hue families. Other applications' theme-file formats are not imported. Unknown theme
names are configuration errors. The selected theme does not change visualization
backgrounds, signal palettes, canvas labels, cursor colors, or album artwork.

Search or browse installed fonts in Settings, including `monospace`, `sans-serif`,
and `serif`. Enter or click to select; custom family names are accepted.

`interface.font` defaults to `monospace`, including empty values. Names must not
contain control characters or exceed 128 UTF-8 bytes. Fontconfig system and user
rules (`~/.config/fontconfig/fonts.conf`) select families and missing-glyph
fallbacks. Restart the GUI after changing those rules. Unavailable primary fonts
produce a warning and fall back to `sans-serif`.

Fontconfig hinting, subpixel, and synthetic-bold settings do not control GUI
rendering. Complex shaping and named variable-font instances may differ from
other applications.

`interface.font_size` accepts integer point sizes from `8` to `18`, default `12`
(16 logical pixels before interface scaling). Apply to update open windows.
It preserves title/secondary text hierarchy without resizing icons or chart
annotations, and does not affect terminal text or replace `interface.scale`.

`interface.scale` accepts finite values from `0.75` to `2.0` (default `1.0`) and
adjusts desktop controls and list density independently of the desktop's display scaling. Menus and editor dialogs
stay within the window; scroll them when not all content fits. Settings dropdowns
close when their control moves or the interface scale changes; reopen them at
the new position.
GUI icons use the system-installed Symbols Nerd Font Mono independently of
`interface.font`. The optional `embed-nerd-font` Cargo feature embeds a build-host font;
see link:../readme.adoc[build instructions] for requirements and licensing.
The TUI requires a Nerd Font or Nerd Symbols fallback in the displaying terminal.
For SSH, configure the local client terminal; installing fonts on the server
does not supply terminal glyphs. Missing glyphs can appear as boxes or blanks.
Use the Mono variant of Symbols Nerd Font for single-cell icons. The TUI shares
`interface.theme`, but its width-dependent information columns are built in;
desktop font, scale, and Library column settings do not configure the terminal client. See
link:04_playback.adoc#_terminal_client[Terminal client] for browsing and full details.

`interface.library_columns` selects desktop Library information columns. Its
boolean keys are `artist`, `album`, `duration`, `codec`, and `bitrate`;
`duration` and `codec` default to `true`. Omitted keys retain those defaults; set all five
to `false` for names only. Change them without restarting from the Library
right-click menu → `Track information`. Both Library views share the saved
selection; full tooltip information is unaffected. See
link:02_library.adoc#_desktop_selection_and_directory_tree[Library display].

=== Output and applying changes

Omitted `playback.output_device` uses the default PipeWire sink. A selected device
must be available to play, but can remain saved while unavailable; playback
reports the failure without substituting another device.
`playback.pipewire_auto_mix` defaults to `true` and permits PipeWire remixing;
disable it to require a compatible speaker layout without remixing.
See link:04_playback.adoc#_output_devices_and_speaker_layouts[Playback] for
normalization, source-rate negotiation and output gain behavior.
Changing either setting rebuilds the output stream and seeks the existing
decoder to the current position, retaining paused state. It does not open a new
decoder or apply a newly saved Decoder hint or media read-buffer size.

Apply validates and saves the settings draft across all four sidebar groups together;
navigation preserves the draft and each page's scroll position. Discard drops unapplied changes and closes
settings. Invalid input or a save failure is reported in settings. Saving an
unavailable output target succeeds; applying it stops playback and reports an
audio error while retaining the saved selection. Settings opened for one Audio Visualizer instance instead
apply only that instance's style, reference lines, and labels to `layout.json`;
applying fails if the instance no longer exists.
Inactive Spectrum fields retain their values and are still validated by Apply.
If a retained value is invalid, open Visualizations → Spectrum: choose a Style
other than Solid to edit bar count, width, or gap, or enable Peak markers to
edit marker hold or gravity. Correct the value, then restore the desired style
or toggle and apply again. Disabling a field does not discard or repair its value.

Saving library roots does not scan or enqueue tracks; use `Scan paths` in Library.
Display-only changes do not reopen audio. Hover an error to read its complete
message, or click its copy icon to copy it.

See link:../readme.adoc[README] for application lifecycle and host behavior.

=== Artwork cache maintenance

Settings → Library → Covers & cache also provides manual maintenance of encoded
cover files on disk. Enter a positive whole number in `Expire files older than (days)`
(initially 30), then choose `Calculate usage` or `Clean expired`. Neither opening
Settings nor starting Rivu scans this directory. These actions run immediately
in the background, do not require Apply, and are not undone by Discard.

The report shows file counts and encoded bytes for total usage, expired
candidates, protected files, successful removals, and failures. Cleanup totals
describe usage before deletion. Age is based on file modification time, not
recent playback; reusing a file does not update its age. Resident lookup results
protect their files, including results still used by GUI or MPRIS. Protected
files are skipped even when expired; the bundled icon and audio files are never
removed. A removed cover is regenerated on demand.

Inspect reported errors and retry after fixing access or permissions. Maintenance
has no automatic schedule or total-capacity guarantee, and the age input is not
saved to `config.toml`. Ownership and retention rationale are documented in
link:22_cache.adoc#_artwork_lookup_retention[Artwork lookup retention].


=== Album artwork

The `Album artwork` panel (`album_artwork` in layout files) follows
the current playback track independently of Metadata. Its configuration is:

[source,toml]
----
[interface.album_artwork]
style = "halo"
mode = "rotating"
period_seconds = 20.0
direction = "clockwise"
fps = 0
----

`style` accepts `plain`, `vinyl`, `glass`, `halo` (default), `metal`, `card`, or
`duotone` and supplies the initial style for new panels. Each panel saves style,
mode, period, and direction in the layout. Its right-click Style and Rotation
actions affect only that panel; Artwork settings edits all four instance options.
Saved panels missing options initialize from the current defaults. All seven styles
support static and rotating
modes. Changing style preserves the current rotation angle. Metal adds
a fixed brushed radial sheen over a circular cover. Card preserves the full
square image inside a rounded frame and shadow that rotate together, with room
for the corners at every angle. Duotone adds a fixed blue/purple edge glow behind
a circular cover, without extracted colors or audio-driven effects.
`mode` accepts `static` or `rotating` (default). `period_seconds` is the time
for one full circle and must be finite and greater than zero; there is no
additional upper limit. `direction` accepts `clockwise` (default) or
`counterclockwise`. `fps` is an integer from 0 through 240 (default 0): zero
follows display callbacks without timer throttling; a positive value caps
animation requests per second. Lower caps reduce rendering work and resource
use at the cost of less smooth motion; zero can render more frequently on
high-refresh displays. Changing the cap preserves the angle. All Album artwork
panels share only frame rate; the analysis rate is independent. Mode, period, and
direction in this configuration supply defaults for new panels, not live overrides.
Rotation follows playback rather than audio energy. Pausing or hiding the panel
preserves its angle; resuming does not catch up on suspended time.
Stopping, changing the current track, or selecting static mode resets the cover
upright. A track without artwork uses Playback's generated default cover with
the same animation, interaction, and lifecycle rules as a real cover. Pending
animation work is cancelled while paused, hidden, or static, and resuming never
produces a catch-up burst. Still Mode does not affect artwork acquisition,
display, track changes, or rotation. Rendering uses GPU transforms, without
rotating geometry on the CPU every frame or introducing an application image
cache. Metadata's full preview is unchanged.


== Layout

The desktop stores named layouts and the current selection in `layout.json` in
the data directory. Each layout has its own panel tree, relative sizes, tab
order and selection, tab-bar visibility, and instance options. Edit locks are
window-local, not saved; every newly opened window starts locked.

All layout state, including the active layout, stays in memory until manual sync
or an orderly application exit writes it to `layout.json`. Closing and reopening
the desktop window keeps the latest in-memory layouts; it does not write them.
An abnormal exit loses changes made since the last successful write. Panel
settings Apply takes effect immediately for this session only; it does not write
the layout file.

Sync and orderly exit skip file writes when the persisted layout content matches
the last successful save or the valid collection loaded at startup. Reverting
edits to that content also skips the write. A missing or invalid file is written
on the next sync or orderly exit, even if no layout edits were made.

Without a saved layout collection, Rivu starts in `Default` and also provides
`Album` and `Visual`. Default opens Library in the main browsing region and
Queue beside it; Albums, Playlists, and Recent tracks are alternative browser
tabs, and Track details shares the side region with Queue. Below them, a cover
sits beside Spectrum above playback controls. These three bottom panels hide
their tab bars. Album starts with Albums and adds a cover above
the side region; its standalone cover also hides its tab bar. Visual starts
with Audio Visualizer, with Spectrum, Spectrogram, and Waveform available as
tabs. Album and Visual retain playback below the main content. Built-in layouts
start locked and use the same global configuration.

Existing layout collections are loaded unchanged. To make another layout,
duplicate an existing layout and edit the copy. Renaming or deleting an initial
layout does not cause it to be restored on restart. For initial proportions, see
link:24_layout.adoc#_scope_and_ownership[Layout design].

The layout list places `Default` first when present, followed by other names in
name order. This does not change the active layout.

Open `Menu > Layouts` to switch layouts, duplicate the current layout under a new
name, rename it, or delete another layout after confirmation. Hover the layout's
row or focus its Delete button with Tab to reveal Delete. Names must be
nonempty and unique after trimming surrounding whitespace. To delete the current
layout, switch to another one first; the collection always retains a layout.
Use the Sync layouts to file icon beside Rename to write the current collection.
Sync cancels any active layout interaction before capturing the collection, so
drag and resize previews are not saved. The panel shows sync progress and confirms
completion, including when no write is needed. A write failure leaves session
layouts unchanged. The error appears in the panel while open, or in the footer
after closing it. Press Sync again to retry; further layout edits do not
automatically retry a failed write.

Switching or duplicating updates the panel tree inside the same window. Playback,
queue, global configuration, window placement, and the active Track details draft
are unchanged. Layouts do not save separate copies of searches, selections,
scroll positions, or editing sessions; switching back is not a restore operation.
Finish or discard settings before changing layouts. Renaming and deleting an
inactive layout do not rebuild the interface.
Press `Escape` to close the layout manager,
including after renaming the current layout.

While unlocked, panels can be added, removed, moved, resized, and reordered.
Right-click a panel to toggle its tab bar, even while locked. Right-click the
bottom-right layout button to toggle the lock, or left-click it to open the panel
catalog. Drag a catalog item into the workspace to add a new instance; single-click
and double-click do not add panels, and there is no keyboard insertion action.
An empty workspace accepts a drop to create its first tab group. Cancelling or
releasing outside a valid target creates nothing.
Playback, tab selection, and layout management remain available while locked.
Locked separators have no resize cursor or hover highlight.

Rows and columns contain two or more ordered regions. New containers divide
their content equally. Docking at an edge splits the target region while
preserving unrelated pane sizes; matching directions become siblings rather
than nested splits. Dragging a separator resizes only its two neighboring
regions, leaving other boundaries unchanged. Removing a region gives its space
to the following neighbor, or the preceding neighbor when the removed region
was last. Empty and single-region containers collapse; same-direction splits
merge while preserving their proportions.

During a panel drag, only the panel under the pointer is a destination. Drop at
its left, right, top, or bottom edge to split that panel region, or at its center
to merge tabs. Enclosing rows, columns, and the entire layout are not separate
targets. The label and outline identify the destination panel, and the shaded
region previews the panel's final position, including source removal when moving
an existing panel. Catalog drags use the same targets and preview as panel moves.
Release to apply that target. Corners and separator gutters do not select an
ambiguous edge.

Dropping anywhere in a visible tab bar reorders or transfers tabs, never splits
the panel. Tab midpoints choose the insertion position; gaps and the unused
tail are included, with the tail appending after the last tab. An unavailable
target shows `Cannot dock here`; releasing there leaves the layout unchanged.
Press Escape to cancel. Leaving or deactivating the window, opening a dialog or
menu, or locking the layout also cancels the drag. Queue-entry drags do not
activate panel docking.

Resizing the window or changing interface or display scaling clears the old
preview. If released before the new geometry is measured, the drag leaves the
layout unchanged; otherwise docking uses the new geometry. Hidden tab bars do
not retain tab targets, but their panels still accept ordinary docking.

Escape or window deactivation also cancels a separator resize and restores its
starting proportions. Resizing the window or changing scale cancels an active
separator resize rather than committing coordinates from its old geometry.

With Layout snapping enabled, separator dragging considers targets in this
priority order: aligned separator centers in other visible same-direction splits,
the equal-content midpoint of the adjacent panes, then the nearest configured
grid line rooted at the container origin.
Reference separators and midpoints capture within 4 logical pixels before
interface scaling; grid snapping selects the nearest grid line.
Targets that violate minimum pane sizes are skipped. Hold Alt to invert the global
setting: it disables snapping when enabled and enables it when disabled.
Releasing Alt restores the configured behavior without changing saved settings.

Layouts support up to 32 nested rows or columns along any path; tab groups do
not add to this depth. Docking that would exceed this limit leaves the layout
unchanged. This is not a limit on the number of sibling regions or tabs.

If `layout.json` cannot be read or validated at session startup, Rivu reports the
load error and opens the default collection. Invalid layout names or operations
leave the UI unchanged. Explicit sync requests use one background worker and
coalesce pending requests, not ordinary edits. Each request captures the current
collection; later edits cannot change that write or suppress its feedback. A
failed write preserves the old file and all session edits. Retry with manual
sync, not another layout edit or instance-settings Apply. Orderly application
exit writes the latest dirty collection, waits for completion, and reports a
remaining failure.
Errors and scan progress appear in the footer. Use the copy action to copy the
complete text, including text truncated on screen. Errors also provide a dismiss
action; these actions remain visible without hovering. Drag the empty footer area
with the left mouse button to move the window using the window manager's native
move operation. Notification text and controls do not start a window move.
Menus and dialogs suppress footer dragging.

See link:24_layout.adoc[Desktop Layout Design] for geometry, ownership, and
editing invariants.


=== Layout file

The file uses one format, without runtime IDs or version fields. `active` names
an entry in the nonempty `layouts` object. Each entry requires `root`; `null`
means an empty layout. Lock state is not stored; each newly opened window starts
locked.

[source,json]
----
{
  "active": "Work",
  "layouts": {
    "Work": {
      "root": {
        "type": "split",
        "axis": "horizontal",
        "children": [
          {"type": "tabs", "panels": [{"kind": "library"}]},
          {"type": "tabs", "panels": [{"kind": "queue"}]},
          {"type": "tabs", "panels": [{"kind": "waveform"}]}
        ]
      }
    }
  }
}
----

`horizontal` orders children left to right; `vertical` orders them top to bottom.
Children are direct node objects, not wrappers. An omitted or empty `boundaries`
array divides the content equally, as in the example. To give the first pane
half the content and each remaining pane a quarter, add
`"boundaries": [0.5, 0.75]` beside `children`. Explicit boundaries must contain
exactly one fewer value than children, all finite, strictly increasing, and
strictly between `0` and `1`. They are cumulative fractions of pane content
length, excluding separator gutters, not weights or fractions of adjacent panes.
Splits require at least two children and cannot directly contain a split in the
same direction. At most 32 splits may occur along any root-to-leaf path; tabs
do not count toward this limit.
Configuration remains TOML; layout persistence remains JSON.

`tabs` requires a nonempty `panels` array. Its optional `active` is a zero-based
index, defaulting to `0`. Panel objects require `kind`; `show_tab_bar` defaults to
`true`. Audio Visualizer objects additionally store `style`, `reference_lines`,
and `labels` directly in the panel object. These three fields must be supplied
together or omitted together; omission initializes the instance from global
defaults when that layout is opened. Once initialized, all three choices are
saved explicitly. Unknown fields, invalid structures, and out-of-range indices
are errors.


== Visualization dB ranges

`visualizations.db_range` defaults to `70` dB. The optional `visualizations.spectrum.db_range`,
`visualizations.spectrogram.db_range`, and `visualizations.audio_visualizer.db_range` override it only for their
named view. Every supplied range must be finite and between `1` and `160` dB,
inclusive. An explicit override remains an override even if it equals the shared
default; changing General later affects only views without overrides.

In TOML, omit a view's override key to inherit the shared default. Do not write an empty
string or a blank assignment: overrides are numeric when present. Saving an
inherited range omits that override key.

[source,toml]
----
[visualizations]
db_range = 80.0

[visualizations.spectrum]
db_range = 60.0

[visualizations.audio_visualizer]
db_range = 100.0
# visualizations.spectrogram.db_range is omitted, so Spectrogram uses 80 dB
----

These ranges affect display mapping only, not FFT analysis, decoded audio,
playback volume, or Waveform's RMS/Peak gains. Spectrogram recolors retained
history without discarding it. Changing an unused shared default or setting an
override equal to the current resolved value leaves the display unchanged.

== Visualizations

Live FFT analysis runs during playback only when Still Mode is off, the
application window is visible, and a Spectrum, Spectrogram, or Audio Visualizer
panel is visible.
`visualizations.analysis_fps` accepts `5`–`60` and defaults to `20`.
`visualizations.palette` accepts `tokyo_night` or `deadbeef` (default `deadbeef`) and is
shared by Spectrum, Spectrogram, and Waveform. See
link:../src/config.rs[`Config`] for the full setting ranges and defaults.
`visualizations.cache` defaults to `true`; disabling it preserves the displayed
results but rebuilds derived graphics on repaint. It does not affect Radial
Spectrum. See link:22_cache.adoc[Caching and Resource Lifecycles] for scope and trade-offs,
and link:23_visuals.adoc[Visualization Rendering Design] for rendering choices.

Before audio data is available, visualization panels show no waiting message;
their backgrounds and any applicable reference guides remain. Loading, failure,
Still Mode, and unavailable frequency-data messages remain distinct from this
normal initial state.

=== Still Mode

`visualizations.still_mode` defaults to `false`. Enabling it replaces all four visualization
views with a static status, stops analysis sampling and FFT work, and discards
all visualization results. Progressive waveform collection stops; any running
full-waveform request is cancelled, and new requests are unavailable.

Playback, seeking through the playback slider, ordinary interface effects,
library operations, covers and their animation, IPC, MPRIS, and the tray are unchanged.
Layout and visualization settings are preserved, including `visualizations.cache`.

Disabling Still Mode starts the visible views fresh, without reopening audio
output or the decoder. Views rebuild from new audio; leaving the mode while
paused does not restore an old picture. Waveform starts
accumulating from subsequently decoded PCM, with discarded and skipped intervals
left blank. An interrupted traversal is not marked complete. Full-waveform
requests do not restart automatically; request one explicitly after leaving the
mode if needed. Ordinary playback pause remains different: it freezes the current
visualizations without discarding their results.

=== Waveform

Waveform shows a whole-track timeline, relative to the subtrack for CUE. Left is
above the centerline, right below; the filled body is RMS amplitude and the outer
line is peak amplitude. Unknown intervals remain blank. Playback builds the
preview progressively; `Load full waveform now` requests the complete preview.
Click or drag to seek the current track; a non-playing selection preview does
not seek playback.
Seeking gestures stay bound to the queue entry at press time. If playback moves
to another entry before release, the old gesture cannot seek the new entry.
Escape or a geometry change cancels the gesture without seeking.
To preview a track without starting playback, select it in Library and use
`Load full waveform now`. A selected track with no decoded samples can also
build its preview through playback.

`visualizations.waveform.seek_enabled` defaults to `true`. Disable Click and drag to seek in
the Waveform settings page or its panel right-click menu to prevent accidental
seeks. Disabling it cancels any active waveform drag and preview; the playback
slider remains available.

RMS uses a center-to-edge palette gradient; Peak uses the palette color at its
level. Known silence remains visible as a minimum-height RMS fill; unknown
intervals stay blank.

Waveform labels (`visualizations.waveform.labels`) default to `false`;
`cursor_color` and `glow` control the cursor and glow. Amplitude settings are:

[cols="2,1,1",options="header"]
|===
|`visualizations.waveform.*` key |Range |Default
|`rms_gain` |0–3 |0.94
|`peak_gain` |0–2 |1.0
|`peak_gamma` |0.25–3 |2.0
|===

Gamma above `1` reduces low peaks; below `1` lifts them. These settings affect
rendering only, not playback volume or decoded preview data.

=== Spectrum and Spectrogram

Spectrum shows current frequency energy. `visualizations.spectrum.style` accepts `bars`,
`outline`, `led`, `line`, or `solid` (default `solid`). The remaining `visualizations.spectrum.*`
settings control band density, spacing, bar and peak hold, release motion,
smoothing, reference lines, labels, and display range. `visualizations.spectrum.bars = 0`
(default) chooses the band count automatically; explicit counts accept `1`–`512`.
Motion freezes while paused.
The default bar falling acceleration (`visualizations.spectrum.bar_gravity`) is
`200` dB/s². Labels and reference lines both default to off.

`visualizations.spectrum.interpolate` defaults to `false` and controls frequency interpolation and whether `solid` has a
continuous or stepped boundary. `line` always connects valid body points
continuously and skips empty slots rather than drawing them at the floor.
Peak indicators remain discrete in every style.

Spectrogram shows recent frequency history; unavailable history stays blank.
Its `visualizations.spectrogram.*` settings include:

* `labels`: default `false`.
* `history_seconds`: `1`–`60`, default `20`; retained history also depends on panel
  width and analysis rate.
* `sampling_points_scale`: `0.4`–`1.4`, choosing source frequency rows relative to
  visible panel height.
* `interpolation_points` (Maximum frequency rows): `64`–`4096`, default `1024`.
  This limits rendering rows with or without interpolation; it does not change
  FFT size or add measured frequency detail.

The startup-only `interface.gpu_material_budget_mb` setting accepts `16`–`1024`
MiB and defaults to `64`. Restart the GUI to apply a change. It limits the shared
charged material buffers per window, including initialization copies and uploads
awaiting GPU completion, not image atlases, render targets or total GPU memory.
Edit it in Settings > Visualizations > General > Processing / cache using
Shared GPU buffer budget (MiB).
Spectrogram also caps frequency rows against that startup budget; long histories
can have fewer display rows than the configured maximum. Time resolution and
playback audio are unchanged.
Both views use a logarithmic frequency axis and share `visualizations.analysis_fft_size` and
`visualizations.analysis_window`. Their independent `visualizations.spectrum.db_range` and
`visualizations.spectrogram.db_range` overrides inherit `visualizations.db_range` when omitted;
see <<_visualization_db_ranges,Visualization dB ranges>>.

=== Audio Visualizer

Each Audio Visualizer instance stores its style, reference-line visibility, and
label visibility in `layout.json`. Right-click the instance and open `Style` to
choose a style; `Back` returns without changing it. The main menu's `Display`
group independently toggles `Reference lines` and `Labels`; a checkmark means
enabled. Choosing a style or toggling an overlay closes the menu. Visualizer
settings lets you apply these choices together to that instance.
Moving panels and restarting preserve their choices. Different styles can run
simultaneously. Global `visualizations.audio_visualizer.style`, `visualizations.audio_visualizer.grid`, and
`visualizations.audio_visualizer.labels` seed new instances only. Style defaults to `bars_rings`;
both overlay defaults are `false`.

Reference lines and labels are independently optional. Radial guides show
normalized bar levels; analysis views use their measured axes; fractal guides
show normalized scene coordinates, not audio measurements. Small views omit
labels that would overlap. Available styles:

* `bars`, `rings`, and `bars_rings` use the radial Spectrum presentation.
  Rotation, bar width/glow, ring opacity, inner diameter, and idle fade apply
  to these styles only. Sensitivity and Bloom also affect the fractal styles.
* `stereo_density` shows a Mid/Side occupancy field: horizontal Side `(L−R)/2`,
  vertical Mid `(L+R)/2`, both fixed at ±1 without automatic gain. Equal channels
  form a vertical trace; opposite channels form a horizontal trace. Its readout
  reports correlation, left/right energy balance, and the Side share of energy
  over the current FFT window. Correlation is undefined for silence or a silent
  channel. Color represents decaying sample occupancy in dB, not audio dBFS.
* `spatial_spectrum` shows logarithmic frequency vertically and left/right
  energy balance horizontally, with color representing frequency-bin power in
  dBFS. Equal-energy channels appear at the center even when their phases differ;
  this is not a source-direction or phase measurement.
* `fractal_beams` maps low-frequency energy to branch length, mids to bending,
  and highs to fine-branch intensity. Energy rises launch outward pulses;
  these are not detected beats.
* `fractal_flow` maps low, mid, and high energy to filament motion;
  energy rises brighten the trails.

Both fractal styles are generative art, not amplitude or phase measurements.

All styles share `visualizations.analysis_fft_size`, `visualizations.analysis_window`, `visualizations.analysis_fps`, and the
two `visualizations.audio_visualizer.*_color` endpoints. `visualizations.audio_visualizer.db_range` inherits
`visualizations.db_range` when omitted; it controls color mapping, not playback
volume or measured amplitude. The two analysis styles retain a 0.5-second
exponential trail measured in accepted audio time, so pausing freezes the field.
Seeking, signal gaps, style changes, and FFT size/window changes clear the trail.

The fractal styles use `visualizations.audio_visualizer.sensitivity` and `visualizations.audio_visualizer.db_range`
to map measured energy into shape and brightness; `visualizations.audio_visualizer.bloom_intensity`
controls the halo. Rotation, bar/ring shape, and idle fade do not apply. Motion
and decay follow accepted audio time: silence extinguishes the light, while
pause freezes it. Seeking, signal gaps, hiding the view, and style/FFT changes
reset the scene. See link:23_visuals.adoc[Visualization Rendering Design] for
analysis continuity, scene resource boundaries, and rendering trade-offs.
