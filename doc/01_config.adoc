= Configuration and settings
:toc:
:toclevels: 2

Rivu reads `~/.config/rivu/config.toml` by default (or the XDG configuration
directory); path overrides are described in
link:00_getting_started.adoc#files-and-data-directories[Files and data directories].
A missing file uses defaults. The optional top-level `schema_version` defaults
to the current schema; see <<configuration-schema,Configuration schema>>.
Omitted setting groups and fields use their defaults. Unreadable files, malformed
TOML, unknown keys, misplaced fields, unsupported explicit schema versions, and
invalid values are errors, not a reason to fall back to defaults.
Paths are literal: `~` and environment variables are not expanded.

Use Settings to change the running instance, then Apply to save. To edit TOML
directly, exit Rivu first, edit the file, and restart; the core does not watch
external edits. Configuration controls application-wide defaults. Panel trees
and instance preferences are saved separately in link:05_layout.adoc#layout[`layout.json`].

Settings are grouped under `[library]`, `[playback]`, `[interface]`, `[logging]`,
and `[visualizations]`. Dotted parameter names below identify TOML paths.
Visualization behavior and parameters are described in link:06_visualizations.adoc[Visualizations];
additional processing tables in <<audio-processing-defaults,Audio processing defaults>>.

A minimal example (all omitted settings retain their defaults):

[source,toml]
----
[library]
roots = [] # Add music-directory paths before scanning

[playback]
volume_percent = 70

[interface]
font = "monospace"
font_size_pt = 12
theme = "rivu_dark"

[logging]
level = "warning"

[visualizations.general]
enabled = true
----

[[saving-configuration]]
== Saving configuration

[[persistence-responsibilities]]
[cols="2,3,3,2,2",options="header"]
|===
|Data / storage |Immediate state after an edit |Disk-write trigger |Closing desktop windows |Abnormal exit risk

|Application configuration / `config.toml`
|Accepted controls update core memory. Settings drafts remain unsubmitted until Apply. New-panel defaults do not replace existing layout-local panel preferences.
|Settings Apply, IPC Settings patches, accepted processing edits (graph, Monitor EQ, presets, restoration or neural settings), live Textures edits, and orderly Core exit. Processing and Textures edits save immediately; other controls (playback, output, visualization enablement, Waveform seeking, Library columns and folders) wait for the next save.
|Does not exit the Core or trigger its exit save.
|Changes since the last successful save can be lost.

|Layouts and panel-instance preferences / `layout.json`
|Layout edits, panel-settings Apply and layout selection update desktop-session memory only.
|Explicit Sync layouts to file, or orderly exit of the desktop process when its last window closes.
|The last window flushes the final layout and ends the desktop event loop; the Core service continues. A new desktop process loads the persisted collection.
|Unsaved desktop-session edits can be lost. Failed input is protected from replacement on ordinary exit; see link:05_layout.adoc#layout[Layout].

|Queue / library database
|Queue order, removals and current occurrence change independently of configuration and layouts.
|Queue mutations save as they execute. Shutdown retries only an unsaved runtime selection.
|Not a queue-save boundary; successful database saves do not depend on window close.
|Only successfully saved state is recoverable. Restart restores the selected occurrence in Stopped state at position zero, not playback position, playing/paused state or shuffle history; see link:04_playback.adoc#queue[Queue recovery].
|===

Configuration saves patch values changed since startup or the last successful save, preserving
untouched values, comments and formatting. Omitted defaults stay absent; explicitly
written defaults remain, and returning a field to its default writes it explicitly.
Clearing an optional setting removes its key. Changed arrays may be replaced as
a unit, including their internal comments and formatting. New files contain only
default overrides.

Unchanged configuration needs no write. Startup leaves an existing file untouched;
a missing file is created on the first save or orderly exit. Database and layout
persistence are independent of configuration saving.

[[apply-and-validation]]
=== Apply and validation

Apply validates all Settings pages and merges edited fields into the latest
configuration, preserving unrelated changes from other controls and clients.
An edited field wins over a concurrent change to that field; folder edits replace
the roots list. Playback controls already accepted in memory are included.

Validation or save failure retains the draft; earlier runtime changes remain
active. Invalid text blocks Apply even in an inactive control. Settings opens
the affected page; Reset field text restores only that field's accepted value.
Edits made while Apply is pending await the next Apply, and the editor cannot
close until completion. Discard then closes it and drops unsubmitted edits.

Apply reserves capacity for changed audio parameters before saving. Unchanged
audio settings are not resent, except output settings. Every explicit Apply sends
output settings; an unchanged device and remix configuration is revalidated only
when no source is playing, paused or opening. With an existing source, unchanged
output settings are not reapplied. Display-only changes do not reopen audio.

Settings Apply validates and saves editable configuration; processing-graph changes
use their separate revision-checked commands and cannot be applied here.

Save failures appear in logs, `rivu status` and the desktop notice. Correct the
cause and retry; exit makes one final attempt. Atomic replacement prevents partial
writes, not power loss. An audio-application failure after a successful save does
not roll back the saved configuration.

[[file-access-and-external-editors]]
=== File access and external editors

The configuration path must be valid UTF-8, including when derived from
`--data-dir`. Existing inputs must be ordinary files; symlinks to ordinary files
are accepted. Directories, devices, sockets, and FIFOs are rejected without waiting
for input. Configuration is limited to 4 MiB of UTF-8 TOML, including retained
comments and formatting; an oversized save leaves the existing file untouched.

Saving follows symlinks, including relative chains and missing targets, and
atomically replaces the target rather than the links. Link loops and inaccessible
targets are errors.

GUI and TUI changes share the host core. Separate hosts sharing a configuration
file and external editors are not coordinated: format preservation is not
conflict detection or a concurrent-edit merge. Exit Rivu before editing the file
manually, then restart to load the changes.

== Parameters

=== Library roots and scanning

`library.roots` defaults to an empty list; add existing directories before
scanning. `library.scan_max_depth` defaults to `64` and must be at least `1`.
Loading validates settings and the processing graph once and retains logically
normalized roots in their configured order, without rewriting the configuration file.
`library.scan_min_duration_seconds` is an unsigned 32-bit integer in whole seconds,
defaulting to `0` (disabled). Both controls are in desktop Library settings.
See link:02_library.adoc#minimum-duration-for-new-tracks[Minimum duration for new tracks]
for the admission policy, and link:02_library.adoc[Library] for roots, scan
boundaries, and CUE/path rules.

=== Browsing and keyboard navigation

`interface.query_batch_size` accepts `20`–`256` (default `64`) and tunes internal GUI/TUI
query batches, not visible pages or CLI listing/export batches. Browsing scrolls
continuously; query batch tuning stays in the configuration file, not desktop settings. Queue behavior is described in
link:04_playback.adoc#queue[Playback]; query and batch contracts in
link:02_library.adoc#paged-views[Library].

Long desktop lists support mouse-wheel scrolling and a draggable right-hand
scrollbar; click its track to jump. Edge fades indicate more content above or below.

[[desktop-keyboard-navigation]]
==== Desktop keyboard navigation

Use `Tab` and `Shift+Tab` to move between enabled controls; a border marks focus.
`Enter` or `Space` activates a focused button, switch, or panel tab. Open a panel
tab's menu with `Shift+F10` or the Menu key.

In menus, `Up`/`Down` or `Tab`/`Shift+Tab` moves between available actions with
wraparound, and `Enter` chooses one. `Escape` or `Left` returns from a submenu
or closes the top-level menu without triggering playback shortcuts.

Open Shortcuts from the application menu to view desktop bindings;
`Escape` or the close button dismisses the list. `F1` and `?` do not open or close it.

Dialogs keep keyboard traversal inside their controls. In Settings, activate a
page button with `Enter`, then tab through fields and Apply/Discard.

Open dropdowns with `Enter` or `Space`; select with `Up`/`Down` or
`PageUp`/`PageDown`, then accept with `Enter` (`Space` also works in non-editable
dropdowns). `Tab`/`Shift+Tab` closes the dropdown and moves focus.

Editors and input methods retain their own keys. Successive `Escape` presses
cancel preedit, close a dropdown, leave the editor, then close the dialog.
Playback shortcuts apply to the layout, not focused editors or buttons.
Playback keys: link:04_playback.adoc#keyboard-controls[Keyboard controls].

=== Language

`interface.language` selects the GUI and tray presentation language: `auto`
(default), `en-US`, or `zh-CN`. Translations are embedded; no language pack
installation is needed.
`auto` uses the first nonempty `LC_ALL`, `LC_MESSAGES`, or `LANG` value, ignoring
encoding and modifier suffixes. English and Simplified Chinese are supported;
unavailable languages, including Traditional Chinese, fall back to English.
Explicit configuration values are `auto`, `en-US`, or `zh-CN` (case-insensitive;
underscores are accepted and normalized to hyphens); other values are errors.
Choose Language in Settings → Interface → Appearance & layout, then Apply to save.
Restart the GUI to apply the saved language to its windows. The tray keeps the
Core service's startup language and requires restarting that service.
CLI output, TUI, command-line help, and localized diagnostics always use automatic
selection from the process environment, independently of `interface.language`.
They do not read configuration for localization. Starting a host or probing media
still loads and validates configuration for the operation itself.
Missing translations fall back to English. Configuration keys, command names,
machine-readable output, paths, and user metadata are not translated. Diagnostic
details may remain in English.

=== Decoding and read buffering

`playback.media_read_buffer_mib` defaults to `2`; accepted sizes are `1`, `2`, `4`, `8`,
and `16` MiB.

`playback.ffmpeg_enabled` defaults to `false`. The default build includes the `ffmpeg`
feature; see link:00_getting_started.adoc#ffmpeg-and-native-only-builds[FFmpeg and native-only builds]. Enabling permits
FFmpeg use on future source opens; it does not load or validate runtime libraries.
Libraries load on the first native-unsupported source in Auto mode, a track opened
with the FFmpeg decoder hint, or an explicit
link:02_library.adoc#metadata-and-favorites[enhanced probe]. Missing libraries
are reported when needed; native decoders continue to work. A load failure is
retained until restart. Disabling stops a track currently decoded through FFmpeg;
native-decoded playback is unaffected.
Runtime availability updates when the first explicit load completes, including
loads initiated by GUI waveform work; an unused extension has no periodic status polling.

[[volume-and-playback-controls]]
=== Volume and playback controls

[[volume]]
`playback.volume_percent` accepts a finite percentage from `0` to `100`, including
fractions, and defaults to `70`. Zero mutes; positive values use a dB-linear
control curve: gain in dB is `0.6 * (percent - 100)`. Thus 50% is -30 dB and
100% is unity gain (no amplification). This approximates uniform perceived
steps; it does not normalize loudness between tracks.
Settings accept fractional percentages; CLI inputs remain integer percentages.
Slider, IPC, and MPRIS values use the same curve, with normalized `0–1` levels
for IPC and MPRIS. Values are not rounded to whole percentages internally.

`playback.replaygain_enabled` defaults to `false`. The desktop Playback settings
switch applies the library's single track gain in dB, without loudness analysis.
Missing values leave playback unchanged; there is no album fallback.
`playback.replaygain_peak_policy` accepts `off` (default) or `prevent_clipping`.
The latter limits ReplayGain using the opened original file's valid track sample-peak
tag. Unknown peaks leave the requested gain unchanged; processed auditions do not
reuse the original peak. This is not a limiter or a guarantee after EQ or device mixing.
See link:04_playback.adoc#replaygain[ReplayGain] for playback scope and
link:02_library.adoc#inline-track-details-edits[Track details] for editing and file tags.

`playback.shuffle` defaults to `false`; `playback.repeat` accepts `off`, `all`, or `one` and defaults
to `off`. `playback.play_count_threshold_percent` defaults to `20` and must be finite and
in `[0, 100)`; zero still requires some confirmed heard time. Edit the threshold
in the configuration file or desktop settings; see
link:02_library.adoc#play-counts-and-recent-tracks[Library] for counting semantics.

`interface.confirm_queue_replace` defaults to `true`. GUI and TUI actions that
replace a non-empty queue ask for confirmation. Disable it in desktop settings
under Playback & Audio → Playback to replace the queue without prompting.
CLI and IPC commands do not prompt.

=== Output and desktop integration

Output selection and application errors are described under
<<output-and-applying-changes,Output and applying changes>> and in
link:04_playback.adoc#output-devices-and-speaker-layouts[Playback output].
`interface.tray_enabled` and `interface.mpris_enabled` both default to `true` and
independently control desktop integration. Tray changes require a Core service
restart; MPRIS changes apply while running. Requirements and recovery are in
link:04_playback.adoc#desktop-tray-and-window-lifecycle[Desktop tray and window lifecycle]
and link:04_playback.adoc#mpris-and-artwork[MPRIS and artwork].

[[logging-and-diagnostics]]
=== Logging and diagnostics

`logging.level` accepts `debug`, `info`, `warning` (default), or `error` and
controls file logging. By default, stderr receives warnings and errors.
Global `--log-level LEVEL` overrides stderr and enabled file logging for this
process's lifetime.

`logging.to_file` defaults to `false`; enabling it writes weekly logs under the
data directory. `logging.max_log_files` accepts `1`–`128` and defaults to `4`.
The appender prunes matching log files when opening or rotating a file, limiting
their count rather than their age or total bytes. Changing the limit takes effect
the next time file logging is enabled or the host restarts. Reopening can leave
fewer files than the limit; with a limit of `1`, it can discard earlier records
from the same week.
Stderr colors are enabled only for a terminal by default. `RIVU_COLOR=always`
forces colors even when redirected; `NO_COLOR` takes precedence over it, and
`NO_COLOR` or `RIVU_COLOR=never` disables colors for both levels and fields.
The timestamp and level letter share the level's color; target and message text
are outside that prefix styling.
File logs never include generated ANSI styling.
Text stderr escapes control characters in event fields at the terminal boundary.
With `--json`, tracing diagnostics instead use one JSON object per line with
`timestamp`, `level`, `target` and `error`; file logging retains its text format
and original field contents independently of the stderr format.

File logging starts after configuration is loaded. Records may be dropped under
load; forced termination can lose pending records.
Preparing an appender can prune files even if configuration persistence later
fails; pruning is not rolled back. Output and level changes still require a
successful configuration save.

[[audio-processing-defaults]]
=== Audio processing defaults

Audio processing additionally uses top-level `[equalizer]`, `[denoise]`, and
`[neural]` tables, `[[equalizer.bands]]`, and named `[[equalizer_presets]]`. The
processing DAG, including node-local parameters, connections and canvas positions,
lives in `[processing_graph]` and its nested
arrays. These are core settings in `config.toml`, not preferences in `layout.json`.
The default graph connects Source directly to Output; the top-level Monitor EQ
and restoration/neural defaults do not implicitly insert graph nodes.
The graph edit revision is a runtime-only optimistic-edit token, not a TOML field.
Unknown graph fields are rejected, as elsewhere in configuration.

`playback.processing_bypassed` defaults to `false`. It bypasses playback
processing without changing `equalizer.enabled` or effect parameters;
see link:07_audio_processing.adoc#playback-bypass[Playback bypass]. Retained
audition selections remain session-owned and are not restored after restart.

For example, this sets Monitor EQ and restoration defaults without constructing
a processing graph:

[source,toml]
----
[equalizer]
enabled = true
preamp_db = -3.0
output_gain_db = 0.0

[[equalizer.bands]]
kind = "peak"
frequency_hz = 1200.0
gain_db = 3.0
q = 0.8

[denoise]
mode = "adaptive"
strength = 1.0
spectral_gain_floor_db = -18.0
wet = 0.8

----

Neural models require explicit preparation; missing manifests leave operations
unavailable rather than triggering downloads. Use `rivu processing setup MODEL`
and follow the full
link:07_audio_processing.adoc#explicit-neural-installation-and-offline-deployment[neural setup guide]
for bundle selection, activation and compatible worker/interpreter paths. Paths
are literal; no shell expansion occurs.
See link:07_audio_processing.adoc[Audio processing] for graph editing, filter
semantics, shared and isolated Python environments, licensing, CLI examples and bounds.

[[desktop-settings]]
== Desktop settings

Settings groups Library, Playback & Audio, Interface, and Visualizations.
Interface uses one scrollable page; Visualizations has General and style-specific
pages. General separates Appearance from Frequency analysis. New-panel defaults
affect only subsequently created instances. Sidebar groups scroll when needed;
hover truncated labels, fields and errors for their full text, accepted ranges
and application timing. Errors also provide Copy. See
<<desktop-keyboard-navigation,Desktop keyboard navigation>> for dropdown controls.

Add folders from Library; Settings lists them individually for removal. Paths are
literal, not delimited text, and retain semicolons and trailing spaces. Removal
changes only the draft until Apply. Empty field hints are not submitted values;
clearing an optional numeric override restores inheritance on Apply. Untouched
numbers retain their TOML precision even if Settings displays fewer decimal places.

Media read buffering affects future opens, including finite PCM reads, without
reopening the current track. The application-menu Visualizations entry toggles
enablement immediately, outside the Settings draft, but does not write the
configuration file immediately. Apply or a normal Core shutdown saves the value.
Detailed controls remain under Settings → Visualizations; see
link:06_visualizations.adoc#visualization-enablement[Visualization enablement].
Draft merging, validation, Discard and save failures follow
<<apply-and-validation,Apply and validation>>.

Interface → Layout includes Layout snapping and Layout grid spacing. These save
`interface.layout_snap_enabled` (default `true`) and `interface.layout_snap_grid_px` (default `16`,
integer `1`–`64` logical pixels before interface scaling) in `config.toml`.

Library → Covers & cache includes Encoded cover file limit (MiB), saved as
`interface.artwork_file_limit_mib`: an integer from `1` to `64`, default `16`.
It limits each encoded embedded or directory image, not its decoded memory.
Apply saves the value; restart the entire application, including its core, to use
the new limit. Closing and reopening only the window does not apply it.

Library → Covers & cache includes Cover decode budget (MiB per cover), saved as
`interface.artwork_decode_budget_mib`: an integer from `1` to `1024`, default `64`.
It limits the retained decoded frames of each cover, not total process or GPU
memory. Different covers and windows add their own costs. Apply re-evaluates open
covers, including previously rejected images; an over-budget image shows the
default cover rather than a partial animation. Increasing the budget does not
remove other image-admission limits. See
link:22_cache.adoc#artwork-lookup-retention[Artwork resource boundaries].

For Artwork defaults and per-panel controls, see <<artwork,Artwork>>.

[[animation]]
=== Animation

Settings → Interface → Animation exposes `interface.animation_fps`, an integer
from `0` through `240` (default `0`). It caps animation requests for Artwork,
Spectrum, Spectrogram and Audio Visualizer panels; `0` follows native window
frames without timer throttling. Lower caps reduce rendering work at the cost
of less smooth motion. The cap does not force idle panels to refresh, change
audio analysis or Waveform processing, or throttle input and business updates.
It is not a hard limit on total window submissions and does not control textures.
Apply updates open panels without restarting or resetting rotation.

=== Appearance and library display

`interface.theme` in `config.toml` selects the shared desktop and terminal theme.
Presets are built in; no separate theme files are needed. Choose Theme in
Settings → Interface → Appearance & layout, then Apply to save and update open
clients without restarting. Discard leaves the active theme unchanged.
The TUI adapts each preset to semantic track-field, playback-state, input, and
operation-feedback colors without changing the desktop palette.

[cols="1,2"]
|===
|Theme |Accepted value
|Rivu Dark (default) |`rivu_dark`
|Tokyo Night |`tokyo_night`
|Tokyo Night Day |`tokyo_night_day`
|===

Rivu Dark is a blue-gray preset; Tokyo Night Day is a light theme. The Tokyo Night
presets adapt https://github.com/folke/tokyonight.nvim[Tokyo Night]. Unknown names
are configuration errors; other applications' theme files are not imported.
Themes do not change visualization backgrounds, signal palettes, canvas labels,
cursor colors, or artwork.

The application-menu *Textures* entry and Settings → Interface → *Textures* open
the same live material card. Changes preview and save immediately, outside the
Settings draft. Closing the card returns to the workspace or the existing
Settings draft, according to its entry point, without applying or discarding
that draft. Closing it or restarting the desktop retains the selected preset,
enable state and each preset's adjustments. Settings Discard does not undo those
independently saved changes. Save failures are reported rather than silently
treated as saved.
The application menu's texture status switch toggles effects without opening the
card; the item body and Settings entry open the card without toggling effects.

[source,toml]
----
[interface.material]
enabled = true
default_artwork_fallback = true
selected = "still_water"
----

Omitting this table leaves effects disabled with `satin` selected, ready to enable.
The effects switch preserves the selected preset and its adjustments. While
effects are off, preset selection, adjustments, Experimental expansion and Reset
are read-only; enable effects before editing. Preset identities are stable
snake_case names, independent of translated labels; `still_water` is displayed as
Rain ripples. No-effect rendering is controlled solely by `enabled = false`.

`default_artwork_fallback` defaults to `true`. The image icon button to the right
of Experimental controls whether missing, rejected or failed covers use the
bundled SVG in artwork-dependent material backgrounds. Turning it off preserves
real-cover backgrounds and all other material effects. It does not affect cover
panels, About or MPRIS artwork. Reset and preset changes preserve this shared switch.

Edited parameters are stored under
`[interface.material.presets.<preset>]`; Reset restores only the selected preset.
These preferences are independent of theme colors and GPU resource limits.
Each saved preset table contains the complete parameter set; use the card to
create one before editing it by hand. All values must be finite and nonnegative.
Opacity, feather, highlight, grain and edge fade are at most `1`; wave is at most
`16`, cover blur `24`, backdrop blur `32`, and transition seconds and speed `3`.
Color steps is `0` (off) or an integer from `2` to `16`.
See link:24_layout.adoc#material-appearance[Material appearance] for preset
compositions and rendering boundaries, and link:10_upgrading.adoc[Upgrading]
for Core/client compatibility when upgrading.

Scene filters have separate per-window limits under Settings → Visualizations →
General → Appearance, after the shared GPU buffer budget:

[cols="2,2,1",options="header"]
|===
|`[interface]` key |Accepted range |Default
|`gpu_filter_budget_mib` |`16`–`1024` MiB of filter textures |`128`
|`gpu_filter_max_depth` |`1`–`4` nested filter layers |`4`
|===

Apply updates these limits in open windows for subsequent frames; no restart is
needed. Discard leaves the active limits unchanged. When a frame exceeds either
limit, all scene filters are skipped for that frame while the base interface
remains visible. This does not change the selected material; filters can resume
when the frame fits the limits. Water-surface count limits are independent and
skip water effects separately. The texture budget is not a total GPU-memory cap
and is separate from the startup-only shared GPU buffer budget described below.

`interface.gpu_material_budget_mib` accepts `16`–`1024` MiB, default `64`. Change it
under Settings → Visualizations → General → Appearance, then restart the
GUI. It limits shared material buffers per window, not total GPU memory.
Long Spectrogram histories may use fewer frequency rows to fit this budget;
time resolution and playback audio are unchanged. See
link:22_cache.adoc#visualization-caching[Visualization caching] for resource scope.

Search or browse installed fonts in Settings, including `monospace`, `sans-serif`,
and `serif`. Enter or click to select; custom family names are accepted.
The empty field identifies the `monospace` fallback; hover for font-search guidance.

`interface.font` defaults to `monospace`, including empty values. Names must not
contain control characters or exceed 128 UTF-8 bytes. Fontconfig system and user
rules (`~/.config/fontconfig/fonts.conf`) select families and missing-glyph
fallbacks. Restart the GUI after changing those rules. Unavailable primary fonts
produce a warning and fall back to `sans-serif`.

Fontconfig hinting, subpixel, and synthetic-bold settings do not control GUI
rendering. Complex shaping and named variable-font instances may differ from
other applications.

`interface.font_size_pt` accepts integer point sizes from `8` to `18`, default `12`
(16 logical pixels before interface scaling). Apply to update open windows.
It adjusts desktop text and icon glyphs, not plot annotations or terminal text,
and is independent of `interface.scale`.

`interface.scale` accepts finite values from `0.75` to `2.0` (default `1.0`) and
adjusts desktop controls and list density independently of the desktop's display scaling. Menus and editor dialogs
stay within the window; scroll them when not all content fits. Settings dropdowns
close when their control moves or the interface scale changes; reopen them at
the new position.
GUI icons use the system-installed Symbols Nerd Font Mono independently of
`interface.font`. The optional `embed-nerd-font` Cargo feature embeds a build-host font;
see link:00_getting_started.adoc#font-embedding[Font embedding] for requirements and licensing.
The TUI requires a Nerd Font or Nerd Symbols fallback in the displaying terminal.
For SSH, configure the local client terminal; installing fonts on the server
does not supply terminal glyphs. Missing glyphs can appear as boxes or blanks.
Use the Mono variant of Symbols Nerd Font for single-cell icons. The TUI shares
`interface.theme`, but its width-dependent information columns are built in;
desktop font, scale, and Library column settings do not configure the terminal client. See
link:08_tui.adoc#terminal-client[Terminal client] for browsing and full details.

`interface.library_columns` selects desktop Library information columns. Its
boolean keys are `artist`, `album`, `duration`, `codec`, and `bitrate`;
`duration` and `codec` default to `true`. Omitted keys retain those defaults; set all five
to `false` for names only. Change them without restarting from the Library
right-click menu → `Track information`. Both Library views share the saved
selection; full tooltip information is unaffected. See
link:02_library.adoc#desktop-selection-and-directory-tree[Library display].

[[output-and-applying-changes]]
=== Output and applying changes

`playback.output_device` selects the default PipeWire sink when omitted, or an
exact name from `rivu playback devices`. `playback.pipewire_auto_mix` defaults to
`true`; disable it to require a compatible speaker layout without remixing.
Selection syntax, unavailable-device recovery, output rebuilding, normalization,
and source-rate negotiation are documented in
link:04_playback.adoc#output-devices-and-speaker-layouts[Playback output].

An unavailable output target can be saved; applying it reports an audio error and
can stop playback while retaining the saved selection. See
<<apply-and-validation,Apply and validation>> for the shared Apply contract.

For Artwork panel options, see <<artwork,Artwork>>; for their persistence, see
link:05_layout.adoc#layout[Desktop layout and panels]. Visualization panel controls and
parameters are documented in link:06_visualizations.adoc[Visualizations].

Saving library roots does not scan or enqueue tracks; use `Scan paths` in Library.
Each folder entry shows its recursive catalog track count and audio file size in
IEC units. Sizes use existing scanned metadata, not a filesystem traversal or
disk-usage measurement. Missing tracks retain their last scanned size; CUE
segments count as tracks while their shared source path contributes bytes once.
Separate source paths count separately even when their content is identical.
Unscanned folders show zero after loading. Statistics load asynchronously when
Settings opens and refresh after catalog changes or draft-root changes. Removing
a root changes the draft only; Discard restores the saved roots.

[[artwork-cache-maintenance]]
=== Artwork cache maintenance

Settings → Library → Covers & cache also provides manual maintenance of encoded
cover files on disk. Enter a positive whole number in `Expire files older than (days)`
(initially 30), then choose `Calculate usage` or `Clean expired`. Neither opening
Settings nor starting Rivu scans this directory. These actions run immediately
in the background, do not require Apply, and are not undone by Discard.

The report shows file counts and encoded bytes for total usage, expired
candidates, successful removals, and failures. Cleanup totals describe usage
before deletion. Age is based on file modification time, not recent playback;
reusing a file does not update its age. Cleanup can remove expired originals and
thumbnails even while GUI or MPRIS consumers retain them. It never removes audio
sources or the bundled GUI icon.

If cleanup affects cover display, restart Rivu including its background Core
service; reopening only the GUI may not restore MPRIS covers.

Usage and cleanup include generated thumbnails, which can be regenerated without
removing the original cover. Maintenance handles only managed cache files; it
does not follow symlinks or scan arbitrary subdirectories.

Inspect reported errors and retry after fixing access or permissions. Maintenance
has no automatic schedule or total-capacity guarantee, and the age input is not
saved to `config.toml`. Ownership and retention rationale are documented in
link:22_cache.adoc#artwork-lookup-retention[Artwork lookup retention].

[[artwork]]
=== Artwork

The `Artwork` panel (`artwork` in layout files) follows the current playback
track independently of Track details and does not require album metadata.
Its configuration is:

[source,toml]
----
[interface.artwork]
style = "halo"
mode = "rotating"
period_seconds = 20.0
direction = "clockwise"
----

Settings → Interface → Artwork and `[interface.artwork]` supply defaults for new
panels, not live overrides of existing instances. Saved panels missing options
initialize from the current defaults.

`style` accepts `plain`, `vinyl`, `glass`, `halo` (default), `metal`, `card`, or
`duotone`. All styles support static and rotating modes; changing style preserves
the rotation angle. `mode` accepts `static` or `rotating` (default).
`period_seconds` is the time for one full circle and must be finite and greater
than zero; there is no additional upper limit. `direction` accepts `clockwise`
(default) or `counterclockwise`. Static mode retains the rotation parameters.

Each panel's right-click Style and Rotation actions apply immediately to that
instance. Artwork settings edits its style, mode, period and direction with Apply
and Discard; Apply fails if the instance no longer exists. These choices survive
docking and layout duplication in session memory; saving them is covered under
link:05_layout.adoc#layout[Desktop layout and panels].

All Artwork panels use the shared `interface.animation_fps` cap described under
<<animation,Animation>>. Playback-driven rotation and animated source covers have
separate clocks; their playback, visibility and visualization-enable behavior is
documented in link:05_layout.adoc#artwork-panel[Artwork panel]. Track details'
full, static preview does not use the animation cap.

[[configuration-schema]]
== Configuration schema

The application reads only the current configuration schema; explicit noncurrent
versions are rejected. Its authority is documented under
link:27_migration.adoc#configuration-schema[Configuration schema]. Normal saves
preserve an omitted `schema_version` rather than adding it.
Declaring the current schema does not bypass field or value validation. Malformed
TOML and file-access errors retain their specific causes.

`rivu-migrate` validates the selected configuration without rewriting it. Its
commands and offline ownership requirements are documented in
link:27_migration.adoc[Database and configuration migration]. Configuration and
database schemas are independent of the application release number; layout files
have their own contract under link:05_layout.adoc#layout-file[Layout file].
