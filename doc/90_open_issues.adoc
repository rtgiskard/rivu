== Open and deferred

=== Portal file chooser cache warning

Status: deferred, 2026-10-12. Keep the published `ashpd` 0.13.13 dependency;
no vendor backport, upstream Git replacement, or log filtering.

Clicking the Library `+` button prints the following warning on each invocation:

[source,text]
----
zbus::proxy: Failed to populate properties cache via GetAll: org.freedesktop.DBus.Error.UnknownMethod: Object does not exist at path “/org/freedesktop/portal/desktop/request/…”. Property change streams will not produce values.
----

The user confirmed successful folder selection and library-root addition. ashpd
creates a property-cached Request proxy before `OpenFile` creates the transient
object, so `GetAll` fails; results arrive through an independent `Response`
signal. Playlist import/export share this mechanism.

Upstream fix:
https://github.com/bilelmoussaoui/ashpd/commit/e9e38113ad075042fcc48b8401010ca5f905db55[Disable property caching for Request/Session objects].
The fix is on upstream mainline, not in the 0.13.13 release branch inspected
at the time of investigation. Revisit when a compatible published release
includes it; verify successful selection, cancellation, and absence of this
warning without suppressing other logs.

=== Queue feedback while waiting for a query worker

Status: deferred, 2026-10-18. The open policy question is whether loading
feedback should include time waiting for an obsolete physical worker to retire.

Queue loading text starts its 150 ms delay when a page query is submitted. After
search replacement or hide/reopen, unloaded rows can remain blank while an obsolete
physical worker retires. This is a scheduling observation from code inspection,
not a reproduced GUI failure or confirmed permanent stall: retirement wakes the
current demand automatically.

If feedback is extended to this waiting interval, its identity and elapsed delay
must follow current demand without reviving obsolete search feedback or bypassing
the occupied worker. Verify search replacement, hide/reopen and failed-page retry
behind a query longer than 150 ms. See
link:22_cache.adoc#query-projection-retention[Query projection retention].

=== Different data directories sharing one database file

Status: deferred, 2026-10-29; conditional ownership risk, not observed corruption.

Exclusive ownership identifies the data-directory inode, not the database inode.
Distinct directories whose `library.db` aliases the same file can therefore
coexist. SQLite locking does not establish the application's offline migration
precondition. A fix must define supported database aliases and involve both the
host and maintenance tool; a maintenance-only lock is insufficient. The
link:26_migration.adoc#supported-source-formats[supported database upgrade] performs
its transformation under this data-directory exclusion. Database-file alias
protection remains unresolved.

== Resolved investigations

[[pcm-owner-retirement-coverage]]
=== PCM owner-drop descriptor retirement

Status: resolved in implementation, 2026-11-06; verified under DEC-010.

The original CI correction correctly allowed fd-number reuse but lost the owner-fd
release check. The cross-process regression now compares the reader-pinned memfd's
device/inode with metadata of the old advertised path. A missing path or replacement
passes; the original object fails, as do unexpected metadata errors. Native PCM
remains checked after owner Drop. A real SharedPcmWindow smoke distinguished an
unreleased owner, close without reuse, and reuse by another memfd or a socket while
preserving the original mapped content. No production owner-fd leak was observed.
Ownership and unchanged production attach admission:
link:91_design_decisions.adoc#DEC-010[DEC-010].

[[socket-retirement-test-isolation]]
=== Socket retirement tests and fork inheritance

Status: resolved in implementation, 2026-11-06; verified under DEC-010.

Immediate IPC rebind/EOF and desktop singleton reacquisition checks now construct
their fixtures in bounded isolated test processes, excluding listeners inherited
by unrelated parallel tests. App startup shares the same guarded runner. Actual
child directories in ownership tests retain File pins; GUI fixtures use the shared
pinned directory helper. Ordinary test concurrency is unchanged.

The investigation's controlled fork/exec barrier retained EADDRINUSE and delayed
EOF after local close with or without a directory pin; exec released both. This
explains the precondition gap, not a reproduced Rust-suite failure or the original
PCM CI failure. Directory pins prevent inode recycling, not listener inheritance.
The client crate remains unchanged: no subprocess entry was found in its test binary.
Scope and cleanup boundaries: link:91_design_decisions.adoc#DEC-010[DEC-010].

[[neural-retirement-pid-reuse]]
=== Neural retirement checks and numeric PID reuse

Status: resolved in implementation, 2026-11-06; verified under DEC-010.

The cancellation-after-stdout-EOF and unwind regressions no longer wait or signal
an already-reaped numeric PID. Each runs in an isolated process, checks ordinary
SIGCHLD semantics and an initially empty child set, then requires non-reaping
P_ALL observation to report ECHILD after Finished but before event application or
Core retirement. Live and zombie interpreters fail the assertion.

Inherited lifelines replace the shell busy loops. Their guards retain both endpoints
through asynchronous spawn and the retirement assertion; failure closes the sole
peer before Core joins. Stdout-closed readiness, progress-induced unwind, task-wait
ordering and subsequent processing recovery remain covered.

The investigation forced stale-PID reuse in a disposable namespace; the old cleanup
killed a replacement while a retained-pidfd control left it alive. That was not an
observed production reaping leak. The inherited-endpoint startup/failure probes
establish fixture exit, not descendant reaping. Design and evidence boundaries:
link:91_design_decisions.adoc#DEC-010[DEC-010].

=== Structural GUI demand reconciliation during transport updates

Status: resolved in implementation, 2026-10-29.

Panel membership, active tabs and instance preferences now reconcile at structural
changes rather than every transport update. Source, seek, Stop and progressive
waveform handling remain dynamic. See link:24_layout.adoc[GUI layout].

Historical nested-Wayland and TUI checks covered playback, seek, Stop, toggles,
resize, locking and window recreation. Temporary probes observed no workspace
rediscovery on transport-only changes; these were traversal counts, not frame-time
measurements. The nested backend did not report occlusion reliably, so hidden-window
and shutdown demand relied on deterministic regressions.

=== Stable configuration in high-frequency System IPC state

Status: resolved in implementation, 2026-10-29.

System and Configuration now have independent sections and revisions. Omitted
sections retain client values; configuration-only changes wake Watch, and restart
requires a fresh Hello. See link:21_ipc.adoc#revisions-and-watching[Revisions and watching].

A historical comparison with 256 long-path roots and three clients reduced each
client's 100 runtime reads from 3,444,600 to 20,900 bytes, repeated three times.
Selective reads and restart recovery were exercised. This is transfer/work-count
evidence, not latency or RSS measurement.

Update, 2026-11-05: Processing also has its own section and revision. Watch selects
the sections its consumer needs; the TUI excludes processing task updates.

=== Query timeout and physical worker retirement

Status: resolved in implementation, 2026-10-19.

The 12-second GUI deadline ends logical waiting without releasing the physical
worker slot. Late results cannot publish; the latest demand starts only after
physical retirement. See
link:22_cache.adoc#query-projection-retention[Query projection retention].

Update, 2026-11-05: Demand replacement and logical timeout cancel the corresponding
read through IPC, including executing SQL. Cancellation still waits for a reply or
disconnection before releasing the physical slot; it does not cancel accepted writes.

=== Multi-root scan missing reconciliation

Status: resolved in implementation, 2026-10-31.

A historical 1,000-root/1,000-absent-source probe counted 500,500 root predicates

=== Repeated playlist import identity resolution

Status: resolved in implementation, 2026-10-31.

Repeated import occurrences reuse identity lookups within that import while
preserving order, multiplicity, admission rules and separate scan/playlist commits.
No identity cache survives the import.

A historical CLI probe counted five identity queries across an import with 10,000

and multiplicity; these are query counts, not latency or RSS measurements. See

=== PCM continuity and frontend readiness from branch review

Status: resolved in implementation, 2026-11-06.

Review of `wip/commit-review-20261104` found unchanged settings revoking PCM
identity, prefetch exceeding fixed native retention, skipped growing tails and
unconsumed clearing frames. Terminal entry operations could retry an unchanged
failed playlist title, and executable bootstrap waited before terminal input
could cancel readiness. These behaviors were corrected on mainline owners rather
than by merging the old branch; the already-absorbed palette fix was retained.

Regression checks covered unchanged settings, growing tails, title failures and
shared-sample overwrite/reconfiguration. Against a stalled Hello in a real PTY,
`q`, Ctrl-C and SIGTERM each exited, restored terminal settings and left the
independent socket owner accepting connections. This does not establish device
A/V synchronization, latency or physical GPU retirement. Retention sizing and
before/after frame counts are in link:91_design_decisions.adoc#DEC-007[DEC-007];
current mechanisms belong in link:21_ipc.adoc[PCM transport] and
link:04_playback.adoc[frontend controls].

The separate GUI complexity review retains cache/animation ownership, with
independent disk-reload and cached-consumer behavior coverage rather than a
production redesign; see link:91_design_decisions.adoc#DEC-008[DEC-008].
