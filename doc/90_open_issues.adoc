== Open and deferred

[[pipewire-context-retention]]
=== Native PipeWire context retirement retains libdbus allocations

Status: reproduced, unresolved, 2026-11-07. No production fix authorized.

On PipeWire 1.6.10 / libdbus 1.16.2, each native output creates a fresh PipeWire
context. Stop joins its owner and destroys the connection, but allocations from
the realtime module's libdbus calls remain.

Two isolated runs of debug artifact `0408252db99373b9` used an eight-second
48 kHz stereo PCM source, three warmup reopens and 120 additional reopens, with
MPRIS/tray disabled. Exact jemalloc profiles each showed 472,320 retained libdbus
bytes across 4,080 objects: 3,936 bytes and 34 objects per reopen. Disabling
`module-rt` reduced total live-byte growth to 992. FD/thread counts returned to
baseline in a separate glibc run.

A standalone `pw_context` create/destroy loop also reproduces growth; disabling
the RT module or keeping libdbus loaded greatly reduces it. The exact upstream
cleanup defect remains unidentified. These controls are not adopted fixes.

Reconsider context/module ownership or a dependency fix while preserving realtime
scheduling, strict routing, recovery and physical retirement; see
link:91_design_decisions.adoc#unapproved-candidates[candidates]. This small
per-reopen retention does not explain GUI/full-waveform RSS growth; observed
task-buffer release and allocator retention are recorded in
<<waveform-rss-retention,the waveform RSS investigation>>.

[[waveform-rss-retention]]
=== Full-waveform buffer release and residual RSS retention

Status: investigated, residual attribution unresolved, 2026-11-07. No trimming
policy adopted.

The 2026-11-07 nested-Wayland check (debug `98a9d345c85c3292`, glibc 2.44,
240-second stereo WAVs at 48/44.1 kHz, tray/MPRIS disabled) confirmed that full-read

After twelve further completions and eight switch-driven cancellations, about

The separate <<pipewire-context-retention,native retention>> remains unresolved.

=== Portal file chooser cache warning

Status: deferred, 2026-10-12. Keep the published `ashpd` 0.13.13 dependency;
no vendor backport, upstream Git replacement, or log filtering.

Clicking the Library `+` button prints the following warning on each invocation:

[source,text]
----
zbus::proxy: Failed to populate properties cache via GetAll: org.freedesktop.DBus.Error.UnknownMethod: Object does not exist at path “/org/freedesktop/portal/desktop/request/…”. Property change streams will not produce values.
----

The user confirmed successful folder selection and library-root addition. ashpd
creates a property-cached Request proxy before `OpenFile` creates the transient
object, so `GetAll` fails; results arrive through an independent `Response`
signal. Playlist import/export share this mechanism.

Upstream fix:
https://github.com/bilelmoussaoui/ashpd/commit/e9e38113ad075042fcc48b8401010ca5f905db55[Disable property caching for Request/Session objects].
The fix is on upstream mainline, not in the 0.13.13 release branch inspected
at the time of investigation. Revisit when a compatible published release
includes it; verify successful selection, cancellation, and absence of this
warning without suppressing other logs.

=== Queue feedback while waiting for a query worker

Status: deferred, 2026-10-18. The open policy question is whether loading
feedback should include time waiting for an obsolete physical worker to retire.

Queue loading text starts its 150 ms delay when a page query is submitted. After
search replacement or hide/reopen, unloaded rows can remain blank while an obsolete
physical worker retires. This is a scheduling observation from code inspection,
not a reproduced GUI failure or confirmed permanent stall: retirement wakes the
current demand automatically.

If feedback is extended to this waiting interval, its identity and elapsed delay
must follow current demand without reviving obsolete search feedback or bypassing
the occupied worker. Verify search replacement, hide/reopen and failed-page retry
behind a query longer than 150 ms. See
link:22_cache.adoc#query-projection-retention[Query projection retention].

=== Different data directories sharing one database file

Status: deferred, 2026-10-29; conditional ownership risk, not observed corruption.

Exclusive ownership identifies the data-directory inode, not the database inode.
Distinct directories whose `library.db` aliases the same file can therefore
coexist. SQLite locking does not establish the application's offline migration
precondition. A fix must define supported database aliases and involve both the
host and maintenance tool; a maintenance-only lock is insufficient. The
link:26_migration.adoc#supported-source-formats[supported database upgrade] performs
its transformation under this data-directory exclusion. Database-file alias
protection remains unresolved.

== Resolved investigations

[[socket-eof-fixture-gaps]]
=== Drop-driven socket EOF isolation

Status: resolved and verified, 2026-11-06; see DEC-010 for the feature matrix.

Frontend startup cancellation, IPC abandoned-query admission, query/Watch
disconnect handling, PCM aggregate disconnect, and GUI full waveform cancellation
now construct their sockets inside bounded single-test subprocesses. Their
Drop-driven EOF/cancellation assertions and operation timeouts remain unchanged.
A controlled socket-pair fork/exec barrier kept a 2-second read from observing EOF
after local peer close; exec then permitted EOF without retry. This proves the
missing ownership precondition, not a reproduced failure of these Rust cases.

Directory identity pins do not close inherited socket FDs. Explicit write shutdown
already protects the PCM/waveform pipelining fixtures from this particular EOF
dependency. Unrelated test binaries without subprocess entry points retain their
ordinary concurrency. The now-isolated App shutdown cases no longer retain the
obsolete process-wide logging-session test lock.
See link:91_design_decisions.adoc#DEC-010[DEC-010].

[[socket-directory-pin-gaps]]
=== Abstract socket directory identity fixtures

Status: resolved and verified, 2026-11-06; see DEC-010 for the feature matrix.

The root App duplicate-start and blocking-pool IPC cases, desktop-host activation
after disconnect, GUI waveform cancellation/resumption, and visual core-instance
rejection now use the existing pinned directory fixture. The extra full-scan
mock request/response forwarding test was removed rather than retaining its
raw-listener fixture; source identity behavior and real server authority checks
remain covered.
The duplicate empty-callback gap test was also removed; its full helper scenario
remains exercised by the actual GUI staging regression.

Both root and GUI test binaries contain subprocess launches. Without a pin, a
child could retain an inherited listener after local fixture deletion and, if the
temporary filesystem recycled its directory inode, a later fixture could collide
with the stale abstract address. No inode-reuse collision was reproduced in this
review. Pins and link:#socket-eof-fixture-gaps[EOF isolation] address different
lifetimes; neither substitutes for the other.

[[model-boundary-retirement]]
=== Obsolete neural PCM boundaries retained through inference

Status: resolved in implementation, 2026-11-06.

Materializing a model input previously released only unreachable original source;
obsolete model boundaries remained charged until the next inference completed.
The same reachability traversal now retires both before inference output allocation,

[[denoise-hum-work-admission]]
=== Denoise hum arithmetic-work admission

Status: resolved, 2026-11-06. Realtime admission now charges active hum harmonics
and width-dependent impulse repair. No measured device underrun or audible dropout.

The original realtime estimate did not depend on enabled hum harmonic count,
although each frame/channel executed every configured notch even with spectral
Off. The pre-fix public `GraphRunner::plan` / prepare / process probe used
48 kHz, 18 channels, two serial full-wet Denoise nodes, hum at 50 Hz, spectral
Off and repair disabled. All configurations were admitted and processed a
256-frame block with finite output:

[cols="1,1,1",options="header"]
|===
|Harmonics per node |Estimated work units/second |Hum scalar arithmetic operations/second
|1 |248,352,000 |15,552,000
|8 |248,352,000 |124,416,000
|32 |248,352,000 |497,664,000
|===

The final column counts five multiplications and four add/subtracts per notch,
excluding validation, blending and buffer work. Identical charges despite
independently increasing notch work exposed the admission gap; these source-derived
counts are not hardware FLOPs, timings or proof of a device-deadline failure.
The pre-fix probe linked a locked, no-default-features audio build with SHA-256
prefixes `c380c04c82f43702` for `crates/rivu-audio/src/graph.rs` and
`2c2aa07e76bc6336` for `crates/rivu-dsp/src/denoise/processor.rs`.

The corrected planner charges active hum harmonics and width-dependent repair;
the 300,000,000-unit limit, state admission, format validation, bypass and explicit
execution-mode semantics are unchanged. Current allowances are documented in
link:27_audio_processing.adoc[Audio processing budgets].

A standalone post-fix execution admitted the one-harmonic graph at 269,088,000
units/second and matched 4,096 frames exactly against two direct DSP processors.
The eight- and 32-harmonic graphs were rejected. At 48 kHz stereo with six repair
nodes, width 1 remained admissible while width 8 was rejected. Behavioral
regressions cover disabled effects, Wet=0 and independently disabled hum/repair
with spectral processing still active; existing bypass format/Profile rejection
coverage remains unchanged. These are admission and sample-equivalence checks,
not CPU-time or device-deadline measurements.
The separate state-budget decision remains
link:91_design_decisions.adoc#DEC-003[DEC-003].

Status: resolved in implementation, 2026-11-06; verified under DEC-010.

The original CI correction correctly allowed fd-number reuse but lost the owner-fd

[[socket-retirement-test-isolation]]
=== Socket retirement tests and fork inheritance

Status: resolved in implementation, 2026-11-06. Follow-up
link:#socket-eof-fixture-gaps[EOF] and link:#socket-directory-pin-gaps[identity fixture]
corrections are recorded separately.

The corrected IPC rebind/EOF and desktop singleton reacquisition checks construct
their fixtures in bounded isolated test processes, excluding listeners inherited
by unrelated parallel tests. App startup and shutdown share the same guarded
runner; normal shutdown and final-save failure retain immediate reacquisition
checks. Actual child directories in ownership tests retain File pins; GUI and App

[[neural-retirement-pid-reuse]]
=== Neural retirement checks and numeric PID reuse

Status: resolved in implementation, 2026-11-06; verified under DEC-010.

The cancellation-after-stdout-EOF and unwind regressions no longer wait or signal
an already-reaped numeric PID. Each runs in an isolated process, checks ordinary
SIGCHLD semantics and an initially empty child set, then requires non-reaping
P_ALL observation to report ECHILD after Finished but before event application or
Core retirement. Live and zombie interpreters fail the assertion.

Inherited lifelines replace the shell busy loops. Their guards retain both endpoints
through asynchronous spawn and the retirement assertion; failure closes the sole
peer before Core joins. Task-wait ordering and subsequent processing recovery
remain covered. The separate
link:#neural-unwind-trigger-coverage[unwind trigger observation] now excludes ordinary early failures.

The investigation forced stale-PID reuse in a disposable namespace; the old cleanup
killed a replacement while a retained-pidfd control left it alive. That was not an
observed production reaping leak. The inherited-endpoint startup/failure probes
establish fixture exit, not descendant reaping. Design and evidence boundaries:
link:91_design_decisions.adoc#DEC-010[DEC-010].
