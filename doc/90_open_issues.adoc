= Open issues

== Portal file chooser cache warning

Status: deferred, 2026-10-12. Keep the published `ashpd` 0.13.13 dependency;
no vendor backport, upstream Git replacement, or log filtering.

Clicking the Library `+` button prints the following warning on each invocation:

[source,text]
----
zbus::proxy: Failed to populate properties cache via GetAll: org.freedesktop.DBus.Error.UnknownMethod: Object does not exist at path “/org/freedesktop/portal/desktop/request/…”. Property change streams will not produce values.
----

The user confirmed that the folder chooser opens and adding a library root
succeeds. The warning comes from ashpd constructing a transient Request proxy
with property caching enabled before sending `OpenFile`. The Request object
has not yet been created, so the cache's `GetAll` fails; selection results use
an independent `Response` signal. Playlist import/export use the same request
mechanism and can be affected as well.

Upstream fix:
https://github.com/bilelmoussaoui/ashpd/commit/e9e38113ad075042fcc48b8401010ca5f905db55[Disable property caching for Request/Session objects].
The fix is on upstream mainline, not in the 0.13.13 release branch inspected
at the time of investigation. Revisit when a compatible published release
includes it; verify successful selection, cancellation, and absence of this
warning without suppressing other logs.

=== Popup latency is unresolved

The user reports a roughly 400 ms delay from clicking Add until the chooser
appears, on every invocation; this is a subjective estimate, not a timed GUI
measurement. A throwaway probe against the current session bus measured 30
warmed iterations per variant, alternating their order:

[cols="3,1,1",options="header"]
|===
|Request preparation |Median |Min–max
|Current cache + version read + Response subscription |1.439 ms |1.338–1.556 ms
|No cache, no version read + Response subscription |0.399 ms |0.353–0.536 ms
|===

This probe reconstructed request preparation; it did not measure the release
application's click-to-visible-window path. The measured difference does not
explain the reported delay. It also removed the version read, whereas the
upstream warning fix retains that read. GPUI scheduling and portal window
creation/display remain unmeasured; do not claim the warning fix resolves
popup latency.

== Local GPUI rendering extensions

Status: maintained local patch, 2026-10-14. `Cargo.toml` overrides `gpui` and
`gpui_wgpu` with `vendor/gpui` and `vendor/gpui_wgpu`. The upstream baseline is
https://github.com/zed-industries/zed/tree/df48a139ce9c292738b523252c12f044697e673f[Zed revision df48a139ce9c292738b523252c12f044697e673f];
the remaining GPUI platform crates keep that same pinned revision. This is a
rendering capability patch, not a replacement GUI framework or a dependency
upgrade. The standalone vendor manifests retain the pinned dependency sources.

`vendor/gpui_wgpu` has an isolated regression-test workspace so its shader and
headless GPU tests can run without making the copied upstream crates Rivu's
workspace lint targets. This keeps the application checks scoped to Rivu,
without suppressing upstream warnings or mixing framework cleanup into the
rendering patch. Test-only font/image fixtures retain their upstream licenses;
the standalone test command is documented in
link:23_visuals.adoc#_pinned_gpu_extensions[Pinned GPU extensions].

=== Why the patch is needed

* *GPU image transforms:* the Album artwork panel rotates the decoded cover
  without generating or uploading a new bitmap for each angle. `Img` forwards
  the existing transformation matrix through image painting to the WGPU sprite
  shader. Local image coordinates also drive rounded-image coverage, while the
  screen-space content mask still clips the result. Both are needed to rotate
  the actual cover without moving its circular edge or losing panel clipping.
* *Caller-authored path textures:* `Window::paint_path_with_texture` fills actual
  path geometry with a caller-owned `RenderImage`, using `path.bounds` as the
  texture mapping rectangle. The pinned plain-path fill could not express
  Spectrum's full authored cubic palette. The former workaround repeated the
  same geometry for masked two-stop linear intervals; it changed the intended
  color transition and multiplied path submissions. Spectrum now supplies one
  shared vertical palette image and submits its body geometry once per plot.
  Retaining the old stitched colors or pixel equivalence is not an acceptance
  requirement; preserving the authored smooth palette is.

The Rust scene records, WGPU pipeline/bindings, and WGSL/WebGL shader layouts
change together so image transforms and path texture coordinates reach the
fragment shader consistently. Textured paths use the existing image atlas,
path antialiasing, opacity and intermediate compositing. Adjacent paths using
the same atlas texture can batch without changing submission order; plain
fills retain their untextured pipeline. The Rivu palette owner, rather than
the renderer, owns palette generation and image retirement. See
link:23_visuals.adoc#_spectrum[Spectrum] for the mapping and lifetime contract.

=== Maintenance boundary and removal criteria

The implemented rendering backend is WGPU. Native Metal rejects these new
painting operations rather than silently substituting a different result;
Linux/Vulkan runtime evidence does not establish Metal or browser support.
The extra fields also increase shared vertex/sprite record sizes, so this
patch must not be described as a universal rendering or memory improvement.

When updating GPUI, compare these extensions against their pinned baseline,
keep Rust and shader record layouts synchronized, and preserve transformed
image clipping, path texture mapping, atlas lifetime and drawing order.
Revalidate ordinary untransformed images and plain paths as well as the two
new consumers. Drop the local overrides and obsolete vendor code only when
the selected upstream revision supplies the required behavior and all Rivu
callers have migrated; a newer dependency version alone is not sufficient.

Verification records are kept separately from this issue's design rationale;
the local consolidated record is
`.cache/worktree-test-records/album-artwork/README.md` from the repository that
hosts the Album artwork worktree. It distinguishes final integration checks,
historical GUI evidence and the bounded renderer benchmark, rather than
claiming every earlier check was rerun on the final source.
