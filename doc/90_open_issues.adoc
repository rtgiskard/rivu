Each entry records its investigation or resolution date. Resolved entries retain
the original problem and evidence boundary; they are not new verification runs.
Current behavior belongs in the linked user guides and design documents.

== Open and deferred

=== Portal file chooser cache warning

Status: deferred, 2026-10-12. Keep the published `ashpd` 0.13.13 dependency;
no vendor backport, upstream Git replacement, or log filtering.

Clicking the Library `+` button prints the following warning on each invocation:

[source,text]
----
zbus::proxy: Failed to populate properties cache via GetAll: org.freedesktop.DBus.Error.UnknownMethod: Object does not exist at path “/org/freedesktop/portal/desktop/request/…”. Property change streams will not produce values.
----

The user confirmed successful folder selection and library-root addition. ashpd
creates a property-cached Request proxy before `OpenFile` creates the transient
object, so `GetAll` fails; results arrive through an independent `Response`
signal. Playlist import/export share this mechanism.

Upstream fix:
https://github.com/bilelmoussaoui/ashpd/commit/e9e38113ad075042fcc48b8401010ca5f905db55[Disable property caching for Request/Session objects].
The fix is on upstream mainline, not in the 0.13.13 release branch inspected
at the time of investigation. Revisit when a compatible published release
includes it; verify successful selection, cancellation, and absence of this
warning without suppressing other logs.

=== Queue feedback while waiting for a query worker

Status: deferred, 2026-10-18. The open policy question is whether loading
feedback should include time waiting for an obsolete physical worker to retire.

Queue loading text starts its 150 ms delay when a page query is submitted.
After a search replacement or a window hide/reopen, current demand may wait
behind an obsolete physical worker. During that interval, unloaded rows can
have no loading text. This concerns database query scheduling, not tracks
waiting for playback. The interval is established by code inspection; it has
not been reproduced as a live GUI failure.

Physical completion releases the occupied slot and notifies the view so current
demand can submit without user input. This is not a confirmed permanent stall;
obsolete search loading must remain retired.

If policy expands feedback to logical waiting, bind its identity and elapsed
delay to current demand. Obsolete completion cannot clear it, submission cannot
restart the delay, and no replacement worker may bypass the occupied slot.
Verify hide/reopen and search replacement behind a query longer than 150 ms,
including failed-page retry. See
link:22_cache.adoc#_query_projection_retention[Query projection retention].

=== Structural GUI demand reconciliation during transport updates

Status: deferred, 2026-10-29; repeated work established by code inspection,
not a measured rendering bottleneck.

Playback-position updates still reconcile layout consumers and presentation
demand even when layout structure and visibility are unchanged. Multiple album
panels also repeat layout searches. Splitting this work requires invalidation
at layout, active-tab, visibility and relevant configuration boundaries without
skipping source/seek identity, playback-state or progressive-waveform updates.
The album-cover completion path is optimized independently; it does not resolve
this broader demand ownership. Revisit with a transport-heavy, multi-panel
workload and verify hide/reopen, tab changes and seek invalidation together.

=== Different data directories sharing one database file

Status: deferred, 2026-10-29; conditional ownership risk, not observed corruption.

Exclusive ownership identifies the data-directory inode, not the database inode.
Distinct directories whose `library.db` aliases the same file can therefore
coexist. SQLite locking does not establish the application's offline migration
precondition. A fix must define supported database aliases and involve both the
host and maintenance tool; a maintenance-only lock is insufficient. Current
migration CLI Apply validates rather than executing registered transformations.
Revisit before enabling such transformations or supporting shared-file aliases;
see link:26_migration.adoc[Migration ownership and backups].

== Resolved investigations

=== Stable configuration in high-frequency System IPC state

Status: resolved in implementation, 2026-10-29.

Runtime System and Configuration have independent IPC sections and revisions.
Only explicit Configuration reads convert and transfer the effective Config;
omitted sections preserve retained client values and do not acknowledge unread
tokens. Configuration-only publications wake Watch, and a new instance requires
a fresh Hello. See link:21_ipc.adoc#_revisions_and_watching[Revisions and watching].

The recorded comparison used 256 long-path roots and three retained clients,
each reading System 100 times, repeated three times. Response bytes per client
fell from 3,444,600 to 20,900; configuration-bearing runtime frames fell from 100
to zero. Temporary probes at both Config wire conversions observed zero calls
during runtime reads, then one encode/decode per explicit configuration read.
Real configuration-only Watch, selective reads and restart recovery were also
exercised. These are transfer/work-count results, not latency or RSS claims.


=== Query timeout and physical worker retirement

Status: resolved in implementation, 2026-10-19.

The 12-second GUI waiting deadline now delivers a logical error independently
of the submitted reader's lifetime. Feature-local loading settles without
releasing its physical worker slot. The original reply or disconnection retires
that slot; late data and obsolete timeout feedback cannot publish, and only the
latest retained demand may then start. Non-GUI query and command deadlines are
unchanged. The ownership contract is documented in
link:22_cache.adoc#_query_projection_retention[Query projection retention].

=== Drag-only panel catalog insertion

Status: resolved in implementation, 2026-10-21.

Catalog insertion is drag-only, including the first panel in an empty workspace.
Clicks and keyboard activation insert nothing; cancellation and invalid drops
leave the tree unchanged. Preview candidates do not allocate live IDs.

The recorded acceptance used layout tests and an isolated nested Wayland GUI:
inert clicks, center/edge insertion, empty layouts, invalid drops, Escape and tab
transfers. This is historical evidence, not a new run. Current operations are in
link:01_config.adoc#_layout[Configuration and layout].

=== Small visualization canvas feedback

Status: resolved in implementation, 2026-10-29.

Small plots now degrade without size warnings or tooltips. The earlier proposal
to extend `Enlarge panel` feedback to every visualizer was replaced by quiet
sizing behavior: Spectrum and Spectrogram retain their drawing cutoffs but no
size message; Audio Visualizer styles keep their existing small-geometry rules.
Waveform omits time labels before losing its narrow plot, and an undrawable
surface retires its capture and seek preview rather than retaining an invisible
seek target. A fresh press works after the surface regains room.

Acceptance used GUI behavior tests and a real nested Wayland window with labels
enabled: capture, shrink until undrawable, grow while still held, release without
a seek, then seek through a fresh press. Configured labels remained enabled and
returned on larger surfaces. Current sizing belongs in
link:24_layout.adoc#_geometry_and_constrained_viewports[Geometry and constrained viewports].
