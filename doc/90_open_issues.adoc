= Open issues

Unresolved defects and user-facing risks, ordered by user impact. Each entry
states the trigger, impact, current boundary or workaround, and status. Remove an
entry once its defect is fixed; current behavior belongs in the linked guides, and
accepted tradeoffs and reconsideration conditions in
link:91_design_decisions.adoc[Engineering conclusions and design decisions].

[[midi-short-sample-loops]]
== RustySynth can index past short sample loops at high pitch

Status: open, upstream; identified 2026-11-19.

Trigger:: MIDI playback (default `midi` feature) of a note whose per-sample pitch
step exceeds its SoundFont sample's loop length, such as a very short loop played
far above its root key.
Impact:: RustySynth 1.3.8's
https://github.com/sinshu/rustysynth/blob/8aa60afb3c14be0fd53d3ef40ef44a7ff8b72a45/rustysynth/src/oscillator.rs#L140-L155[oscillator]
subtracts at most one loop period per output sample, so the position can remain
past the loop end and eventually index past the sample data. That indexing is
bounds-checked: rendering panics instead of producing audio.
Boundary:: Rivu uses the published crate without a downstream patch; validating
SoundFont table boundaries does not prevent this. Revisit when an upstream release
handles steps that cross multiple loop periods.

[[database-file-aliases]]
== Different data directories can share one database file

Status: open, deferred 2026-10-29; conditional risk, no corruption observed.

Trigger:: Two data directories whose `library.db` is the same file, for example
through a symbolic link, hard link or file bind mount.
Impact:: Exclusive ownership is keyed on the data directory's identity, not the
database file's, so two hosts, or a host and the maintenance tool, can open the
same database at once. Hard-linked aliases can also give each host a separate
WAL file, so crash recovery is not guaranteed, and none of these aliases provide
the exclusive access the
link:10_upgrading.adoc#supported-source-formats[database upgrade] assumes.
Boundary:: Keep one database file per data directory. A fix must define supported
database aliases and cover both the host and the maintenance tool; a
maintenance-only lock is insufficient.

[[pipewire-context-retention]]
== Native PipeWire output reopen retains libdbus allocations

Status: open, reproduced 2026-11-07; upstream cleanup defect unidentified.

Trigger:: Each native output opens its own PipeWire context and destroys it on
Stop or reopen. Reproduced with PipeWire 1.6.10 and libdbus 1.16.2.
Impact:: Allocations from the realtime module's libdbus calls remain after context
destruction: about 3.9 KB in 34 objects per reopen, so growth is slow and
proportional to reopen count. File descriptors and threads return to baseline.
Boundary:: Disabling `module-rt` or keeping libdbus loaded largely removes the
growth, also in a standalone `pw_context` create/destroy loop. These are
diagnostic controls, not fixes. A fix must change context/module ownership or the
dependency while preserving realtime scheduling, strict routing, recovery and
physical retirement; see
link:91_design_decisions.adoc#unapproved-candidates[unapproved candidates]. This
retention does not explain <<waveform-rss-retention,waveform RSS growth>>.

[[waveform-rss-retention]]
== Process RSS stays elevated after full-waveform reads

Status: open, attribution unresolved 2026-11-07; no trimming policy adopted.

Trigger:: Full-waveform reads of long sources that complete or are cancelled by
track switches.
Impact:: Task buffers are released, but the allocator keeps the freed space
resident: after Stop, about 10.7 MiB of free glibc arena remained in a
240-second stereo test, and glibc in-use arena accounting (not measured RSS) grew
by 90,160 bytes across 12 further completions and eight cancellations, unattributed.
A separately reported 28–50 MB growth remains unexplained.
Boundary:: No leak has been established; the Core-owned PCM window is expected
residency. PCM transport and summary ownership are in
link:91_design_decisions.adoc#DEC-006[DEC-006].

[[queue-worker-wait-feedback]]
== Queue rows lack loading feedback while an obsolete query worker retires

Status: open, deferred 2026-10-18; feedback policy undecided. Found by code
inspection, not reproduced as a GUI failure.

Trigger:: Queue search replacement or hide/reopen while an earlier page query
still occupies the physical query worker.
Impact:: Unloaded rows stay blank without loading text until that worker retires,
because the 150 ms loading delay starts only when the next page query is
submitted. Retirement wakes the current demand, so rows do not stall
permanently.
Boundary:: Feedback for this interval must follow current demand identity and
elapsed delay without reviving obsolete search feedback or bypassing the occupied
worker; see link:22_cache.adoc#query-projection-retention[Query projection retention].

[[unmaintained-dependencies]]
== Unmaintained transitive dependencies

Status: open, identified 2026-11-14; requires upstream migrations.

The locked graph retains these RustSec maintenance advisories:

* `paste` 1.0.15, through Lofty and platform-specific Metal:
  https://rustsec.org/advisories/RUSTSEC-2024-0436[RUSTSEC-2024-0436]
* `ttf-parser` 0.25.1, through GPUI's font stack:
  https://rustsec.org/advisories/RUSTSEC-2026-0192[RUSTSEC-2026-0192]
* `zbus_names` 4.3.5, `zvariant` 5.15.1 and `zvariant_derive` 5.15.1, through
  GPUI's AccessKit/AT-SPI accessibility dependencies:
  https://rustsec.org/advisories/RUSTSEC-2026-0371[RUSTSEC-2026-0371],
  https://rustsec.org/advisories/RUSTSEC-2026-0370[RUSTSEC-2026-0370] and
  https://rustsec.org/advisories/RUSTSEC-2026-0372[RUSTSEC-2026-0372]

These are unmaintained-package notices, not known exploitable defects. Rivu's
direct D-Bus consumers and GPUI's portal and secret-service consumers use zbus 6.
Removing the old crates requires compatible upstream migrations, not a
semver-incompatible lockfile substitution. The findings came from a cached
advisory database and are not an exhaustive security assessment.
