= Engineering conclusions and design decisions

This record explains consequential choices and their evidence boundaries, not
implementation steps or delivery checklists. Current behavior belongs in the
linked guides; link:90_open_issues.adoc[open issues] owns defects and resolutions.

== Maintenance

Record a decision when meaningful alternatives, non-obvious costs or long-lived
constraints would otherwise be lost. A routine fix does not require a new entry.
Keep the choice, its reason and the evidence needed to distinguish alternatives;
add reconsideration conditions where useful, without a fixed per-entry template.

Use `DEC-NNN` identifiers and update repository references when renumbering.
Distinguish implemented behavior, retained choices and unapproved recommendations.
Update affected entries when their assumptions or status change. Historical checks
are not new verification; measurements retain workload, baseline and limits.
Do not retain test totals, temporary paths or delivery transcripts here.

== Decisions

[[DEC-001]]
=== DEC-001: Optional spectrum publication does not imply invalidation

Status: implemented, 2026-11-06.

An unrequested spectrum is not evidence of invalid audio. Publications carry
request state; consumers check signal identity and settings independently rather
than inferring semantic validity from an empty optional payload. A nested-Wayland
Bars -> playing Oscilloscope -> pause -> Bars check retained drawing without a
source-generation or seek-revision change; it did not establish physical GPU
retirement. See link:23_visuals.adoc#ingestion-and-publication[analysis publication].

[[DEC-002]]
=== DEC-002: Dependency recovery must not become a new scan

Status: implemented, 2026-11-06.

Filtered counts depend on unfiltered root totals. Keep failed dependencies
retryable under filters; explicit recovery retries counts, while filter changes
must not automatically retry persistent failures or bypass physical-worker
ownership. A fault-injected missing table originally routed recovery into scan
task 1. After correction, isolated nested-Wayland input recovered `0/0` counts
without changing the system revision or allocating a scan task. This is dependency
recovery evidence, not an ordinary schema fault or host-desktop acceptance.
See link:02_library.adoc[Library recovery].

[[DEC-003]]
=== DEC-003: Admit denoise state at the allocation boundary

Status: implemented, 2026-11-06.

Account for adapter storage and independently enabled hum/impulse processors,
including spectral Off, instead of applying a blanket multiplier or charging
storage twice. At 48 kHz stereo with spectral Off and hum enabled, the original
estimate was 6,144 bytes versus 12,088 net live allocated bytes; bypass retained
4,424 bytes despite the same estimate. Three repetitions matched and drop returned
the allocation delta to zero. Allocation regressions and standalone processing
smoke passed after correction. These counts establish missing state accounting,
not a process RSS bound or a demonstrated whole-graph 64 MiB overrun.
See link:27_audio_processing.adoc[Audio processing budgets].

Keep arithmetic policy in the graph planner, separate from this memory accounting:
charge active hum per harmonic and repair per configured width without raising
the work limit. Heavy valid graphs may require Hybrid/Offline execution;
bypassed effects still undergo format validation. The resolved
link:90_open_issues.adoc#denoise-hum-work-admission[arithmetic admission investigation]
records the counterexample and verification boundaries.

[[DEC-004]]
=== DEC-004: Bound ready cancellation work without releasing query ownership

Status: implemented, 2026-11-06.

A bounded channel does not bound a polling round when cancellation controls remain
ready. Use cumulative cooperative work limits while preserving cancellation
identity and the physical reply slot. Executor regressions cover sustained-ready
fairness; an actual IPC connection completed a retained query with 128 unmatched
cancellation controls and kept its next State response aligned. Flood latency
was not measured; ordinary one-cancel clients were not shown to stall.
See link:21_ipc.adoc[IPC lifecycle and limits].

[[DEC-005]]
=== DEC-005: Keyset serves sequential traversal, not arbitrary viewport offsets

Status: retained after consumer review, 2026-11-06; no new API required.

CLI TrackBatch, playlist occurrence continuations and playlist-export snapshots
already serve sequential traversal. Keep random-access page contracts for GUI/TUI
viewports and GUI range selection; keyset cannot replace their absolute offsets
without changing jump semantics. Cursor scope must include ordering, filters and
revision. Revisit for a new sequential consumer lacking continuation support or
a measured random-access bottleneck.

An isolated SQLite 3.54.1 experiment used the actual schema/indexes and projection,
100,000 ASCII tracks and ten pages of 100 rows. Three repetitions returned
identical rows:

[cols="2,1,1",options="header"]
|===
|Workload |Deep OFFSET VM steps |Known-anchor keyset VM steps
|Unfiltered |2,552,660 |29,140--29,194
|One-in-ten substring matches |9,071,660 |187,140
|===

Counts exclude initial anchor acquisition and count queries; they are not
application latency measurements. See link:21_ipc.adoc[Query contracts].

[[DEC-006]]
=== DEC-006: Latest PCM snapshots cannot replace continuous analysis

Status: retained after review, 2026-11-06.

A 4096-frame latest snapshot cannot reconstruct a 32768-frame FFT or every sample
needed by continuous Density accumulation. Retain worker analysis instead of
substituting the latest snapshot. The PCM cutover (implemented,
2026-11-07) retains one continuous GUI reader/fold for live analysis and bounded
session waveform summaries. Explicit whole-source reads use a separate bounded,
lossless finite stream with backpressure and physical worker ownership; they do
not reconstruct missing realtime history. Independently retained optional payloads
must not acquire a shared lifetime solely to reduce type count. See
link:23_visuals.adoc#waveform[Waveform ownership] and
link:21_ipc.adoc#finite-pcm-rendering[finite PCM rendering].

Finite Before/After reads reuse the audio renderer rather than a waveform scan.
The GUI reduces PCM off the foreground executor and coalesces bounded progress
publications; display changes neither decode audio nor clear session statistics.

Progressive summaries share the GUI PCM reader instead of a dedicated
waveform-client thread. This reduces waveform-specific coupling, but moving
statistics does not by itself reduce total CPU or RSS. Finite reads transport PCM
instead of summaries: a
60-second 48 kHz stereo `f32` source sends 23,040,000 sample bytes, consumed and
discarded incrementally. Finite transport batches contiguous render events into
at most 4096 frames and 32 KiB of samples per packet. Four reusable PCM buffers
retain at most 128 KiB per render, with two packets queued; this permits filling
one while another is written and two await sending. This replaces three
1024-frame buffers and per-render-event sends. Decoder/graph memory,
encoded/socket buffers and shared-window residency remain separate costs.

Delivery review removed migration-local allocation and computation waste. A
1024-bin snapshot retains 114,688 array bytes; the summary also keeps 24,576
energy bytes. A standalone allocator-counted smoke observed zero allocations
for ingestion and warmed snapshot publication. For one 4096-frame block at
30 seconds in that 60-second timeline, two bins are touched: finalizing RMS
per touched bin reduces the new reducer's square-root evaluations from 12,288
to 6 without changing energy/count/peak results. These are capacity and operation
counts, not a timing or RSS comparison against the old architecture.

An actual Core smoke delivered all 2,880,000 frames of a 60-second stereo source
and 240,000 frames of its 10–15 second range for both signals, with continuous
media positions and concurrent seek leaving the captured stream unchanged.
Source/seek mapping, replay replacement, late full/live overlap and physical
cancellation retirement are covered by the affected behavior suites.

An isolated 1280×800 nested-niri GUI check started capture at 30 seconds and left
the earlier timeline blank. The actual full-load menu filled the complete source;
a waveform click sought from 41.37 to 20.06 seconds without discarding its display.
Closing the window preserved Core and playback state; reopening while paused
showed no inherited summary. Input used Wayland virtual pointer events, not direct
business-method calls. This does not establish desktop-shell, IME or multi-output
behavior.

After rebasing onto `fc4bb47b`, `make lint` and `make test-rust` passed, including
default/all/disabled workspace features and GUI-only/TUI-only root combinations.
The cutover's default-feature application artifact also built successfully.
Subsequent ownership/cost cleanup passed `make lint` and the affected audio,
GUI and visuals suites with all features and with default features disabled.
The standalone reducer smoke also checked midtrack blank coverage, independent
scalar peak/RMS/count results, and replay replacement preserving untouched bins.

The four-buffer batching update passed `make lint`, finite-IPC tests with default
features enabled and disabled, and a default-feature application build. An
isolated Core smoke read 48,017 frames at 48 kHz: stereo used 12 packets and
18-channel PCM used 106, respecting the byte limit. Before/After and selected
ranges preserved every sample and media position; source mutation returned the
valid partial tail before Error, never Complete. Regressions cover media jumps,
step changes, partial tails, cancellation and backpressured worker retirement.
These establish batching and lifecycle behavior, not CPU, RSS or latency gains.


[[DEC-007]]
=== DEC-007: PCM retention needs conservative prefetch headroom

Status: implemented, 2026-11-06.

Size native retention for bounded output prefetch with conservative headroom,
not byte-tight minimum capacity; the user explicitly preferred avoiding extreme
capacity minimization. Preserve finite storage/scheduling bounds without adding
states merely to save a few blocks.

In a standalone quarter-second stereo publication, the original 32-slot window
retained all frames at 48 kHz but only 32,640 of 48,000 at 192 kHz and 32,512 of
96,000 at 384 kHz. After correction it retained every frame at all three rates,
including fragmented writes. This establishes retention coverage, not measured
audible dropout, device A/V synchronization or latency. Other corrections from
the same review belong in link:90_open_issues.adoc#pcm-continuity-and-frontend-readiness-from-branch-review[the resolution record].
See link:21_ipc.adoc[PCM transport] and link:22_cache.adoc[resource lifecycles].

[[DEC-008]]
=== DEC-008: Keep GUI cache ownership until cold-path measurements justify change

Status: retained after review, 2026-11-06; redesign not authorized.

Keep disposable content-addressed thumbnails, the reusable decode seat and
acknowledged pixel retirement. Window animation demand, per-panel rotation and
source-frame cursors have distinct ownership; global redraw is not an equivalent
replacement for targeted cached-scene invalidation.

Tier loads read/hash the original before disk reuse; cold generation persists the
thumbnail before returning pixels, on the same decode seat. Publishing pixels
first might shorten the critical path but adds retained bytes, cancellation and
shutdown ownership. No latency or aggregate-memory measurement yet justifies that
change. Frame-deadline scheduling likewise needs cursor/deadline integration, not
another independent timer. Revisit with cold-load or animation-load measurements
and equivalent failure/retirement evidence. Per-image budgets do not establish a
window-wide decoded/GPU cap. See link:22_cache.adoc[Artwork retention] and
link:23_visuals.adoc#artwork-composition-and-animation[Artwork animation].

[[DEC-009]]
=== DEC-009: Stream uncached native exports instead of retaining output PCM

Status: implemented, 2026-11-06.

Use a block sink in the existing native engine for uncached, native-only selected
output. Do not create a second DSP engine, worker or file protocol. Cached exports
share existing PCM; model ancestors and retained Hybrid contexts keep their PCM
requirements. This avoids charging complete file-only output to the 512 MiB PCM
budget even though it will not remain in an audition slot.

The pre-optimization production PcmBuilder, fed 256-frame stereo blocks at 48 kHz,
charged the following bytes in three identical repetitions. A 128-frame slice
retained the whole charge until its final owner dropped:

[cols="1,1,1",options="header"]
|===
|Seconds |Raw float32 PCM bytes |Charged retained bytes
|10 |3,840,000 |3,870,802
|30 |11,520,000 |11,550,802
|120 |46,080,000 |46,170,194
|===

After optimization, native export regressions with a zero-byte PCM budget matched
retained execution across short EOF, delayed/branched filters, STFT and Profile.
An isolated 30-second, 48 kHz stereo CLI export matched all 1,440,000 source frames
and produced the same WAV bytes as the cached route. Repeated destinations were
rejected; a file-size-limit failure left no export file after shutdown.

Exact decoded EOF owns preroll/tail cropping; estimated duration is insufficient.
Core, not worker completion, owns cancellation/source/destination revalidation and
atomic no-clobber publication. Retain these boundaries even if the sink changes.
For fixed graph/format, output PCM retention is duration-independent; decoder,
DSP/profile state, delays and existing results still cost memory. This evidence
is not an RSS or export-latency measurement, nor a promise of unlimited WAV size.
See link:27_audio_processing.adoc#tasks-retention-and-audition[Processing and export].

[[DEC-010]]
=== DEC-010: Scope retirement regressions to stable resource ownership

Status: implemented and verified, 2026-11-06.

Use pinned identity for PCM and bounded single-test isolation only where immediate
retirement requires exclusive process ownership. Keep production ownership,
protocols and ordinary test concurrency unchanged; these cases share an ownership
rule, not necessarily one observation primitive.

The PCM reader already pins the original memfd. Compare its `(dev, ino)` with
metadata of the owner's advertised path after Drop: a missing path or a different
object is valid retirement; the same object exposes an owner-fd leak. Keep the
retained PCM check too. Do not require path disappearance or reopen the replacement:
an fd reused for a socket need not support that open. This restores coverage lost
when the original path-unopenable assertion was removed, without extra isolation.

Isolate socket retirement checks from unrelated forking tests, keeping immediate
rebind/EOF assertions inside the live isolated case. This includes App startup,
normal shutdown and final-save failure: `481a602d` omitted the two shutdown cases,
and subsequent CI exposed a reacquisition failure in the final-save-error case.
Both now enter isolation before constructing App or its pinned directory fixture;
reacquisition errors retain their diagnostics rather than becoming boolean failures.
Directory pins prevent inode recycling, not listener inheritance; preserve existing
pins without treating them as isolation. Scope any shared runner access to these
tests, not the whole suite.

A subsequent global review found additional Drop-dependent EOF cases and unpinned
abstract-listener fixtures. Those cases now use bounded single-test isolation and
the existing pinned fixture without retries or relaxed operation deadlines. Keep
their evidence in link:90_open_issues.adoc#socket-eof-fixture-gaps[EOF fixtures] and
link:90_open_issues.adoc#socket-directory-pin-gaps[directory identity fixtures].
Do not infer exclusive socket ownership merely from a passing feature matrix.

For the two neural regressions, the isolated case must own only its interpreter as
a direct child and retain ordinary SIGCHLD wait semantics, without an independent
reaper. After terminal delivery, before applying it or retiring Core, require
`ECHILD` from `waitid(P_ALL, 0, ..., WEXITED | WNOHANG | WNOWAIT)`. Live and zombie
children fail without transferring production wait ownership. Preserve the
stdout-closed readiness barrier; remove stale numeric-PID checks and cleanup.
If exclusive child-set ownership cannot be established, a pidfd acquired before
retirement remains an alternative, not the default.

Child absence must be paired with evidence that the intended failure path ran.
Fault injection made the old neural unwind regression pass after replacing its
worker script with an ordinary early exit. A test-owned atomic observation now
records execution immediately before the injected progress panic and is checked
before applying Finished or retiring Core. This hook is test-only; production
processing and protocols are unchanged. See
link:90_open_issues.adoc#neural-unwind-trigger-coverage[unwind trigger coverage].

Replace the fixtures' busy loops with a blocking builtin read on an inherited
lifeline endpoint. Create its guard only inside the isolated case; both endpoints
must survive asynchronous spawn and the retirement assertion. Only the inherited
endpoint clears CLOEXEC; its peer stays exclusively owned by the runner. Do not
clone or shut down that peer before failure or assertion completion: cooperative
EOF must not make a missing production kill pass. The scripts use builtins without
spawning descendants. Declare the guard after Core so failure unwind closes it
before Core joins; cleanup only closes owned FDs. Direct inheritance avoids a
named FIFO's startup race: if its last writer dies before the shell opens the FIFO,
a blocking open can wait forever.

`src/test_support.rs` exposes the bounded runner through the existing `test-support`
boundary for GUI cases; App startup and shutdown use the same helper. A guard kills
and waits for the owned runner on timeout or unwind. The foreground process group is unchanged:
a new group needs explicit terminal-signal forwarding, and group kill plus leader
wait does not prove descendant reaping. Lifeline EOF lets these fixtures terminate
when their runner dies, even before the first read; it is failure cleanup, not a
synchronous resource-retirement assertion or a general process-tree supervisor.
There are no retries, observer threads or global subreaping.

No production PCM attach change is indicated by this review. Mapping precedes
enabling; ingestion requires a matching nonzero subscription revision acknowledged
on the same connection. Buffered revision-zero status cannot admit enabled PCM.
Preserve this ordering rather than adding instance metadata or FD transfer solely
because the advertised path can be reused.

`make lint` and `make test-rust` passed after integrating the App shutdown fixes,
global-review corrections and test cleanup. Coverage includes default/all/disabled
workspace features and GUI-only/TUI-only root runs. Both neural retirement
regressions passed in all five root combinations; the affected EOF assertions and
the retained GUI gap/staging integration also passed. Repeating the ordinary
early-exit injector now fails on missing trigger evidence with exit 101, while the
normal progress-panic case passes. Immediate socket retirement assertions remain
intact; neither retries nor relaxed operation deadlines were introduced.

After identifying the omitted App shutdown cases, a controlled fork/exec probe
again distinguished retained pre-exec listeners from immediate post-exec rebind,
with the directory inode pinned. An existing debug CLI artifact exercised normal
and failed final saves: both quit acknowledgements succeeded, the service exited
with 0 and 1 respectively, invalid config remained untouched, and immediate IPC
rebind plus an exclusive SQLite transaction succeeded after each exit.

The cross-process PCM regression checks descriptor retirement and retained native
samples together. A real SharedPcmWindow smoke distinguished owner leaks, close
without reuse, and memfd/socket reuse while preserving PCM. The shared-runner smoke
checked success, child failure, timeout and unwind after spawn, requiring no remaining
direct children. Prior PID-namespace probes distinguished live, zombie and reaped
children without consuming status; an actual Rust Command and /bin/sh probe covered
lifeline exit before its first read and after startup. Fixture exit is not descendant
reaping. Production PCM admission was checked statically. Investigation records:
link:90_open_issues.adoc#pcm-owner-retirement-coverage[PCM owner-drop],
link:90_open_issues.adoc#socket-retirement-test-isolation[socket isolation]
and link:90_open_issues.adoc#neural-retirement-pid-reuse[child identity].

[[DEC-011]]
=== DEC-011: Retire playback without discarding current settings failures

Status: implemented, 2026-11-06.

Playback retirement suppresses transport terminal actions, not independent
settings failure reporting. Normal and retiring dispatch share output-request
and EQ configuration/generation validation; stale failures remain ignored.
Do not route retiring terminal events through ordinary dispatch, which can
recursively Stop or advance navigation. Evidence and resolution:
link:90_open_issues.adoc#retiring-settings-failures[retiring settings failures].

[[DEC-012]]
=== DEC-012: Retire unreachable model boundaries before inference output allocation

Status: implemented, 2026-11-06.

After a model input is materialized, traverse remaining graph demand with that
model as a cut point and retire unreachable PCM boundaries and original source.
Other branches keep their reachable boundaries; an aliased input pins its own
backing storage. Apply the same reachability ownership after model completion.
This changes PCM lifetime, not the budget, graph result or model execution policy.
Evidence and resolution:
link:90_open_issues.adoc#model-boundary-retirement[model-boundary retirement].

[[DEC-013]]
=== DEC-013: Keep scan error copying with the retained task result

Status: implemented, 2026-11-07.

Failed media-task results expose Copy beside Dismiss in their existing heading.
Copy writes the full projected message to the clipboard without mutating or
dismissing the task. Library scan failures remain local to Library; copying does
not require publishing them as window-global errors. Reuse the existing icon
button and clipboard API without adding a notification or selection mechanism.
User behavior is documented in link:02_library.adoc[Roots and scanning].

An isolated nested-Wayland run produced a real missing-root scan failure. A
virtual-pointer click on Copy followed by a clipboard read preserved the exact
full error beyond the visible truncation, while the failed result stayed open.
`make lint`, the Core scan-error ownership regression, and existing GUI Library
tests passed. This verifies the nested-compositor path, not host-desktop input.
