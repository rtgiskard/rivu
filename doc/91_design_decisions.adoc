= Engineering conclusions and design decisions

This record explains consequential choices and their evidence boundaries, not
implementation steps or delivery checklists. Current behavior belongs in the
linked guides; link:90_open_issues.adoc[open issues] owns defects and resolutions.

== Maintenance

Record a decision when meaningful alternatives, non-obvious costs or long-lived
constraints would otherwise be lost. A routine fix does not require a new entry.
Keep the choice, its reason and the evidence needed to distinguish alternatives;
add reconsideration conditions where useful, without a fixed per-entry template.

Use `DEC-NNN` identifiers and update repository references when renumbering.
Distinguish implemented behavior, retained choices and unapproved recommendations.
Update affected entries when their assumptions or status change. Historical checks
are not new verification; measurements retain workload, baseline and limits.
Do not retain test totals, temporary paths or delivery transcripts here.

== Decisions

[[DEC-001]]
=== DEC-001: Optional spectrum publication does not imply invalidation

Status: implemented, 2026-11-06.

An unrequested spectrum is not evidence of invalid audio. Publications carry
request state; consumers check signal identity and settings independently rather
than inferring semantic validity from an empty optional payload.
See link:23_visuals.adoc#ingestion-and-publication[analysis publication].

[[DEC-002]]
=== DEC-002: Dependency recovery must not become a new scan

Status: implemented, 2026-11-06.

Filtered counts depend on unfiltered root totals. Keep failed dependencies
retryable under filters; explicit recovery retries counts, while filter changes
must not automatically retry persistent failures or bypass physical-worker
ownership. See link:02_library.adoc[Library recovery].

[[DEC-003]]
=== DEC-003: Admit denoise state at the allocation boundary

Status: implemented, 2026-11-06.

Account for adapter storage and independently enabled hum/impulse processors,
including spectral Off, instead of applying a blanket multiplier or charging
storage twice. At 48 kHz stereo with spectral Off and hum enabled, the original
estimate was 6,144 bytes versus 12,088 net live allocated bytes; bypass retained
4,424 bytes despite the same estimate. Three repetitions matched and drop returned
the allocation delta to zero. These counts establish missing state accounting,
not a process RSS bound or a demonstrated whole-graph 64 MiB overrun.
See link:27_audio_processing.adoc[Audio processing budgets].

Keep arithmetic policy in the graph planner, separate from this memory accounting:
charge active hum per harmonic and repair per configured width without raising
the work limit. Heavy valid graphs may require Hybrid/Offline execution;
bypassed effects still undergo format validation. The resolved
link:90_open_issues.adoc#denoise-hum-work-admission[arithmetic admission investigation]
records the counterexample and verification boundaries.

The per-runner realtime estimate is separate from the Offline engine: Offline
caps each edge's delay at 64 MiB but
does not aggregate DSP/delay allocations across the graph. Concurrent playback
and finite render workers also own separate runners. Neither limit nor the
512 MiB retained-PCM budget is a service-wide DSP or RSS bound. Aggregate Offline
state admission remains an unapproved candidate, not an implemented guarantee.

[[DEC-004]]
=== DEC-004: Bound ready cancellation work without releasing query ownership

Status: implemented, 2026-11-06.

A bounded channel does not bound a polling round when cancellation controls remain
ready. Use cumulative cooperative work limits while preserving cancellation
identity and the physical reply slot. Sustained-ready cancellation must yield
without losing query ownership or misaligning the next response.
See link:21_ipc.adoc[IPC lifecycle and limits].

[[DEC-005]]
=== DEC-005: Keyset serves sequential traversal, not arbitrary viewport offsets

Status: retained after consumer review, 2026-11-06; no new API required.

CLI TrackBatch, playlist occurrence continuations and playlist-export snapshots
already serve sequential traversal. Keep random-access page contracts for GUI/TUI
viewports and GUI range selection; keyset cannot replace their absolute offsets
without changing jump semantics. Cursor scope must include ordering, filters and
revision. Revisit for a new sequential consumer lacking continuation support or
a measured random-access bottleneck.

An isolated SQLite 3.54.1 experiment used the actual schema/indexes and projection,
100,000 ASCII tracks and ten pages of 100 rows. Three repetitions returned
identical rows:

[cols="2,1,1",options="header"]
|===
|Workload |Deep OFFSET VM steps |Known-anchor keyset VM steps
|Unfiltered |2,552,660 |29,140--29,194
|One-in-ten substring matches |9,071,660 |187,140
|===

Counts exclude initial anchor acquisition and count queries; they are not
application latency measurements. See link:21_ipc.adoc[Query contracts].

[[DEC-006]]
=== DEC-006: Latest PCM snapshots cannot replace continuous analysis

Status: retained after review, 2026-11-06.

A 4096-frame latest snapshot cannot reconstruct a 32768-frame FFT or every sample
needed by continuous Density accumulation. Retain worker analysis instead of
substituting the latest snapshot. One continuous GUI reader/fold owns live
analysis and bounded session waveform summaries. Explicit whole-source reads use
a separate bounded, lossless finite stream with backpressure and physical worker
ownership; they do not reconstruct missing realtime history. Independently
retained optional payloads must not acquire a shared lifetime solely to reduce
type count. See
link:23_visuals.adoc#waveform[Waveform ownership] and
link:21_ipc.adoc#finite-pcm-rendering[finite PCM rendering].

Finite Before/After reads reuse the audio renderer. Progressive summaries share
the GUI PCM reader, with reduction and coalesced publications off the foreground
executor. Display changes neither decode audio nor clear session statistics.
This reduces waveform-specific coupling, not necessarily total CPU or RSS.
Transporting PCM instead of summaries is a real cost: a 60-second, 48 kHz stereo
`f32` source sends 23,040,000 sample bytes, consumed and discarded incrementally.
Packet, buffer and cancellation bounds belong to the finite PCM contract above;
decoder/graph memory and shared-window residency remain separate costs.

Task-buffer release does not imply immediate allocator or RSS reclamation; no
trimming policy was adopted. Evidence and unresolved attribution belong in
link:90_open_issues.adoc#waveform-rss-retention[the waveform RSS investigation].

[[DEC-007]]
=== DEC-007: PCM retention needs conservative prefetch headroom

Status: implemented, 2026-11-06.

Size native retention for bounded output prefetch with conservative headroom,
not byte-tight minimum capacity; the user explicitly preferred avoiding extreme
capacity minimization. Preserve finite storage/scheduling bounds without adding
states merely to save a few blocks.

In a standalone quarter-second stereo publication, the original 32-slot window
retained all frames at 48 kHz but only 32,640 of 48,000 at 192 kHz and 32,512 of
96,000 at 384 kHz. After correction it retained every frame at all three rates,
including fragmented writes. This establishes retention coverage, not measured
audible dropout, device A/V synchronization or latency. Failure details belong in
link:90_open_issues.adoc#pcm-continuity-and-frontend-readiness-from-branch-review[the resolution record].
See link:21_ipc.adoc[PCM transport] and link:22_cache.adoc[resource lifecycles].

[[DEC-008]]
=== DEC-008: Keep GUI cache ownership until cold-path measurements justify change

Status: decode cache and scheduling design retained after review, 2026-11-06;
their redesign remains unapproved. Explicit shared-disk cleanup is simplified
to permit removal of in-use files, superseding inode-lock protection,
2026-11-09. Material preference authority is covered by <<DEC-015>>.

Keep disposable content-addressed thumbnails, the reusable decode seat and
acknowledged pixel retirement. Window animation demand, per-panel rotation and
source-frame cursors have distinct ownership; global redraw is not an equivalent
replacement for targeted cached-scene invalidation.

Tier loads read/hash the original before disk reuse; cold generation persists the
thumbnail before returning pixels, on the same decode seat. Publishing pixels
first might shorten the critical path but adds retained bytes, cancellation and
shutdown ownership. No latency or aggregate-memory measurement yet justifies that
change. Frame-deadline scheduling likewise needs cursor/deadline integration, not
another independent timer. Revisit with cold-load or animation-load measurements
and equivalent failure/retirement evidence. Per-image budgets do not establish a
window-wide decoded/GPU cap. See link:22_cache.adoc[Artwork retention] and
link:23_visuals.adoc#artwork-composition-and-animation[Artwork animation].

Infrequent, user-initiated artwork cleanup may delete in-use files, avoiding
cross-process file-lock coordination. Keep process-local shared ownership without
adding automatic cache invalidation or recovery. See
link:01_config.adoc#artwork-cache-maintenance[maintenance effects and recovery] and
link:22_cache.adoc#artwork-uri-leases[URI ownership].

Atlas-key invalidation does not retire physical tiles still needed by replayable
scenes. The renderer owns that lifetime without changing the sprite ABI or replacing
Rivu's source-generation acknowledgements and targeted invalidation; hidden replayable
scenes can retain GPU resources. See link:22_cache.adoc[Cache and retention].

Materials reuse artwork ownership, consumer-owned negative lookup identities and
the existing decode admission; they do not add a cache or relax the album-card
size cap. Full-cover demand promotes through the same decode seat using exact
oriented source dimensions. Resolved boundary defects are recorded under
link:90_open_issues.adoc#material-atmosphere-negative-demand[negative demand],
link:90_open_issues.adoc#material-artwork-panel-routing[panel routing] and
link:90_open_issues.adoc#material-cover-decode-sizing[Cover sizing].

[[DEC-009]]
=== DEC-009: Stream uncached native exports instead of retaining output PCM

Status: implemented, 2026-11-06.

Use a block sink in the existing native engine for uncached, native-only selected
output. Do not create a second DSP engine, worker or file protocol. Cached exports
share existing PCM; model ancestors and retained Hybrid contexts keep their PCM
requirements. This avoids charging complete file-only output to the 512 MiB PCM
budget even though it will not remain in an audition slot.

The pre-optimization production PcmBuilder, fed 256-frame stereo blocks at 48 kHz,
charged the following bytes in three identical repetitions. A 128-frame slice
retained the whole charge until its final owner dropped:

[cols="1,1,1",options="header"]
|===
|Seconds |Raw float32 PCM bytes |Charged retained bytes
|10 |3,840,000 |3,870,802
|30 |11,520,000 |11,550,802
|120 |46,080,000 |46,170,194
|===

Exact decoded EOF owns preroll/tail cropping; estimated duration is insufficient.
Core, not worker completion, owns cancellation/source/destination revalidation and
atomic no-clobber publication. Retain these boundaries even if the sink changes.
For fixed graph/format, output PCM retention is duration-independent; decoder,
DSP/profile state, delays and existing results still cost memory. This evidence
is not an RSS or export-latency measurement, nor a promise of unlimited WAV size.
See link:27_audio_processing.adoc#tasks-retention-and-audition[Processing and export].

[[DEC-010]]
=== DEC-010: Scope retirement regressions to stable resource ownership

Status: implemented and verified, 2026-11-06.

Use pinned identity for PCM and bounded single-test isolation only where immediate
retirement requires exclusive process ownership. Keep production ownership,
protocols and ordinary test concurrency unchanged; these cases share an ownership
rule, not necessarily one observation primitive.

Retirement observations follow the resource's identity and ownership:

* PCM checks compare the reader-pinned memfd's `(dev, ino)` with the owner's
  advertised path after Drop, and still verify retained samples. A missing path
  or different object is valid retirement; path disappearance or reopening a
  replacement FD is not required.
* Socket rebind/EOF checks construct fixtures inside bounded single-test
  subprocesses when unrelated forks could inherit listeners. Directory pins
  prevent inode recycling, not listener inheritance; neither replaces the other.
  Keep immediate assertions and operation deadlines, without retries or global
  test serialization.
* Neural checks own an exclusive direct-child set with ordinary SIGCHLD semantics.
  After terminal delivery, before applying Finished or retiring Core, non-reaping
  `waitid(P_ALL, 0, ..., WEXITED | WNOHANG | WNOWAIT)` must report `ECHILD`.
  Live and zombie children fail. A pidfd acquired before retirement is an
  alternative when exclusive child-set ownership cannot be established; stale
  numeric PIDs are not safe identities. Child absence must also be paired with
  proof that the intended failure path actually ran.

Inherited lifelines provide failure cleanup, not proof of production retirement.
Keep their peer exclusively owned through the retirement assertion so cooperative
EOF cannot hide a missing kill. On failure, close that peer before Core joins;
the runner guard kills and waits for its owned child. Direct inheritance avoids
a named FIFO's blocking-open startup race. These fixtures neither supervise a
general process tree nor change terminal-signal ownership or production reaping.
No production PCM attach change follows from FD reuse: preserve the existing
link:21_ipc.adoc#realtime-pcm-transport[subscription admission ordering].

The investigation records own the counterexamples and detailed evidence:
link:90_open_issues.adoc#pcm-owner-retirement-coverage[PCM owner-drop],
link:90_open_issues.adoc#socket-retirement-test-isolation[socket isolation],
link:90_open_issues.adoc#socket-eof-fixture-gaps[EOF fixtures],
link:90_open_issues.adoc#socket-directory-pin-gaps[directory identity fixtures],
link:90_open_issues.adoc#neural-retirement-pid-reuse[child identity] and
link:90_open_issues.adoc#neural-unwind-trigger-coverage[unwind trigger coverage].

[[DEC-011]]
=== DEC-011: Retire playback without discarding current settings failures

Status: implemented, 2026-11-06.

Playback retirement suppresses transport terminal actions, not independent
settings failure reporting. Normal and retiring dispatch share output-request
and EQ configuration/generation validation; stale failures remain ignored.
Do not route retiring terminal events through ordinary dispatch, which can
recursively Stop or advance navigation. Evidence and resolution:
link:90_open_issues.adoc#retiring-settings-failures[retiring settings failures].

Accepted refinement: listening duration, heard-time, count-commit, activity-commit
and deferred bitrate facts belong to their source session. Retired settlement
consumes that session explicitly, without installing it in the current playback
slot. Release the single retained source only after physical close and all
required count/activity writes are confirmed. A real write failure retains that
source and blocks replacement; a failed History SELECT does neither once those
conditions hold. History projection recovery has its own bounded responsibility,
so it cannot delay the next track or keep a settled source alive.

[[DEC-012]]
=== DEC-012: Retire unreachable model boundaries before inference output allocation

Status: implemented, 2026-11-06.

After a model input is materialized, traverse remaining graph demand with that
model as a cut point and retire unreachable PCM boundaries and original source.
Other branches keep their reachable boundaries; an aliased input pins its own
backing storage. Apply the same reachability ownership after model completion.
This changes PCM lifetime, not the budget, graph result or model execution policy.
Evidence and resolution:
link:90_open_issues.adoc#model-boundary-retirement[model-boundary retirement].

[[DEC-013]]
=== DEC-013: History collection outlives presentation visibility

Status: implemented and independently reviewed, 2026-11-07.

Configured Waveform and Spectrogram views continue bounded audio collection while
their panels or window are hidden. Visibility controls drawing, animation and
derived GPU publication, not whether played audio enters their history. Reveal
uses the latest collected history rather than replaying a hidden backlog or
waiting for an empty window to fill. Removing the corresponding layout views,
disabling visualizations or destroying the window still relinquishes collection.

Spectrogram is a rolling audio-stream record: seek and track replacement start
new analysis intervals without discarding compatible historical columns. Waveform
remains a per-source, media-position summary rather than a cross-track stream.
Incompatible analysis settings may invalidate frequency history; actual capture
loss is not evidence of measured silence. The accepted cost is continued bounded
PCM/analysis work while history views are configured, not a claim of negligible
CPU or power use. See link:23_visuals.adoc[Visualization Rendering Design].

Collection and presentation have separate acceptance points: audio notifications
append CPU history, while capped callbacks commit live presentation. Pause retires
unpresented live input; revealing a paused/stopped Spectrogram uses its collected
domain and matching labels without accepting another live frame. Deterministic
lifecycle checks and an isolated nested-Wayland run cover hidden-tab collection,
initial Waveform reveal, seek/track retention and stopped higher-rate reveal.
This is not a claim of compositor-specific occlusion notification coverage.

An optimized GUI-only build on a Ryzen 7 8745HS measured 48 kHz mono PCM,
FFT 8192, analysis 28 Hz, a 20-second history and a 60 FPS presentation cap in a
1280×800 nested Wayland window. Each state used three five-second process-CPU
samples after warm-up; 100% means one logical CPU, excluding compositor/GPU work.
The no-history baseline used only Queue, not merely inactive history tabs.

[cols="2,1,1",options="header"]
|===
|State |GUI CPU range |Core CPU range
|Both histories configured, Queue visible |1.4–1.8% |1.0%
|Queue only, no history views configured |0.2–0.4% |0.4–0.8%
|===

These observations establish a modest nonzero cost for this workload, not a
worst-case FFT/rate bound or a power measurement. Recommendations from the
subsequent read-only scan were implemented separately under <<DEC-014>>.

[[DEC-014]]
=== DEC-014: Remove redundant history work without reducing collection fidelity

Status: implemented and verified, 2026-11-07; depends on <<DEC-013>>.

Spectrogram history consumes full-bin publications independently of the
musical-band Spectrum payload. Visible Waveform folds every admitted block but
publishes only the latest summary per bounded drain turn, including backlog
continuations, preserving synchronous reveal and source/revision/visibility
fences. Scroll-only Spectrogram frames reuse validated tile metadata and update
placement rather than revalidating each column. Unchanged physical-frequency
domains reuse labels; hidden changed domains refresh on paused/stopped reveal.
Waveform normalization scans combined peaks alone: ingestion, traversal
replacement, coarsening and full/live merging preserve their channel-maximum
invariant, including when the normalization maximum decreases.

No analysis cadence, frequency precision, recording coverage or acceptance guard
is reduced. Existing palette, sampling and resize invalidation remains mandatory.
For 33 retained admissible visible PCM blocks under stable guards, the 32-block
drain bound reduces worker summary copies from 33 to 2; source/reveal/configuration
copies are separate. Each affected normalization reduction visits B rather than
3B peak slots. After warm-up without invalidation, scrolling avoids C historical
column inspections while still iterating tile placements; unchanged domains avoid
frequency/note formatting, not unrelated dB-label work. These are static operation
counts, independently reviewed, not measured allocation or timing reductions.

Matched GUI-only optimized builds repeated the <<DEC-013>> 48 kHz workload, with
both history views configured, three five-second process-CPU samples per state,
and the baseline measured before the new build. GUI CPU means and ranges were:

[cols="2,1,1",options="header"]
|===
|State |Before |After
|Spectrogram visible |9.9% (9.6–10.0%) |9.4% (9.0–9.6%)
|Waveform visible |8.3% (8.0–8.6%) |7.9% (7.6–8.2%)
|Both histories hidden |2.2% (2.0–2.4%) |2.1% (2.0–2.2%)
|===

100% is one logical CPU. Core means remained approximately 1.0%, 1.1% and 1.3–1.4%
respectively. Overlapping or touching short-sample ranges and sequential rather
than randomized measurement do not establish stable percentage speedups, power
savings or a worst-case bound. The removal of duplicate work is the firm result.

Historical verification covered default and GUI-only optimized builds, regression
tests, and nested-Wayland collection/scrolling, pause freeze, stopped higher-rate
reveal, stopped resize and Waveform source/seek behavior. These checks establish
the covered lifecycle behavior, not broader performance gains.

[[DEC-015]]
=== DEC-015: Keep material preferences under Core configuration authority

Status: implemented, 2026-11-07.

Persist material selection, enablement and per-preset parameters through the
existing Core configuration authority, not a second GUI-owned settings file.
These preferences remain independent of semantic theme colors, renderer budgets
and the Settings draft, so discarding that draft does not undo material changes.

Material edits preview immediately and submit narrow configuration mutations.
Core validates and writes them before accepting the new preferences; the GUI
reconciles its preview with authoritative configuration and reports save failures.
Unrelated configuration updates must not overwrite pending material edits.
Preset identity, parameter storage and legal value ranges belong to the shared
format domain. GUI extensions supply labels, grouping, editing steps and GPU
derivations without maintaining a second preset or parameter model.

This replaces session-only preference storage without moving artwork ownership
or changing decode admission; those boundaries remain under <<DEC-008>>.

Preference defaults and migration are described in
link:01_config.adoc#_appearance_and_library_display[Appearance and library display].
The shared card, editing and navigation contract belongs in
link:24_layout.adoc#material-appearance[Material appearance].

[[DEC-016]]
=== DEC-016: Separate committed facts from recoverable projections

Status: implemented, 2026-11-08.

Catalog transactions report authoritative effects independently of fallible
projection preparation. Core accepts confirmed effects and invalidates affected
query domains before refreshing views. Recovery retries projections, never the
mutation; independently committed scan selection, library and playlist effects
retain their own outcome evidence.

Keep bounded pending projection work and refresh it on relevant demand or events,
not a polling timer. Synchronous refresh and background recovery share a request's
recovery opportunity: failure waits for later demand, and satisfaction rejects
late recovery without releasing physical worker ownership.
Queue structure and current-track refresh dependencies must follow their actual
inputs rather than every library change. Control decisions use the playback
session identity and narrow authoritative database facts, not a possibly stale
display Track.
External admission follows the same rule: current-track, count and history
refreshes retain independent recovery responsibility after the write commits.

Playback follows the same commit boundary: count and activity confirmations are
accepted before preparing History. Projection failure preserves the previous
History snapshot, reports the refresh error and retains only projection work;
recovery reads current facts without replaying a confirmed count or activity
timestamp. Deferred active-session write failures remain recoverable on later
related playback events. Count and activity retain independent commit evidence,
so retrying one cannot repeat the other. Source retirement conditions remain
independent of projection readiness as specified in <<DEC-011>>.

Manual edits and removals report History effects from transaction facts, not
request fields or cached History membership. Removals publish exact Track and
playlist metadata scopes while within the shared scope bound; overflow resets
metadata scopes conservatively. This bound does not truncate playlist-entry
structure invalidation. Relocation refreshes the current Track only when the
selected identity is affected, including a stopped selection.

Retain the publication fence, pinned SQL snapshots and consumer generations:
they respectively pair database visibility with Core versions, isolate a read,
and reject results for superseded demand. Moving all views into write transactions
would extend writer occupancy without making audio commands or publication
atomic; replaying incremental display events would duplicate database rules.
See link:21_ipc.adoc#transactional-inputs-and-bounded-storage-queries[storage query contracts]
and link:22_cache.adoc[query retention].

[[DEC-017]]
=== DEC-017: Playback bypass is independent of effect enablement

Status: implemented, 2026-11-09.

Persist master playback bypass separately from Monitor EQ enablement. Bypass
changes the heard route, not the user's effect configuration, and must be
reversible without enabling an independently disabled effect. Keep the public
actual audition distinct from the retained selection eligible for resumption.
The latter is session-owned, source-bound and subject to the existing PCM budget;
it is not a durable instruction to replay an old track after restart.

Core owns explicit bypass intent; neither effect edits nor late task completion
may override it. Route changes require queue admission and saving before
acceptance. Resumption validates the source and reconstructs the frozen
live/hybrid runner rather than deriving a route from current editor settings.
The retained selection owns its frozen route resources as one record. Bypass
changes the actual route without clearing and reconstructing that selection;
successful source replacement updates its generation binding. Selecting a new
result and returning to Original remain distinct operations. Core retains
configuration, command admission and source-validation authority; resource
ownership does not confer permission for late task completion to start playback.
See link:27_audio_processing.adoc#playback-bypass[Playback bypass] for operation,
selection retirement and failure behavior.

[[DEC-018]]
=== DEC-018: File publication does not request storage synchronization

Status: implemented, 2026-11-09.

Application-managed file writes do not call `fsync`, `fdatasync`, or their
file/directory synchronization wrappers. This includes configuration, layouts,
caches, exports, source-tag replacement and its original-file backup, and
migration backups. Avoid explicit storage-flush waits; the operating system
controls writeback. Retain required buffered flushes, format finalization,
normal I/O error handling, source validation and atomic replacement or
no-clobber publication.

Successful completion means the write and publication operations succeeded;
neither the output nor its backup is guaranteed to survive power loss or an
operating-system failure. Do not expose sync-failure states or retry paths for
barriers that are not performed. SQLite's internal synchronization policy is
separate and unchanged; see link:02_library.adoc[Library storage].

[[DEC-019]]
=== DEC-019: Preserve explicit MPRIS re-enable intent across retirement

Status: implemented, 2026-11-10.

Core publishes a runtime-only enable generation alongside MPRIS's current enabled
state. Each committed disabled-to-enabled transition advances that generation;
coalesced notifications therefore cannot erase a re-enable while the controller
waits for old artwork work to physically retire. The generation is not persisted
or added to the IPC configuration contract.

The controller consumes an intent before attempting registration and accepts its
result only while that intent remains current. Retirement rechecks current intent
before starting replacement work. Failure or bus loss alone does not authorize
automatic retries; see link:04_playback.adoc#_mpris_and_artwork[MPRIS recovery].

[[DEC-020]]
=== DEC-020: One Audio processing panel per named layout

Status: implemented, 2026-11-10.

Limit Audio processing to one panel per named layout, with editing state owned
by the window feature. Layouts describe placement, not independent processing
sessions; duplicate editors would require extra input identities and draft
reconciliation without providing a separate workflow.

Insertion and migration behavior: link:24_layout.adoc#_panel_insertion[Panel insertion].
Draft and input lifetime: link:27_audio_processing.adoc#_ownership_and_invariants[Ownership and invariants].

[[DEC-021]]
=== DEC-021: Processing task status has one authoritative record

Status: implemented, 2026-11-10.

Keep one service-owned task record, referenced by current selection, terminal
history and retained resources. Their lifetimes differ, but they must not become
independent status authorities. This avoids synchronizing mutable copies when
an operation's outcome or resource availability changes; publishing a snapshot
does not transfer mutation authority.

Record retention and resource boundaries:
link:27_audio_processing.adoc#_ownership_and_invariants[Ownership and invariants].

[[DEC-022]]
=== DEC-022: Query replacement belongs to the demand owner

Status: implemented, 2026-11-13.

A submission receipt identifies a projection epoch, not every physical read.
Keep replacement policy local: TUI foreground demand and each GUI Playlist lane
are latest-only, while Library branches can share a projection epoch without
revoking one another. Making every shared tracker submission advance the epoch
would cancel valid peer reads.

Use one epoch source for a Playlist lane's publication and loading identity;
pending publication and physical occupancy remain independent. Timeout consumes
publication rights without releasing the worker, and a queued replacement is
already a logical intent before it can execute. Keep payload application and
failure recovery with their business owners rather than introducing a universal
query scheduler. See link:22_cache.adoc#_demand_cancellation_and_physical_retirement[query ownership].
