= Playback
:toc:
:toclevels: 2

Playback follows queue occurrences, with shared controls in the GUI, TUI, CLI
and optional MPRIS service. Output uses native PipeWire; decoder selection and
processing are independent of the output device.

== Transport and timing

Use `rivu playback` for play, pause, resume (`play` without a track ID), stop,
next, previous, seek, volume, shuffle, and repeat controls. Seek positions are
seconds; CLI volume is an integer percentage from 0 to 100.
Volume uses a dB-linear control curve rather than linear amplitude: 0% mutes,
50% is -30 dB, and 100% leaves the source gain unchanged. See
link:01_config.adoc#volume[Volume configuration] for fractional values and
<<keyboard-controls,Keyboard controls>> for relative volume steps.

`playback play` resumes a paused decoder. When stopped, it opens the selected
queue occurrence from the beginning, or the first occurrence if none is selected;
an empty queue is an error. Stop resets the position to zero but retains queue
selection. Pause only changes playing playback; it does not select or open a
track while stopped.

To play a library track, use `rivu playback play TRACK_ID`. This starts the first
existing occurrence of that track in queue order, or appends one if the track is
not queued. It does not replace the queue. Use `rivu queue play QUEUE_ID` when a
particular occurrence matters; track IDs and queue occurrence IDs are not
interchangeable. Desktop Play actions on Library, album tracks, Recent tracks,
and playlist tracks use library-track playback; Queue rows use occurrence playback.

Whole-album and whole-playlist Play replace the queue with the complete saved
order and start its first entry; Append adds the complete collection without
changing playback. CLI `rivu playlist play PLAYLIST_ID` does not ask for confirmation.
The GUI asks before replacing a nonempty queue by default; Cancel or Esc preserves
queue and playback. Configure `interface.confirm_queue_replace` under
link:01_config.adoc#volume-and-playback-controls[Volume and playback controls].

[source,sh]
----
rivu queue add TRACK_ID TRACK_ID
rivu queue list
rivu queue play QUEUE_ID
rivu playback pause
rivu playback play
rivu playback seek 30
----

Keyboard volume steps, repeat cycling, and shuffle toggles accumulate against
the core's current state, even before the display updates. Ctrl+Left/Right and
seek-slider arrows seek by five seconds; slider Home/End and terminal
Ctrl+Home/End seek to zero or the known duration. A delayed seek cannot affect a
different queue occurrence. Pointer dragging and CLI seek/volume specify absolute
targets.

If a manual playback request is rejected by the pre-open file check, for example
because the source is missing or not an ordinary file, active playback continues.
Once that check passes, opening stops the previous playback; a later open or load
failure leaves playback stopped. Neither failure rolls back earlier queue edits,
including an occurrence appended by library-track Play.

Whole-album and whole-playlist Play stop existing playback and save the replacement
queue before opening its first source. An open failure leaves playback stopped
and does not restore the old queue. Inspect Queue and play another entry after
correcting or skipping the source. Failure to open the next entry at natural end
also stops playback.

The desktop Playback panel shows title, artist, album, progress, transport, and
volume. Blank artist or album metadata uses the same symbol placeholders and
missing-field tooltips as playlist entries. Its favorite button changes the current
track's library favorite, not the browsing selection. Use the separate Artwork
panel for covers.
Hover or focus the volume control to see its percentage. The title's crosshair
locates the current queue occurrence; see <<queue,Queue>>.

Repeat cycles Off, All, and One. Previous restarts the current entry when its
position exceeds three seconds; at or before three seconds it navigates back,
using playback history when shuffling.
With Shuffle enabled, each Next independently chooses a queue occurrence with
equal probability, including the current one. Immediate repeats are expected;
duplicate occurrences increase their track's chances. Previous follows playback
history, retaining up to 4096 occurrences during the running session; Next draws
afresh even after Previous. Changing Shuffle, including through configuration,
starts a new history at the current occurrence. Setting Shuffle to its current
value preserves that history. Repeat One repeats the current occurrence at
natural EOF but does not constrain explicit Next.
CUE playback uses the original source without splitting or transcoding it.
Positions and seeks are relative to the subtrack; pregap directives do not
synthesize silence absent from the source.
Ordinary audio plays to actual decoder EOF; an estimated metadata duration is
not a playback cutoff. An explicit CUE subtrack end remains a hard playback bound.
A rescan does not replace an already loaded CUE source or bounds. Seeking uses
the loaded range; the next explicit playback start adopts catalog changes.

Seek targets must be finite, non-negative, and representable on the source
timeline. Invalid targets report an error without stopping playback, including
when rejected after the command was acknowledged; the confirmed position is then
restored. A real decoder seek or output-restart failure stops playback because the
decoder may already have moved. Ordinary file seeks are not clamped by estimated
metadata duration; only an explicit CUE end bounds the target.
Progress updates are fenced by the loaded source and latest accepted seek intent,
so queued pre-seek progress cannot overwrite a newer target. Heard time is still
recorded for that source. Rejecting a seek restores the confirmed position without
blocking subsequent progress from the attempt.

Seeking while paused stays paused. If Pause arrives at actual EOF, the next
occurrence is selected but kept paused; Repeat One instead reloads the current
occurrence paused from its start. At queue end with Repeat Off, playback stops.

Pause lets submitted audio finish before making output inactive, retaining unread
audio for resume. The displayed Paused state is the accepted intent, not an
instantaneous hardware mute. Paused wall time does not advance playback or live
analysis. Late heard-audio confirmations can still update listening statistics;
see link:02_library.adoc#play-counts-and-recent-tracks[Library].

== Queue

Queue entries are independent occurrences, so a track may appear more than once.
The full library can be enqueued without a queue-size cap.
Queue order, removals, and the current occurrence persist in the library database.
Restart preserves occurrence identities, duplicates, and order. Later scans do
not automatically append new tracks. Removing library tracks also removes their
queue and playlist references, never their audio files.

Startup restores the selected occurrence and metadata in Stopped state at position
zero, without opening a decoder. Playback position, playing/paused status, and
shuffle history are not saved. Use Play explicitly to start from the beginning.
Queue mutations save as they execute, independently of Settings Apply, layout
sync, or window close.

If a committed queue edit cannot be refreshed, later selection and edit operations
retry recovery before using it. A failed selection save must also recover before
operations that depend on that selection. Pause and Stop remain available.
If startup loading fails before queue restoration, dependent operations retry
queue recovery too. Exiting without a new selection preserves the saved occurrence;
shutdown retries only an unsaved runtime selection.

Desktop Queue rows use the shared
link:02_library.adoc#track-information[track information and hover rules].

Use `rivu queue list` to find occurrence IDs for `queue play`, `queue remove`,
and `queue move`. Move positions start at zero. `queue add TRACK_ID...` appends
every supplied occurrence in argument order without starting playback;
`queue clear` empties the queue and stops playback. Removing queue occurrences
does not unregister their library tracks. JSON listings contain occurrence rows
with zero-based positions and display metadata. Discard incomplete listings after
concurrent changes and retry; see link:02_library.adoc#paged-views[Paged views].

=== Adding local files

Drag ordinary local audio files from a file manager into Queue. A drop in blank
space appends; a drop on a row inserts at that boundary. No configured library
folder is required, and files may be outside configured folders. Files are
registered persistently, reusing existing track identities. Input order and
repeated files are preserved as separate queue occurrences. Adding files neither
starts nor interrupts playback, replaces the queue, creates a playlist, nor
configures a folder.

This operation does not scan parent folders or apply the scan minimum-duration
filter. Directories, CUE sheets, and playlists are not expanded. Unsupported or
unreadable files are skipped and reported; valid files are still added. Registration
and insertion commit together. If the chosen insertion position becomes stale,
the entire operation fails without registering new tracks or appending elsewhere.

[source,sh]
----
rivu queue add-paths song.wav another.flac song.wav --wait
----

For positional CLI insertion, supply both `--index` and `--expected-revision` from
the observed queue state (`rivu --json status`). `--wait` reports the
operation's completion, including skipped-file errors even when valid files were
saved. Registered tracks appear under their configured folder or in
link:02_library.adoc#other[Other]. Clearing Queue does not remove them from Library.

File additions share the link:02_library.adoc#cancellation[media-task lifecycle]
with scans, Other checks and playlist imports; desktop feedback appears in Queue.
A failed task may still have committed registration and insertion, for example
after skipped inputs or a post-commit refresh failure. Inspect the result and Queue
before retrying: replaying a committed addition creates more occurrences.


=== Queue controls

Queue marks the current occurrence and uses the
link:02_library.adoc#desktop-selection-and-directory-tree[shared selection and track-menu rules].
Double-click or Enter plays an occurrence; Up/Down navigates and Delete removes
selected occurrences. Optional
link:02_library.adoc#desktop-list-search[search] filters the view and selection,
not playback order; repeated tracks remain distinct. Refresh preserves browsing
position where the new result size permits.

Use *Locate playing entry in Queue* in the toolbar or Playback title to reveal and
emphasize the current occurrence, including while paused. The Playback button
opens an existing Queue tab or adds one if the layout is unlocked; it reports an
error if a locked layout has none. Location changes neither selection, playback,
nor the Details target and does not automatically follow playback changes. Without
a current occurrence it is disabled; a removed entry is not replaced by a duplicate.

Hover a row for Favorite, Play, Remove, Move up, and Move down. Actions target
that occurrence without changing selection; Favorite updates the library track
and all its occurrences. The toolbar offers group removal and Save queue as playlist.

Drag a selection to move it in original queue order, or an unselected row to move
only that occurrence. The group stays fixed during the gesture. A row's upper/lower
half inserts before/after it; the accent line marks the boundary, and blank space
appends. Dropping on the group or pressing Esc cancels. Changed queue contents
reject the drag.

Library tracks or directories, albums or their tracks, recent tracks, and playlist
tracks use the same insertion boundaries. Positional drops require an unfiltered
Queue; if the target changes while resolving contents, insertion fails rather
than appending elsewhere. Dragging queue occurrences to a playlist copies every
occurrence in queue order without removing them.
Removing the current occurrence stops playback; removing other occurrences does
not. Queue controls remain available while the layout is locked.

The Queue panel menu contains Randomize queue, Remove duplicates,
Save queue as playlist, and Clear queue. These actions target the entire queue;
Clear requires confirmation. Track-group actions live in row context menus:
Append to queue, Add to playlist, explicit Favorite and Unfavorite, and removal
of the selected occurrences. Play targets the clicked occurrence. Favorite
changes apply once per library track, including repeated queue occurrences.
See the link:02_library.adoc#desktop-selection-and-directory-tree[shared track-menu rules].
Randomizing changes queue order without changing the current playback or shuffle setting.
Removing duplicates keeps each track at its first position; if a later duplicate
is playing, playback continues as that track's retained occurrence.

Saving a queue as a playlist: link:03_playlist.adoc#desktop-ui[Playlists].
Scrolling and query retries: link:02_library.adoc#paged-views[Library].

== Keyboard controls

GUI and TUI share playback keys outside text editors, menus and dialogs:

[cols="1,2",options="header"]
|===
|Key |Action
|Space |Play/pause
|n / p |Next/previous track
|[ / ] |Lower/raise volume by five percentage points (3 dB except at mute)
|r / s |Cycle repeat mode / toggle shuffle
|Ctrl+Left / Ctrl+Right |Seek backward/forward five seconds
|===

The TUI additionally supports `Ctrl+Home` / `Ctrl+End` to seek to the track's
start/known end; `Ctrl+End` does nothing when duration is unknown. The GUI does
not bind these keys; use its playback controls instead.

Bare Left/Right are reserved for container navigation, not seeking. Home/End
select the first/last item in lists supporting row navigation. Enter opens a
directory or plays the current object. `Remove entries` (Delete) removes selected
Queue or playlist entries, never media files; bare `d` is not a removal shortcut.
Undeclared Ctrl/Alt/Shift/Super combinations do not inherit bare-key actions.
Application shortcuts and text editing use Ctrl, not Cmd/Super aliases.

In the TUI, F1 opens context-sensitive help even from the search query editor;
`?` opens it outside that editor. In the GUI, help opens only through *Shortcuts*
in the application menu.
Help scrolls with arrows, PageUp/PageDown, and Home/End. Escape closes GUI help;
F1, `?`, or Escape closes TUI help without acting on the list beneath. Editors
retain their text-editing keys. A focused GUI button owns Enter/Space instead of
also controlling playback.

Reach seek and volume sliders with Tab/Shift+Tab. Arrow keys change seek by five
seconds or volume by five percentage points; Home/End chooses the minimum/maximum.
Seek requires a current occurrence and known positive duration; volume does not.
A slider key ends an active pointer drag so release cannot commit an old preview.
Escape cancels the innermost interaction or leaves the editor first; see
link:01_config.adoc#desktop-keyboard-navigation[desktop control navigation].

== Output devices and speaker layouts

`playback.output_device` is an exact name from `rivu playback devices`, which lists native
PipeWire sinks only. Omit the setting for the default PipeWire sink, or use
`PipeWire: <node.name>` for a named sink. PipeWire must be running; there is no
direct ALSA output or fallback to a different backend.

Playback stays bound to the selected sink. Invalid or disappearing routes fail
instead of rerouting; a failed device change stops playback and retains the
requested setting. Select an available sink and explicitly restart playback to
recover. Reapplying the same setting validates it again, even while stopped.

Output and Monitor EQ application failures remain reportable while Stop or an
audition source replacement retires playback. Superseded setting requests and
inapplicable EQ generations/configurations are ignored; retiring playback events
do not restart transport or advance the queue.

Changing sink or remixing rebuilds output at the final confirmed audible position,
preserving pause without reopening the decoder. The retired output's final position
and heard time remain authoritative even if its replacement fails to open; resetting
analysis for the replacement cannot discard or count those confirmations twice.
Rebuilding output does not apply a newly saved Decoder hint or read-buffer size.
PipeWire handles device-rate conversion.

Multichannel output preserves speaker identities. `playback.pipewire_auto_mix` is enabled
by default and permits PipeWire remixing with channel-level normalization to prevent
gain from summed channels. Downmixing may therefore reduce the level. Disable it to
require a compatible sink layout without remixing. Both modes validate the actual
selected sink and its negotiated speaker layout, including changes to links while
playing. Unsupported routes report an error rather than using an unrelated compatible sink.

Rivu sends 32-bit float audio at the decoded sample rate and suggests that rate to
PipeWire without forcing the shared graph. Actual graph and device rates depend on
system policy and device support; source-rate output alone is not a bit-perfect
guarantee. Floating-point peaks above full scale are preserved before device
conversion, not clipped by Rivu. Downstream gain and integer device conversion can
still cause clipping; Rivu does not add a limiter or dither to its float output.
Non-finite decoded samples, including overflow during conversion to 32-bit float,
are replaced with silence before PCM publication, analysis and playback.
This does not limit extreme finite amplitudes or provide protection against clipping.

Desktop audio mixers receive the current library/CUE title, artist and album,
including edits made while playing or paused. The application identity remains
Rivu. Mixer volume and mute are independent of Rivu's own software volume and
remain effective with remixing disabled.

Unusable output formats or insufficient audio-buffer memory report a playback
error rather than switching routes.

When seeking is unavailable or duration unknown, opening a selection may decode
forward, potentially to EOF. This is cancellable. A valid exhausted selection
returns EOF; a source with no decodable audio fails. Native Matroska supports
backward seeking when seekable; unseekable sources scan forward only.


== Optional FFmpeg decoder

Native decoding is the default. Enable `playback.ffmpeg_enabled` for sources the
native decoder does not support. Container extensions such as MKV or MP4 alone
do not determine whether FFmpeg is needed; the contained codec also matters.
In Auto mode, FFmpeg loads when a native decoder cannot support a source,
not during startup or status queries. Opening a track whose
decoder hint is FFmpeg also loads the extension directly. Decoder status shows
`not loaded` until a load is attempted; missing or incompatible libraries are
reported when needed, and the load result is retained until restart.
Auto fallback covers unsupported native formats detected during opening,
including initial decoding. Corrupt input and cancellation do not trigger fallback.

Track details provides a *Decoder hint* selection. Choosing an option saves it
immediately, independently of tag edits:

* *Auto* preserves automatic native-first selection and FFmpeg fallback.
* *Native* uses only the native decoder, without FFmpeg recognition or fallback.
* *FFmpeg* loads and uses FFmpeg directly. The global setting must be enabled;
  disabling it, missing libraries, or a native-only build reports an error rather
  than falling back to native decoding.

The saved hint survives rescans and restart, is independent for each CUE subtrack,
and applies to the next source open or explicit full-waveform request. It does
not reopen current playback. Changing it cancels an in-flight full-waveform
request and discards its completed preview; request a fresh preview explicitly.

In Auto mode, once FFmpeg is loaded and enabled, future WAVE opens use its format
recognition; ordinary PCM still uses the native decoder. Recognition is not proof
that a file has been fully validated. In Native mode, or Auto mode with FFmpeg
disabled or not loaded, DTS inside a PCM-labelled WAVE may be treated as PCM,
including incorrect metadata and noise on playback. For DTS-WAV, select FFmpeg
and enable the extension; no prior load is required. An explicit enhanced probe
runs in a separate process and does not load FFmpeg in a running playback instance.

Library rows are not automatically reprobed after FFmpeg loads; use a forced
rescan to refresh stored metadata. Probe commands and recognition provenance:
link:02_library.adoc#metadata-and-favorites[Library].

Build prerequisites and ABI compatibility: link:../readme.adoc[README].
Enablement, disabling an active decoder, and build-feature restrictions:
link:01_config.adoc[Configuration].

== Playback metadata updates

Successful playback can improve the library's bitrate information without
rewriting media files. Reliable fixed-encoding metadata can confirm a value at
open. Otherwise, complete playback from the beginning to actual source EOF may
measure the selected encoded audio stream during normal decoding, without an
additional analysis pass.

Seeking, restricted CUE playback, early stop, decode errors, incomplete stream
statistics, or unsupported measurements leave the value estimated or unknown.
Pausing alone does not invalidate measurement. A confirmed bitrate does not
certify file integrity and is never replaced by an estimate. CUE records use
whole-source metadata, not source bytes divided by subtrack duration.

Enrichment updates open views without changing membership or counts. It uses the
already selected decoder and never loads FFmpeg or changes decoder selection.


== Terminal client

`rivu tui` connects to the Core for its data directory, starting an independent
background `rivu serve` when absent. The service survives TUI and terminal closure;
use `:qa` / `:qall` or `rivu quit` to stop it. Closing only the client does not stop
playback. `Tab` cycles
Queue → Playlists → Library → Recent; `Shift+Tab` reverses direction.
Without a search, each page retains its selection and scroll position.
The active tab identifies the page; its selection/total counter appears at the
right of navigation when space permits. The content area adds a heading only for
context such as a directory path or playlist name, not another copy of the tab.
`Right` opens a playlist; Enter plays the selected playlist, track, or queue
occurrence. In Library track lists and playlist details, `e` enqueues the selected
track. `Alt+e` enqueues the selected Library directory or the complete Other
collection, regardless of filters. Selecting a row alone does not change playback.

Outside search editing, help, and details, press `:` to open the command line on
the bottom row. Enter executes; Escape cancels. Submitted search results remain
browsable with command mode, without clearing the search. Commands are bounded
to 256 UTF-8 bytes and support Backspace.
Command input is cyan. Confirmed queue additions/removals and successful scans
use green feedback; ordinary progress is secondary text, warnings orange, and
errors red. Queue-change confirmations do not replace an unexpired warning or
error. Messages still share the bottom row rather than adding extra rows.

[cols="1,3",options="header"]
|===
|Command |Effect
|`:q`, `:quit` |Close this TUI only; Core and playback continue
|`:qa`, `:qall` |Stop playback and shut down Core and all connected GUI/TUI clients
|`:help` |Open the scrollable help page, including command descriptions
|===

Bare `q` has no action outside editors and remains ordinary text inside them.
Escape cancels or returns; it never closes the client. Unknown commands and
rejected shutdown requests show errors without closing it; uncertain shutdown
outcomes are not automatically retried.

Recent shows up to 256 unique tracks in recent-play order, with titles, counts,
and local timestamps where space permits. The playing or paused track uses its
live activity time; reordering preserves selection. Enter plays, `i` opens details,
and `m` toggles favorite. Recent has no selectable sort or removal action. History
and counting rules: link:02_library.adoc#play-counts-and-recent-tracks[Library].

Use `/` to search the current page, then Enter to apply; typing alone does not
change the results. Applying or clearing search keeps the selected entry if it
remains in the results; otherwise it selects the first result, or nothing when
empty. Scrolling adjusts only as needed to keep the selection visible.
Search does not start playback. Press `/` again to edit the query.
Enter on the filtered list keeps its normal play or open action. The editor owns
all printable characters, including Space, `m`, `q`, and `?`; F1 opens help and
Ctrl-C exits even while editing.
The bottom line shows the query. While editing, it hides messages without clearing
them; after submission, messages use the remaining space, prioritizing the query
in narrow terminals.


The search scope follows the page:

* Queue searches its occurrences; Playlists searches playlist names, and playlist
  details searches that playlist's entries. Track searches match title, artist,
  album, and file name, including unloaded pages. Repeated tracks retain their
  distinct queue or playlist occurrence identities for play and removal.
* At Library's top level, search shows matching tracks from the full library,
  matching title, artist, or full source path. Within a directory, search keeps
  immediate tracks and directories with matching descendants, using the same
  fields. In Other, search stays within that collection and preserves its
  favorite/missing filters and sort order.
* Recent filters only the displayed titles in its published history of
  at most 256 tracks.

Searches use case-insensitive literal substrings, not wildcard patterns. Esc
clears and closes the transient editor. Tab/Shift+Tab switches tabs and clears
search even while editing; entering or leaving a directory, Other, or playlist
details also clears it. Queries are not saved per tab. Refresh preserves visible
selection by identity; playlist renames preserve track selection and scroll.

Failed queries wait for changed demand or data, or for the view to be reopened.
Obsolete and cancelled reads retire without a query error. Query lifetime and
resource boundaries: link:22_cache.adoc#terminal-projections[Terminal projections].

Library's link:02_library.adoc#other[Other] entry is hidden at the top level when
the unfiltered collection is empty.
`Alt+f` / `Alt+m` toggle favorite-only / missing-only filters; `Alt+s` cycles ID,
album, and most-played sorting. Selection follows its track through changes while
that track remains in the results. `Alt+c` checks registered files;
`Alt+Shift+c` forces rereading. Collection-wide Alt actions also work on its header.
`Alt+x` cancels an active scan before its saving phase. F1 lists the actions for
the current context.

Outside the query editor, `m` toggles the selected track's favorite in Queue,
Library, Recent, or playlist entries. It never changes a whole directory or
playlist. Track lists prioritize titles as the terminal narrows and keep compact
metadata, favorite, playback-state, and missing-file indicators where space permits.
Truncation does not change stored metadata.
Track lists use semantic colors to distinguish metadata, favorites, and playback
state.

The status row shows volume, shuffle, repeat, and current-track codec, sample rate,
bit depth, and available bitrate in `kbps` where space permits, without distinguishing
estimated and confirmed bitrates. A separate bottom row holds notices, then scan
status, core errors, or the startup help hint, in that priority order. Notices and
startup help expire automatically. Playback transitions update the fixed playback
display rather than replacing messages.

Press `i` outside the query editor for read-only details of the selected track,
directory, or playlist. Playback changes do not replace that target. Track details
includes tags, technical audio metadata, source path, Decoder hint, and playback
history. Missing-file paths remain available; unknowns use `—`, zero counts `0`,
and estimated bitrates `≈`. Loading, query failure, removal, and no selection are
distinct states. This is not a tag editor or decoder control.

Scroll details with arrows, PageUp/PageDown, or Home/End; Esc closes it and restores
the source position. Long query errors can be scrolled independently; loading and
errors preserve the track details' reading position for a later successful refresh.
Help and details own navigation while open; actions do not reach the underlying list.

Position, duration, and playback controls remain available while browsing. Warnings
and errors are distinct; ordinary playback updates do not replace a visible failure.

Left goes to a parent directory; Left/Esc leaves playlist details.
With search closed, Esc returns from Library tree or playlist catalog to Queue.
At Queue's outermost level, Esc has no action. Ctrl-C closes the current TUI from
every view, including editors, overlays, Core startup, and initial connection
waiting. `SIGINT` and `SIGTERM` also close only the client. These exits cancel
frontend readiness waiting and restore terminal mode, screen, and cursor; the
independent Core keeps its own lifetime and playback is not stopped.

Core shutdown exits normally; a lost connection without shutdown state reports an error.

== Desktop tray and window lifecycle

Closing the window, including Close window in the application menu, leaves Core
and playback running. Reopen or focus it with the tray, `rivu gui`, or MPRIS
`Raise`. CLI and MPRIS reopening work without a tray and with a Core started by
`serve`, provided it was built with GUI support. Quit application in the menu or
tray, or `rivu quit`, stops Core and releases the tray and desktop media controls.

`interface.tray_enabled` takes effect on Core restart, not just GUI restart.
The tray requires session D-Bus and a StatusNotifier-compatible host. Failure
does not prevent the window or playback; a later watcher is registered automatically.
The host resolves the `rivu` theme icon, so install icons using the
link:../readme.adoc#build-and-install[installation instructions]. The tray menu
offers Play/Pause, Previous, Next, Shuffle, Repeat, and Quit application. Play/Pause
toggles Core's state at command execution; the asynchronously updated menu label
does not determine the transport command.

== Artwork panel

The *Artwork* panel follows the current playback track, independently of
Library selection and Track details. Add it from the panel catalog; it is also
included in the built-in *Default* layout.

The panel's right-click Style and Rotation actions apply immediately; Artwork
settings edits its options with Apply and Discard. These instance choices survive
docking and layout duplication in session memory. Persist them with layout sync
or orderly exit of the last desktop window, independently of the running Core;
see link:01_config.adoc#layout[Layout persistence]. Settings → Interface → Artwork
instead sets defaults for new panels without overwriting existing instances. See
link:01_config.adoc#artwork[Artwork configuration] for styles,
animation parameters, defaults, and shared frame rate.

Rotation follows playback while the panel is visible. Pausing or hiding it retains
the angle without advancing hidden time; stopping, changing tracks, or choosing
Static resets the cover upright. Animated source covers can continue while paused
or Static; both animation types use the shared frame-rate cap. Lower caps skip
source frames without slowing their timeline. Hiding the panel stops both kinds
of animation, and rotation resumes without catching up on suspended time.
Missing artwork uses the generated default cover. Disabling visualizations does
not affect cover loading or animation. Panels share cover loading but retain
independent rotation and source-animation state. Track details keeps its full,
static preview.

== MPRIS and artwork

`interface.mpris_enabled` controls desktop media integration in graphical and
headless cores and can be changed while running. It requires session D-Bus;
registration failure appears in status without preventing playback. Restore the
bus, then disable and re-enable the setting to retry registration.

MPRIS, Track details, album cards, and the Artwork panel prefer embedded
front-cover artwork, then another supported embedded image. If none is available,
Rivu checks only the audio file's immediate directory, without descending into
subdirectories. Candidate stems must be exactly `cover`, `folder`, or `front`, in
that order, ignoring case. Supported extensions are PNG, JPG/JPEG, GIF, WebP, BMP,
TIF/TIFF, and ICO, also ignoring case. Within each priority, filenames sort
case-insensitively with their original bytes as a tie-breaker. Invalid,
unsupported, or oversized candidates are skipped. File contents determine the
cached image format; an extension alone does not establish it.
The GUI shows a default cover until a real cover is ready or when none is found.
MPRIS uses the bundled application icon as its fallback. Directory discovery is
cached, not watched for edits; moving a track retries it, otherwise restart Rivu
to reliably rediscover changed directory covers. Encoded-file and decoded-image
limits are configured separately in
link:01_config.adoc#desktop-settings[Settings].
Actual covers keep their original aspect ratio in the full, static preview.
Local images are cached under the data directory's `artwork/` and exposed through
`mpris:artUrl` when available. Background loading updates the selected preview
and desktop metadata when ready. Cache failures do not prevent playback.
Use link:01_config.adoc#artwork-cache-maintenance[Settings artwork maintenance]
to inspect disk usage and manually clean expired, unprotected cover files.

MPRIS supports transport, volume, shuffle, and repeat at rate `1.0`. Relative Seek
accumulates against the current position and stays bound to its queue occurrence;
stale or stopped requests are ignored. Seeking strictly beyond a known end advances
if another occurrence exists; the exact endpoint stays within the current one,
and seeking beyond the queue tail does nothing. Out-of-range or stale `SetPosition`
is ignored. `OpenUri` is rejected: import media first. `Raise` requires a Core built
with GUI support; `Quit` also works without it.

MPRIS Next/Previous preserve paused or stopped state; stopped navigation selects
without opening a decoder. CLI, TUI, and GUI navigation instead starts playback
when moving to another occurrence. Protocol and database-admission details:
link:21_ipc.adoc[IPC].

== Equalizer and processed audition

Use the link:27_audio_processing.adoc[Audio processing workflow] for Monitor EQ,
restoration, speech enhancement, separation, and graph audition. Processing never
replaces source media. Original returns from audition to source playback; Monitor
EQ remains in both paths, so keep EQ and level fixed for comparisons. Export a
retained graph output explicitly for a WAV file; audition results stay in memory
and are lost when the core exits.
