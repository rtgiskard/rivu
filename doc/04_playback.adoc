= Playback

Selecting a missing source manually leaves the current track running and reports
an error. If the next entry cannot be opened at natural end, playback stops.

== Transport and timing

Use `rivu playback` for play, pause, resume (`play` without a track ID), stop,
next, previous, seek, volume, shuffle, and repeat controls. Seek positions are
seconds; CLI volume is an integer percentage from 0 to 100.
Volume uses a dB-linear control curve rather than linear amplitude: 0% mutes,
50% is -30 dB, and 100% leaves the source gain unchanged. Keyboard `[` and `]`
change the level by five percentage points (3 dB away from mute). See
link:01_config.adoc#volume[Volume configuration] for fractional values.

The desktop Playback panel shows the current title, artist and album, playback
progress, transport controls, and volume. Transport controls and volume stay on
one row with horizontal scrolling in narrow panels. Use Album artwork for covers.
The crosshair beside its title (*Locate playing entry in Queue*) reveals the
Queue tab and locates the current occurrence, subject to layout locking;
see <<_queue,Queue>>.

Repeat cycles Off, All, and One. Previous restarts the current entry when its
position exceeds three seconds; at or before three seconds it navigates back,
using playback history when shuffling.
With Shuffle enabled, each Next independently chooses a queue occurrence with
equal probability, including the current one. Immediate repeats are expected;
duplicate occurrences increase their track's chances. Previous follows playback
history, retaining up to 4096 occurrences during the running session; Next draws
afresh even after Previous. Setting Shuffle to its current value preserves that
history. Repeat One repeats the current occurrence at
natural EOF but does not constrain explicit Next.
CUE playback uses the original source without splitting or transcoding it.
Positions and seeks are relative to the subtrack; pregap directives do not
synthesize silence absent from the source.
Ordinary audio plays to actual decoder EOF; an estimated metadata duration is
not a playback cutoff. An explicit CUE subtrack end remains a hard playback bound.

Successful playback fills or improves bitrate information in the library without
rewriting media files. Reliable fixed-encoding opening metadata can upgrade an estimate.
Otherwise, complete playback from the beginning to actual source EOF measures
the selected encoded audio stream during normal decoding; there is no additional
full-file analysis pass. Seeking, restricted CUE playback, early stop, and decode
errors cannot produce a complete-playback measured average. Missing packet durations,
known incomplete streams, or unsupported statistics leave the value estimated or
unknown. Native MPEG playback checks available authoritative frame counts at completion;
estimated metadata durations are not completeness evidence. Without reliable
counts, measurement does not certify file integrity. Late results and
source replacements cannot update another track or a changed file.
Native VBRI MP3 can remain estimated because the demuxer consumes its first audio
frame as metadata while the declared frame count still includes it.
Pausing alone does not invalidate complete-stream measurement. Confirmed
values are not replaced by estimates. CUE records use whole-source opening
metadata, never source byte counts divided by a subtrack's duration.
Bitrate measurement does not load FFmpeg or change decoder selection. It only
reuses the decoder selected by the existing enable setting, Decoder hint, and
Auto fallback rules.

Seek targets must be finite and non-negative. Ordinary file seeks are not clamped
by estimated metadata duration; completion requires actual decoder EOF. Only an
explicit CUE end bounds the seek target. Seeking while paused keeps playback
paused. A late EOF notification after pausing does not restart playback or
automatically advance the queue. Pause also pauses live analysis. Listening
statistics use confirmed heard time; see link:02_library.adoc[Library].

Pausing lets already submitted audio finish, then makes the output stream inactive.
Unread audio is retained for resume; paused wall time does not advance playback.

== Output devices and speaker layouts

`playback.output_device` is an exact name from `rivu playback devices`, which lists native
PipeWire sinks only. Omit the setting for the default PipeWire sink, or use
`PipeWire: <node.name>` for a named sink. PipeWire must be running; there is no
direct ALSA output or fallback to a different backend.

PipeWire handles device-rate conversion. Playback stays bound to its selected
sink; invalid or disappearing routes fail explicitly instead of silently
rerouting. Select an available sink and start playback again to recover.
Changing to an invalid or unavailable sink stops playback and keeps the newly
requested setting. Subsequent playback attempts still target that sink; neither
the previous selection nor the default sink is substituted automatically.
Device-application failures are reported while stopped as well as during
playback. If playback is already stopped, a failure reports a configuration error
for the latest output request. Reapplying unchanged settings while stopped
validates them again. If applying settings actually terminates active playback,
that playback remains stopped regardless of a later device selection. Events
from an older playback cannot stop a newer playback.
Changing the sink or remixing setting rebuilds the output at the current
position and preserves paused state. The existing decoder is retained; these
changes do not apply a newly saved Decoder hint or media read-buffer size.

Multichannel output preserves speaker identities. `playback.pipewire_auto_mix` is enabled
by default and permits PipeWire remixing with channel-level normalization to prevent
gain from summed channels. Downmixing may therefore reduce the level. Disable it to
require a compatible sink layout without remixing. Both modes validate the actual
selected sink and its negotiated speaker layout, including changes to links while
playing. Unsupported routes report an error rather than using an unrelated compatible sink.

Rivu sends 32-bit float audio at the decoded sample rate and suggests that rate to
PipeWire without forcing the shared graph. Actual graph and device rates depend on
system policy and device support; source-rate output alone is not a bit-perfect
guarantee. Floating-point peaks above full scale are preserved before device
conversion, not clipped by Rivu. Downstream gain and integer device conversion can
still cause clipping; Rivu does not add a limiter or dither to its float output.
Non-finite output samples are replaced with silence before being sent to PipeWire.

Desktop audio mixers receive the current library/CUE title, artist and album,
including edits made while playing or paused. The application identity remains
Rivu. Mixer volume and mute are independent of Rivu's own software volume and
remain effective with remixing disabled.

The decoded PCM output queue retains a quarter second of audio, with a minimum of
2048 frames, and is limited to 16 MiB of interleaved 32-bit float samples. Rates
and channel counts must fit that combined budget; for example, 768 kHz with 16
channels and 192 kHz with 32 channels fit. The callback's 256-frame scratch buffer
uses at most another 2 MiB. Invalid formats, capacity arithmetic overflow, formats
above the queue limit, and PCM or scratch allocation failures report playback
errors instead of requesting an unbounded buffer or changing the output route.

== Optional FFmpeg decoder

Native decoding is the default. Enable `playback.ffmpeg_enabled` for additional formats,
including audio in MKV/MP4. In Auto mode, FFmpeg loads when a native decoder cannot
support a source, not during startup or status queries. Opening a track whose
decoder hint is FFmpeg also loads the extension directly. Decoder status shows
`not loaded` until a load is attempted; missing or incompatible libraries are
reported when needed, and the load result is retained until restart.
Native support is checked through the first packet decode: an unsupported
format at that point also permits Auto fallback. Corrupt input and cancellation
do not trigger a decoder fallback.

Track details provides a *Decoder hint* selection. Use *Save* to commit it together
with tag edits; an unsaved selection does not affect playback or waveform decoding:

* *Auto* preserves automatic native-first selection and FFmpeg fallback.
* *Native* uses only the native decoder, without FFmpeg recognition or fallback.
* *FFmpeg* loads and uses FFmpeg directly. The global setting must be enabled;
  disabling it, missing libraries, or a native-only build reports an error rather
  than falling back to native decoding.

The saved choice survives rescans and restart, is independent for each CUE subtrack,
and applies to the next track open or explicit full-waveform request. Saving it
does not reopen current playback. Saving a changed hint cancels an in-flight
full-waveform request and discards its completed preview, without restarting it;
this also applies while the window is hidden. Explicit loading reads the latest
saved hint and replaces any pending request. Its result is independent of the
playing decoder and does not mix with the progressive playback waveform.

In Auto mode, once FFmpeg is loaded and enabled, future WAVE opens use its format
recognition; ordinary PCM still uses the native decoder. Recognition is not proof
that a file has been fully validated. In Native mode, or Auto mode with FFmpeg
disabled or not loaded, DTS inside a PCM-labelled WAVE may be treated as PCM,
including incorrect metadata and noise on playback. For DTS-WAV, select FFmpeg
and enable the extension; no prior load is required. An explicit enhanced probe
runs in a separate process and does not load FFmpeg in a running playback instance.

Library rows are not automatically reprobed after FFmpeg loads; use a forced
rescan to refresh stored metadata. Probe commands and recognition provenance:
link:02_library.adoc#_metadata_and_favorites[Library].

Build prerequisites and ABI compatibility: link:../readme.adoc[README].
Enablement, disabling an active decoder, and build-feature restrictions:
link:01_config.adoc[Configuration].

== Queue

Queue entries are independent occurrences, so a track may appear more than once.
The full library can be enqueued without a queue-size cap.
Queue order, removals, and the current occurrence persist transactionally in the
library database. Restart preserves occurrence identities, duplicates, and order;
clearing the queue does not reuse occurrence IDs. Later scans do not automatically
append newly discovered tracks. Removing library tracks removes their queue and
playlist references in the same database transaction.

Use `rivu queue list` to find occurrence IDs for `queue play`, `queue remove`,
and `queue move`. Move positions start at zero. `queue add TRACK_ID...` appends
occurrences; `queue clear` empties the queue and stops playback. `queue list --json`
returns a streamed JSON array of occurrence rows with absolute zero-based positions
and display metadata. Listings stop on concurrent queue content changes; repeat
the listing to obtain a consistent new traversal.

The Queue panel displays occurrences in order and marks the current occurrence.
Use the link:02_library.adoc#_desktop_selection_and_directory_tree[shared selection rules]
for clicks, ranges, and row context menus. Double-click plays that occurrence.
Up/Down navigate the focused queue, Enter plays the selected occurrence, and Delete
removes selected occurrences.
Optional link:02_library.adoc#_desktop_list_search[Desktop list search] filters
the visible occurrences without changing playback order. Selection actions apply
to the matching occurrences; repeated tracks remain distinct queue entries.
Background refreshes preserve the browsing position with or without a search
filter; a shorter result set clamps scrolling only when its new total arrives.

Use the crosshair button (*Locate playing entry in Queue*) in the Queue toolbar
or beside the Playback title to scroll to the current occurrence and briefly
emphasize it. The Playback button reveals an existing Queue tab first, or adds a
Queue panel when the layout is unlocked; it reports an error rather than adding
a missing panel to a locked layout. Duplicate tracks are located by occurrence,
not by their shared track identity. Both buttons also work while paused and are
unavailable without a current occurrence. Locating never changes selection,
playback, or an unsaved Track details draft, and playback changes do not
automatically scroll the queue. A removed occurrence is not replaced by another
duplicate.

Hover a queue row to reveal its favorite, play, remove, move-up and move-down
controls. Each action targets that occurrence without changing the selection;
the favorite toggle updates its library track, including other occurrences.
Move-up is unavailable on the first row and move-down on the last. The toolbar
offers removal for a multi-selection and saving the entire queue as a playlist.
Dragging a selected row moves the selected group in its original queue order;
dragging an unselected row moves only that occurrence. The group is fixed at
drag start, even if selection changes during the gesture. Dropping on a row
inserts before it; dropping below the rows appends. Dropping on a member of the
dragged group or pressing Esc leaves queue order unchanged. A drag is rejected
if queue contents change before it is dropped.
Dragging Library tracks or directories, album cards or tracks, recent tracks,
or playlist tracks onto Queue appends the resolved tracks. Dragging queue
occurrences to a named playlist catalog row copies their track IDs in queue
order without removing occurrences; playlist deduplication still applies.
Removing the current occurrence stops playback; removing other occurrences does
not. Queue controls remain available while the layout is locked.

The Queue panel menu contains Randomize queue, Remove duplicates,
Save queue as playlist, and Clear queue. These actions target the entire queue;
Clear requires confirmation. Track-group actions live in row context menus:
Append to queue, Add to playlist, explicit Favorite and Unfavorite, and removal
of the selected occurrences. Play targets the clicked occurrence. Favorite
changes apply once per library track, including repeated queue occurrences.
See the link:02_library.adoc#_desktop_selection_and_directory_tree[shared track-menu rules].
Randomizing changes queue order without changing the current playback or shuffle setting.
Removing duplicates keeps each track at its first position; if a later duplicate
is playing, playback continues as that track's retained occurrence.

Saving a queue as a playlist: link:03_playlist.adoc#_desktop_ui[Playlists].
Scrolling and query retries: link:02_library.adoc#_paged_views[Library].

== Keyboard controls

GUI and TUI share playback keys outside text editors, menus and dialogs:

[cols="1,2",options="header"]
|===
|Key |Action
|Space |Play/pause
|n / p |Next/previous track
|[ / ] |Lower/raise volume by five percentage points
|r / s |Cycle repeat mode / toggle shuffle
|Ctrl+Left / Ctrl+Right |Seek backward/forward five seconds
|===

The TUI additionally supports `Ctrl+Home` / `Ctrl+End` to seek to the track's
start/known end; `Ctrl+End` does nothing when duration is unknown. The GUI does
not bind these keys or the TUI's bare `q` action; use its window controls and
menus instead.

Bare Left/Right are reserved for container navigation, not seeking. Home/End
select the first/last item in lists supporting row navigation. Enter opens a
directory or plays the current object. `Remove entries` (Delete) removes selected
Queue or playlist entries, never media files; bare `d` is not a removal shortcut.
Undeclared Ctrl/Alt/Shift/Super combinations do not inherit bare-key actions.
Application shortcuts and text editing use Ctrl, not Cmd/Super aliases.

In the TUI, F1 opens context-sensitive help even from the search query editor;
`?` opens it outside that editor. In the GUI, help opens only through *Shortcuts*
in the application menu.
Equivalent keys and paired operations share a help row; paired descriptions follow
the displayed key order. Help can be scrolled with Up/Down, PageUp/PageDown and
Home/End. Escape closes GUI help; F1, `?` or Escape closes TUI help, without
operating the list underneath.
Editors retain their text and editing keys, including spaces, `R` and `?`.
In the GUI, a focused button owns Enter/Space instead of also controlling playback.
The GUI seek and volume sliders are reachable with Tab/Shift+Tab and show a
focus border. On a focused slider, unmodified Left/Down decrease and Right/Up
increase the value: five seconds for seek, five percentage points for volume.
Home/End choose the minimum/maximum. Seeking requires a current queue entry and
a known positive duration; volume remains adjustable independently. These local
keys do not extend the scope of the layout's playback shortcuts. A slider key
ends any active pointer drag before applying its command, so a later pointer
release cannot commit an obsolete seek preview.
Escape cancels only the innermost interaction or leaves the focused editor before
returning from its containing view. See
link:01_config.adoc#_desktop_keyboard_navigation[desktop control navigation].

== Terminal client

When the terminal client receives shutdown state, it exits normally and restores
the terminal, including while the first snapshot is loading. A Watch connection
ending without a shutdown snapshot is an error and also restores the terminal.
Exiting the client locally does not stop the core or playback.

`Tab` cycles Queue → Playlists → Library → Queue; `Shift+Tab` reverses the order.
The current top tab is highlighted and bold. Switching retains each page's
selection and scroll position, including an open playlist or library directory.
Help and track-details overlays keep navigation inside the overlay.
Help groups the canonical current-context bindings under Navigation, Playback,
Current page, and Help / exit, omitting empty groups. Bold group headings are
unindented; binding rows have a two-cell indent. Key/description columns align
by terminal display cells; narrow screens stack descriptions with a hanging
indent. Help is read-only with no selected-row highlight: scrolling accounts for
headings and wrapped lines. Its fixed title identifies the current context.
Details and Keys use a plain title row followed by the same structural separator
as the main page, without nested boxes or cards.
`/` opens Library search. Navigation, playback, removal, and help keys:
<<keyboard-controls,Keyboard controls>>.

In Search, `Tab`/`Shift+Tab` switches between the query and results. `Enter` from
the query focuses results; on a result it plays the track. `Esc` from results
returns to the query; from the query it returns to Queue. Typing appends to the
query, and Backspace removes its last character. The visible text follows the
query's end when it exceeds the available width. The query owns printable
characters, including `?`; F1 still opens help. Playback keys apply after
focusing results.
Text edits use the same
link:02_library.adoc#_desktop_list_search[delayed application and immediate clearing]
as desktop list searches.

`Right` opens playlist entries; `Enter` plays a selected playlist, track, or queue
occurrence. In playlist details, `a` enqueues the selected track. Moving selection
does not change the playing occurrence; its marker distinguishes playing, paused,
and stopped states.

Press `m` (mark) to toggle the selected track's favorite state in Queue, Library, Search
results, or playlist entries. It affects only that track, not a directory or an
entire playlist. In the search query editor, `m` remains text input.

Track lists show titles with compact artist, album, codec, and duration information.
Artist and album widths adapt to loaded content within bounded widths; secondary
information hides as the terminal narrows, and titles take priority. Codecs are
shown in lowercase and unknown durations as `–:––`. Long values are shortened with
an ellipsis without changing metadata. These automatic widths are independent of
the desktop Library column settings.
Playback status, favorites, and missing-file warnings occupy compact fixed slots
at the right edge, after the duration, rather than before track titles. Directory
and playlist type icons precede their names. Library directory-view files likewise
show the desktop file icon before their titles. Each type prefix reserves a
two-cell icon slot followed by one empty cell; other track lists do not reserve
type-icon slots. Status slots hide below 14 columns.
Playback, favorite, missing-file, directory, and search symbols match their desktop
counterparts. Unfavorited tracks leave the favorite slot blank.
Queue, Library, Playlists, and search result lists leave one character cell empty
on each side. Playlist-detail tracks have one additional cell of left indentation
relative to their list header. These insets reduce the width available for columns;
narrow windows still clip content to fit. Entering Library directories does not
add indentation or tree branches.

Outside the query editor, `i` opens read-only details for the corresponding
selected item. A real track is read in full from Queue, Library, Search results,
or playlist tracks; playback changes never replace this target. Folders and
playlist containers show their full path/name without pretending to be tracks.
With no selected track or container, details explain where to select one.
`Esc` closes details and preserves the source selection and scroll position.
There are exactly three top-level tabs; Details is not a fourth tab.

The summary shows the full title once, source and ID, favorite, and availability.
One scrollable body presents Tags (artist, album, disc/track numbers and release),
Audio (codec, sample rate, channels, duration, bitrate and source bit depth), File
(path and decoder hint), and Playback history (play count and last played).
Paths remain visible even for missing files. Unknown values use `—`, zero play
counts remain `0`, and estimated bitrates use `≈`. Loading, failed reads, removed
tracks, and no target have distinct states. Full text wraps by grapheme cell width;
short fields pair at 90 body cells or wider and stack below that width.
Labels and unknowns are secondary, values normal, headings/favorites accent,
missing files warning, and failures error-colored using the current theme.
Up/Down, PageUp/PageDown, and Home/End scroll Details. Playback, activation,
tab-switching and removal keys do not operate the underlying list while the
overlay is open. There is no tag editor, decoder toggle, artwork, or additional
playback progress. Closing the overlay restores the unchanged main playback area.

Without a current track, the playback line shows only an idle message; with a
current track, it retains the playing, paused, or stopped symbol and track title.

The bottom area keeps playback position, duration, volume, and playback modes
available while browsing. Shuffle and repeat use dim icons when disabled and
highlighted icons when enabled; single-track repeat has its own icon. The volume
icon and percentage use the same enabled color while nonzero and are dimmed when
muted. Notifications retain explanatory text: warnings and failures have distinct
symbols, and ordinary
playback updates do not replace a still-visible failure. At startup, Queue shows a
brief `F1 / ?` help hint for about five seconds. Notices, opening help or details,
or leaving the initial view dismiss it; returning to Queue does not show it again.
Open help to view the current bindings.

Left/Backspace goes to the parent directory; Left/Esc leaves playlist details.
Esc returns from search, the tree, or the playlist catalog to Queue.
`Close client` (`q`) exits outside Search without stopping the core.
Ctrl-C exits from every terminal view, including the query editor, help, details,
and initial connection screen, without stopping the core. While initially connecting,
`q` also exits the loading screen. `SIGINT` and `SIGTERM` close only the terminal
client, including during connection setup. Connection errors, normal exits, and
these signals restore the terminal's input mode, screen, and cursor; the core keeps
running.

== Desktop tray and window lifecycle

Closing the window, including the application menu's Close window action, leaves
the core and playback running. Activate the tray icon, use `rivu gui`, or invoke
MPRIS `Raise` to reopen or focus the window. CLI and MPRIS reopening work with
the tray disabled or unavailable; a headless core has no graphical host to raise.
Use the application menu's Quit application action, tray Quit, or `rivu quit`
to stop the core. Quitting also removes the tray item and releases desktop media
controls; closing only the window does not.

`interface.tray_enabled` controls tray startup and takes effect after restarting the
graphical host, not merely reopening its window. The tray requires a session
D-Bus and a StatusNotifier-compatible desktop host. Bus connection and watcher
registration run in the background without delaying the window or playback;
failures are logged and leave both usable. A watcher that starts or restarts
later is registered automatically. Quitting cancels pending connection and
registration work rather than waiting for the desktop host to reply.
Its menu offers Play/Pause, Previous, Next, Shuffle, Repeat, and Quit.
Repeat follows the cycle described under
<<_transport_and_timing,Transport and timing>>.

== Album artwork panel

The built-in *Default* layout includes Album artwork for the current playback
track. Existing saved layouts are not overwritten: add *Album artwork* from the
panel catalog. Unlike Track details, browsing or selecting a different library
track does not change this panel.

Use the panel's right-click Style or Rotation actions for immediate changes, or
Artwork settings to edit its options with Apply and Discard. These choices are
saved with the layout and survive docking, layout duplication, and reload.
Settings → Interface → Album artwork changes defaults for new panels without
overwriting existing panels. See
link:01_config.adoc#_album_artwork[Album artwork configuration] for styles,
animation parameters, defaults, and shared frame rate.

Rotation follows playback while the panel is visible. Pausing or hiding it retains
the angle without advancing hidden time; stopping, changing tracks, or choosing
Static resets the cover upright. Missing artwork uses the generated default cover.
Still Mode does not affect cover loading or rotation. Panels share cover loading
but retain independent rotation state. Track details keeps its full, static preview.

== MPRIS and artwork

`interface.mpris_enabled` enables desktop media controls for graphical and headless cores
and can be changed while running. Registration runs in the background and does
not delay the first window or playback. Disabling it or quitting cancels an
unfinished registration without waiting for a session-bus reply. A session D-Bus
is required; unavailable media controls are reported in status without preventing
playback. If enabling fails, disable and re-enable the setting after restoring
the session bus; registration does not retry automatically.

MPRIS and Track details prefer embedded front-cover artwork, then another
supported image. Without a cover, MPRIS uses the bundled icon; Track details uses
the generated default artwork, including while a cold lookup is pending.
Actual covers keep their original aspect ratio in the full, static preview.
Local images are cached under the data directory's `artwork/` and exposed through
`mpris:artUrl` when available. Background loading updates the selected preview
and desktop metadata when ready. Cache failures do not prevent playback.
Use link:01_config.adoc#_artwork_cache_maintenance[Settings artwork maintenance]
to inspect disk usage and manually clean expired, unprotected cover files.

MPRIS supports transport, volume, shuffle, and repeat; only rate `1.0` is supported.
Relative `Seek` beyond a known end advances when a next occurrence is available;
out-of-range `SetPosition` is ignored. `OpenUri` is rejected: import media first.
`Raise` is unavailable for a headless core, while `Quit` remains available.
Next and Previous preserve paused or stopped state when used through MPRIS.
Navigation uses the authoritative state when the core executes it, without a
temporary Playing transition or a later status-restoration command. Stopped
navigation selects the occurrence without opening its decoder; paused navigation
loads it paused. CLI, TUI, and GUI Next/Previous retain their normal play-starting
behavior when navigating to another occurrence.
`SetPosition` for an occurrence other than the current one is ignored.
