= Playback
:toc:
:toclevels: 2

Playback follows queue occurrences, with shared controls in the GUI, TUI, CLI
and optional MPRIS service. Output uses native PipeWire; decoder selection and
processing are independent of the output device.

== Transport and timing

Use `rivu playback` for play, pause, resume (`play` without a track ID), stop,
next, previous, seek, volume, shuffle, and repeat controls. Seek positions are
seconds; CLI volume is an integer percentage from 0 to 100.
Volume uses a dB-linear control curve rather than linear amplitude: 0% mutes,
50% is -30 dB, and 100% leaves the source gain unchanged. Keyboard `[` and `]`
change the level by five percentage points (3 dB away from mute). See
link:01_config.adoc#volume[Volume configuration] for fractional values.

`playback play` resumes a paused decoder. When stopped, it opens the selected
queue occurrence from the beginning, or the first occurrence if none is selected;
an empty queue is an error. Stop resets the position to zero but retains queue
selection. Pause only changes playing playback; it does not select or open a
track while stopped.

Keyboard volume steps, repeat cycling, and shuffle toggles accumulate against
the core's current state, even before the display updates. Ctrl+Left/Right and
seek-slider arrows seek by five seconds; slider Home/End and terminal
Ctrl+Home/End seek to zero or the known duration. A delayed seek cannot affect a
different queue occurrence. Pointer dragging and CLI seek/volume specify absolute
targets.

Selecting a missing source manually leaves the current track running and reports
an error. If the next entry cannot be opened at natural end, playback stops.

The desktop Playback panel shows title, artist, album, progress, transport, and
volume. Blank artist or album metadata uses the same symbol placeholders and
missing-field tooltips as playlist entries. Its favorite button changes the current
track's library favorite, not the browsing selection. Use the separate Album
artwork panel for covers.
Hover the volume icon or slider to see its current percentage. The same value
remains visible while dragging the slider or using it with keyboard focus.
The crosshair beside its title (*Locate playing entry in Queue*) reveals the
Queue tab and locates the current occurrence, subject to layout locking;
see <<_queue,Queue>>.

Repeat cycles Off, All, and One. Previous restarts the current entry when its
position exceeds three seconds; at or before three seconds it navigates back,
using playback history when shuffling.
With Shuffle enabled, each Next independently chooses a queue occurrence with
equal probability, including the current one. Immediate repeats are expected;
duplicate occurrences increase their track's chances. Previous follows playback
history, retaining up to 4096 occurrences during the running session; Next draws
afresh even after Previous. Changing Shuffle, including through configuration,
starts a new history at the current occurrence. Setting Shuffle to its current
value preserves that history. Repeat One repeats the current occurrence at
natural EOF but does not constrain explicit Next.
CUE playback uses the original source without splitting or transcoding it.
Positions and seeks are relative to the subtrack; pregap directives do not
synthesize silence absent from the source.
Ordinary audio plays to actual decoder EOF; an estimated metadata duration is
not a playback cutoff. An explicit CUE subtrack end remains a hard playback bound.
A rescan can update the catalog's CUE source and boundaries without replacing
the source already loaded for playback. The active track retains its loaded
path, range and duration while editable metadata continues to refresh. Seeking
uses that active range; the next explicit playback start adopts the new catalog source.

Seek targets must be finite, non-negative, and representable on the source
timeline. Invalid targets report an error without stopping playback, including
when rejected after the command was acknowledged; the confirmed position is then
restored. A real decoder seek or output-restart failure stops playback because the
decoder may already have moved. Ordinary file seeks are not clamped by estimated
metadata duration; only an explicit CUE end bounds the target.

Seeking while paused stays paused. If Pause arrives at actual EOF, the next
occurrence is selected but kept paused; Repeat One instead reloads the current
occurrence paused from its start. At queue end with Repeat Off, playback stops.

Pause lets submitted audio finish before making output inactive, retaining unread
audio for resume. The displayed Paused state is the accepted intent, not an
instantaneous hardware mute. Paused wall time does not advance playback or live
analysis. Late heard-audio confirmations can still update listening statistics;
see link:02_library.adoc#_play_counts_and_recent_tracks[Library].

== Queue

Queue entries are independent occurrences, so a track may appear more than once.
The full library can be enqueued without a queue-size cap.
Queue order, removals, and the current occurrence persist in the library database.
Restart preserves occurrence identities, duplicates, and order. Later scans do
not automatically append new tracks. Removing library tracks also removes their
queue and playlist references, never their audio files.

Startup restores the selected occurrence and metadata in Stopped state at position
zero, without opening a decoder. Playback position, playing/paused status, and
shuffle history are not saved. Use Play explicitly to start from the beginning.
Queue mutations save as they execute, independently of Settings Apply, layout
sync, or window close.

If a committed queue edit cannot be refreshed, later selection and edit operations
retry recovery before using it. A failed selection save must also recover before
operations that depend on that selection. Pause and Stop remain available.

Desktop Queue rows use the shared
link:02_library.adoc#_track_information[track information and hover rules].

Use `rivu queue list` to find occurrence IDs for `queue play`, `queue remove`,
and `queue move`. Move positions start at zero. `queue add TRACK_ID...` appends
occurrences; `queue clear` empties the queue and stops playback. `queue list --json`
returns a streamed JSON array of occurrence rows with absolute zero-based positions
and display metadata. Listings stop on concurrent queue content changes; repeat
the listing to obtain a consistent new traversal.

=== Adding local files

Drag ordinary local audio files from a file manager into Queue. A drop in blank
space appends; a drop on a row inserts at that boundary. No configured library
folder is required, and files may be outside configured folders. Files are
registered persistently, reusing existing track identities. Input order and
repeated files are preserved as separate queue occurrences. Adding files neither
starts nor interrupts playback, replaces the queue, creates a playlist, nor
configures a folder.

This operation does not scan parent folders or apply the scan minimum-duration
filter. Directories, CUE sheets, and playlists are not expanded. Unsupported or
unreadable files are skipped and reported; valid files are still added. Registration
and insertion commit together. If the chosen insertion position becomes stale,
the entire operation fails without registering new tracks or appending elsewhere.

[source,sh]
----
rivu queue add-paths song.wav another.flac song.wav --wait
----

For positional CLI insertion, supply both `--index` and `--expected-revision` from
the observed queue state (`rivu --json status`). `--wait` reports the
operation's completion, including skipped-file errors even when valid files were
saved. Registered tracks appear under their configured folder or in
link:02_library.adoc#_other[Other]. Clearing Queue does not remove them from Library.

File additions share one media-task slot with scans, Other checks, and playlist
imports. Accepted-task feedback belongs to the desktop Queue panel; shared status
queries, result dismissal, cancellation, and shutdown are documented under
link:02_library.adoc#_cancellation[Library cancellation]. A failed task can still
have registered files and inserted occurrences, for example when some input files
were skipped or a refresh failed after commit. Inspect its result and the queue
before retrying: replaying a committed addition creates more occurrences.


=== Queue controls

The Queue panel displays occurrences in order and marks the current occurrence.
Use the link:02_library.adoc#_desktop_selection_and_directory_tree[shared selection rules]
for clicks, ranges, and row context menus. Double-click plays that occurrence.
Up/Down navigate the focused queue, Enter plays the selected occurrence, and Delete
removes selected occurrences.
Optional link:02_library.adoc#_desktop_list_search[Desktop list search] filters
the visible occurrences without changing playback order. Selection actions apply
to the matching occurrences; repeated tracks remain distinct queue entries.
Background refreshes preserve the browsing position with or without a search
filter; a shorter result set clamps scrolling only when its new total arrives.


Use the crosshair button (*Locate playing entry in Queue*) in the Queue toolbar
or beside the Playback title to scroll to the current occurrence and briefly
emphasize it. The Playback button reveals an existing Queue tab first, or adds a
Queue panel when the layout is unlocked; it reports an error rather than adding
a missing panel to a locked layout. Duplicate tracks are located by occurrence,
not by their shared track identity. Both buttons also work while paused and are
unavailable without a current occurrence. Locating never changes selection,
playback, or an unsaved Track details draft, and playback changes do not
automatically scroll the queue. A removed occurrence is not replaced by another
duplicate.

Hover a row for Favorite, Play, Remove, Move up, and Move down. These actions
target that occurrence without changing selection; Favorite updates the library
track and all its occurrences. Move up/down is unavailable at the corresponding
end. The toolbar offers multi-selection removal and Save queue as playlist.
Dragging a selected row moves the selected group in its original queue order;
dragging an unselected row moves only that occurrence. The group is fixed at
drag start, even if selection changes during the gesture. Dropping on a row's
upper half inserts before it; its lower half inserts after it. An accent line
marks the insertion boundary. Dropping below the rows appends. Dropping on a
member of the dragged group or pressing Esc leaves queue order unchanged. A drag
is rejected if queue contents change before it is dropped.
Dragging Library tracks or directories, album cards or tracks, recent tracks,
or playlist tracks onto a Queue row uses the same before/after insertion line;
blank space appends. Positional drops are unavailable while Queue is filtered.
If the target queue changes during content resolution, the old position is
rejected rather than falling back to append. Dragging queue occurrences to a
playlist copies every occurrence in queue order, including repeated tracks,
without removing source occurrences.
Removing the current occurrence stops playback; removing other occurrences does
not. Queue controls remain available while the layout is locked.

The Queue panel menu contains Randomize queue, Remove duplicates,
Save queue as playlist, and Clear queue. These actions target the entire queue;
Clear requires confirmation. Track-group actions live in row context menus:
Append to queue, Add to playlist, explicit Favorite and Unfavorite, and removal
of the selected occurrences. Play targets the clicked occurrence. Favorite
changes apply once per library track, including repeated queue occurrences.
See the link:02_library.adoc#_desktop_selection_and_directory_tree[shared track-menu rules].
Randomizing changes queue order without changing the current playback or shuffle setting.
Removing duplicates keeps each track at its first position; if a later duplicate
is playing, playback continues as that track's retained occurrence.

Saving a queue as a playlist: link:03_playlist.adoc#_desktop_ui[Playlists].
Scrolling and query retries: link:02_library.adoc#_paged_views[Library].

== Keyboard controls

GUI and TUI share playback keys outside text editors, menus and dialogs:

[cols="1,2",options="header"]
|===
|Key |Action
|Space |Play/pause
|n / p |Next/previous track
|[ / ] |Lower/raise volume by five percentage points
|r / s |Cycle repeat mode / toggle shuffle
|Ctrl+Left / Ctrl+Right |Seek backward/forward five seconds
|===

The TUI additionally supports `Ctrl+Home` / `Ctrl+End` to seek to the track's
start/known end; `Ctrl+End` does nothing when duration is unknown. The GUI does
not bind these keys or the TUI's bare `q` action; use its window controls and
menus instead.

Bare Left/Right are reserved for container navigation, not seeking. Home/End
select the first/last item in lists supporting row navigation. Enter opens a
directory or plays the current object. `Remove entries` (Delete) removes selected
Queue or playlist entries, never media files; bare `d` is not a removal shortcut.
Undeclared Ctrl/Alt/Shift/Super combinations do not inherit bare-key actions.
Application shortcuts and text editing use Ctrl, not Cmd/Super aliases.

In the TUI, F1 opens context-sensitive help even from the search query editor;
`?` opens it outside that editor. In the GUI, help opens only through *Shortcuts*
in the application menu.
Help scrolls with arrows, PageUp/PageDown, and Home/End. Escape closes GUI help;
F1, `?`, or Escape closes TUI help without acting on the list beneath. Editors
retain their text-editing keys. A focused GUI button owns Enter/Space instead of
also controlling playback.

Reach seek and volume sliders with Tab/Shift+Tab. Arrow keys change seek by five
seconds or volume by five percentage points; Home/End chooses the minimum/maximum.
Seek requires a current occurrence and known positive duration; volume does not.
A slider key ends an active pointer drag so release cannot commit an old preview.
Escape cancels the innermost interaction or leaves the editor first; see
link:01_config.adoc#_desktop_keyboard_navigation[desktop control navigation].

== Output devices and speaker layouts

`playback.output_device` is an exact name from `rivu playback devices`, which lists native
PipeWire sinks only. Omit the setting for the default PipeWire sink, or use
`PipeWire: <node.name>` for a named sink. PipeWire must be running; there is no
direct ALSA output or fallback to a different backend.

PipeWire handles device-rate conversion. Playback stays bound to its selected
sink; invalid or disappearing routes fail explicitly instead of silently
rerouting. Select an available sink and start playback again to recover.
Changing to an invalid or unavailable sink stops playback and keeps the newly
requested setting. Subsequent playback attempts still target that sink; neither
the previous selection nor the default sink is substituted automatically.
Device-application failures are reported even while stopped; reapplying the same
settings validates them again. Choose an available sink, then explicitly restart
playback if the failure stopped it.
Changing the sink or remixing setting rebuilds output at the current position and
preserves paused state. It does not reopen the decoder or apply a newly saved
Decoder hint or read-buffer size.
Recovery uses the old output's final confirmed audible position after retirement,
so audio confirmed during output closure is not replayed.

Multichannel output preserves speaker identities. `playback.pipewire_auto_mix` is enabled
by default and permits PipeWire remixing with channel-level normalization to prevent
gain from summed channels. Downmixing may therefore reduce the level. Disable it to
require a compatible sink layout without remixing. Both modes validate the actual
selected sink and its negotiated speaker layout, including changes to links while
playing. Unsupported routes report an error rather than using an unrelated compatible sink.

Rivu sends 32-bit float audio at the decoded sample rate and suggests that rate to
PipeWire without forcing the shared graph. Actual graph and device rates depend on
system policy and device support; source-rate output alone is not a bit-perfect
guarantee. Floating-point peaks above full scale are preserved before device
conversion, not clipped by Rivu. Downstream gain and integer device conversion can
still cause clipping; Rivu does not add a limiter or dither to its float output.
Non-finite decoded samples, including overflow during conversion to 32-bit float,
are replaced with silence before waveform generation, analysis and playback.
This does not limit extreme finite amplitudes or provide protection against clipping.

Desktop audio mixers receive the current library/CUE title, artist and album,
including edits made while playing or paused. The application identity remains
Rivu. Mixer volume and mute are independent of Rivu's own software volume and
remain effective with remixing disabled.

Unusable output formats or insufficient audio-buffer memory report a playback
error rather than switching routes.

Opening a selection can require decoding forward when seeking is unavailable or
duration is unknown. This work is cancellable, but a distant target can require
reading to EOF. Estimated duration is only a seek aid, not a playback cutoff.
A valid selection exhausted at open returns EOF; a source with no decodable audio
fails. Seekable native Matroska supports backward seeking, including after EOF;
unseekable sources retain forward-only scanning.


== Optional FFmpeg decoder

Native decoding is the default. Enable `playback.ffmpeg_enabled` for sources the
native decoder does not support. Container extensions such as MKV or MP4 alone
do not determine whether FFmpeg is needed; the contained codec also matters.
In Auto mode, FFmpeg loads when a native decoder cannot support a source,
not during startup or status queries. Opening a track whose
decoder hint is FFmpeg also loads the extension directly. Decoder status shows
`not loaded` until a load is attempted; missing or incompatible libraries are
reported when needed, and the load result is retained until restart.
Native support is checked through the first packet decode: an unsupported
format at that point also permits Auto fallback. Corrupt input and cancellation
do not trigger a decoder fallback.

Track details provides a *Decoder hint* selection. Use *Save* to commit it together
with tag edits; an unsaved selection does not affect playback or waveform decoding:

* *Auto* preserves automatic native-first selection and FFmpeg fallback.
* *Native* uses only the native decoder, without FFmpeg recognition or fallback.
* *FFmpeg* loads and uses FFmpeg directly. The global setting must be enabled;
  disabling it, missing libraries, or a native-only build reports an error rather
  than falling back to native decoding.

The saved hint survives rescans and restart, is independent for each CUE subtrack,
and applies to the next source open or explicit full-waveform request. It does
not reopen current playback. Changing it cancels an in-flight full-waveform
request and discards its completed preview; request a fresh preview explicitly.

In Auto mode, once FFmpeg is loaded and enabled, future WAVE opens use its format
recognition; ordinary PCM still uses the native decoder. Recognition is not proof
that a file has been fully validated. In Native mode, or Auto mode with FFmpeg
disabled or not loaded, DTS inside a PCM-labelled WAVE may be treated as PCM,
including incorrect metadata and noise on playback. For DTS-WAV, select FFmpeg
and enable the extension; no prior load is required. An explicit enhanced probe
runs in a separate process and does not load FFmpeg in a running playback instance.

Library rows are not automatically reprobed after FFmpeg loads; use a forced
rescan to refresh stored metadata. Probe commands and recognition provenance:
link:02_library.adoc#_metadata_and_favorites[Library].

Build prerequisites and ABI compatibility: link:../readme.adoc[README].
Enablement, disabling an active decoder, and build-feature restrictions:
link:01_config.adoc[Configuration].

== Playback metadata updates

Successful playback can improve the library's bitrate information without
rewriting media files. Reliable fixed-encoding metadata can confirm a value at
open. Otherwise, complete playback from the beginning to actual source EOF may
measure the selected encoded audio stream during normal decoding, without an
additional analysis pass.

Seeking, restricted CUE playback, early stop, decode errors, incomplete stream
statistics, or unsupported measurements leave the value estimated or unknown.
Pausing alone does not invalidate measurement. A confirmed bitrate does not
certify file integrity and is never replaced by an estimate. CUE records use
whole-source metadata, not source bytes divided by subtrack duration.

Enrichment updates open views without changing membership or counts. It uses the
already selected decoder and never loads FFmpeg or changes decoder selection.


== Terminal client

The TUI controls the running core. Leaving it does not stop playback. `Tab` cycles
Queue → Playlists → Library; `Shift+Tab` reverses direction, retaining each page's
selection and scroll position. `Right` opens a playlist; Enter plays the selected
playlist, track, or queue occurrence. In playlist details, `a` enqueues the selected
track. Selecting a row alone does not change playback.

Use `/` to open Library search. Tab/Shift+Tab switches between query and results;
Enter from the query focuses results, and Enter on a result plays it. Esc from
results returns to the query; Esc from the query returns to Queue. The query owns
printable characters, including playback shortcuts and `?`; F1 still opens help.
Text edits use the shared
link:02_library.adoc#_desktop_list_search[delayed application and immediate clearing].

Library also offers link:02_library.adoc#_other[Other], a flat collection of
registered tracks outside configured folders (all tracks when no folders are
configured). Within Other, `/` edits its own search, applying text changes
immediately; `Alt+f` and `Alt+m` toggle
favorite-only and missing-only filters, and `Alt+s` cycles ID, album, and most-played
sorting. Selection follows the same track ID through sort/filter changes and
library refreshes while that track remains in the results, including when another
change arrives before relocation or page loading finishes. Obsolete results cannot
move selection back. `e` appends the selected track; `Alt+e` appends the complete
Other collection independently of filters. `Alt+c` checks its registered files;
`Alt+Shift+c` forces metadata rereading. The collection-wide Alt actions also work
on the Other header.

Outside the query editor, `m` toggles the selected track's favorite in Queue,
Library, Search, or playlist entries. It never changes a whole directory or
playlist. Track lists prioritize titles as the terminal narrows and keep compact
metadata, favorite, playback-state, and missing-file indicators where space permits.
Truncation does not change stored metadata.

Press `i` outside the query editor for read-only details of the selected track,
directory, or playlist. Playback changes do not replace that target. Track details
includes tags, technical audio metadata, source path, Decoder hint, and playback
history. Missing-file paths remain available; unknowns use `—`, zero counts `0`,
and estimated bitrates `≈`. Loading, query failure, removal, and no selection are
distinct states. This is not a tag editor or decoder control.

Scroll details with arrows, PageUp/PageDown, or Home/End; Esc closes it and restores
the source selection and scroll position. Help and details keep navigation inside
the overlay, preventing playback, activation, tab switching, or removal from
operating the underlying list. Details is an overlay, not a fourth top-level tab.

The bottom area keeps position, duration, volume, shuffle, and repeat available
while browsing. Notifications distinguish warnings and errors; ordinary playback
updates do not replace a still-visible failure. Queue briefly shows an `F1 / ?`
help hint on first entry; open help for the current context's bindings.

Left/Backspace goes to a parent directory; Left/Esc leaves playlist details.
Esc returns from Search, Library tree, or playlist catalog to Queue. `q` closes
the client outside Search and also works during initial connection. Ctrl-C exits
from every view, including editors, overlays, and connection setup. `SIGINT` and
`SIGTERM` also close only the client. All these exits restore terminal mode,
screen, and cursor, leaving the core running.

A shutdown snapshot exits normally, even during first load. A Watch connection
ending without shutdown state is an error, but still restores the terminal.

== Desktop tray and window lifecycle

Closing the window, including the application menu's Close window action, leaves
the core and playback running. Activate the tray icon, use `rivu gui`, or invoke
MPRIS `Raise` to reopen or focus the window. CLI and MPRIS reopening work with
the tray disabled or unavailable; a headless core has no graphical host to raise.
Use the application menu's Quit application action, tray Quit, or `rivu quit`
to stop the core. Quitting also removes the tray item and releases desktop media
controls; closing only the window does not.

`interface.tray_enabled` controls tray startup and requires restarting the graphical
host, not just reopening its window. The tray needs session D-Bus and a
StatusNotifier-compatible desktop host. Failures are logged without preventing
window use or playback; a watcher starting or restarting later is registered
automatically.
Its menu offers Play/Pause, Previous, Next, Shuffle, Repeat, and Quit.
Repeat follows the cycle described under
<<_transport_and_timing,Transport and timing>>.

== Album artwork panel

The *Album artwork* panel follows the current playback track, independently of
Library selection and Track details. Add it from the panel catalog; it is also
included in the built-in *Default* layout.

Use the panel's right-click Style or Rotation actions for immediate changes, or
Artwork settings to edit its options with Apply and Discard. These choices belong
to the panel instance and survive docking and layout duplication in memory.
Use layout sync or quit the application normally to persist them across restarts;
instance Apply and closing the desktop window do not write `layout.json`.
Settings → Interface → Album artwork changes defaults for new panels without
overwriting existing panels. See
link:01_config.adoc#_album_artwork[Album artwork configuration] for styles,
animation parameters, defaults, and shared frame rate.

Rotation follows playback while the panel is visible. Pausing or hiding it retains
the angle without advancing hidden time; stopping, changing tracks, or choosing
Static resets the cover upright. Animated source covers can continue while paused
or Static; both animation types use the shared frame-rate cap. Lower caps skip
source frames without slowing their timeline. Hiding the panel stops both kinds
of animation, and rotation resumes without catching up on suspended time.
Missing artwork uses the generated default cover. Still Mode does not affect cover
loading or animation. Panels share cover loading but retain independent rotation
and source-animation state. Track details keeps its full, static preview.

== MPRIS and artwork

`interface.mpris_enabled` controls desktop media integration in graphical and
headless cores and can be changed while running. It requires session D-Bus;
registration failure appears in status without preventing playback. Restore the
bus, then disable and re-enable the setting to retry registration.

MPRIS, Track details, album cards, and the Album artwork panel prefer embedded
front-cover artwork, then another supported embedded image. If none is available,
Rivu checks only the audio file's immediate directory, without descending into
subdirectories. Candidate stems must be exactly `cover`, `folder`, or `front`, in
that order, ignoring case. Supported extensions are PNG, JPG/JPEG, GIF, WebP, BMP,
TIF/TIFF, and ICO, also ignoring case. Within each priority, filenames sort
case-insensitively with their original bytes as a tie-breaker. Invalid,
unsupported, or oversized candidates are skipped. File contents determine the
cached image format; an extension alone does not establish it.
The GUI shows a default cover until a real cover is ready or when none is found.
MPRIS uses the bundled application icon as its fallback. Directory discovery is
cached, not watched for edits; moving a track retries it, otherwise restart Rivu
to reliably rediscover changed directory covers. Encoded-file and decoded-image
limits are configured separately in
link:01_config.adoc#_desktop_settings[Settings].
Actual covers keep their original aspect ratio in the full, static preview.
Local images are cached under the data directory's `artwork/` and exposed through
`mpris:artUrl` when available. Background loading updates the selected preview
and desktop metadata when ready. Cache failures do not prevent playback.
Use link:01_config.adoc#_artwork_cache_maintenance[Settings artwork maintenance]
to inspect disk usage and manually clean expired, unprotected cover files.

MPRIS supports transport, volume, shuffle, and repeat; only rate `1.0` is supported.
Relative `Seek` accumulates against Core's position at execution time and stays
bound to the originating queue occurrence. It preserves pause and does nothing
after that occurrence is replaced or playback stops. Strictly exceeding a known
end advances when a next occurrence is available; the exact endpoint seeks within
the current occurrence, and the queue tail is unchanged when no next item exists.
Seeks within the current occurrence remain available during scan or external-file
Saving and database isolation, just like `SetPosition`. Only an over-end seek
that needs Next is rejected by database admission; ignored stale/stopped requests
and tail no-ops do not touch the database or change deferred navigation intent.
Out-of-range `SetPosition` is ignored. `OpenUri` is rejected: import media first.
`Raise` is unavailable for a headless core, while `Quit` remains available.
Next and Previous preserve paused or stopped state when used through MPRIS.
Stopped navigation selects an occurrence without opening its decoder; paused
navigation loads it paused. CLI, TUI, and GUI Next/Previous instead start playback
when navigating to another occurrence.
`SetPosition` for an occurrence other than the current one is ignored.

== Equalizer and processed audition

Use the link:27_audio_processing.adoc[Audio processing workflow] for Monitor EQ,
restoration, speech enhancement, separation, and graph audition. Processing never
replaces source media. Original returns from audition to source playback; Monitor
EQ remains in both paths, so keep EQ and level fixed for comparisons. Export a
retained graph output explicitly for a durable WAV; audition results stay in memory

== Audio runtime crate

The `rivu-audio` crate provides decoding, probing, output, and playback workers.
`ProbeResult` reports the actual probing and decoding implementations independently
using `AudioBackend`; these results are distinct from the requested `DecoderHint`.
Application ownership is described in
link:21_ipc.adoc#_core_and_client_boundary[IPC]; build and runtime prerequisites
are in link:../readme.adoc[README].
