= Playback
:toc:
:toclevels: 2

Playback follows queue occurrences, with shared controls in the GUI, TUI, CLI
and optional MPRIS service. Output uses native PipeWire; decoder selection and
processing are independent of the output device.

[[audio-formats]]
== Audio format support

Common input formats and what you need to play them:

[cols="1,2",options="header"]
|===
|Input |Playback requirements

|FLAC, MP3, WAV/AIFF (PCM), Ogg (Vorbis/Opus), M4A (AAC/ALAC)
|Native decoding. Native Opus supports mono and stereo with mapping family 0;
native AAC supports AAC-LC up to stereo. Other AAC profiles and multichannel
AAC need FFmpeg.

|Additional codecs, such as DTS
|Enable the <<optional-ffmpeg-decoder,FFmpeg extension>>.

|DSD (`.dsf`, `.dff`)
|Requires FFmpeg. <<dsd-playback,Plays as PCM>>; no native DSD output or DoP.

|Tracker (`.mod`, `.xm`, `.it`, `.s3m`)
|Requires FFmpeg with the <<_tracker_modules_and_dsd_files,`libopenmpt` demuxer>>.

|Standard MIDI (`.mid`, `.midi`), formats 0 and 1
|Uses Rivu's MIDI synthesizer with a <<midi-playback,General MIDI SoundFont>>.
|===

During directory scans, the filename extension identifies candidates, not
playability. A container such as MP4 or MKV can hold different audio codecs, and
the codec determines whether it can play natively or needs FFmpeg. To check a
specific file without adding it to the library, use `rivu library probe PATH`.
Add `--enhanced` to load FFmpeg for that command only; it does not enable FFmpeg
in a running instance.

See link:02_library.adoc#roots-and-scanning[Library scanning] for importing
files and link:07_audio_processing.adoc#encoded-export[Encoded export] for
writable output formats.

[[optional-ffmpeg-decoder]]
=== Optional FFmpeg decoder

To use the extension, build with the `ffmpeg` feature and set
`playback.ffmpeg_enabled = true` (off by default). The installed FFmpeg must
provide the demuxer and audio decoder for the file.

For tracks other than MIDI, use *Decoder hint* in Track details to choose the
playback backend. The choice saves immediately, independently of tag edits:

* *Auto* preserves automatic native-first selection and FFmpeg fallback.
* *Native* uses only the native decoder, without FFmpeg recognition or fallback.
* *FFmpeg* uses the extension directly, with no fallback to the native decoder
  if the extension is disabled or unavailable.

The saved hint survives rescans and restart, is independent for each CUE subtrack,
and applies to the next source open or explicit full-waveform request. It does
not reopen current playback. Changing it cancels an in-flight full-waveform
request and discards its completed preview; request a fresh preview explicitly.

In Auto mode, FFmpeg loads when native support is missing, including during
initial decoding. Corrupt input and cancellation do not trigger fallback.
An explicit FFmpeg hint also loads it on open. Startup and status queries do
not load it; decoder status shows `not loaded` until the first attempt, whose
result is retained until restart.

In Auto mode, once FFmpeg is loaded and enabled, future WAVE opens use its format
recognition; ordinary PCM still uses the native decoder. Recognition is not proof
that a file has been fully validated. In Native mode, or Auto mode with FFmpeg
disabled or not loaded, DTS inside a PCM-labelled WAVE may be treated as PCM,
including incorrect metadata and noise on playback. For DTS-WAV, select FFmpeg
and enable the extension; no prior load is required.

Library rows are not automatically reprobed after FFmpeg loads; use a forced
rescan to refresh stored metadata. Probe commands and recognition provenance:
link:02_library.adoc#metadata-and-favorites[Library].

Build prerequisites and ABI compatibility:
link:00_getting_started.adoc#ffmpeg-and-native-only-builds[FFmpeg and native-only builds].
Enablement, disabling an active decoder, and build-feature restrictions:
link:01_config.adoc[Configuration].

[[_tracker_modules_and_dsd_files]]
=== Tracker modules

Modules use their own instruments and samples. Rivu exposes one track per
file, using FFmpeg's default subsong selection. Tags come from Lofty, which
does not read module titles. The reported sample rate and channel count
describe the rendered PCM, not an encoded PCM stream in the file.

[[dsd-playback]]
=== DSD files

FFmpeg decodes DSD to PCM for Rivu's normal processing and output path. The
reported sample rate is the decoded PCM rate, not the DSD bit clock.

[[midi-playback]]
=== MIDI file playback

The default build includes the `midi` feature. Scanning and probing read the
sequence without loading a SoundFont. If setting a *Decoder hint* for a MIDI
track, use *Auto* or *Native*: forcing *FFmpeg* fails. Playback, full waveforms
and exports use the same SoundFont.
Files that use more than one MIDI port are rejected. System-exclusive messages
and MIDI hardware input/output are not supported.

Playback requires a General MIDI SoundFont (`.sf2`). On Arch Linux, install
`soundfont-fluid` for `/usr/share/soundfonts/FluidR3_GM.sf2`. On other distributions,
Rivu also checks `/usr/share/sounds/sf2/FluidR3_GM.sf2` and
`/usr/share/sounds/sf2/default-GM.sf2`. To use a different bank, set
`RIVU_MIDI_SOUNDFONT` to its absolute path in the environment that starts Core.
Restart Core to change banks or retry a failed load. Rivu does not ship a bank
or download one automatically.

The playback duration includes one second for note release and effects after
the last track ends. Seeking ahead of the current synthesis cursor renders and
discards the intervening audio; seeking behind it rebuilds synth state from the
beginning. Long seeks can therefore take more work than in a WAV file.

[[transport-and-timing]]
== Transport and timing

Use `rivu playback` for play, pause, resume (`play` without a track ID), stop,
next, previous, seek, volume, speed, shuffle, and repeat controls. Seek positions are
seconds; CLI volume is an integer percentage from 0 to 100.
Volume uses a dB-linear control curve rather than linear amplitude: 0% mutes,
50% is -30 dB, and 100% leaves the source gain unchanged. See
link:01_config.adoc#volume[Volume configuration] for fractional values and
<<keyboard-controls,Keyboard controls>> for relative volume steps.

[[playback-speed]]
=== Playback speed

Playback speed ranges from 0.5× to 2× and preserves pitch. Set it with
`rivu playback speed 1.25`, the keyboard (<<keyboard-controls,Keyboard controls>>)
or MPRIS `Rate`. It applies to every track until the instance exits; each launch starts
at 1×, and the setting is not saved in the configuration. A speed other than 1×
appears in the desktop transport, the terminal status row and `rivu status`;
JSON status always includes `playback.playback.speed`.

A change restarts output at the audible position, like a seek, so the change is
audible after a short output restart rather than instantly. Positions, durations,
seeks and CUE boundaries stay in track time: a 4-minute track still shows 4:00
and finishes after 2 minutes at 2×. Play-count thresholds also measure track time
heard, so the same portion of a track counts at any speed.

At 1× audio passes through unchanged. Other speeds time-stretch the processed
signal after audio processing and before output, using the bundled
link:../vendor/signalsmith-stretch/README.adoc[Signalsmith Stretch] library.
While stretching, visualizations show the stretched audio as heard for either
`visualizations.general.signal` value; `before` samples have no one-to-one output
frame to align with. See link:23_visuals.adoc[Visualizations].

[[replaygain]]
=== ReplayGain

Enable ReplayGain in Playback settings or with `playback.replaygain_enabled = true`.
Playback applies the library's single track gain in dB. Missing or invalid gain
leaves playback unchanged. Album gain is not used. This is a fixed adjustment,
not dynamic compression or a loudness scan.

The switch and edits to the playing track take effect without restarting playback;
master volume remains independent. ReplayGain is playback-only and does not change
source samples, stored files, or processing exports. Scanning and explicit file-tag
operations are described under link:02_library.adoc#inline-track-details-edits[Track details].

`playback.replaygain_peak_policy = "prevent_clipping"` optionally constrains
the requested gain using `REPLAYGAIN_TRACK_PEAK` from the opened original source:
the applied dB gain is the smaller of the requested gain and `-20*log10(peak)`.
The default `off` preserves the requested gain, including positive gain that can clip.
Peak tags are runtime-only: opening reads them without changing library records
or source files. Missing/invalid peaks leave gain unchanged and are reported as unknown.
Processed PCM and graph auditions never reuse original-source peaks. Master volume
does not influence the peak constraint; disabling ReplayGain disables the policy.
The constraint covers source sample peaks only, not true peaks, later EQ/mixing,
PipeWire processing or device conversion. Output diagnostics show requested/applied
gain and the peak basis independently of final measured output levels.

[[output-diagnostics]]
=== Audio output diagnostics

Open the information button in the Playback panel for Audio diagnostics.
The Copy button beside Close copies the complete diagnostic text, including rows
outside the visible scroll area. Source and application-stream speaker positions
use the same abbreviations, such as `FL` and `FR`.
`rivu status -v` includes the runtime audio diagnostics; `rivu --json status`
places the snapshot under `playback.playback.audio_output`. No diagnostics are
written to the database or periodically logged. The snapshot is retained after
Stop and cleared when a new queue occurrence is selected; exiting the instance
discards it.

Details distinguish the actual decoded/audition source, applied processing and gain,
negotiated application stream, connected PipeWire sink and permitted remixing.
The PipeWire graph clock shows the quantum in frames and, when the rate is known,
milliseconds. The stream-to-graph row compares the nominal rates: a mismatch
shows the conversion direction, while equal rates do not establish bit-perfect
output. Resampling quality is the `resample.quality` stream property read after
negotiation, including client overrides; it is not a quality measurement and does
not describe sink-side conversion. Graph clock observations are not physical-device
parameters; unavailable hardware facts remain unknown. Permission to remix does
not prove a remix occurred.

Rivu supply-underrun events count contiguous shortages, with missing frames and
callback counts. Startup wait, pause and confirmed EOF padding are not underruns.
A shortage pending confirmation remains visible as supply wait: later PCM proves
a gap, while a published final input boundary can prove normal EOF padding.
Segment counters restart when output is rebuilt; session totals retain confirmed
underruns across seeks, device changes and audition replacement. These counters do
not claim to include every PipeWire or hardware xrun.

Sample peaks and over-range frame counts are measured after Rivu DSP and software
gain, before PipeWire. A frame counts once if any channel exceeds full scale.
Recent peak and headroom use a short callback-time window; peak hold covers the
output segment. Silence, no measurement and unknown hardware state remain distinct.
Negative sample headroom indicates downstream clipping risk, not proven clipping;
sample headroom is not true-peak headroom. Dynamic snapshots are rate-limited and
paused playback does not create a diagnostics polling timer.

Accumulated source loudness uses BS.1770 on decoded PCM before application DSP and
gain. It covers the current playback segment, including bounded prefetch, not a
whole-track scan; seek/source changes reset it and pause retains it. Reference gain
targets −18 LUFS without peak limiting and never changes tags or playback gain.
Insufficient data and sources without original PCM show `-`.

=== Playback navigation

`playback play` resumes a paused decoder. When stopped, it opens the selected
queue occurrence from the beginning, or the first occurrence if none is selected;
an empty queue leaves playback stopped without error. Stop resets the position to zero but retains queue
selection. Pause only changes playing playback; it does not select or open a
track while stopped.

To play a library track, use `rivu playback play TRACK_ID`. This starts the first
existing occurrence of that track in queue order, or appends one if the track is
not queued. It does not replace the queue. Use `rivu queue play QUEUE_ID` when a
particular occurrence matters; track IDs and queue occurrence IDs are not
interchangeable. GUI and TUI Play actions on Library and playlist tracks use
library-track playback, as do album and Recent track actions. Queue rows use
occurrence playback.

Whole-album and whole-playlist Play replace the queue with the complete saved
order and start its first entry; Append adds the complete collection without
changing playback. CLI `rivu playlist play PLAYLIST_ID` does not ask for confirmation.
The GUI and TUI ask before replacing a nonempty queue when
`interface.confirm_queue_replace` is enabled (the default). Cancelling preserves
queue and playback. Configure it under
link:01_config.adoc#volume-and-playback-controls[Volume and playback controls].

[source,sh]
----
rivu queue add TRACK_ID TRACK_ID
rivu queue list
rivu queue play QUEUE_ID
rivu playback pause
rivu playback play
rivu playback seek 30
----

Keyboard volume and speed steps, repeat cycling, and shuffle toggles accumulate against
the core's current state, even before the display updates. Ctrl+Left/Right and
seek-slider arrows seek by five seconds; slider Home/End and terminal
Ctrl+Home/End seek to zero or the known duration. Interactive seeks, including
absolute slider seeks, bind to the displayed queue occurrence; a delayed request
cannot seek a different occurrence. `rivu playback seek 30` is an absolute
seek without an occurrence ID: it applies to the track current when Core
executes it. CLI volume also specifies an absolute target.

Manual selection stops at a source that cannot be opened or decoded, including
a missing file or a track requiring disabled FFmpeg support. Previous playback
stops; the failed occurrence remains selected at position zero, with playback
Stopped and an error reported. Play or Resume retries it from the beginning.

Automatic advancement with Repeat Off or Repeat One also stops on source errors;
a failed Repeat One source stays selected instead of switching to another track.
With Repeat All enabled, automatic playback skips failed sources and searches for
a playable occurrence from the next position, or a random one when shuffling,
wrapping when necessary. Each queue occurrence is attempted at most once per
search. If all candidates fail, playback stops on the last failed occurrence with
a summary. Output-device, processing, and other system errors stop playback
instead of skipping tracks.
A missing file under an absent, unreadable, or empty music folder, such as an
unmounted drive, also stops playback and reports the folder instead of skipping.

Skipped-source messages are aggregated and remain visible after playback
continues, in the GUI footer, TUI message area, `rivu status -v`, and JSON
status (`system.last_error`). These are application messages, not desktop notifications.

An open failure does not roll back earlier queue edits, including an occurrence
appended by library-track Play. Whole-album and whole-playlist Play are manual
requests: they save the replacement queue before opening its first source;
failure keeps that queue and selects its failed first occurrence rather than
restoring the old queue.

The desktop Playback panel shows title, artist, album, progress, transport, and
volume. Blank artist or album metadata uses the same symbol placeholders and
missing-field tooltips as playlist entries. Its favorite button changes the current
track's library favorite, not the browsing selection. Use the separate Artwork
panel for covers.
Hover or focus the volume control to see its percentage. The title's crosshair
locates the current queue occurrence; see <<queue,Queue>>.

Next and Previous preserve Core's playback state when the command executes,
across CLI, TUI, GUI, tray, and MPRIS controls. Playing continues on the selected
occurrence; paused navigation loads it paused; stopped navigation selects it
without opening a decoder. Use Play or Resume to explicitly start playback.
An earlier queued Pause or Stop therefore also governs a later Next or Previous.

Repeat cycles Off → One → All → Off. Manual Next or Previous without a target leaves
the current occurrence and position unchanged. Previous ignores playback position
and follows queue order, or navigation history when shuffling.
With Shuffle enabled, each Next independently chooses a queue occurrence with
equal probability, including the current one. Immediate repeats are expected;
duplicate occurrences increase their track's chances. Previous follows playback
history, retaining up to 4096 occurrences during the running session; Next draws
afresh even after Previous. Changing Shuffle, including through configuration,
starts a new history at the current occurrence. Setting Shuffle to its current
value and resuming the same stopped occurrence preserve that history. Repeat One
repeats the current occurrence at natural EOF but does not constrain explicit Next.
CUE playback uses the original source without splitting or transcoding it.
Positions and seeks are relative to the subtrack; pregap directives do not
synthesize silence absent from the source.
Ordinary audio plays to actual decoder EOF; an estimated metadata duration is
not a playback cutoff. An explicit CUE subtrack end remains a hard playback bound.
A rescan does not replace an already loaded CUE source or bounds. Seeking uses
the loaded range; the next explicit playback start adopts catalog changes.

Seek targets must be finite, non-negative, and representable on the source
timeline. Invalid targets report an error without stopping playback, including
when rejected after the command was acknowledged; the confirmed position is then
restored. A real decoder seek or output-restart failure stops playback because the
decoder may already have moved. Ordinary file seeks are not clamped by estimated
metadata duration; only an explicit CUE end bounds the target.
Older progress updates cannot overwrite a newer seek target. Rejecting a seek
restores the confirmed position and normal progress updates continue; listening
statistics retain audio already heard from that source.

Seeking while paused stays paused. If Pause arrives at actual EOF, the next
occurrence is selected but kept paused; Repeat One instead reloads the current
occurrence paused from its start. At queue end with Repeat Off, playback stops.

Pause lets submitted audio finish before making output inactive, retaining unread
audio for resume. The displayed Paused state is the accepted intent, not an
instantaneous hardware mute. Paused wall time does not advance playback or live
analysis. Late heard-audio confirmations can still update listening statistics;
see link:02_library.adoc#play-counts-and-recent-tracks[Library].

[[queue]]
== Queue

Queue entries are independent occurrences, so a track may appear more than once.
The full library can be enqueued without a queue-size cap.
Queue order, removals, and the current occurrence persist in the library database.
Restart preserves occurrence identities, duplicates, and order. Later scans do
not automatically append new tracks. Removing library tracks also removes their
queue and playlist references, never their audio files.

Startup restores the selected occurrence and metadata in Stopped state at position
zero, without opening a decoder. Playback position, playing/paused status, and
shuffle history are not saved. Use Play explicitly to start from the beginning.
Queue mutations save as they execute. For their independence from configuration
and layouts, see link:01_config.adoc#persistence-responsibilities[persistence responsibilities].

If a committed queue edit cannot be refreshed, later selection and edit operations
retry recovery before using it. A failed selection save must also recover before
operations that depend on that selection. Pause and Stop remain available.
If startup loading fails before queue restoration, dependent operations retry
queue recovery too. Exiting without a new selection preserves the saved occurrence;
shutdown retries only an unsaved runtime selection.

Desktop Queue rows use the shared
link:02_library.adoc#track-information[track information and hover rules].

Use `rivu queue list` to find occurrence IDs for `queue play`, `queue remove`,
and `queue move`. Move positions start at zero in the queue after removing the
moved selection; the end position is valid, larger positions are rejected.
For `queue move QUEUE_ID INDEX --expected-revision REVISION`, first read
`queue.revision` from `rivu --json status`, then run `queue list` and choose the
position using that listing. Submit the earlier revision; `queue list` binds
its current-occurrence marker and all batches to one revision but does not
print it. If Core rejects a stale revision, fetch the revision and listing
again in that order and choose the position anew.
`queue add TRACK_ID...` appends
every supplied occurrence in argument order without starting playback;
`queue clear` empties the queue and stops playback. Removing queue occurrences
does not unregister their library tracks. JSON listings contain occurrence rows
with zero-based positions and display metadata. For incomplete listing output,
see link:09_cli.adoc#cli-command-conventions[CLI conventions].

[[adding-local-files]]
=== Adding local files

Drag ordinary local audio files from a file manager into Queue. A drop in blank
space appends; a drop on a row inserts at that boundary. No configured library
folder is required, and files may be outside configured folders. Files are
registered persistently, reusing existing track identities. Input order and
repeated files are preserved as separate queue occurrences. Adding files neither
starts nor interrupts playback, replaces the queue, creates a playlist, nor
configures a folder.

This operation does not scan parent folders or apply the scan minimum-duration
filter. Directories, CUE sheets, and playlists are not expanded. Unsupported or
unreadable files are skipped and reported; valid files are still added. Core
rechecks the insertion position before Saving. Registration, insertion, and the
current queue selection are written in one transaction. A stale position fails
the operation without registering new tracks or appending elsewhere.

[source,sh]
----
rivu queue add-paths song.wav another.flac song.wav --wait
----

For positional CLI insertion, read `queue.revision` before listing Queue, as
for `queue move` above. Pass the chosen `--index` and that `--expected-revision`.
A terminal result can report skipped-file errors even when valid files were
saved. Registered tracks appear under their configured folder or in
link:02_library.adoc#other[Other]. Clearing Queue does not remove them from Library.

File additions share the link:02_library.adoc#cancellation[media-task lifecycle]
with scans, Other checks and playlist imports; desktop feedback appears in Queue.
A failed task may still have committed registration and insertion, for example
after skipped inputs or a post-commit refresh failure. Inspect the result and Queue
before retrying: replaying a committed addition creates more occurrences.

=== Queue controls

Queue marks the current occurrence and uses the
link:02_library.adoc#desktop-selection-and-directory-tree[shared selection and track-menu rules].
Double-click or Enter plays an occurrence; Up/Down navigates and Delete removes
selected occurrences. Optional
link:02_library.adoc#desktop-list-search[search] filters the view and selection,
not playback order; repeated tracks remain distinct. Refresh preserves browsing
position where the new result size permits.

Use *Locate playing entry in Queue* in the toolbar or Playback title to reveal and
emphasize the current occurrence, including while paused. The Playback button
opens an existing Queue tab or adds one if the layout is unlocked; it reports an
error if a locked layout has none. Location changes neither selection, playback,
nor the Details target and does not automatically follow playback changes. Without
a current occurrence it is disabled; a removed entry is not replaced by a duplicate.

Hover a row for Favorite, Play, Remove, Move up, and Move down. Actions target
that occurrence without changing selection; Favorite updates the library track
and all its occurrences. The toolbar offers group removal.

Drag a selection to move it in original queue order, or an unselected row to move
only that occurrence. The group stays fixed during the gesture. A row's upper/lower
half inserts before/after it; the accent line marks the boundary, and blank space
appends. Dropping on the group or pressing Esc cancels. Changed queue contents
reject the drag.

Cross-collection drops use these same boundaries. For supported sources, copy
versus reorder semantics, and occurrence preservation, see
link:03_playlist.adoc#transfers-and-queue-saving[Transfers and queue saving].
Removing the current occurrence stops playback; removing other occurrences does
not. Queue controls remain available while the layout is locked.

The Queue panel menu contains Randomize queue, Remove duplicates,
Save as playlist…, and Clear queue. These actions target the entire queue;
Clear requires confirmation. Track-group actions live in row context menus:
Append to queue, Add to playlist, explicit Favorite and Unfavorite, and removal
of the selected occurrences. Play targets the clicked occurrence. Favorite
changes apply once per library track, including repeated queue occurrences.
See the link:02_library.adoc#desktop-selection-and-directory-tree[shared track-menu rules].
Randomizing changes queue order without changing the current playback or shuffle setting.
Removing duplicates keeps each track at its first position; if a later duplicate
is playing, playback continues as that track's retained occurrence.

Saving a queue as a playlist: link:03_playlist.adoc#transfers-and-queue-saving[Playlists].
Scrolling and query retries: link:02_library.adoc#paged-views[Library].

[[keyboard-controls]]
== Keyboard controls

GUI and TUI share playback keys outside text editors, menus and dialogs:

[cols="1,2",options="header"]
|===
|Key |Action
|Space |Play/pause
|n / p |Next/previous track
|[ / ] |Lower/raise volume by five percentage points (3 dB except at mute)
|{ / } |Lower/raise playback speed by 0.05×, within 0.5–2×
|r / s |Cycle repeat mode / toggle shuffle
|Ctrl+Left / Ctrl+Right |Seek backward/forward five seconds
|===

The TUI additionally supports `Ctrl+Home` / `Ctrl+End` to seek to the track's
start/known end; `Ctrl+End` does nothing when duration is unknown. The GUI does
not bind these keys; use its playback controls instead.

Bare Left/Right are reserved for container navigation, not seeking. Home/End
select the first/last item in lists supporting row navigation. Enter opens a
directory or plays the current object. `Remove entries` (Delete) removes selected
Queue or playlist entries, never media files; bare `d` is not a removal shortcut.
Undeclared Ctrl/Alt/Shift/Super combinations do not inherit bare-key actions.
Application shortcuts and text editing use Ctrl, not Cmd/Super aliases.

In the TUI, F1 opens context-sensitive help even from the search query editor;
`?` opens it outside that editor. In the GUI, help opens only through *Shortcuts*
in the application menu.
Help scrolls with arrows, PageUp/PageDown, and Home/End. Escape closes GUI help;
F1, `?`, or Escape closes TUI help without acting on the list beneath. Editors
retain their text-editing keys. A focused GUI button owns Enter/Space instead of
also controlling playback.

Reach seek and volume sliders with Tab/Shift+Tab. Arrow keys change seek by five
seconds or volume by five percentage points; Home/End chooses the minimum/maximum.
Seek requires a current occurrence and known positive duration; volume does not.
A slider key ends an active pointer drag so release cannot commit an old preview.
Escape cancels the innermost interaction or leaves the editor first; see
link:01_config.adoc#desktop-keyboard-navigation[desktop control navigation].

[[output-devices-and-speaker-layouts]]
== Output devices and speaker layouts

`playback.output_device` is an exact name from `rivu playback devices`, which lists native
PipeWire sinks only. Omit the setting to follow the system's default PipeWire
sink, including changes during playback or pause. Use `PipeWire: <node.name>`
to stay bound to a named sink regardless of system default changes. PipeWire must
be running; there is no direct ALSA output or fallback to a different backend.

A missing system default does not interrupt a still-valid route. If the current
route becomes invalid with no replacement default, or a selected route fails to
open, playback stops without guessing a fallback or changing the setting.
Select an available output and explicitly restart playback to recover. Settings
Apply does not resend unchanged output preferences. An explicit device selection
can revalidate the same device while idle without reopening an existing source.

Output and Monitor EQ application failures can still be reported after Stop or
an audition source change, but cannot restart playback or advance the queue.
Errors from superseded settings do not replace the current request's result.

Changing sink or remixing rebuilds output at the final confirmed audible position,
preserving pause without reopening the decoder. The final position and heard time
are retained even if the replacement output fails to open; listening statistics
are not lost or counted twice.
Rebuilding output does not apply a newly saved Decoder hint or read-buffer size.
PipeWire handles device-rate conversion.

Multichannel output preserves speaker identities. `playback.pipewire_auto_mix` is enabled
by default and permits PipeWire remixing with channel-level normalization to prevent
gain from summed channels. Downmixing may therefore reduce the level. Disable it to
require a compatible sink layout without remixing. Both modes validate the actual
selected sink and its negotiated speaker layout, including changes to links while
playing. Unsupported routes report an error rather than using an unrelated compatible sink.

Rivu sends 32-bit float audio at the decoded sample rate and suggests that rate to
PipeWire without forcing the shared graph. Actual graph and device rates depend on
system policy and device support; source-rate output alone is not a bit-perfect
guarantee. When the graph rate differs, PipeWire resamples the stream at Rivu's
requested `resample.quality = 10` instead of its default 4; a `stream.properties`
entry in PipeWire's `client.conf` overrides it. Sink-side device-rate conversion
is outside this setting. See link:91_design_decisions.adoc#DEC-029[resample quality decision].
Floating-point peaks above full scale are preserved before device
conversion, not clipped by Rivu. Downstream gain and integer device conversion can
still cause clipping; Rivu does not add a limiter or dither to its float output.
Non-finite decoded samples, including overflow during conversion to 32-bit float,
are replaced with silence before PCM publication, analysis and playback.
This does not limit extreme finite amplitudes or provide protection against clipping.

Desktop audio mixers receive the current library/CUE title, artist and album,
including edits made while playing or paused. The application identity remains
Rivu. Mixer volume and mute are independent of Rivu's own software volume and
remain effective with remixing disabled.

Unusable output formats or insufficient audio-buffer memory report a playback
error rather than switching routes.

When seeking is unavailable or duration unknown, opening a selection may decode
forward, potentially to EOF. This is cancellable. A valid exhausted selection
returns EOF; a source with no decodable audio fails. Native Matroska supports
backward seeking when seekable; unseekable sources scan forward only.

Native decoding presents the timeline the container declares, not every decoded
frame. Encoder delay and padding are removed for MP4 (a single normal-rate media
edit, otherwise the `iTunSMPB` tag of a file with one audio track, with Opus
codec pre-skip as fallback, plus a shortened final sample), Matroska
(`CodecDelay` and discard padding), MP3
(Xing/LAME header), Ogg Vorbis and Opus. Matroska AAC without discard padding
keeps its trailing padding frames; raw ADTS declares neither and plays whole.
MP4 edit lists with several media edits or a non-unit rate are not applied.
After a seek, native AAC and MP3 output is not guaranteed to be bit-exact with
continuous decoding. For timing ownership and decoder seek recovery, see
link:91_design_decisions.adoc#DEC-027[encoder-delay ownership].

[[playback-metadata-updates]]
== Playback metadata updates

Successful playback can improve the library's bitrate information without
rewriting media files. Reliable fixed-encoding metadata can confirm a value at
open. Otherwise, complete playback from the beginning to actual source EOF may
measure the selected encoded audio stream during normal decoding, without an
additional analysis pass.
For a finite MP4 presentation span, this includes complete priming and boundary
packets needed to decode that span, not wholly hidden trailing media. The
denominator is their encoded duration, not the cropped PCM duration.

Seeking, restricted CUE playback, early stop, decode errors, incomplete stream
statistics, or unsupported measurements leave the value estimated or unknown.
Pausing alone does not invalidate measurement. A confirmed bitrate does not
certify file integrity and is never replaced by an estimate. CUE records use
whole-source metadata, not source bytes divided by subtrack duration.

Enrichment updates open views without changing membership or counts. It uses the
already selected decoder and never loads FFmpeg or changes decoder selection.

For terminal navigation, searches and client shutdown, see
link:08_tui.adoc[Terminal client].

[[desktop-tray-and-window-lifecycle]]
== Desktop tray and window lifecycle

Closing the window, including Close window in the application menu, leaves Core
and playback running. Reopen or focus it with the tray, `rivu gui`, or MPRIS
`Raise`. CLI and MPRIS reopening work without a tray and with a Core started by
`serve`, provided it was built with GUI support. Quit application in the menu or
tray, or `rivu quit`, stops Core and releases the tray and desktop media controls.

`interface.tray_enabled` takes effect on Core restart, not just GUI restart.
The tray requires session D-Bus and a StatusNotifier-compatible host. Failure
does not prevent the window or playback; a later watcher is registered automatically.
The host resolves the `rivu` theme icon, so install icons using the
link:00_getting_started.adoc#build-and-install[installation instructions]. The tray menu
offers Play/Pause, Previous, Next, Shuffle, Repeat, and Quit application. Play/Pause
toggles Core's state at command execution; the asynchronously updated menu label
does not determine the transport command.

[[mpris-and-artwork]]
== MPRIS and artwork

`interface.mpris_enabled` controls desktop media integration in graphical and
headless cores and can be changed while running. It requires session D-Bus;
registration failure, bus loss, and publisher failure appear in status without
interrupting playback. A failed service releases its bus name and does not retry
automatically. Restore the bus if needed, then disable and re-enable the setting
to retry. A re-enable committed while the old service waits for artwork work to
retire is retained and retried after retirement.

MPRIS, Track details, album cards, and the Artwork panel prefer embedded
front-cover artwork, then another supported embedded image. If none is available,
Rivu checks only the audio file's immediate directory, without descending into
subdirectories. Candidate stems must be exactly `cover`, `folder`, or `front`, in
that order, ignoring case. Supported extensions are PNG, JPG/JPEG, GIF, WebP, BMP,
TIF/TIFF, and ICO, also ignoring case. Within each priority, filenames sort
case-insensitively with their original bytes as a tie-breaker. Invalid,
unsupported, or oversized candidates are skipped. File contents determine the
cached image format; an extension alone does not establish it.
Invalid first-frame pixel data falls through to the next candidate just like
invalid headers. Admission and resource bounds are described in
link:22_cache.adoc#artwork-lookup-retention[Artwork lookup and retention].
The GUI shows a default cover until a real cover is ready or when none is found.
GUI defaults, the About logo, desktop/tray icons and the MPRIS fallback share the
same bundled SVG. MPRIS publishes its exported file URL. Directory discovery is
cached, not watched for edits; moving a track retries it, otherwise restart Rivu
to reliably rediscover changed directory covers. Encoded-file and decoded-image
limits are configured separately in
link:01_config.adoc#desktop-settings[Settings].
Actual covers keep their original aspect ratio in the full, static preview.
Local images are cached under the data directory's `artwork/` and exposed through
`mpris:artUrl` when available. Background loading updates the selected preview
and desktop metadata when ready. Cache failures do not prevent playback.
Use link:01_config.adoc#artwork-cache-maintenance[Settings artwork maintenance]
to inspect disk usage and manually clean expired cover files.

MPRIS supports transport, volume, shuffle, repeat and `Rate` from `MinimumRate`
0.5 to `MaximumRate` 2; out-of-range rates are clamped and `Rate` 0 pauses. Relative Seek
accumulates against the current position and stays bound to its queue occurrence;
stale or stopped requests are ignored. Seeking strictly beyond a known end follows
Next, including Shuffle selection and Repeat All wraparound. With no available
Next target it does nothing; the exact endpoint stays within the current occurrence.
Out-of-range or stale `SetPosition` is ignored. `OpenUri` is rejected: import media first. `Raise` requires a Core built
with GUI support; `Quit` also works without it.

MPRIS uses the same Next/Previous commands and execution-time playback-state
semantics as the other controls. Protocol and database-admission details:
link:21_ipc.adoc[IPC].
