= CUE playback

== Import and play

Configure the directory containing the sheet as a library root before importing.
Every source audio file must have a logical path within a configured library root;
it may use another configured root or a symlink to audio outside those roots.
Paths are normalized without resolving symlinks. Logical references outside all
configured roots are rejected before metadata probing or fingerprinting.

[source,sh]
----
rivu library scan album.cue --wait
rivu playlist import album.cue --wait
rivu library list
rivu playback play TRACK_ID
----

Rivu supports standard audio CUE `FILE`, `TRACK`, `INDEX`, `TITLE`, and `PERFORMER`
commands, including single-file and multi-file sheets. Relative source paths are
resolved from the sheet's directory. Sources must be supported audio with a
readable duration; data tracks are not supported.

Each subtrack has its own library identity and statistics. Playback positions and
seeks are relative to the subtrack. Audio is decoded directly from the source,
without splitting or transcoding it. Editing library metadata does not rewrite
the sheet or audio file.

== Boundaries and scanning

* `INDEX 01` sets the start at 75 CD frames per second. The next track's
  `INDEX 01` in the same source sets the end; the final track ends at source EOF.
* `INDEX 00` pregaps belong to the preceding track. `PREGAP` and `POSTGAP` do not
  synthesize silence absent from the source.
* UTF-8, with or without BOM, and BOM-marked UTF-16 are supported.
* Invalid indices, unavailable sources, and out-of-range boundaries reject the
  entire sheet, not just individual tracks.
* Rescanning rereads the sheet while retaining matching track IDs and user data.
  Directory scans avoid additionally importing whole sources represented by CUE
  tracks. Explicitly scanning a source can still import it as a whole track;
  existing whole-track records are not removed.

== Playlist exchange

M3U/M3U8 uses ordinary paths. A CUE path represents all its tracks in sheet order.
Export therefore writes each complete, contiguous, correctly ordered sheet run
as one CUE path. Ordinary audio and complete sheets may be mixed.

Playlists retain the first occurrence of each track ID; repeating a sheet does
not duplicate its tracks. Queues may contain repeated tracks.

Standard M3U cannot select individual CUE subtracks. Partial or reordered sheet
runs cannot be exported losslessly: Rivu reports an error before opening the
output file, preserving any existing file. It neither emits private directives
nor silently expands a selection to the whole album. Such selections can still
be stored inside Rivu. Rescan externally edited sheets before exporting.
